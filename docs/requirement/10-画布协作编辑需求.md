# 画布协作编辑需求

## 1. 原始需求与确认

用户要求完整迁入Lucky画布能力，并明确：“切换我们当前的协作方案为Yjs 协作编辑”。应用服务统一通过Docker启动，保留现有基础依赖。协作能力支持免费生产使用和自托管。

多人编辑、个人贡献撤销、生成来源保护及跨端恢复使用COL编号追踪。数据与引用依赖[需求08](08-画布数据库持久化与DAG需求.md)，实时传输依赖[需求09](09-画布WebSocket实时同步需求.md)。

来源承接：SRC-SAVE-02已授权在调研后整理多人协作工程设计，见[需求08来源表](08-画布数据库持久化与DAG需求.md#11-保存需求来源与归属)。本轮不撤销既有Yjs/Go方向，也不把竞品OT或本地journal自动变成我们的选型。协作规则继续沿FR-COL/BR-COL/AC-COL追踪；客户端origin、光标和共享库功能不等于授权、本人贡献保护或持久确认已经实现。

## 2. 用户与范围

同账号多端使用者、同项目获得授权的编辑者及只读访问者。覆盖节点、关系、Tiptap正文、引用、在线状态、个人撤销和版本恢复。

## 3. 功能需求

| ID        | 能力                                                           |
| --------- | -------------------------------------------------------------- |
| FR-COL-01 | 使用Yjs合并多客户端兼容编辑，同步节点、关系、富文本与引用      |
| FR-COL-02 | 撤销与重做本人的编辑，保留其他人的有效贡献                     |
| FR-COL-03 | 生成结果绑定发起时的输入和引用版本，保留后续用户输入及任务身份 |

在线成员、光标、选择与拖动预览实时可见并在离线后过期。历史版本可浏览，授权恢复生成新的持久版本。个人视图独立保存。

## 4. 业务规则

| ID        | 规则                                                             |
| --------- | ---------------------------------------------------------------- |
| BR-COL-01 | 每份画布具有唯一协作epoch和可核实的持久接受修订；各端最终收敛    |
| BR-COL-02 | 更新接受前校验权限、图、schema和引用，拒绝保持已接受数据完整     |
| BR-COL-03 | 创建、删除、属性、位置、尺寸、连线、分组和富文本均有明确并发语义 |
| BR-COL-04 | 乐观状态与持久状态区分，拒绝后可恢复已接受基线与本页输入         |
| BR-COL-05 | 撤销只作用于本人的贡献，并遵守当前权限、对象和素材约束           |
| BR-COL-06 | 编辑及系统回写使用统一接受合同，持久化与回执分别沿DATA和SYNC专项 |

### 4.1 冲突与恢复的用户可见合同

以下细化BR-COL-02～05，不改变原始能力范围：

- 不同字段/对象及可合并正文的兼容编辑共同保留；同字段互斥赋值按设计的确定性规则得到一个结果，不能宣称“最后到达服务器者必胜”或“每个赋值都同时保留”。被接受后遭并发覆盖与业务拒绝须可区分；不得为了恢复自己旧值而自动循环重提。
- 非法图、无权引用和已删除对象的迟到修改不能因CRDT收敛而被接受。拒绝不污染权威图；依赖被拒更新的后继输入保留在本页恢复区，不直接重放其二进制增量。重新应用会覆盖他人有效内容时，需用户明确处理。
- 稳定对象及引用身份沿DR-DATA-02/03；撤销删除不能擅自退化成“复制成新节点”并遗失原引用/历史。防止旧编辑复活对象的生命周期机制由设计定义和验证，不能以库默认行为代替。
- 个人撤销/重做不得回滚他人的后继字段、正文或依赖关系。如果撤销本人动作已无法独立完成，应说明受阻并保留现状，不能以整图回退或强制删除他人贡献实现“成功撤销”。普通无冲突撤销/重做仍须完成；该例外不能成为整体禁用个人撤销的理由。
- 恢复与重建以当前授权及最新权威基线为准。未知请求先查证；新epoch不自动重放旧输入；尚未恢复或明确放弃的本页内容不得被“已保存”提示掩盖。

## 5. 质量要求

| ID         | 要求                                                       |
| ---------- | ---------------------------------------------------------- |
| NFR-COL-01 | 排空未确认更新后，各端共享内容与数据库投影一致             |
| NFR-COL-02 | 兼容编辑完整保留，接受后的图合法，重复处理保持一次业务效果 |

未确认更新与恢复处理有资源上限；浏览器业务内容保留在本页内存，个人视图偏好按白名单持久化。生产容量以真实测量验收。

## 6. 验收

| ID        | 场景与结果                                                                                        |
| --------- | ------------------------------------------------------------------------------------------------- |
| AC-COL-01 | 两账号修改不同节点及同节点不同属性，兼容修改全部保留                                              |
| AC-COL-02 | 同字段、富文本、删除与编辑、依赖建立交错，结果符合设计规则且图合法                                |
| AC-COL-03 | A编辑后B编辑，A撤销与重做，保留B有效修改                                                          |
| AC-COL-04 | 生成期间产生新输入，结果保留原来源，新输入完整，任务与费用不重复                                  |
| AC-COL-05 | 三客户端并发和连续编辑，覆盖中文、emoji、IME、格式与引用，内容和引用身份一致                      |
| AC-COL-06 | 真实WebSocket提交后回执前断线，他端继续编辑；重连、服务重启与重开后数据库和各端一致，保存状态准确 |

AC-COL-02/03分别检查“accepted但同字段合并值被覆盖”“确定rejected”“无法安全撤销”三类结果；AC-COL-06检查重建期间他人继续编辑、旧epoch原请求查证以及已撤权后的会话隔离。每类须验证内容和提示，不以最终JSON相等单独证明全过程无丢失。

补充检查在线状态过期、撤权、版本恢复、旧画布转换及同一画布写入通道隔离。
