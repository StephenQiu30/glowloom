## 2. 用户目标与统一术语

创作者应能选择一个具体生成任务，也能把一个创作目标交给 Agent；两条路径复用正式能力、资产和费用合同。完成后，结果应可继续作为参考、进入画布/时间线或导出。系统应能回答：正在做什么、使用什么输入、需要什么确认、产物在哪里、实际完成到哪一步、已发生多少消费。

| 概念 | 定义与边界 |
| --- | --- |
| 工作上下文 | 对话、项目、画布、分集或时间线；规定资源归属与写入目标 |
| 创作类型 | 用户任务类别：七种类型；不等同底层模型或服务进程 |
| 子能力/子模式 | 精确的执行语义，如文本朗读、全能配音、歌曲/纯音乐、视频首尾帧、动作驱动 |
| 规划模型 | Agent 理解目标、调用工具与组织结果所使用的 LLM；与媒体模型独立 |
| 媒体模型 | 正式生成所用的精确供应商/模型/能力版本；同名跨渠道也有不同身份 |
| Skill | 可版本化的方法包和约束，依赖受权工具；不是基础模型，不自动授予权限 |
| 专业 Agent | 完成受限职责的子任务上下文；角色存在不等于有并发、音频理解或专属模型 |
| 计划/步骤 | 创作目标的依赖与验收条件；包含输入、责任、输出及是否采用 |
| Operation/尝试 | 已受理的正式业务操作及一次执行身份；幂等重传与显式新尝试不同 |
| 产物/采用 | 可追踪的实际资源及用户或规则明确选中的版本；文本总结不构成采用 |
| 完成 | 分别判断回复、步骤、供应商、归档、工作区写入、导出和结算，不能合成一个布尔值 |

## 3. 七种类型的目标合同

以下为待评审的产品要求；范围是能力类别，不承诺任意供应商、型号或参数都可用。所有格式、大小、数量、时长及模型候选以当前已发布能力为准。

| ID / 类型 | 必要输入及差异 | 可配置约束 | 正式结果与接续 |
| --- | --- | --- | --- |
| FR-MAC-01 / Agent | 目标、已有上下文、合法参考及可选Skill；不明确的交付范围先形成澄清/提案 | 规划模型、媒体偏好/硬约束、总预算、自动化边界 | 可检查计划、正式业务结果、产物引用及可编辑工作区；允许只交付文字方案 |
| FR-MAC-02 / 图片 | 文本与/或该模式允许的参考图、主体；图片理解与生成分别校验 | 媒体模型、比例、清晰度、数量及已支持的专用参数 | 一张或多张独立图片及提交快照；可用作视频参考、角色或画布素材 |
| FR-MAC-03 / 视频 | 区分纯文本、首尾帧、全能参考等实际能力；每个素材有精确角色 | 模型、时长、比例、清晰度、数量与参考约束 | 视频及可验证元数据；可进时间线或被后续任务引用。没有驱动的编辑/长视频/多帧模式不伪装可用 |
| FR-MAC-04 / 音乐 | 区分歌曲与纯音乐等已支持子能力；歌词与风格描述不可混淆 | 音乐模型、智能/指定时长、已支持的歌曲参数 | 音乐资产和真实返回的附加信息；可进时间线。无分轨回执不展示独立分轨 |
| FR-MAC-05 / 音频 | 文本朗读与全能配音分开；音色、参考、台词及时间描述按能力校验 | 模型、音色、语速/音量等实际支持参数；可选字幕 | 音频、播放时长、原始计费时长/字符用量和真实字幕；可用于数字人或时间线 |
| FR-MAC-06 / 数字人 | 基础能力消费角色图和驱动音频；直接台词入口按FR-MAC-07处理 | 当前支持的表演/清晰度/速度参数；不能把竞品档位直接映射成任意型号 | 角色表演视频，保留角色及音频来源、生成尝试与工作上下文 |
| FR-MAC-07 / 数字人文本组合 | 台词+音色须先得到可用配音，再以角色图+已采用音频生成视频；已有音频可跳过配音步骤 | 整体预算与分步费用、采用方式、是否允许后续自动执行 | 至少两个可追踪操作和中间音频；视频失败后可复用原音频，不自动重复收费生成声音 |
| FR-MAC-08 / 动作模仿 | 角色图+动作视频；禁止用提示词替代驱动视频 | 实际动作模型支持的参数及参考限制 | 动作驱动视频；输入角色明确。当前不接prompt的能力须禁用文本并说明原因 |

音乐/音频同属音频产物，数字人/动作模仿同属视频产物，但各自的输入、能力及价格身份必须独立。中间音频与动作视频能否理解，与能否作为生成条件传给驱动分别检查。

## 5. Agent 服务的编排要求

### 5.1 一个创作目标的业务流程

目标与参考进入 → 验证可理解范围 → 形成结构化计划 → 确认必要的输入、候选与预算 → 调用受权业务工具 → 按需等待/采用中间结果 → 写入目标工作区 → 核验交付物及费用 → 汇报实际结果。直接生成绕过规划步骤，继续使用相同正式能力合同。

| ID | 需求 | 可接受结果 |
| --- | --- | --- |
| FR-MAC-17 | 计划步骤声明输入版本、依赖、执行角色、所需工具、产物和完成条件 | 用户可检查步骤与当前阻塞；“写完一段总结”不能让生成、归档或导出步骤自动完成 |
| FR-MAC-18 | 复用 producer 与 script/art/storyboard/shot/voice/edit/qa 专业分工；按实际可用工具限制职责 | 脚本产物有来源；美术/分镜传采用版本；声音传音频与时间信息；剪辑传时间线；QA报告可核查问题 |
| FR-MAC-19 | Skill 为可发现、可选择、版本固定的方法包，按既有权限与预算激活 | 一次运行可查所用版本及依赖；没有可执行工具/driver时诚实阻止，不以技能描述代替执行 |
| FR-MAC-20 | 专业任务输出结构化资源与来源；父任务明确采用后才能作为后续依赖 | 采纳、拒绝、修改和重做有区别；子Agent自然语言声称完成不能直接写业务对象 |
| FR-MAC-21 | 落实需求19 AGH-006已有的实际并行目标，统一预留根预算、约束写入及收束取消 | 无依赖任务可实际并行；状态来自真实任务而非配置数字；依赖未就绪不执行；子任务不能各自花掉同一剩余额度。当前顺序执行是实现缺口，本轮不改代码，限额及安全设计单独细化 |
| FR-MAC-22 | 变更只重做受影响步骤，保留成功产物与采用历史 | 明确依赖失效和新尝试；改配乐不无理由重做全部镜头；改配音后需重新核验受其影响的数字人/剪辑结果 |
| FR-MAC-23 | 提案与正式操作分离，继续使用已有Go审批及Agent树收束/continuation | 人工确认绑定候选、输入、工作区版本与报价；变更或过期后重新核验，Agent不能用“已批准”文本授权自己 |
| FR-MAC-24 | 公开活动展示可理解的计划、工具进度、采用结果和问题 | 不要求展示隐藏思考；模型回答、工具受理、媒体成功与费用状态分别有事实来源 |

### 5.2 逻辑对象及关联要求

此处要求可追踪关系，不指定新表、DTO或接口，不为已有对象引入同义副本。

| 对象 | 必须可关联的信息 | 权威归属 |
| --- | --- | --- |
| 创作目标/运行 | 原始输入快照、工作上下文、用户约束、采用Skill及规划模型版本、预算 | 现有Agent运行及Go授权/预算，各管自己的状态 |
| 计划步骤/专业任务 | 输入版本、依赖、责任、工具回执、结果、采用及重做关系 | Agent执行状态；正式资源仍由业务模块持有 |
| 生成请求/Operation | 创作类型、精确子模式、模型/配置/价格版本、引用、参数、请求身份 | Go正式业务操作 |
| 产物 | 操作来源、归属、媒体类型、实际元数据、存储身份、上游素材版本 | Go资产/业务模块；前端与Canvas引用 |
| 工作区变更 | 目标画布/分集/时间线、基准版本、已采用素材、正式写入回执 | 既有业务写入口及协作合同 |
| 消费/结算 | 原调用身份、报价/预算占用、实际用量、未知/待核对状态、最终账本回执 | 既有计量、积分和钱包 |

### 5.3 服务职责约束

| 现有模块 | 应承担的职责 | 边界 |
| --- | --- | --- |
| 前端 | 类型选择、共享草稿、参考与参数交互、确认、进度、结果及编辑入口 | 不自行判断消费成功、退款、上游取消或最终业务完成 |
| Agent | 持久化规划、受限角色/Skill、任务依赖、结果采用、工具提议、恢复执行 | 不持有供应商凭据、不直写业务表、不另建钱包或绕过正式工具出站 |
| Go业务后端 | 身份、资源、模型发布/出站、报价、正式命令、Operation、资产、计费与原回执核对 | 不复制Agent计划/子会话状态机 |
| Canvas与现有编辑模块 | 正式资源的协作呈现与编辑，按已有版本合同同步 | 不把本地节点变化当作供应商生成或资产归档成功 |
| 供应商适配器 | 每个精确能力的输入映射、提交/查询、结果及用量归一 | 不用统一文本请求抹平协议差异，不隐含承诺取消/回调 |

## 6. 执行状态、计费、恢复及产物接续

| ID | 需求 | 可接受结果 |
| --- | --- | --- |
| FR-MAC-25 | 分开呈现Agent运行、媒体Operation、归档/工作区写入、结算状态 | Agent回复结束后，媒体仍可排队；供应商成功但归档失败不展示“可下载”；已交付但待结算不能当免费 |
| FR-MAC-26 | 停止Agent、请求取消媒体、供应商确认取消、退款为不同动作和事实 | 供应商不支持取消时明确说明；停止保留已完成结果并阻止新的未授权动作；不承诺回收已发生费用 |
| FR-MAC-27 | 每个调用使用既有幂等身份和内容校验；显式再生成产生新尝试 | 双击、超时和重传查原请求；同一身份内容变化拒绝；重新编辑只回填，不调用模型 |
| FR-MAC-28 | 重连/重启先核对原执行与回执；未知结果不自动重发付费请求 | 保留原任务和预算占用；区分未提交、已受理、最终失败及未知；可查询异步能力查原任务，不可查询同步/流式能力沿原回执/账单核对；审批接续与崩溃恢复遵守现有不同合同 |
| FR-MAC-29 | 目标总预算包括规划、压缩、子Agent、媒体、可计费分析及导出等实际收费项 | 分项预计与实际可解释；不将媒体预算误作全目标预算；缺用量按未知处理，不补零 |
| FR-MAC-30 | 报价锁定真实输入及模型/价格版本，智能选择和组合任务也不能跳过 | 用户硬上限不可满足时停止并说明；不因“自动”而静默换模型、降清晰度、补图或无限质检重试 |
| FR-MAC-31 | 原始采购计量与播放/编辑元数据分离，复用现有算法和商业规则 | TTS字符、音乐/音频原始时长、视频实际计量分别保存；不按剪辑后播放时长重写采购费用 |
| FR-MAC-32 | 真实结果先归档成为正式资产，再开放稳定复用与下载 | 临时地址过期可恢复原产物归档；重复归档不重复创作；缺媒体或元数据时有明确失败/待核对状态 |
| FR-MAC-33 | 图片→视频、配音→数字人、角色+动作视频→动作模仿、声音/镜头→时间线使用同一资源谱系 | 后续任务可追溯输入版本、采用决定和原Operation；不能从回复中的任意URL绕过权限及格式校验 |
| FR-MAC-34 | 画布、故事板、时间线、导出均经正式工具和版本校验 | 编辑冲突保留产物并要求重新确认目标；导出受理不冒称成片完成；交付链接指向真实可播放或可下载对象 |
| FR-MAC-35 | 部分失败允许交付已成功部分，并清楚列出尚缺项与可继续动作 | 某镜头或配乐失败不抹掉其他成功素材；局部重做有独立费用与来源；不将不完整成片标为全部完成 |
| FR-MAC-36 | 资源与执行始终按本人/团队/项目作用域检查，运行冻结不替代当前授权 | 跨会话引用不公开私人对话；撤权后不再新增读取/写入；共享成品不自动共享Skill私有内容或子Agent上下文 |

用户可见状态可采用“准备、待确认、排队、处理中、部分完成、已完成、已停止、失败、状态待核对”等文案；这只是呈现建议。正式状态枚举与转换继续由各既有领域设计持有，不能据此新造一套跨服务总状态机。

## 7. 典型用户故事与验收场景

创作者想直接生成单个媒体时，可以跳过Agent规划，完整指定能力与参数；想制作一条短片时，可以让Agent组织脚本、参考、镜头、声音与时间线，并在必要位置采用和确认；中途修改或失败时，可以复用已成功素材，从明确的步骤继续。

### 七类共同的真实闭环接受标准

每种准备开放的精确子能力，均应有“目录/发布 → 合法输入 → 报价 → 受理 → 真实供应商结果 → 归档 → 复用 → 用量/结算”的可核验链路，并覆盖至少一个不受理分支和一个未知/失败恢复分支。无供应商取消能力时，验收正确的限制说明及后续核对，不要求虚构取消。真实付费验证需按届时单独明确的目标、环境及预算执行，本轮文档不提供该授权。
