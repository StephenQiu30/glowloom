# AI 工具对齐即梦需求

## 原始需求与执行顺序

用户要求逐项核查即梦 AI 工具并形成完整需求，第一阶段独立建立产品基线，不读取 Glowloom 功能实现。以现有 Glowloom Figma 文件更新名称、目录和工具入口。第二阶段对照当前实现，登记缺口并补齐，再按设计实现和验收。

- 目录和面向用户的工具名称对齐即梦。目录卡片、工具标题、打开工具的上下文菜单、返回入口和可访问名称采用同一套文案。
- 工具按用户任务和媒体类型分流。功能相近的入口可以复用编辑器，但保留各自的选择范围、默认模式和结果形态。
- 已证实的交互作为一致性要求。未完成实测的字段进入复核清单，Figma 中如需表现，标注为 Glowloom 设计决策或待验证。

## 一手证据

采集日期为 2026-11-07（北京时间）。JM-01 为用户提交的页面快照和 Chrome 登录态目录。JM-02 为逐项点击后的 DOM 和导航状态。JM-03 为资产库打开状态。JM-04 为导演台画布及插件安装页。JM-05 为分类切换。来源为 [即梦 AI 工具目录](https://jimeng.jianying.com/ai-tool/tools)。

## 交互与验收要求

| ID | 规则 | 验收 |
| --- | --- | --- |
| AC-AT-01 | AI工具为独立目录，固定分类和工具顺序，工具名在导航、卡片、弹窗和模式名一致 | 桌面、窄屏、键盘切换全部和单分类，核对 4/4/7/6 项及 21 个入口 |
| AC-AT-02 | 16 项素材工具先展示说明与导入入口，支持拖放、本地上传和从资产库选择 | 核对空态、文件不匹配、读取中、读取失败及取消后焦点。校验输入媒体类型和导入来源 |
| AC-AT-03 | 资产库保留类型、搜索、时间和筛选。显示选择数量，零选择禁用确认 | 至少覆盖双媒体、单视频、空资产、搜索无结果、确认与返回上一层 |
| AC-AT-04 | 三个创作类入口分别预选图片生成、视频生成、数字人模式 | 三条直达入口、创作模式初始状态、必要参数校验，缺输入禁用生成 |
| AC-AT-05 | 编辑工具区分空间标记、时间片段、续写和边界扩展。保留原素材与本次编辑结果的可追溯关系 | 用同一输入核对智能编辑与图片／视频编辑分流。独立验证重拍、延长、消除笔、局部重绘与扩图 |
| AC-AT-06 | 输出按类型继续创作。提示词可编辑，图层可分别编辑，全景可取景，动作深度可作参考 | 核对输出预览与再引用，核对图层和全景专有操作。异常时保留源输入与可重试参数 |
| AC-AT-07 | 导演台和插件按入口语义分流。模板画布有明确的创建中、打开和失败状态。插件入口展示宿主、版本和真实可用性 | 确认模板只创建一次；检查支持项和不可用状态；独立验收宿主安装及回传 |
| AC-AT-08 | Glowloom 服务能力、权限和报价决定可提交性。报价、进行中、成功、失败和状态未知须可区分 | 通过既有报价、任务和资产合同验收，覆盖权限失效、重复提交、报价过期、失败重试和状态恢复 |

AC-AT-05～08 包含 Glowloom 设计要求。工具卡片出现在目录仅表明存在入口。后续实现核查应逐项记录实际路由、界面名称、输入、能力绑定、计价、产物、失败行为和真实验收结果。

## 待复核

- 素材工具的导入后控制项、允许格式、大小、时长、数量限制、自动提交触发点、确切输出和异常状态。
- 资产选择器出现某媒体标签与确认后真正接受该类型的差别，优先复测图片编辑、视频编辑和智能编辑。
- 图片生成、视频生成和数字人的各模型参数矩阵，数字人角色、音色及上传音频之间的校验关系。
- 3D 导演台从模板进入静态／动态编辑与导出的逐步状态，及 Blender/Maya 插件安装、版本兼容和回传。与 [导演台专题设计](../design/30-导演台一致性与实现整理设计.md) 交叉核查。
- 即梦目录及弹窗的手机布局、刷新／前进／后退时状态保留、任务受理和收费后路径。REA 在 390px 隔离窗口加载目录，但图片分类点击超时，见 Evidence `ev_a5b9a5fc5b35a2b296c156ab2b3da8c6b69eb4ae51ce5a7b77ed83a0f33bede9`。当前没有生成结果用于验证这些行为。
