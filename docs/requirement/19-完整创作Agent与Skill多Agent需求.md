## 3. 核心场景

创作者导入一份剧本，Supervisor 调度 `script_worker` 给出带来源定位的人物/场景/台词提案。用户修订后，Supervisor 将已采用版本交给美术与分镜 Worker；相互独立的任务可并行，镜头生成必须等待相应参考确认。生成提案发出时，图执行器主动挂起（Interrupt），前端弹出审批卡片；确认后恢复执行。声音 Worker 与剪辑 Worker 只消费明确采用的素材与时间信息，形成可播放且可编辑的结果。

创作者安装并选择一份分镜 Skill，系统展示所需模型、工具与脚本权限。运行固定 Skill 版本；Skill 更新或停用后，新任务按新状态判断，旧任务继续持有历史版本引用或被明确撤销。用户把其中一个镜头改为夜景，系统通过现场比对识别差异，只重做受该变更影响的步骤，已成功的其他镜头保留。

用户离开页面、系统崩溃或某个 Worker 失败后，可以回到原运行查看实际状态。状态从最后一个 Checkpoint 恢复，未批准的提案保持挂起，不会被自动重复执行或扣费。

## 4. 非目标与待评审细节

“完整”描述目标能力的闭环，不代表首个实现切片即可标记全部完成。不包含模型训练、自动发布成片到外部平台或开放任意宿主机 shell。对外 MCP/CLI 是扩展接入面，不能替代站内完整创作能力。

单主机故障恢复与跨主机高可用分别验收；本轮采用 Go 进程内原生 LangGraph 模式，彻底剔除外部 Node 宿主运维依赖。
