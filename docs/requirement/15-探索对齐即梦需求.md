# 探索对齐即梦需求

来源：2026-10-28 用户明确请求。研究依据：[即梦探索完整需求分析](../research/11-即梦探索完整需求分析.md)。

## 原始诉求

> 对即梦中的探索进行检查以及完整的需求的分析，并整理到我们当前的项目中的一些功能进行检查和整理，这一步不需要查看我们当前的功能实现，先进行完整的分析，第二步对照我们的当前的实现，更正和补齐，保持和即梦的一致性，同时我们的命名方式也需要更新，对设计稿进行彻底更改，然后在落实我们的代码实现。而且我们当前的页面中，上方的筛选栏，而且是右侧的头像的位置一行，所以对应的我们应该怎么实现的。

用户显式指定 reverse-engineer-anything 技能。本轮按第一阶段独立研究处理，不以当前实现限制需求。

## 独立观察形成的结论

- 作品一级分类为短剧漫剧、影视作品、动画动漫、广告营销、平面设计、电商、其他；技能和活动是同排独立频道。
- 各分类的二级场景、技能分类、搜索结果类型和发布分类分别定义，不混为一个全局类别。
- 顶栏窄桌面使用分类横向滚动；右侧账号区保留。搜索展开不应使头像另起一行。
- 做同款、用作参考图、查看创作过程、复制项目、添加技能、发布短片是不同业务动作。
- 完整功能清单与验收定义在研究基线中；其中建议和未验证事项不是用户逐项确认，也不是即梦实现证明。

## 接受条件

1. 第一阶段研究具有日期、来源、观察编号、截图和未知清单，且未读取项目功能实现。
2. 第二阶段每项差异能链接竞品证据和本地实现证据，不把 mock、静态截图或入口存在当作真实闭环。
3. 探索一级分类与账号头像同一条顶栏；二级场景独立，窄桌面溢出可达，不重叠、不挤走账号操作。
4. 命名统一保留业务语义和存量映射，不能因改名丢掉已有内容、链接或权限约束。
5. 后续设计稿、design、PRD、Plan 与代码保持同一有效基线；设计在代码之前完成，不用分析文档冒充 Figma 已修改。
6. 未登录、移动端、真实发布、技能添加、复制项目等未测内容分别列明，不宣称已全面与即梦等价。

第一阶段不自动产生提交、推送、服务启动、真实生成或对外发布。实施状态与调度仍由 [BACKLOG](../../BACKLOG.md) 维护。
