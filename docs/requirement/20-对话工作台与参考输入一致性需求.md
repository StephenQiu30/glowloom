## 3. 继承的业务约束

- BR-CONV-01：对话内容为用户私有；项目成员身份或画布共享不自动授予读取其他用户对话的权限。身份、空间、项目和引用访问权由Go检查，执行状态只由独立`agent`持有，沿[需求19](19-完整创作Agent与Skill多Agent需求.md)。
- BR-CONV-02：模型、Skill、工具、审批、预算和收费继续沿原领域权威；不另造聊天费用算法、兼容引擎或本地假结果。缺失费用显示待核对，不显示0或退款。
- BR-CONV-03：断开浏览器连接、切换页面和切换会话不等于停止。Stop与媒体供应商取消不是同一件事；未知原调用先核查，不自动补买。
- BR-CONV-04：本轮禁止发起即梦或本项目的真实收费生成，不充值、不重试已有收费任务。先前10分额度不重新开放。离线、模拟及隔离数据库测试不能冒称实际供应商接受。
- BR-CONV-05：引用编号、撤销、上传尝试、文档和引用绑定沿[需求03](03-多参考提示词编辑器需求.md)，共享导航与响应式沿[需求11](11-统一工作台与创作入口需求.md)。不使用第二套Textarea或contenteditable保存另一份输入。
- BR-CONV-06：保留并行工作区改动及既有业务数据；文档和代码工作不授权清库、重放已有数据库初始化SQL、发布或提交推送。

## 4. 验收意图与未确认扩展

AC-CONV-SRC-01：首页→添加参考→发送→对话→停止→重新生成→历史重开是一个完整可验证链；逐项对应PRD22的验收与Plan31的执行场景。

AC-CONV-SRC-02：无文字时，移除最后一个可用参考后不能发送；保留文字时仍按模型和输入能力检查发送资格。纯引用内容是否可发送由设计35定义，不能把装饰标签当用户新指令。

AC-CONV-SRC-03：无固定示例素材、模拟完成延时、假历史或前端虚构费用进入真实用户流程。Figma有限状态演示仅作为交互证据。

自动标题、历史排序与分页、路由结构、一次活动运行、引用解析合同等是设计35中的实施选择，不冒称用户逐项指定。对话分享、删除/回收站、重命名、跨项目汇总搜索、语音听写和分支编辑不在本轮已确认范围；若新增，独立补需求和验收，不以“完整”泛化授权。

竞品观察及证据局限见[对话流程基线](../research/2026-11-04-即梦对话流程与设计基线.md)。研究、设计建议、实现与验收互不替代。
