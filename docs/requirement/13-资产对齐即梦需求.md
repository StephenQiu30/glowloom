# 资产对齐即梦需求

## 1. 原始要求与确认

来源：2026-10-28 用户请求。

> 对即梦中的资产进行检查以及完整的需求的分析，并整理到我们当前的项目中的一些功能进行检查和整理，这一步不需要查看我们当前的功能实现，先进行完整的分析，第二步对照我们的当前的实现，更正和补齐，保持和即梦的一致性，同时我们的命名方式也需要更新，对设计稿进行彻底更改，然后在落实我们的代码实现。

已确认：按竞品独立分析 → 实现差异核查 → 更新需求和设计稿 → 代码实施的顺序执行；资产信息架构、功能及用户可见命名对齐即梦。该要求替代需求11中“素材库优先”作为资产总入口的旧顺序；原上传素材、文件夹、回收与恢复的业务能力保留为参考素材管理，不能因改名删除用户数据。

竞品事实见[调研08](../research/08-即梦资产完整需求分析.md)，织光方案由[设计26](../design/26-资产信息架构与即梦对齐设计.md)唯一持有。

## 3. 补充确认与待明确合同

已确认（2026-10-28用户补充）：用户进一步要求“我们需要全量对其，保证功能和设计完全一致”，因此本次包括全部资产交互闭环，不以只读核心完成替代全量交付。生成历史仅显示“本人发起的生成记录”；处理方式保持与即梦一致。现有字段不能无证据地将确认者等同创建者，缺少可靠发起人事实的历史数据不可冒充本人的记录。

已补证与验证边界：

- 共享发行代码已证明历史画布为旧画布/旧草稿工作流；织光使用显式来源，不映射协议版本、归档或回收。
- 短剧采用显式分类，但既有对象如何归类需独立规则；不得按视频或剧本节点猜测，不自动改写已有项目。
- 已取得结果级操作、PDF/Markdown格式、批量上限与部分失败客户端证据；即梦当前账号非空运行样本仍缺少，织光真实SQL与合成UI夹具分别验收。

这些待明确事项不影响先完成观察报告、差异表与设计结构；不得据此声称完整一致性或真实生命周期验收完成。进度与下一步仅在[BACKLOG](../../BACKLOG.md)维护。

2026-10-28用户继续要求：“先将代码提交到main并推送，对我们的页面进行完整的整理并实现”；随后明确范围为“资产相关页面：生成历史、画布、短剧、参考素材”。本轮先提交已完成资产实现，再核对该范围的真实读取、可回访状态、键盘／触屏、加载／错误／权限及设计一致性，不扩为整个产品改造。

## 2026-10-29 补充确认：删除过度设计

用户原文：“当前我们的资产展示中，你需要认真对比并逆向拆解即梦的uiux以及页面的设计，当前我们存在很多的过度设计的地方，比如当前的系统模版是我们需要的吗，还有我们的工具栏的内容的展示，即梦没有的东西我们就不做”。

确认：资产展示以实际观察为准，删除自增工具和独立系统模板分区；企业服务仍不需要。实测即梦确有模板卡片，按设计26第7.1.1节混排展示，不能把“没有独立模板区”扩展为“没有模板”。不删除其他模块的数据或后端能力。

## 2026-11-03 删除反馈（FR-AST-09）

用户原文：“这里我们的删除了之后不需要这些操作内容，而是使用shadcn中的提示信息来实现，我们的所有的删除操作的内容都是需要通过shadcn中的toast组件来实现删除的提示，不要过度设计。”

已确认：删除结果使用现有shadcn/Radix Sonner全局Toast；生成历史不再逐项堆积“操作完成”卡片，也不罗列被删除内容。资产、主体、画布及其他删除入口使用同一反馈方式。成功只一条短提示，批量部分失败仅汇总数量与简短原因；保留失败选择和原请求重试，不把未知结果报成成功。删除前确认与既有权限、幂等、回收和计费合同保持。

## 2026-11-12 工具栏统一与素材上传调研（FR-AST-10/11）

来源ID：SRC-AST-20261112-01。本轮用户原文（应用/技能标记保留为名称）：

- FR-AST-10：统计即梦资产页的来源、工具栏、分类筛选与批量状态，区分现场观察、发行文件静态证据和未知；以现有Figma文件和共享组件调整工具栏一致性。六来源当前已经存在，不能把三来源历史说明误当现状，也不自行增加参考素材辅助导航。
- FR-AST-11：查证本地文件输入与独立可复用素材库是否成立，提出与现有架构衔接的大文件、断点续传、失败重试与结果查证方案。用户要求调研与设计，不等于已确认技术参数、扩容、修改部署或开放真实云上传。
- AC-AST-10：研究留有六来源矩阵和观察边界；Figma桌面/手机引用同一共享组，批量保留分类筛选，参考素材与生成结果保持分源。该编号定义接受条件，不表示本轮真实产品验收通过。
- AC-AST-11：先核对实际上传、进度和失败后用户操作，再据此调整局部Figma状态；SDK分片、重试和缓存能力不直接变成新界面。32 MiB/8 MiB/并发3只在设计08保留历史待议，未转写为即梦参数或本轮用户要求。

## 2026-11-12 继续核对生成器失败与重试（FR-AST-13）

来源ID：SRC-AST-20261112-03。用户原文：“继续把即梦生成器上传失败后的提示和重试流程查清楚，再补齐 Figma，保持和即梦实际交互一致，不要自行扩展。”

FR-AST-13/AC-AST-13：按实际模式区分上传、审核与生成提交，不套用主体Toast；保留原参考图、移除和添加入口，只把已观察的局部状态补入既有生成器。视频全能参考离线样本显示“审核请求失败，请发送后重试”，参考图保留；恢复网络后从卡片移除，再重选同图，可正常上传/审核和预览。Agent样本请求失败后超过1分钟仍显示缩略图Spinner，未见失败文字或独立重试；重新添加可再次发起上传，但可能保留原引用形成重复，不声称有去重或一键重试。没有新增上传记录、失败队列或管理面板。

文案引导的“发送后重试”尚未点击或作生成验收，不将可点发送当成重试成功；本轮未付费生成。当前Figma28区与现场/静态证据见[研究](../research/2026-11-12-资产工具栏与素材上传核对.md#生成器失败与恢复续查src-ast-20261112-03)。
