## 1. 原始诉求与来源

**原始需求表述：作为创作者，我希望点击“新建画布”就能开始一个独立的创作项目，在其中组织素材、保留生成过程，并在离开后找到原来的内容继续创作，而不必先完成一套项目配置。**

上述表述是对本轮诉求的产品化整理，不是逐字引用。创建不是用户的最终目的；能开始、保存并继续完成创作才是完整结果。

## 2. 用户、场景与价值

主要用户沿产品范围定义，为围绕图片、视频、声音开展创作的个人和内容制作者。以下场景用于需求分析，尚无本轮用户访谈或漏斗数据证明各场景的频率。

| 场景             | 用户想完成的事                         | 当前需要解决的障碍                   | 用户可感知的结果                     |
| ---------------- | -------------------------------------- | ------------------------------------ | ------------------------------------ |
| 快速试想法       | 先放一句提示词或一张参考图，再探索方向 | 开始前被名称、比例和风格配置打断     | 进入空白画布即可添加内容             |
| 围绕一个主题制作 | 在同一处组织参考、节点、候选和采用结果 | 不清楚哪些内容属于同一项目           | 素材与创作过程能在原画布继续使用     |
| 离开后继续       | 找回昨天的修改和待完成任务             | 分不清项目、画布与生成历史           | 从最近画布进入同一对象与保存内容     |
| 团队范围内创作   | 在有权限的团队上下文开始工作           | 归属或可见范围不清，切换后可能串内容 | 创建前能识别当前归属，创建后权限一致 |

价值主张：让创作者把一次想法尽快变成可继续编辑的创作空间，减少开始前的配置，并保留从输入、参考到结果的上下文。替代做法是反复使用独立生成页、下载再整理素材或跨工具保存；本专项优先改善开始和继续的连贯性，不宣称生成质量优于竞品。

## 3. 已确认的对象关系

**一个项目对应一张主画布。创建项目与创建主画布由一次“新建画布”动作完成。**

| 对象     | 用户语义                               | 边界                                                               |
| -------- | -------------------------------------- | ------------------------------------------------------------------ |
| 项目     | 一次独立创作的归属与管理单位           | 承载身份归属、创作资料和主画布关系；不要求用户先填写项目表单       |
| 主画布   | 项目的主要可视化编辑空间               | 承载节点、位置、引用关系与编辑状态；本轮不提供项目内多画布切换     |
| 节点     | 画布中的文本、媒体或生成草稿等编辑对象 | 一张画布可有多个节点；节点不是另一个项目                           |
| 资产     | 可被创作引用的素材或结果               | 资产归属、可见性和生命周期沿资产合同；从画布移除引用不等于删除资产 |
| 生成任务 | 对指定输入进行的一次执行               | 项目创建、节点创建与生成提交是不同动作                             |
| 导出文件 | 从创作产物形成的交付文件               | 与可继续编辑的项目、画布分开                                       |

项目和画布可有不同的内部标识，但用户不应为了开始创作理解这些标识。“一张主画布”不授权清理已有额外画布、迁移历史数据或收缩服务端协议；历史情况必须在后续设计中核对。

“一张主画布”指唯一、稳定的主要编辑入口，不等于数据库已具备“每项目最多一条画布记录”的约束。不得通过“最近修改的画布”临时猜选主画布，也不得因存在其他历史文档自动换绑。主画布关联缺失或失效时进入可解释的异常路径。

建议在主要导航、列表与创建按钮中统一使用“画布／我的画布／新建画布”。“项目信息”可保留为管理语义。主画布标题与项目展示名建议保持同一个用户名称，避免列表和编辑器出现两个名字。

## 5. 核心用户流程

### 5.1 从空白开始

1. 用户在首页画布模式、侧栏或“我的画布”列表点击“新建画布”；这些入口表示同一个动作。
2. 系统核验登录态与当前个人/团队范围。需要登录时保留“新建画布”的意图，登录成功后恢复，不重复创建。
3. 建立一项独立项目及其空白主画布，给出默认名称；不要求先选模型、比例、风格或充值。
4. 打开新画布，能识别当前名称、归属与保存状态，并知道如何添加文本、媒体节点或素材。
5. 用户添加内容。只有明确提交生成时才进入模型、输入校验和报价流程。
6. 用户返回列表或关闭后重开，能够找到同一项目、同一主画布及已保存的内容。

以上第1、3步的快捷开始方向来自 PC-S02；默认名称、无表单及恢复细节为实现该方向的产品建议。

### 5.2 继续已有创作

1. 用户从最近画布、完整列表或原链接打开对象。
2. 系统读取项目与匹配的主画布，展示真实保存内容和真实任务状态。
3. 加载失败提供重试；没有权限或已被回收时说明访问状态，不自动创建替代项目。
4. 编辑、自动保存、返回和再次打开形成闭环；未保存修改不能被“已保存”文案掩盖。

### 5.3 从生成结果或资产开始

这是需单独评审的候选流程：用户明确选择“添加到现有画布”或“新建画布并添加”；新建路径沿5.1，已有路径不得偷偷创建项目。引用导入失败时保留已建画布并允许重试，不误报内容已放入，也不重复上传或生成。浏览、预览和下载动作本身不创建项目。

### 5.4 当前阶段的身份与入口衔接

当前[阶段入口设计08](../design/08-统一顶栏与阶段入口设计.md)隐藏个人/团队切换、团队和邀请入口，但保留已有服务授权与归属。PC-F03不要求因此重开空间切换器或先创建团队；有有效会话时沿服务端确认的当前范围创建，没有可确认范围时先处理登录/上下文恢复，不能自行猜测为个人或其他团队。归属可在原有上下文或项目信息中识别，具体呈现待交互评审。

游客关闭或取消登录时仍停留原页面，不创建项目。认证后只能恢复同一账号及授权范围下的创建意图；若身份或范围已改变，先告知原操作未继续，用户重新发起新建。已失效身份的私有内容按用户系统合同隔离，不为了“保留草稿”将其交给另一个账号。

## 6. 功能性需求建议

以下 PC-F 为待评审的具体行为，不因编号存在而成为已接受合同。

| 编号   | 用户需要                     | 可观察行为                                                                                                       |
| ------ | ---------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| PC-F01 | 从主要位置快速开始           | 首页画布模式、侧栏、完整列表的“新建画布”调用同一语义；只切换模式、浏览页面不创建对象                             |
| PC-F02 | 不填写长表单也能开始         | 点击新建后直接进入可编辑空画布；名称自动给出，可随后修改；比例、风格、分辨率、模型不作为开始门槛                 |
| PC-F03 | 清楚内容属于哪里             | 个人用户沿当前个人范围创建；团队用户沿既有授权范围创建；有多个范围时，在开始前能识别当前范围                     |
| PC-F04 | 一次操作得到完整空间         | 创建成功代表项目和唯一主画布均可读取；列表中不出现无法打开的半成品                                               |
| PC-F05 | 连点或网络重试不建多个副本   | 同一次创建意图仅返回一个项目及主画布；明确发起下一次新建才创建另一个对象                                         |
| PC-F06 | 空画布知道从哪里开始         | 提供添加文本、媒体节点、上传或从资产选择的有效起点；只有可用能力显示为可执行动作                                 |
| PC-F07 | 能改名并认出自己的作品       | 默认名“未命名画布”；列表、顶部标题、最近记录一致；同名可存在，以标识区分；非法名称给原因                         |
| PC-F08 | 找到并继续原内容             | 列表显示名称、真实更新时间、封面或空白态；支持按名称查找与最近修改排序；失败、空列表、无搜索结果分开             |
| PC-F09 | 明白数据是否已保存           | 区分加载、保存中、已保存、未保存/失败和冲突；只有确认持久化后才能显示已保存                                      |
| PC-F10 | 关闭或刷新后继续             | 已保存节点、引用和既有合同支持的视口能够读回；失败重试保留可恢复输入，不能覆盖服务器较新内容                     |
| PC-F11 | 创建失败时知道下一步         | 明确失败允许重试；请求结果未知先恢复原结果；创建成功但打开失败重开原对象，不另建                                 |
| PC-F12 | 权限或登录变化不导致串项目   | 保留可恢复草稿并沿认证合同处理续期；会话确认失效后停止私有写入；账号/团队切换后不复用旧范围创建意图              |
| PC-F13 | 创建不会意外扣费             | 建项目、建画布、改名、移动或添加空节点均不触发付费生成；生成前继续使用真实模型和报价确认                         |
| PC-F14 | 已有项目仍可继续             | 未命名、无封面、旧版或主画布关联异常分别处理；关联异常不得伪装成空白，也不得自动覆盖旧内容                       |
| PC-F15 | 修改后的项目能在最近列表找回 | 最近修改的时间与排序反映已成功保存的主画布内容或项目资料变更；仅打开/预览不能伪造修改；分页与同时间排序保持稳定  |
| PC-F16 | 打开项目时知道能否继续编辑   | 区分可编辑、归档只读、复制处理中、已回收和访问受限；状态在服务端核验；项目可见不代表可写，缺失状态不能默认可编辑 |

### 创建时的信息要求

| 信息                 | 创建时用户是否必填 | 建议规则                                                                                  |
| -------------------- | ------------------ | ----------------------------------------------------------------------------------------- |
| 展示名称             | 否                 | 自动给“未命名画布”；改名按约定集合去首尾空白后1～50 Unicode码点，见PC-D04；不要求全局唯一 |
| 个人/团队归属        | 沿当前明确上下文   | 由真实授权决定；不静默落到另一范围；不新增团队创建步骤                                    |
| 项目说明、业务分类   | 否                 | 后续有明确管理需要再补，不阻断开始                                                        |
| 比例/分辨率          | 否                 | 属于具体生成节点或导出目标；无限画布不被一个固定媒体尺寸锁定                              |
| 模型、风格、参考素材 | 否                 | 在用户执行对应创作任务时设置；不能伪造默认已可用模型                                      |
| 封面                 | 否                 | 空项目使用中性占位；不得使用别人的私有素材或假生成结果                                    |
| 成员与分享权限       | 否                 | 创建沿已有可见范围，不自动公开；额外分享单独发起                                          |

已有数据若包含更长名称、旧风格、比例或分辨率，仍应可读取；新增规则不授权截断或重写历史内容。

## 7. 业务、数据与衔接规则

| 编号   | 规则建议                                                                                                  | 依据或边界                                                                     |
| ------ | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| PC-B01 | 一次新建成功对应一个项目与一张主画布，二者属于同一授权范围                                                | 对象关系来自 PC-S02；完整成功语义由本专项建议                                  |
| PC-B02 | 用户明确点击新建后即建立可找回的空项目；仅打开入口或切换模式不创建                                        | 建议采用即时创建；不以首次生成成功作为项目存在条件                             |
| PC-B03 | 主画布作为该项目的编辑入口，不提供单独“删除主画布但保留无入口项目”动作                                    | 建议；不批改历史数据；旧API新请求的守卫与有效回执兼容按PC-D05明确调整          |
| PC-B04 | 项目重命名不改变标识、节点、引用或生成记录；主画布与项目展示名保持一致                                    | 具体方案见PC-D04与设计12第6节；待评审                                          |
| PC-B05 | 名称、比例和项目元信息不能静默修改已生成媒体或历史输入快照                                                | 沿引用与生成专项约束                                                           |
| PC-B06 | 素材引用不自动扩大素材权限；创建与打开都校验对象权限和范围                                                | 沿用户系统与资产合同                                                           |
| PC-B07 | 请求未知与明确失败分开；恢复同一创建时不能更换身份、归属或意图后仍复用原回执                              | 沿现有幂等与身份隔离原则                                                       |
| PC-B08 | 新建空画布不提交生成、不触发自动执行、不要求预充值；后续生成可因能力或额度不可用而受限                    | 创建与模型/报价分开                                                            |
| PC-B09 | 有未保存修改时切换项目、退出或重试，应明确风险并提供已有合同支持的恢复路径                                | 沿画布保存与认证连续性；不承诺未经设计的离线同步                               |
| PC-B10 | 主画布使用稳定关联；针对主画布的改名、删除须与项目名称及可打开状态协调，不能从另一接口破坏项目入口        | 建议；适配既有画布API及历史调用方的方案须单独设计                              |
| PC-B11 | 同一创建意图冻结账号、范围、默认名称及兼容参数；未知回执恢复不重新生成默认值或换幂等身份                  | 建议；页面刷新、会话续期和明确发起另一次新建的边界须设计                       |
| PC-B12 | 名称、说明、封面及主画布内容的成功保存可计为项目最近修改；浏览/预览、单纯视口移动和失败保存不作为内容修改 | 建议；项目元数据时间、画布版本时间和最近访问时间分清，不能直接假定已有字段满足 |

需要保留的数据语义包括：项目稳定标识、主画布稳定标识、所有者与范围、展示名称、创建/真实内容更新时间、生命周期状态，以及服务端已保存版本。草稿、任务、节点与资产按各自合同关联，不在此规定表名、接口或新数据库结构。

仅查看或打开不应伪造“内容已修改”；若需记录最近访问，应与内容更新时间分开。已有旧字段作为兼容事实处理，不能因为数据库存在1080p或风格字段就在新建界面强制用户选择。

创建界面不必填参数，不等于现有接口允许省略必填字段。当前创建合同仍要求名称与画幅；设计阶段须明确默认值由谁提供、如何与同一创建意图冻结以及如何保留旧调用方，未完成前不能只删除前端表单。
