# 模型号池与多供应商路由｜原始需求

2026-11-13 · 需求评审稿 · [调研与源码依据](../research/2026-11-13-模型号池与多供应商路由调研.md)

**创作者选一次模型、确认一次报价，织光负责选择合格的供应商和 API Key。** “无感”指正常换路不需要用户操作；所选模型、输入、价格上限、数据授权和任务身份不能因此改变。上游可能已开始收费时，优先找回原任务，即使池里还有空闲 Key。

## 1. 来源与范围

<a id="src-pool-01"></a>
**SRC-POOL-01｜用户原文（节选）**

> 我想要将我们的模型的接入服务优化一下一个可以持续更新的号池服务，需要做成的部分是像 openrouter 那种集成很多供应商服务的平台，来服务我们当前的项目
>
> 当前我们的需求中除了有目标非目标之外还需要考虑到一些比如我们如果无感路由到不同的供应商或者不同的apikey中
>
> 不要过度设计，保持极简克制，冗余的文字不要出现

<a id="src-pool-02"></a>
**SRC-POOL-02｜重新设计的依据**

> 不要参考任何我们当前的实现
>
> 当前我们的项目中还需要参考的项目还有 beeftv 这种开源的项目

用户明确要求从零设计。模型接入、号池路由、管理员倍率与折扣、任务恢复及账务均须独立验收，初始可用状态为待验证。商业换算与确认价上限来自此前的用户确认。下列规则为设计评审建议。[设计40](../design/40-模型号池与销售计费设计.md) · [商业规则来源](21-模型商业计费与积分系统需求.md#src-credit-04)

| 目标 | 非目标 |
| --- | --- |
| 管理员可持续增加、测试、启停和轮换合法获配的供应商线路和凭据；已支持的协议内的变更无需发版。 | 不建公共中转站、第三方入驻或售卖 Key；不纳入个人订阅会话、本地 Codex 登录或创作者自带 Key。 |
| 同一已发布模型有多个合格供给；单个 Key 或渠道不可用时，其他独立供给仍可服务。 | 不自动换模型、删参数、降分辨率、改变数据处理范围；不把不同 Key 当成可绕过共享限额的独立容量。 |
| 对每笔业务能回答：选了哪条线路、为什么换、供应商是否受理、用户应付多少。 | 本专题范围外包括充值支付、最低价竞价、可视化策略编排和并发竞速；不承诺所有模态一次开放。 |

## 2. 谁使用，管理什么

| 故事 | 所需结果 |
| --- | --- |
| US-POOL-01 创作者在画布、工作室、对话选定模型；Agent 按授权调用。 | 相同输入和报价走同一准入规则；正常换路无弹窗、无重复任务。授权明确固定发布或端点时只走被授权线路。 |
| US-POOL-02 平台接入管理员更换即将到期的 Key，或为模型接入备用供应商。 | 新凭据验证后接新单；原凭据停止接新单但能收尾。能预览变更影响，紧急撤销和正常退役有明确区别。 |
| US-POOL-03 值班或账务人员排查“视频在生成但上游没有回执”。 | 用一个业务任务 ID 查各次尝试、账户归属、原回执和费用状态；可以核对原单，不用再生成一条视频。 |

**最少四个概念：** 模型是创作者选定的精确版本、能力和参数合同；渠道是某个供应商连接/端点上经过发布验证的同一能力；凭据是渠道可使用的授权 Key 版本，记录实际配额归属；号池是该模型被允许使用的渠道及凭据集合。一个渠道只有一把 Key、一个模型只有一条线路，都有效。展示名相同、兼容 OpenAI 协议或同属一个品牌，都不足以判定等价。

## 3. 功能与业务规则

| ID | 需求 | 可观察边界 |
| --- | --- | --- |
| FR-POOL-01 | 管理员在号池后台维护渠道、端点、上游精确模型/模式、凭据及共享额度归属；可新增、替换、排空、撤销。 | 默认仅新增草稿；Key 只能写入或替换，只显示掩码、状态和到期信息（如有）。创作者不可读取、导出或指定任意上游地址/Key。 |
| FR-POOL-02 | 支持手工刷新及按配置周期从已授权来源检查模型、能力、价目或凭据有效性；记录来源、版本、上次成功和差异。无发现接口时可人工维护。 | 新模型/新价只形成候选；部分刷新失败保留上次有效版本并标陈旧。删除、到期、硬成本或能力证据失效阻止相关新单；短暂目录缺项先核实。免费检查不等于可生产，收费探测须另获预算。 |
| FR-POOL-03 | 发布前逐条校验精确能力、参数、价格、凭据、可用性证据和恢复方式。预览对模型及在途任务的影响，整版发布或撤回；并发修改冲突可见。 | 发布失败保持旧版；新请求只见一个完整版本。成功撤销后所有执行实例派发前须拒绝旧凭据；回滚不得复活已撤销或已过期的 Key。 |
| FR-POOL-04 | 先按权限、固定发布/端点、精确模型版本、输入模式、所有必需参数、地区/数据策略、计量、报价及采购上限筛选渠道；再选其中有容量、已验证的 Key。 | 别名须有当前等价证据。工具调用、结构化输出、参考图角色、音色、视频时长等任一不兼容即剔除。换路时不得转移未经新渠道授权的文件或复用其无法读取的上游文件 ID。 |
| FR-POOL-05 | 建议只设主、备顺序。同级合格线路均分；渠道内可用 Key 轮询；先选渠道再选 Key，Key 多不会自动提高渠道份额。 | 优先使用健康主路；同一请求排除已失败候选。并发准入同时遵守 Key、账号/项目共享额度、连接和业务预算；容量不足选独立合格资源，无候选则明确不可用。 |
| FR-POOL-06 | 区分鉴权失效、额度耗尽、暂时限流/故障、参数错误、内容拒绝、取消和受理未知；先判定错误影响谁，再判定本笔能否再次派发。 | Key 失效只隔离本人；账号共享余额耗尽隔离同额度组；渠道故障作用于对应线路。暂时冷却尊重供应商恢复时间，受控检查成功再逐步接流；撤销、欠费、模型下架不能靠超时自动解封。 |
| FR-POOL-07 | 只有一个层级负责本笔自动换路。建议首次派发外至多一次安全补尝试，共用原截止时间；候选数再多也不延长等待。 | 上游代理、SDK、客户端、Agent 不叠加重试。上游是聚合商时须约束其下游端点/回退和付款来源；不能证明可约束，就不参加受这些条件限制的池。具体处理见 §4。 |
| FR-POOL-08 | 保持业务请求、任务编号、确认价和取消动作稳定；每次尝试单独记录实际发布/端点、凭据版本引用、受理证据、上游请求/任务 ID 以及恢复所需的账号范围。 | 重复提交、重连、服务重启仍查同一操作。查询、取消、下载与归档回原身份；排空支持在途任务，紧急撤销立即阻断使用，受影响任务转核对。 |
| FR-POOL-09 | 确认时冻结足额积分，结算时写入可追溯流水。分开记录业务售价与各尝试的实际采购价版本、单位、币种、用量来源及费用。 | 用户只为同一业务结果结算一次且不超确认上限。更贵备线超采购预算不得发出；超过确认价的差额由平台承担。采购金额未知不补零，不因换路、断流或查不到任务而自动退款。 |
| FR-POOL-10 | 管理列表显示“可用/不可用”，详情解释可选渠道数、冷却/阻断原因、配额归属、恢复条件及近期变更。 | 管理员按业务 ID 查看脱敏尝试链及变更人/时间；普通用户只见当前任务状态、可操作原因及本人费用信息。日志和导出不含 Key、鉴权头、完整提示词或私有素材地址。 |

管理员须可调整模型销售倍率和折扣。FR-POOL-09 的用户侧计价沿用[需求04 FR-AI-65～67](04-AI平台接入与预设管理需求.md#src-ai-49)，后台可据业务单比对确认的折后售价与实际命中渠道的采购成本。

## 4. 换路判定：先看上一条是否可能受理

| 当前证据 | 本笔动作 | 后续新请求 |
| --- | --- | --- |
| 尚未发送；Key 到期、额度不足、渠道维护，或能证明未发出 | 同渠道的 Key 独立且可用就选它；账号/渠道整体受限则选不同故障范围的合格渠道。 | 避开已知失效的资源；无路可选时显示暂不可用。 |
| 已发出，上游契约与可核验回执明确“未受理、无费用”；属于可恢复供应问题 | 在总时限与尝试上限内换一次。相同输入的格式错误、内容拒绝、无权访问、用户取消均停止，不换路。 | 按故障范围冷却或禁用；不能仅凭裸 401、429、5xx 或首字节未到认定未受理。 |
| 已返回流片段、工具调用或上游任务句柄 | 绑定原线路继续读取、查询或取消。断流显式显示中断；不得从备用线路拼接输出或重复执行工具。 | 独立的新请求才可重新选路；依赖原会话、文件或缓存身份的请求须满足原绑定。 |
| 已发送但超时、响应丢失、服务重启或费用不明 | 标记“状态待核对”，保留原任务/资金占用；凭原请求 ID、回执、查询或账单核对。无可查询接口则进入人工核对；不向备线补发。 | 无关请求可按当前健康状态另选；用户显式再次生成是新操作，说明原单仍可能收费。 |

## 5. 验收场景（建议，未执行）

| ID / 对应规则 | 给定条件与动作 | 必须能看到的结果 |
| --- | --- | --- |
| AC-POOL-01 / 01、03、05 | 从空池录入首条渠道及第一把 Key，验证后发布，再增加第二把独立 Key 并轮换第一把。 | 空池没有可售线路，首条线路验证发布后才可报价和派发；新凭据无需重启即可接单，排空 Key 只服务原任务。 |
| AC-POOL-02 / 04～07 | 甲方 K1 在派发前到期、K2 可用；随后把甲方整条线路维护，乙方有同版本同能力。 | 两次请求分别选甲/K2、乙；创作者没有改参数或重提任务。固定甲或固定 release 的 Agent 不走乙。 |
| AC-POOL-03 / 04～06 | K1/K2 同属一个已限流账号，同时从多个实例提交；乙方独立。 | 共享上限不被叠加，不会轮换 K2 继续消耗该额度；有余量走乙，无余量不发送。 |
| AC-POOL-04 / 04、07、09 | 备用同名模型缺首尾帧、工具调用、不满足数据地区或超过采购上限；另有会自主换下游的代理。 | 分别剔除不合格候选；全部不合格时明确不可用，上游收到零次请求，不丢参数、不加价。 |
| AC-POOL-05 / 06、07 | 合同明确未受理的暂时拒绝后，下一线路成功或再次拒绝；另测内容拒绝、取消及只有状态码的拒绝。 | 前者总付费提交尝试不超过两次且不跨截止时间；内容拒绝/取消无补发，无充分证据转核对。 |
| AC-POOL-06 / 07、08 | 流已输出正文/工具片段后中断，或视频 POST 已送出但回复丢失，随后重复点击并重启。 | 流不拼接、工具不重复执行、视频不重建；仍是原操作。可查询则查原单，无法证明结果则保持待核对。 |
| AC-POOL-07 / 01、03、08 | 视频已受理后排空旧 Key、发布新路；再执行紧急撤销并尝试回滚。 | 排空期间以原身份查、取消或归档；撤销成功后不能用旧 Key，回滚也不能复活它，无替代身份则人工核对。 |
| AC-POOL-08 / 08、09 | 首线路明确未受理、乙成功，结算回调重复；另测供应商成功但用量缺失。 | 用户只有一次结算且不超原报价；采购按实际线路留证。用量缺失保留待对账，不能按零费用关闭。 |
| AC-POOL-09 / 02、03 | 同步出现新增型号、费率变化、接口超时；两位管理员同时发布不同版本。 | 差异可审阅，无自动启用；失败刷新不清空好配置，新旧配置不混用；冲突和最后有效版本可见。 |
| AC-POOL-10 / 06、10 | 单 Key 冷却后恢复；管理员、创作者分别查看失败请求、配置和日志。 | 仅相关范围停接，恢复状态可查；管理员能关联原任务及尝试，创作者不能读取或编辑凭据，两者均看不到秘密。 |

产品效果按同一时间窗比较单线路基线与启用号池后的**业务成功率**（成功业务单/终态业务单，另列未知单）、**安全换路挽回率**（备用成功单/发生安全换路单）和端到端 P95；同时核对重复受理、超确认价扣费、撤销后新派发的件数，验收用例中这三项均须为零。模拟上游用于复现故障；真实入池资格须按模型、模式、凭据、回执与费用证据逐项确认，不从模拟结果外推。

## 6. 待确认的产品选择

| ID | 选择 | 建议默认值 |
| --- | --- | --- |
| DEC-POOL-01 | 哪个模型先开放、哪些账号或中转端点可视为等价？ | 优先选择一个可取得授权的文本模型、两条可证明同版本的渠道及同渠道两把 Key；验证通过的单线路只声明单路能力。视频等有实单恢复依据再逐项开放。 |
| DEC-POOL-02 | 主备排序、补尝试上限和更新时效如何定？ | 主备加同级均分，最多两次总尝试；每类能力的总时限、目录刷新周期、普通发布生效时限依据真实基线确定。紧急撤销不得依赖普通刷新周期。 |
| DEC-POOL-03 | 哪些价差可由平台承担，哪些供应商可接收哪些数据？ | 在既有报价与预算下只用明确批准的采购范围和数据白名单；边界未核定的线路不自动加入。 |
