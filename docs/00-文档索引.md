## 阅读顺序

1. 先读最新用户确认和 [BACKLOG](../BACKLOG.md)，确定范围与当前调度。
2. 从[产品总 PRD](prd/10-产品总览与交付边界.md)定位专项，核对原始需求和唯一来源设计。
3. 负责人评审对应 PRD 的价值、范围和验收；执行者按其 Plan 的依赖及退出条件推进。
4. 工程遵循 [PROJECT](../PROJECT.md)、[AGENTS](../AGENTS.md)，视觉与共享交互遵循 [DESIGN](../DESIGN.md)。

## 维护与证据

技术合同回 design，范围与验收回 PRD，步骤与实际证据回 Plan，状态、优先级、估算、承诺及阻塞回 BACKLOG；跨领域依赖用链接表达，不合并来源正文。原始需求及确认保留独立身份和稳定 ID。

文档恢复保留原日期、版本、环境、命令、结果与未覆盖边界。历史通过、失败、跳过、模拟、真实数据库、浏览器、真实供应商与产品接受分别使用；文档、评审、实现和发布不是同一状态。

每个目录使用 00 导航及独立文件编号，已有文件名与业务 ID 保持稳定。原始来源不为模板重编；后续明确重编时同步正文、索引、链接及配置。docs 为 Markdown／Obsidian 文档目录，不加入网站、脚本、测试或依赖工程；根规范及工程 README 保留原位置。
