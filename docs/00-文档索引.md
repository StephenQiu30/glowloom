## 内容职责

- [requirement](requirement/00-需求导航.md)：有效需求、确认、业务规则、来源与稳定 ID。
- [design](design/00-设计导航.md)：当前方案、模块职责、状态、权限、数据、接口、取舍及技术验收条件。
- [prd](prd/00-PRD导航.md)：用户价值、功能范围、非目标、故事与产品验收条件。
- [plan](plan/00-Plan导航.md)：依赖、步骤、任务、验证方法、退出条件、迁移与回退；必要的实际证据绑定版本与环境。
- [research](research/00-调研导航.md)：可复查的外部事实与选型依据，作为主链的参考。
- [模板与编写规范](templates/00-模板导航.md)：各层内容边界与维护规则。

画布保存与协作的外部依据见[竞品研究03](research/03-画布节点保存与协作机制竞品研究.md)，工程总览见[设计17](design/17-画布Yjs协作编辑设计.md#70-工程边界与部署建议)；原始需求分别由需求08/09/10持有，不新增重复总需求。

## 使用与维护

从领域需求进入设计，经 PRD 明确交付范围，再沿 Plan 执行。进度、优先级、阻塞和下一步统一见 [BACKLOG](../BACKLOG.md)。工程约定见 [PROJECT](../PROJECT.md) 与 [AGENTS](../AGENTS.md)，视觉及共享交互见 [DESIGN](../DESIGN.md)。

新结论直接更新对应知识的所有者，同时同步下游引用。已替代方案、临时修复、检查快照和交接流水不继续作为正文或独立设计文件；历史过程查 Git。清理时先迁入仍有效的规则和必要证据，再删除重复载体并修复链接，不另建历史堆积目录。

稳定业务 ID 与仍有效的用户确认保留，文件编号允许空缺。证据说明其日期、版本、环境及未覆盖范围；单元、模拟、真实数据库、浏览器、供应商、产品接受和发布分开判断。
