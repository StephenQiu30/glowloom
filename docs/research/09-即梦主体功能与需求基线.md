# 即梦主体功能与需求基线

观察日期：2026-10-28（Asia/Shanghai）。目标：[即梦主体](https://jimeng.jianying.com/ai-tool/elements)。本文件在查看 Glowloom 功能实现之前建立，第二阶段只能据此比较，不能用项目现状反推竞品需求。

## 1. 调研结论与边界

主体是可命名、可描述、可反复引用的创作对象，包含主参考素材，并可绑定音色。界面采用「主体」独立导航、卡片库和「设置主体」共用新建/编辑弹窗；创作输入通过 `@` 选择主体。当前样本支持非人物几何图，不应把主体收窄为人物或训练模型。

本次实际完成：空库检查、授权几何图上传、命名及描述、智能配音、保存、重新打开及独立标签页回读、名称必填、收藏、搜索、列表控制、批量零/一项、删除确认取消、Agent/图片/视频主体引用插入。未提交图片/视频生成，未确认删除。页面账户积分显示始终为 66；这不能证明所有音色操作免费。

这是桌面单账号下的功能基线，包含完整的问题目录及明确的覆盖边界，**不是全产品、全模型、服务端合同或生成一致性的完整验证**。

## 4. 术语和信息架构

| 对象/位置 | 对齐用词 | 说明 |
| --- | --- | --- |
| 全局入口、库、对象 | 主体 | 包含人物以外内容，不用角色库、模型库、元素库替换 |
| 库入口 / 引用菜单入口 | 新建主体 / 创建主体 | 即梦有这一区别，按位置对齐 |
| 新建/编辑标题、卡片菜单 | 设置主体 | 共用一个表单，而非人为增加详情→编辑层级 |
| 表单媒体区域 | 参考主体 | 与「主体对象」本身分开建模 |
| 主素材 | 主图 / 主参考图 | 封面与主参考的关系在后续设计明确，不能凭截图推断所有媒体规则 |
| 声音 | 添加音色 / 上传音色 / 智能配音 | 音色绑定与普通音频附件需区分 |
| 输入区 | 主体引用 | 分析用语；候选可见标题为「可能@的内容」 |
| 技术领域名 | 建议保留 Subject | `/elements`只是即梦路由，不足以要求项目所有API改为Element |

主体库 → 设置主体 → 参考素材/名称/描述/可选音色 → 保存 → 在创作中@引用。这是已观察的核心闭环。资产库是素材来源，不应将其直接等同于主体库。

## 5. 状态、异常和权限分析

界面状态归纳（分析，不代表即梦内部枚举）：空表单 → 素材上传中 → 可保存 → 保存中 → 已保存；音色独立经历无音色 → 加载中 → 可播放/可移除。选择模式、收藏、查询和删除确认各自独立，取消删除不能丢失已有主体。

需要后续工程设计覆盖但本次未故障注入的情况：上传/保存/音色失败、重复点击、并发编辑、主体被删除后旧提示词重开、批量部分失败、失效素材、权限切换及网络中断。单账号观察不能证明团队主体共享和授权规则；未出现分类、训练、版本、公开分享不能被写成这些能力绝不存在。

## 7. Glowloom采用与验收建议
