# 即梦探索完整需求分析

观察日期：2026-10-28（Asia/Shanghai）。目标：[即梦探索](https://jimeng.jianying.com/ai-tool/explore)。来源需求：[探索对齐即梦需求](../requirement/15-探索对齐即梦需求.md)。

本文是第一阶段的独立需求基线：未读取 Glowloom 当前功能代码、当前页面或 Figma 设计稿，不判断项目已有或缺少什么。完整性指覆盖需求分析的功能边界、状态、命名和验收；不表示已实测全部账号状态、写入结果或即梦内部实现。

## 1. 核心结论

即梦探索是从公开内容发现进入创作的入口，包括作品、技能、活动三种内容与交互模型。不能把所有内容压成一种图片卡片，也不能把用途分类、媒体类型、场景、技能分类和排序混成同一级筛选。

**一级分类与右侧搜索、消息、头像共用同一条顶栏。二级场景在下一行。** 实测 1869×873 视口下一级按钮中心纵坐标为 76.25，头像中心也为 76.25；二级按钮中心为 124.25。1280×800 下一级分类区域收缩并横向滚动，左右箭头提供剩余分类入口，右侧头像仍可见。滚动内容时分类与场景仍留在顶部。

图片作品的“做同款”与“用作参考图”是不同动作：前者回填提示词、参考和生成参数；后者在当前表单追加参考图。短剧的“查看创作过程”进入只读画布，“复制项目”是另一个有写入效果的动作。技能的“添加技能”也不能改名为“做同款”。

上述事实基于本次已登录桌面会话。文中“建议”是 Glowloom 的候选设计；“待验证”不能作为即梦已实现的事实。

## 3. 信息架构与准确命名

### 3.1 作品分类与场景

下表均为当前界面观察值，不由 Glowloom 现有分类反推。

| 一级分类 | 二级场景（顺序） | 本次可确认事项 |
| --- | --- | --- |
| 短剧漫剧 | 短剧作品、漫剧作品 | 初始/重新进入默认短剧作品；短剧采用封面、标题、作者网格 |
| 影视作品 | 短片作品、音乐MV、视觉设定 | 视觉设定实测为图片瀑布流；不能把影视作品整体当作视频 |
| 动画动漫 | 动画影片、视觉设定 | 仅确认场景标签，不推断全部列表内容 |
| 广告营销 | 品牌广告、社媒营销 | 仅确认场景标签；发布入口随所选场景变化 |
| 平面设计 | 海报、品牌设计 | 海报实测为图片瀑布流 |
| 电商 | 电商头图、商品展示 | 仅确认场景标签 |
| 其他 | 灵感、短片 | 灵感是该分类下的场景，也是搜索结果类型名称；不是所有探索内容的同义词 |

与这七个作品分类同排的是“技能”“活动”，视觉上以间隔/分隔表达频道差异。没有观察到顶层“全部、图片、视频、热门、最新”这一套筛选，不能凭惯例添加并声称与即梦一致。

切换到另一个作品分类时，实测回到该分类首个场景；重选当前影视作品分类时保留当前视觉设定。搜索框展开后占用更多顶栏宽度，分类可用宽度相应减少。

### 3.2 技能分类

顺序为：热门推荐、影视短片、电商、商业广告、通用创作、平面设计、社媒营销、娱乐、动漫游戏、大师风格复刻、专业运镜、发现。

“影视短片”与作品一级分类“影视作品”不同；“商业广告”与作品一级分类“广告营销”、二级场景“品牌广告”也不同。对齐时保留各自语境，内部标识应有命名空间，不能用相同显示文案作为全局唯一键。

### 3.3 搜索与发布各自有独立分类

- 搜索结果标签：**灵感、技能、短片**。从短剧场景输入“海报”后，实测先进入短片结果；切换灵感后 URL 类型与选中项同步改变，加载图片结果。
- 发布分类菜单：**品牌广告、短片作品、剧集作品、音乐MV、动画影片、其他**，界面提示最多选 2 个。
- 发布的“剧集作品”和浏览的“短剧作品”并不完全同名。记录这一差异，不擅自推断服务端编码或一对一映射；后续需以业务映射表明确联系。

## 5. 核心用户流程与对象边界

| 用户目标 | 观察到的主路径 | 后续必须补齐的契约 |
| --- | --- | --- |
| 找视觉灵感并继续创作 | 探索 → 分类 → 场景 → 图片详情 → 做同款/用作参考图 → 编辑生成表单 | 参数兼容、不可用模型提示、参考权限、重复追加规则 |
| 学习短剧制作方式 | 短剧漫剧 → 作品详情 → 查看创作过程 → 只读画布 | 关闭返回、加载失败、原作品删除、复制后的归属 |
| 寻找可复用创作能力 | 技能 → 分类 → 技能详情 → 详情/添加技能 | 添加后位置、重复添加、版本变化、实际调用方式 |
| 发现活动 | 活动 → 活动详情 → 规则/参赛作品/获奖作品 | 状态有效期、外部链接、报名条件、截止后处理 |
| 跨内容搜索 | 顶栏搜索 → 结果 → 灵感/技能/短片 → 详情 | 查询与类型持久化、空态、错误、返回上下文 |
| 分享视频作品 | 发布短片 → 视频/封面/标题/分类 → 简介/下载许可 → 发布 | 上传校验、发布权限、审核、重复提交和结果回执 |

建议的数据边界：公开作品、个人资产、生成任务、只读创作过程、可复制项目、技能定义、用户技能关系、活动、活动投稿、收藏关系、关注关系分别表达。探索只引用公开内容，不应隐式把个人生成历史当作社区作品。

做同款建议传递结构化创作意图（来源作品、类型、提示词、参考、公开参数），由创作入口校验本平台能力。不能硬编码即梦模型品牌作为 Glowloom 的真实可用能力；“一致性”要求操作含义和结果一致，不能用假模型选项、假计费或空按钮替代。

## 6. 顶栏应该如何实现

以下为独立布局建议，不引用当前项目组件或 CSS。

```text
┌──────────┬───────────────────────────────────────────────────────────┐
│ 品牌/侧栏 │ 一级分类及频道（可横向滚动） │ 搜索 │ 全局操作 │ 头像 │
│          ├───────────────────────────────────────────────────────────┤
│ 主导航   │ 当前分类的二级场景                         发布短片（按需） │
│          ├───────────────────────────────────────────────────────────┤
│          │ 当前频道的作品流 / 技能卡片 / 活动卡片                    │
└──────────┴───────────────────────────────────────────────────────────┘
```

1. 由页面壳提供一个共享顶栏，左侧注入探索一级导航，右侧渲染账号操作。头像与分类必须在同一个布局上下文中，不用两个独立绝对定位区域“对齐像素”。
2. 顶栏采用两列布局：`minmax(0, 1fr) auto`。左侧容器允许缩小并内部横向滚动；右侧内容不收缩。Flex 等价实现为左侧 `flex: 1; min-width: 0`，右侧 `flex-shrink: 0`。
3. 一级分类按钮不换行，整个分类区域不把页面撑出横向滚动；溢出箭头根据实际滚动边界显示，选中项自动进入可见范围。
4. 搜索展开时只重新分配左侧可用空间，不把头像挤到第二行。明确搜索折叠、聚焦、提交和返回的状态。
5. 二级场景属于内容工具栏，可与发布入口同排；技能切换成技能分类，活动不保留上一频道场景。
6. 顶栏和二级工具栏的固定/吸顶由壳层统一管理高度与滚动容器，避免内容被遮挡、双重滚动或重复空白占位。
7. 不新增大标题/说明横幅挤占当前内容首屏。页面应有语义标题，必要时可视觉隐藏；不是取消可访问性。
8. 1280 和 1869 的实测只支持桌面行为。移动端折叠菜单、操作收纳、详情布局需单独设计验证，不能宣称已与即梦移动端一致。

**几何验收建议**：桌面一级选中项与头像中心纵坐标差≤1 CSS px；分类容器右边界不超过账号区左边界；1280宽且搜索展开时头像仍可操作，所有一级项可滚动到达；二级行与卡片首屏不重叠。这是本项目建议阈值，不是从竞品代码读取的规则。

## 9. 第二阶段对照方式

在本基线冻结后，才查看项目实现、现有需求与 Figma。每个 `EX-FR/EX-NFR/EX-AC` 建一行对照：**竞品证据 → 当前实现证据 → 差异 → 目标命名/交互 → 设计节点 → 验收证据**。

对照结论使用“已满足、部分满足、缺失、存在冲突、未验证”，不以文件存在或静态截图代替功能完成。旧文案、前端路由、接口枚举、存量数据、埋点、文档与 Figma 命名要分别核对；不能全局替换中文字符串后宣称完成迁移。

先明确真实业务能力与公开/私有边界，再重做页面及关键状态设计，更新 design → PRD → Plan 的唯一来源关系，最后实现并验证。现有收藏、技能、活动、发布能力若不满足契约，应补真实流程；不填入静态假数据冒充即梦功能，也不隐式接入即梦内部接口。

本阶段不创建“本地缺失数量”或实现进度表，不修改并行工作中的共享布局、设计文档和代码；实施调度由 BACKLOG 统一维护。
