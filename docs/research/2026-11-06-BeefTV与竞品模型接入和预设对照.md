## 1. BeefTV 怎样接入服务、配置模型

| 环节 | 固定源码中的行为 | 可复核来源 |
| --- | --- | --- |
| 托管 BeefAPI | 服务端发起设备授权，轮询取得令牌并保存加密 Key，完成确认后加载账号目录。刷新使用保存的凭据，返回时重新核对账号、Token、服务地址及状态。更换账号替换模型集合。同账号合并资料，对部分返回保留已有有效的版本化能力，托管价格由服务端目录写入。 | [授权与保存][b-auth] · [刷新][b-refresh] · [目录合并][b-apply] |
| 自定义服务 | 界面分「连接服务」「选择模型」。供应商选项预填服务地址与目录协议，第三方兼容服务可填地址。显式读取目录，可搜索、选择和手填 ID。读取失败时仍可继续手填。LL2 有预填模型和插件协议，可一键保存并启用。普通服务选完用「保存并使用」，测试是另一动作。 | [服务预设][b-ui-presets] · [接入编辑器][b-editor] |
| 在线目录 | 拉取后按 OpenAI 风格的 `data` 或 Gemini 的 `models` 解析并按 ID 去重。附带的能力类型、端点提示、默认值、可选项和媒体规格按有无规范化。后端可再叠加已知视频规格与渠道补充条目。自定义渠道刷新合并已保存的模型和用户设置。 | [目录解析][b-fetch] · [渠道合并][b-pane] |
| 模型协议与规格 | `serviceModelProfile` 优先保留可用的既有选择，结合显式能力、目录元数据、已知型号和服务类型提出协议，只绑定宿主提供且能力匹配的协议。协议适配层将统一输入转成供应商提交、查询、取消请求。媒体规格还能来自内置或托管的版本化合同。 | [模型规格与协议建议][b-profile] · [协议注册][b-driver] · [视频合同][b-video] |
| 验证 | 选定具体模型和协议后可测试。生成测试的确认明确说明会发真实请求、由供应商计费，结果可在任务中心查看。目录读取和生成确认有独立入口。 | [模型测试][b-test] |

### 预设有三层

1. **服务连接模板**。前端的第三方兼容、LL2、OpenAI、Gemini、火山方舟卡片提供服务名称、地址、目录格式等。固定版本的 `presetCatalogFor` 只为 LL2 返回前端预置候选。其余卡片可走在线读取、手填或对应插件流程，不能把服务卡片数量当预置模型数量。 [前端预设][b-ui-presets]
2. **渠道内置模型资料**。后端通过 `go:embed` 读版本化 JSON。本次树中内置目录文件是 `beefapi.v1.json`，含渠道身份、目录协议及模型能力、协议和规格。加载时检查模型重复、协议合法、规格 JSON 与秘密字段。LL2 属于另一条插件预设来源。托管账号当前可见模型仍由账号目录决定。 [内置解析][b-builtin] · [BeefAPI 预设][b-json]
3. **实际使用配置**。渠道选中的模型形成 `modelProfiles`，再绑定能力、协议和规格。BeefTV 的本地工作区保存后即可创作用，Glowloom 的平台管理场景需要继续经过证据、价格和发布门槛。BeefTV 源码含不同许可历史，Glowloom 只借鉴交互与边界，独立编写实现。 [保存路径][b-editor] · [固定版本许可][b-license]

## 3. 上游目录能证明什么

Context7 查得 OpenAI 列表返回对象类型与 `data[]`，模型对象包含 `id`、`object`、`created`、`owned_by`，文档也列有可选的 `shutdown_date`。返回合同没有生成端点、参考角色、可用参数、价格或成功生成的证明。兼容渠道的附加字段依各渠道文档独立核验。设计把目录记录为指定连接下的可见性证据，能力和参数来自精确型号对应的已核验合同，实际调用证据绑定所测配置、模型和模式。 [OpenAI 列表合同][o-list] · [模型详情合同][o-get]

## 4. Glowloom 源码对照

| 问题 | 现状及影响 | 设计决策 |
| --- | --- | --- |
| 入口职责 | 接入弹窗先 `preset.connect` 再 `credential.set`，两次回执。预设页有独立入口，模型页可按连接添加。接入弹窗还承载多选和自定义候选。 | 保留一个常规弹窗，默认只需选择供应商和填凭据。候选摘要与可选调整从属于主流程，正式管理放模型页。 |
| 候选如何产生 | `ModelCatalogForPreset` 以适配器内置目录和预设模型模板合成，`AddPresetModel` 锁连接并按上游 ID 与能力复用。当前后台已读到凭据探测和预设候选；在接入、添加模型入口及对应 catalog HTTP 合同中未找到单独供管理员选取的在线候选入口。 | 内置预设优先。仅已支持的驱动提供显式只读目录，结果进入当前弹窗的候选列表。需要接入点的占位不进默认选择，手填精确 ID 仍可建草稿。 |
| 候选和发布混用 | `ConnectPreset` 先实例化预设里的全部 `ModelTemplates`，可生成禁用模型及模型版本、价格版本、发布草稿，再处理候选选择。前端可选条目与模板实际落库的集合有出现差异的条件。 | 新接入按界面确认的集合创建模型。仅有候选资料的条目保留待配置或待审核状态。已保存的旧模板、价格与发布记录按原版本可读。 |
| 验证粒度 | 模型配置检查已有无价格、无发布的路径。另有首次接入批量激活：`ActivateProviderOnboarding` 允许一个匹配当前凭据及配置的 `model_access` 回执，循环激活该连接下符合条件的多个草稿。源码注释也区分这一回执与逐模式推理证据。 | 连接级与模型级结果分别展示。新模型走现有发布门禁；批量操作可提交多项，每项独立核验，不能跨型号借用通过结果。 |
| 创作端目录 | 项目目录已有地域策略、版本模式、参数规格与价格；托管路径取已发布的版本，管理候选来自另一入口。 | 创作端以发布版本为准，按类型、模式、权限和参考输入投影。已有任务继续按冻结绑定查询和恢复。 |
