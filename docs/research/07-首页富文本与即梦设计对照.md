# 首页富文本与即梦设计对照

观察日期：2026-10-27。范围为织光首页、Tiptap 创作输入区及类型、模型、参数、项目选择浮层。用户明确要求使用 Figma、reverse-engineer-anything 与 shadcn 检查并修复。采用规则归[设计09第7.11节](../design/09-统一顶栏与阶段入口设计.md#711-首页富文本与-shadcn-浮层校正2026-10-27)，运行证据归[Plan16](../plan/16-Figma设计落地实施计划.md)。

## 1. 来源与方法

- Chrome 当前登录态[即梦首页](https://jimeng.jianying.com/ai-tool/home/)：观察 Agent 与图片模式、创作类型菜单。输入卡片集中放置参考、正文及设置，主体内容弱于主要输入任务；营销渐变和技能推荐不作为织光新增范围。
- REA 以临时浏览器访问即梦公开首页，关闭公开促销弹窗后打开创作类型菜单，采集 DOM、可访问树及截图，证据为 `ev_e0f416b6e852d79af181caa798b960b0212485c6901c9ec46b3a3be6b825f2d7`。公开页面与当前 Chrome 登录态分开记录，不推断私人资产或内部实现。
- REA 以 390×844 临时浏览器打开织光，等待并点击“创作类型”，证据为 `ev_330f7d4fc4bc796dab5248da42aa92dcde93d8b2261d0449def1de03fd9019c8`。该次采集早于最后一轮选项触控高度调整；最终尺寸以浏览器复核为准。
- Figma 读取正式首页1361:26、1361:989、共享富文本1254:100085和原菜单实例；源码检查 HomeCreation、HomePrompt、PromptEditor、RichGeneration、ReferenceControls、ModelPicker 及共享控件。shadcn CLI 确认项目为 Radix Nova、Geist、Lucide、Tailwind v4，沿用已安装组件。

## 2. 对照与问题

| 位置       | 本轮观察到的问题                                                | 采用的修复                                                          |
| ---------- | --------------------------------------------------------------- | ------------------------------------------------------------------- |
| 创作区     | 首页及 Figma 将160px输入框放在240px区域中居中，额外制造上下空白 | 内容决定高度，保留明确区块间隔，移除区域嵌套滚动                    |
| 全能参考   | RichGeneration 将整个参考条塞入64px网格列                       | 参考条独占完整一行，正文与引用继续由同一Tiptap会话持有              |
| 工具栏     | 项目与积分各用自动边距；手机模型等操作被横滑隐藏                | 设置集中排列，只有积分靠右；手机换行并保留44px触控高度              |
| 设计下拉项 | 类型和模型选项原来是普通Button实例，缺少选择角色和搜索结构      | 类型使用Select角色实例；模型使用Command角色实例及搜索输入           |
| 动态标签   | 模型名、比例文本及箭头挤在固定宽度中                            | 分配可容纳现有变量标签的宽度，保留选择变量及原型动作                |
| 手机原型   | 类型与模型打开1460px桌面覆盖层                                  | 新增390×844覆盖层，选项44px，并重连手机触发器                       |
| 项目原型   | 选择项目按钮连接更多工具或比例菜单                              | 所属项目Popover内组合字段、Select、查找输入与按钮，选项仅为原型样例 |
| 参数原型   | 参数入口只连接比例菜单                                          | 组合比例、清晰度、数量的参数Popover，并分别复用Select选项           |
| 弹层皮肤   | 代码模型与参数弹层各自覆盖表面、圆角和阴影                      | 移除局部皮肤，复用共享shadcn Popover                                |

即梦可迁移的是清晰的主输入区域、设置层级与锚定菜单。织光保留既有中性色和真实功能边界，不引入广告、示例余额、技能或虚构模型。

## 3. 组件依据

类型及参数枚举沿[shadcn Select](https://ui.shadcn.com/docs/components/radix/select)；可搜索模型沿[Command](https://ui.shadcn.com/docs/components/radix/command)与[Popover](https://ui.shadcn.com/docs/components/radix/popover)；草稿动作沿[DropdownMenu](https://ui.shadcn.com/docs/components/radix/dropdown-menu)；输入容器沿[InputGroup](https://ui.shadcn.com/docs/components/radix/input-group)。Tiptap继续承担正文与引用模型，不用Textarea替换。

## 5. 后续无边框纠正与审查边界

用户随后明确：富文本必须无边框，先确定落实方案，配色可以必要优化。本次只读检查确认首页默认态外壳为透明边框且无阴影，正文无可见边框；但源码保留聚焦整圈box-shadow，独立编辑入口保留border与ring-2。Figma共享组件全部40个根变体仍有1px描边。因此上一轮首页截图不能证明全局富文本已经统一，早期“一层边框/焦点”和首页整圈聚焦环方案已由本轮确认覆盖。
