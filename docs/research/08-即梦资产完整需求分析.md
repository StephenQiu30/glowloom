## 2. 信息架构与对象边界

```text
资产
├─ 生成历史
│  ├─ 图片
│  ├─ 视频
│  ├─ 音频
│  └─ 文档
├─ 画布
│  ├─ 画布
│  └─ 历史画布
└─ 短剧
```

侧栏还有创作、探索、主体、短剧工作室，以及对话/最近画布快捷区。主体是同级入口，不能因为主体使用图片就合并到资产图片列表。资产是统一回访入口，生成历史是按创作来源组织的分类，图片等是媒体类型，画布和短剧是创作容器；这些词不互为别名。

观察到即梦自身保留“新建项目”“复制项目”“未命名项目”等历史文案，与“画布”并存。这是竞品原文事实，不足以证明项目与画布在内部是一对一关系。织光应统一面向用户的语义，不能机械复制竞品残留用词。

## 5. 状态、视觉与交互需求

1. 普通空态：“暂无相关资产”。筛选导致列表为空时：“当前已开启筛选，部分内容可能被隐藏”。两者必须区分，后者不能误导为账户没有内容。
2. 查询工具栏与批量工具栏是不同模式；显示计数，零选中禁用危险/无效动作，退出清空临时选择。
3. 已选来源分类和媒体子分类需要可辨认状态；卡片主区域打开内容，更多菜单和收藏不得误触主导航。
4. 资产页采用深色内容背景、固定左侧导航、上方两层分类与查询行；卡片网格与空态处于同一内容区域。顶部营销条、会员额度和剪映品牌集成属于即梦商业外壳，不能自动成为织光需求。
5. 页面结构中存在生成输入区，本轮默认显示 Agent 模式，与用户截图图片生成模式不同；它是跨入口的创作工具，不代表资产页只服务图片。底部实际显隐及遮挡应以截图核对，不能只按辅助树确定视觉位置。
6. 键盘焦点、菜单关闭、读屏标签、窄屏布局、失败重试、加载骨架、翻页/无限滚动均需要验收；本轮没有形成即梦跨端结论。

## 6. 织光采用边界与命名建议

用户已明确要求对齐资产功能及命名。以下是面向织光的产品设计建议，第二阶段仍须结合既有业务合同核对，不能当成即梦内部实现事实。

| 用户可见名称        | 定义与使用边界               | 避免混用                             |
| ------------------- | ---------------------------- | ------------------------------------ |
| 资产                | 全部个人创作回访入口         | 素材库、作品库、资源库轮流指同一导航 |
| 生成历史            | 生成任务及其产出的回访分类   | 所有上传文件或画布的总列表           |

| 历史画布            | 即梦确有此子分类，语义待补证 | 自动解释成版本/回收站                |
| 短剧                | 独立创作容器分类             | 把全部视频资产称短剧                 |
| 主体                | 独立的可复用角色/对象入口    | 与资产统称“素材”                     |
| 参考素材            | 创作输入或上传参考内容       | 自动写成生成结果                     |

展示命名先统一导航、标题、按钮、搜索占位、空态、菜单、可访问名称和设计稿。内部资源 ID、数据库表、API、历史链接不可仅为文案一致性直接破坏性重命名；需要变更时先列迁移和兼容合同。
