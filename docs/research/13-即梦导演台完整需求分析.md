## 2. 产品目标与信息架构

导演台是在无限画布内打开的 3D 预演编辑器：先构图/摆姿，再编排运动，产出可用作后续创作参考的图片或视频。它不是普通图片节点，也不是通用视频剪辑时间线。

| 区域     | 现场名称与职责                                                                                   | 证据                                                      |
| -------- | ------------------------------------------------------------------------------------------------ | --------------------------------------------------------- |
| 画布入口 | 导演台节点、进入导演台、返回画布                                                                 | R 入口观察                                                |
| 顶栏     | 3D导演台、快捷键、保存状态、静态预演/动态预演、拍摄、镜头素材；动态增加导出视频                  | R `static-restored.txt` / `dynamic-workspace.txt`         |
| 左栏     | 资产：角色、物体、背景、机位；搜索素材及子分类                                                   | R `objects.txt` / `camera-assets.txt` / `backgrounds.txt` |
| 中部     | 3D 视口；选择/移动/旋转/缩放、落地、视图设置；导演视角/机位切换；可收起、缩放的机位预览/分屏预览 | R `static-camera.jpg` / `view-settings.txt`               |
| 右栏     | 对象树（分类、搜索、折叠、选择、聚焦、锁定、显隐）；属性（根据选中对象变化）；可收起/调整宽度    | R `camera-properties.txt` / `static-pose-properties.txt`  |
| 动态底栏 | 时间轴、播放、循环、隐藏无动画轨道、时间/帧、帧率、总时长、缩放、对象轨道和分镜编排              | R `dynamic-workspace.txt`                                 |
| 输出面板 | 镜头素材选择/下载/添加到画布；导出视频配置与进度                                                 | R `shots-gallery.txt` / `export-video.txt`                |

## 3. 命名合同

| 概念              | 对用户统一显示                       | 说明                                     |
| ----------------- | ------------------------------------ | ---------------------------------------- |

| 角色控制          | 对象 / 姿势；预设姿势、重置姿势      | 动态中使用动作/静态姿势片段              |

内部类型/文件名称按项目规范在第二阶段确定；显示名变更不应未经迁移直接破坏历史节点或 API 字段。

## 5. 核心用户流程与例外

### 单帧构图

画布节点 → 进入导演台 → 恢复本地草稿（若有） → 静态预演 → 选择角色/物体/背景 → 放置 → 对象与姿势调整 → 创建/选择机位 → 预览 → 拍摄 → 镜头素材 → 添加到画布。

拍摄不是保存场景；回写失败不能删除已经生成的素材。放置时 Esc/取消不能残留对象；锁定对象不可被移动；只读不能打开修改路径。

### 动态预演

切到动态 → 明确选择是否复制静态场景 → 选择角色 → 动作库/路径 → 配置片段/关键帧 → 运镜暂存与预览 → 确认 → 分镜编排 → 预览 → 选择固定机位或分镜导出 → 下载/加入画布。

覆盖动态不能丢掉现有时间线引用；同一角色片段冲突回退；时长改变不能截断有效内容；播放时计算帧不等同编辑持久化。

### 返回静态

选择静态 → 可不同步直接切换，或确认用当前动态帧覆盖 → 保留当前姿势与机位，去掉运动片段/关键帧。取消不更改任一工作区。

### 保存与恢复

编辑 → 本地草稿 → 显式保存云端 → 等待确认才显示已保存。进入发现未保存草稿时提供恢复/使用云端；退出提供继续、仅留本地、保存并关闭；云端新版本不得无提示覆盖。

## 6. 数据与集成合同（D，待第二阶段映射）

1. 场景文档包含带版本的静态/动态工作区、对象/机位稳定 ID、资源引用、环境、姿势、轨道、片段、关键帧、分镜、拍摄/导出关联；所有坐标/角度/时间明确单位与边界。
2. 编辑态包含选择、工具、视角、播放头、面板、拖拽暂存、加载与输出进度；不应将每帧播放或鼠标 hover 写入业务持久化。
3. 渲染态包含 Three 场景、加载缓存、mixer、camera、render target、骨架和资源清理；由生命周期持有，不塞进可序列化 DTO。
4. 画布集成通过当前项目节点/资产/权限/保存通道完成。导演台场景编辑与画布多人协作的冲突粒度需另行设计；不把上游本地 store 替代项目的协作模型。
5. 资产上传与导出采用已有服务；真实资源 ID/版本为引用依据，临时 blob URL 不作为跨设备的永久来源。
6. 历史节点、命名和数据必须有明确迁移；内部 enum 是否更名以兼容成本为准，不机械全局替换。

## 7. BeefTV 实现整理范围

使用固定 MIT 基线，保留许可和来源。优先整理纯函数与行为：变换采样/四元数插值、路径采样/重定时、相机绑定/解绑、拖拽事务、资源释放、过期加载阻断、截图前后状态恢复、保存队列与输出身份检查。

Glowloom 自己负责模式、中文术语、组件布局、权限、项目/资产服务、场景 schema、协作与设计 token。BeefTV 四模式不能直接替代即梦两工作区；它的快捷键、MediaRecorder 导出、角色库及景深声明不能无条件视为一致。详见[19项能力整理表](evidence/2026-10-29-director/beeftv-audit.md)。

不直接复制即梦发布源码、私有资产或动作库。742 个动作是观察数量，不是已取得可再分发素材；可用模型与动作的来源许可及骨架兼容需要独立核验。文字生成动作也必须依项目真正可用的服务对接，不能用占位成功状态冒充。

## 8. 设计稿状态清单与验收

必须覆盖的设计状态：入口节点；首次说明；静态空场景；角色/物体/背景/机位资产库；放置态；对象/姿势属性；机位属性/预览/分屏；环境属性；动态时间轴；动作库与片段属性；关键帧曲线；角色路径；运镜预设/自定义/预览确认；分镜编排；镜头素材空/有选中；导出配置/进度/失败；草稿恢复/模式覆盖/退出/保存冲突；只读/资源失败/窄屏面板收起。

验收需要真实可执行闭环，不以静态截图代替：

- 单帧：放置、姿势、镜头构图、拍摄真实图、回画布、刷新后资源仍可读。
- 动态：角色动作/路径与机位独立运动、时间轴不重叠、分镜切换、输出可解码视频，比例/帧率/时长正确。
- 数据：静态↔动态同步与不操作两分支；撤销/重做；失败恢复；跨项目/节点切换不会串写；只读拒绝。
- 资源：坏模型、无动画、骨架不兼容、WebGL context lost、卸载加载竞争、重复开关资源清理。
