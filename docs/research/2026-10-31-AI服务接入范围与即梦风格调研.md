# AI 服务接入范围与即梦风格调研

调研日期：2026-10-31（Asia/Shanghai）。源码基线：`0a2292d4`，分支 `main`。本文是调研与方案建议，不代表设计批准、实现完成或真实供应商验收。

## 用户请求

补齐 ChatGPT 官方 API 接入；当前聚焦 DeepSeek、火山方舟、豆包语音、火山音乐，调查产品关系及接入方式；AI 服务接入页面与项目已有即梦设计风格保持一致。本文将 OpenAI 与上述四项合计五个接入入口作为建议范围，尚未将其他既有能力删除。

## 官方事实

| 接入入口 | 产品与调用边界                                                                             | 凭据与建议处理                                                                                      |
| -------- | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| OpenAI   | 官方 API 使用 `api.openai.com/v1`；官方推荐逐步采用 Responses，Chat Completions 仍支持     | 服务端保存官方 API Key；新文本能力优先独立处理 Responses 请求、事件与结果，不把修改地址当作完成适配 |
| DeepSeek | 官方地址 `https://api.deepseek.com`，支持 OpenAI 格式的 Chat API                           | 使用 DeepSeek API Key；方舟托管的 DeepSeek 属于另一连接、凭据与计费路径                             |
| 火山方舟 | 大模型服务平台；模型推理地址 `https://ark.cn-beijing.volces.com/api/v3`                    | 方舟 API Key；按模型核验 Model ID 或 Endpoint ID、参数、权限和价格                                  |
| 豆包语音 | 独立豆包语音产品文档与 `openspeech.bytedance.com` 接口；语音合成、播客、实时语音有各自协议 | 新接口支持语音控制台 API Key；资源 ID、请求体模型字段按具体接口配置，不能照搬方舟 Bearer 鉴权       |
| 火山音乐 | 音视频理解与处理下的音乐 OpenAPI，地址 `https://open.volcengineapi.com`                    | AK/SK 签名，固定地域 `cn-beijing`、服务 `imagination`；不是方舟 API Key                             |

豆包语音和火山音乐属于火山引擎生态，但不能据此认定它们共享方舟接口、密钥、开通权限和计费。方舟的音频理解也不能替代语音合成与音乐生成。

音乐接口包括歌曲 `GenSongForTime` 和纯音乐 `GenBGMForTime` 等调用，需保留异步任务查询。豆包语音新旧控制台存在不同鉴权方式；本项目已有 API Key 路径，建议继续以具体新接口合同为依据，不统一强制用户填写旧 AppID/AccessToken。

官方来源（访问日期均为 2026-10-31）：

- [DeepSeek 首次调用](https://api-docs.deepseek.com/quick_start/agent_integrations/)：官方地址、API Key 与 Chat 请求示例。
- [方舟 API 调用指南](https://docs.volcengine.com/docs/ark/APICallGuide?lang=zh)：检索内容含官方模型调用地址与 API Key 示例；本次直接打开仅返回文档壳，未将其记为完整页面读取成功。
- [豆包语音双向流式合成](https://docs.volcengine.com/docs/doubao-voice/bidirectional-streaming-text-to-speech-websocket?lang=zh)：官方检索内容列出 X-Api-Key、资源 ID 和旧版鉴权入口；直接打开超时。
- [豆包语音播客](https://docs.volcengine.com/docs/doubao-voice/podcast?lang=zh)：直接读取到独立域名、x-api-key 与 x-api-resource-id。用于证明产品鉴权边界，不将播客加入本次实现范围。

- [生成纯音乐](https://docs.volcengine.com/docs/audio-video-understanding-and-processing/generate-pure-music-1?lang=zh)、[生成歌曲](https://docs.volcengine.com/docs/audio-video-understanding-and-processing/generate-vocal-songs?lang=zh)、[查询任务](https://docs.volcengine.com/docs/audio-video-understanding-and-processing/query-task?lang=zh)。

## 当前源码事实与缺口

1. `b7578099` 已包含 OpenAI 接入工作，当前源码并非完全没有 OpenAI：`backend/internal/catalog/domain/adapter_spec.go` 有注册及候选目录，`backend/internal/catalog/domain/provider_preset.go` 有内置预设，`backend/db/openai_provider_incremental.sql` 有增量 SQL，前端有正式名称与 Logo。
2. `backend/internal/operation/adapter/providerhttp/driver_openai.go` 已注册 OpenAI，文本走 Chat Completions、图片走 Images Generations；尚不是 Responses 实现。OpenAI 图片仅允许单张无引用文生图。候选目录仍列 GPT-4o、o1、DALL·E 3 等，写有 reviewed_at 不能证明当前模型生命周期已核验，需重新查官方可用性。
3. 确认存在发布边界缺口：`backend/internal/catalog/adapter/postgres/model_releases.go` 的 CreateModelRelease 最后一组供应商能力白名单未包括 OpenAI，文本与图片均受影响。因此驱动与预设存在仍不足以证明能发布给创作端使用。
4. `backend/internal/operation/adapter/postgres/editor_submission.go` 的发布模型版本选择 CASE 白名单也未含 OpenAI；需在修复发布后一起验证冻结版本、报价与提交，不能仅给接入弹窗添加选项。
5. 已有独立 `volcengine_speech`、`volcengine_music` 适配；`preset-connect.tsx` 已区分 API Key 与音乐 AK/SK。应沿用这些边界，避免重新建一套集成框架。
6. 截图主表显示的是已创建的连接，而非所有可接入预设。两条连接不足以证明 OpenAI 选项缺失；部署版本、预设迁移应用情况、归档状态尚未查验。本次未读取本地数据库、凭据或运行服务。
7. 接入选择仍包含其他既有供应商。建议收敛新建连接入口，保留既有连接及历史任务，不把“当前只支持”解释为删库或破坏历史能力。

## 页面建议（待确认）

依据 `docs/research/06-即梦创作界面与AI接入表单对照.md` 与全站公共组件方向，复用项目当前主题 token、Geist、shadcn 组件和共享外壳；不新增页面专用颜色体系。此处参考的是项目已有即梦对齐资料，本次未重新观察即梦在线页面。

- 页面保留一个接入主按钮，紧凑列表显示连接名称、服务、模型数量、启用状态、配置状态和操作。移除不影响主要任务的常驻说明；高级预设管理维持次级折叠入口。
- 接入弹窗仅提供五个明确的服务入口；火山三项可用简短分组说明表达同一生态，仍分别选择与配置。
- 表单顺序为服务、对应凭据、模型分类与跨分类多选、保存。模型名称为主，技术 ID 与接口细节放详情；无能力的分类不伪造可选项。
- 保存后关闭弹窗、刷新列表并恢复触发器焦点；详情中进行模型验证与显式启用。配置状态只显示“已配置/未配置”，不展示密钥尾号。
- 复用现有中性色、弱边框、选中背景、按钮层级和圆角。桌面保留紧凑表格，窄屏保证操作与焦点可达，按 320/390px 与明暗主题验收；不直接照搬即梦桌面网页的最小宽度。

## 可选组织方式

- 建议：一个页面、五个独立接入入口。管理集中，能复用现有列表、详情与预设流程；表单必须随服务切换鉴权字段。
- 备选：分为语言与视觉、语音与音乐两个管理页面。任务更聚焦，但增加页面、导航与跨服务管理成本，当前五项规模收益有限。

以上均保留服务协议边界。不建议做“填一次方舟 Key 即自动接入全部火山服务”的流程，官方接口不支持这一假设。

## 后续实施验收建议

先核对运行版本与预设落库，再修复 OpenAI 发布及版本冻结链路、核验模型目录与参数，最后落实页面收敛与样式。沿用需求 → 设计 → PRD → Plan 的项目来源关系与已有 Figma 先行约定。确认方案后再更新正式设计与 Figma。

验证应覆盖旧安装幂等升级、只允许目标范围新建连接、五类凭据合同、保存与验证分离、发布到报价与提交的同一版本、音乐异步查询与未知结果不重发，以及响应式/键盘/焦点恢复。受控测试和真实服务调用分别记录；未真实调用时不写成供应商接入验收通过。
