# CI 三类失败修复

基线：38583e6d。原失败记录：https://github.com/StephenQiu30/glowloom-server/actions/runs/40838985679 。本次在独立工作树核验，只交付明确列出的修复；共享工作区其他修改保留。

## 修复

- 业务存储：首页与文本驱动的草稿位置只保留页面内内存引用，正式草稿仍由项目 API 保存，通过编辑器已有的服务端草稿列表恢复。页面重新打开不自动读取本机业务指针；引用按账号/项目作用域隔离。音色待确认请求改为按账号/项目隔离的内存记录，保留同请求 ID 重试；明确重新打开页面后需从服务端音色库核对结果。未扩大浏览器持久存储白名单。
- 资产：测试夹具采用实际序列化的 OperationID 字段；重验进一步确认个人历史仅识别小写字段、任务详情仅识别大写字段的不一致。两处现统一兼容两种已存回执字段，保留发起者与组织判定，不放宽候选媒体访问。新增两种回执形式及另一账号不可访问的回归。
- 模型目录：覆盖当前八个内置预设与唯一标识，按声明的 text 能力验证文本协议及模板；非文本服务必须拒绝文本模板。未将音频、数字人或动作协议强行改成聊天协议。

## 验证

修复前，原 CI 中业务存储检查、两个资产用例、四个模型目录顶层用例失败。修复后执行完整前端业务测试、生产构建、standalone 协作传输、协作运行时测试和独立 PostgreSQL 的后端 Race 检查。实际结果在交付回复中列明。

本地首次后端全量运行缺少 canvas-collab 的依赖，造成运行时启动失败及失败路径的数据竞争报告；补齐 CI 相同的 frozen-lockfile 安装后重跑相关包。本地首次前端运行包含正在调整的旧草稿恢复断言及其他用例超时，保留其失败事实，最终代码另行执行完整检查。
