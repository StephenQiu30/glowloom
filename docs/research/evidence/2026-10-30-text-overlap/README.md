# CR-075 顶栏、筛选及文字遮挡修复

用户原文：“当前我们的文字的展示有遮挡的部分，需要修复和调整，同时我们的主体和和资产的页面也要处理和修复”。随后确认重点为“顶栏和筛选工具”。先实际复现，再改Figma与事实来源，最后修改代码并检查真实页面。没有执行用户数据删除、主体创建或模型生成。

## 问题与修复

主体768px桌面展开搜索时，原顶栏把筛选列压成0px、批量列仅17px，搜索盖住时间与批量操作。subjects-768-before.png/json是原始证据。当前产品内容容器宽度不足850px时，普通工具顶栏改为两排：搜索/账号独立上排，筛选/批量下排；容器边界跟随侧栏宽度，筛选内容增加时高度自然增长。批量replace-base仍独立展示真实操作。source截图subjects-768-final.png和subjects-header-after.png显示筛选列390px、批量82px、搜索账号447px，互不遮挡。

资产时间浮层新增16px碰撞安全边距及可用高度内滚动。320px视口实测浮层x16、宽288、右边304；320×500短视口下高222、内容高305，内部overflow-y:auto，底部操作可到达。此前面板贴住屏幕右边缘，不能把没有整页横向滚动视为浮层布局正确。

同时修复资产及主体卡片的文字/更多按钮占位：标题与时间都保留操作列，20px行高，36px桌面/44px手机按钮不压封面；长名称单行省略并保留完整title和可访问名称，批量/引用状态没有更多按钮时释放文字宽度。真实资产320px卡片及长标题源组件fixture都读回：菜单在封面下方，标题/时间文字右边界233，按钮从241开始，保留8px间距。主体fixture中操作隐藏后文字宽度由236增至280px，菜单仍可打开；真实主体页当前没有数据，不把空页验收冒充长卡片验证。
