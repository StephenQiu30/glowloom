# 即梦画布视觉纠正测量（2026-10-28）

## 来源与观察条件

用户在本轮提供即梦文本节点选中截图，并确认“这里我们的设计稿不对，我们要做的是和即梦保持完全一致”。对应REQ-JC-007，目标是实页视觉与交互，不是把即梦操作套用到已有样式。

本次工作流通过用户指定Chrome页面的只读DOM几何、computed style和截图观察取证。目标为“文本 3”选中，画布5节点、0连线，显示缩放136%。本次DOM采样可视区域为1869×873 CSS px，devicePixelRatio为2；它与用户附图窗口高度不同，截图中的绝对坐标不能混用。节点采样屏幕宽约436.56px，对应世界宽320px，说明界面显示的整数136%并非精确几何系数。

证据类型：实页DOM/CSS与可见截图观察；不是源码或后台协议分析。读取没有触发生成、积分消耗、会员购买或共享权限变化。

## 字体与一致性限制

源页面多数中文控件字体栈为`PingFang SC, Hiragino Sans GB, Microsoft YaHei, Arial, sans-serif`；生成器区域另外含Montserrat和CapCut Sans。当前Figma工具返回的可用字体有Noto Sans SC和Montserrat，没有PingFang SC。临时替代字体只能用于继续可编辑排稿，必须明确保留字形、字宽和换行差异；不应标为像素完全一致。

当前数据覆盖一个文本空节点选中状态。编辑态、不同缩放、悬停、键盘焦点、非空媒体、窄视口避让、展开、任务执行和失败等须分别取证。隐藏热区的几何和可见标记必须分开建模；不能只凭AX中存在8个按钮就设计8个可见控制点。

## 纠正与验证规则

1. 旧稿统一44px桌面按钮、52/54px左侧栏、额外八角可见控制点及232px高文本生成器不作为本专项视觉基线。
2. 固定视口、浏览器缩放、画布缩放、内容与选中状态，比较即梦实页、可编辑Figma及正式实现；动态业务数据使用真实值，不能写死示例余额。
3. 比较几何、字号/字宽、颜色、透明度、圆角、图标、边框、阴影及控件状态；记录偏差，结构通过不等于视觉通过。
4. 世界节点坐标与屏幕控件锚点分别验证；不可直接把当前截图x/y作为所有视口的布局常量。
5. 此记录提供来源与限制，不宣布Figma、代码或完整产品接受完成；实际执行状态只见BACKLOG。
