# 即梦创作界面与 AI 接入表单对照

观察日期：2026-10-27。对象：[即梦官方网页](https://jimeng.jianying.com/ai-tool/home)。织光源码基线：`a7cce4cabb02a0653d10cc78ce14a1b7f22232c2`。

本次使用 `reverse-engineer-anything` 的 REA 浏览器场景工具，实际打开首页、创作类型、图片模型、视频模型与登录弹窗，并观察 390px 窄视口。结论用于修正织光的信息层级和组件组合，不代表已修改 Figma 或完成产品实现。

## 1. 结论与适用范围

当前 AI 接入表单的主要问题是信息层级和状态衔接：模型名称与技术 ID 一样弱，辅助说明较多，分类全部展开，保存后替换整段表单，用户需要重新理解页面。仅调整间距和圆角不能解决这些问题。

即梦可借鉴的部分是：一个明确的主要工作区域；创作类型、模型、参数逐层选择；模型名称优先；次要说明按需呈现；菜单与触发器保持位置关系。织光保留已确认的中性色、Geist 与官方 shadcn 组件，不迁移即梦的品牌资产和促销装饰。

即梦本次观察的是面向创作者的单模型选择流程。织光的服务接入是管理员选择多个模型并保存凭据，二者业务不同。下文的分类多选、验证与启用方案来自用户已确认需求及织光合同，不能写成即梦已存在的 BYOK 管理能力。

## 4. 建议的接入弹窗结构

以下结构按需求 SRC-AI-27 修订并同步至 Figma，尚未完成产品实现验收。此前关于接入弹窗内验证的建议已被用户最新确认替代。

1. 标题只保留“接入 AI 服务”。
2. 平台沿用原有单选卡片，保留名称及必要区域信息。
3. API Key 独立一行，使用 InputGroup 的显隐操作和关联错误提示。
4. “模型”一行显示总已选数量，下方为文本、视频、音频、图片 Tabs；分类只筛选列表，不清空跨分类选择。没有可选模型的分类显示真实空状态。
5. 模型以紧凑的 Checkbox 行多选；整行标签可点击，名称突出。默认不为每行增加独立卡片、技术 ID 或大块说明。
6. 接入弹窗仅呈现接入中、失败和成功状态，不包含模型验证。
7. 底部保留取消与“接入服务”。成功后可进入管理详情，另行选择已接入模型并验证；真实调用费用提示仅出现在管理验证区域。

用户最新确认将验证移至管理部分，不再作为接入弹窗的必经步骤；保存连接及单个模型验证均不能把其他模型标为“已验证”。视频任务仅被服务商受理时，仍应明确其尚在生成。API Key 无效、模型无权限、余额不足、限流和结果未知需要保留不同反馈，不能为了简洁把它们统一显示成成功。

组件映射：平台选择使用 RadioGroup + Field；分类使用 Tabs；模型选择使用 FieldSet + Checkbox + FieldContent/FieldTitle；验证模型使用现有 Select/NativeSelect；状态使用 Alert；操作使用 Button + Spinner；弹窗使用 Dialog。列表使用项目现有组件和 CSS 布局，不另造控件。

## 5. 响应式与对齐规则

这些是织光的实现建议，不是即梦的测量值。

- 用 Flex/Grid、内容自然高度、统一 gap/padding 建立布局。固定控件高度和最大内容宽度可以是设计 token；固定整体画板宽度和业务层 left/top 补偿应避免。
- 弹窗随视口收缩，手机两侧保留项目既有 16px 间距；总高度受动态视口约束，内容可滚动，关闭按钮及提交操作可到达。
- 平台卡片在可容纳时保持两列，不足时转一列；不能仅以桌面截图位置推算手机坐标。
- 模型行允许长名称换行，文本容器 `min-width: 0`，选择控件不压缩；错误提示加入后不遮挡操作。
- DataTable 在自身容器横向滚动，不能让整页超宽；批量工具栏允许换行。
- 覆盖 320、390、768、1440px、短视口与 200% 缩放，检查键盘焦点、Escape、回焦、长内容及滚动后的按钮可达性。

依据 [Vercel Web Interface Guidelines](https://vercel.com/design/guidelines)：优先原生布局能力，核对移动和宽屏，保证焦点可见、移动触控目标至少 44px、长内容可用；保留浏览器缩放。其允许为视觉对齐做微量校正，不意味着可以用大量固定坐标替代响应式结构。
