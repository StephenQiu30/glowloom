# 即梦创作完整需求分析

观察日期：2026-10-29，Asia/Shanghai。来源：[即梦创作](https://jimeng.jianying.com/ai-tool/home)。用户要求见[需求16](../requirement/16-创作对齐即梦与全站公共组件需求.md)。

本报告建立独立于织光实现的创作需求基线，覆盖信息架构、七种创作类型、输入与引用、参数、草稿、结果链路、命名和全站公共组件。**“完整”指分析与检查范围，不表示所有竞品执行路径均已实测。** 未读取织光功能源码、未检查织光运行页面，不能据此判断当前实现缺失。当前阶段与后续安排见 [BACKLOG](../../BACKLOG.md)。

## 1. 主要结论

1. 创作不是单一提示词框：上层有「生成 / 画布」，生成下有「Agent 模式、图片生成、视频生成、音乐生成、音频生成、数字人、动作模仿」七类。类型、模型、模式、参数是四个不同层级。
2. 输入外壳可以共享，业务字段不能强行一致。图片是参考图和文本；视频按参考模式变化；音乐有智能时长；音频有音色库；数字人区分说话内容和动作描述；动作模仿禁用文本输入。
3. Agent 与图片在本页切换时各自恢复草稿，图片的比例、分辨率、数量也保留。这支持按创作类型隔离草稿的需求，不证明跨刷新、跨设备或服务端保存。
4. 头像应纳入公共账号区域，而不只是一个图片样式。历史发行脚本及跨路由节点证据支持持久外壳、公共账号动作、页面动作插槽；本轮测得创作页头像图像24px、触发区28px、公共栏36px高、gap 8px。资产页头像样式是用户认可的织光基准，本阶段没有检查其实现。
5. 全站一致性应落实到颜色、字体、间距、控件、菜单、弹窗、空态、焦点和响应式，以及同一组件的所有实例。不能只调整创作首页或复制一份资产页头像。
6. 当前账号生成历史四类均为空，排队、失败、取消、重试、结果详情和下载没有可用样本。本报告列出必须补证的状态，不把推定流程当成即梦已实测事实。
7. 390×844的即梦桌面网页存在横向裁切。桌面视觉一致性与移动端可用性需分别定义，不能把裁切复刻成验收目标。

## 3. 信息架构和命名基线

```text
应用外壳
├─ 左侧导航：创作 / 探索 / 资产 / 主体 / 短剧工作室
├─ 左侧历史：对话（新建对话）/ 画布（全部、新建画布）
├─ 公共账号动作：企业服务 / 积分超市 / 消息 / 积分与会员 / 头像
└─ 创作
   ├─ 生成
   │  ├─ 创作类型：Agent模式 / 图片生成 / 视频生成 / 音乐生成 / 音频生成 / 数字人 / 动作模仿
   │  ├─ 输入：文本、技能、主体或分角色的参考素材
   │  └─ 操作带：类型 → 模型 → 模式/参数 → 费用 → 生成
   ├─ 画布：最近项目 / 全部 / 新建画布 / Agent输入 / 发送
   ├─ 推荐技能
   ├─ 最近上新与工具入口
   └─ 作品内容频道及查看创作过程
```

| 层级/对象 | 对齐用词 | 边界 |
| --- | --- | --- |
| 主导航 | 创作、探索、资产、主体、短剧工作室 | 创作不能改叫生成历史；资产不是仅上传文件 |
| 首页工作方式 | 生成、画布 | 不与图片/视频媒体类型混成一级Tab |
| 创作类型 | Agent 模式、图片生成、视频生成、音乐生成、音频生成、数字人、动作模仿 | 中文显示词与API枚举分开管理 |
| 模型 | 具体模型展示名；数字人/动作模仿可展示产品化模式名 | 不直接显示内部技术ID代替模型名 |
| 视频模式 | 全能参考、首尾帧、智能多帧、智能编辑、超长视频 | 不是五个新的创作类型；可用性由模型决定 |
| 音频模式 | 全能配音、文本朗读 | 音乐生成不是音频模式菜单中的一项 |
| 引用 | 上传参考、参考内容、首帧、尾帧、角色、动作、音色、音色库 | 明确槽位角色，不把所有对象称为附件 |
| Agent | 自动、自定义、生成偏好、技能、更多技能、新建技能、管理技能 | 技能与模型、提示词预设是不同概念 |
| 任务入口 | 生成；画布分支为发送 | 文案与实际副作用一致 |
| 结果组织 | 生成历史；图片、视频、音频、文档 | 这是资产子导航，不等同于七种创作类型 |
| 项目与会话 | 对话、新建对话、最近项目、新建画布、历史画布 | 不因同属历史记录就合并语义 |
| 复用动作 | 做同款、用作参考图、查看创作过程 | 全配置回填、追加素材、浏览过程分别建合同（历史研究11） |

后续重命名须建立「当前用词 → 目标用词 → 页面/上下文 → 国际化键 → 是否涉及路由/API/存量数据」映射；本阶段不填造“当前用词”。Logo和品牌名称不能用即梦品牌替代织光，字体是否引入须核对授权和原有项目约束。

## 7. 设计稿改造的输入清单

按用户要求，设计稿应覆盖整套组件和页面状态，而非增加一张与旧稿脱节的创作参考图。

1. **全局基础**：颜色层级、文字样式、间距、圆角、描边/阴影、图标、尺寸及交互状态。记录竞品观察值与织光采用值，差异必须有理由。
2. **公共外壳与账号**：展开/折叠侧栏、普通页导航插槽、账号动作组、头像fallback、菜单展开、批量替换、无账号态；以资产页认可样式为核对点。
3. **创作主画板**：生成/画布两分支，七种类型默认态，Agent自定义、技能与@、图片参数、视频各参考模式、音乐时长、音频两模式与音色库、人物类型槽位。
4. **交互状态**：模型菜单、长列表、选中/禁用、无模型、加载/错误、空/有输入、参考上传/失败、草稿往返、长文本/展开、生成中及结果状态；未知竞品态清晰标成待补证设计。
5. **跨入口交接**：探索做同款/参考回用、主体引用、资产生成器、画布入口；同一个组件必须使用实例和统一变量，页面差异用属性表达。
6. **响应式**：至少320/390/768/1280/1440、短视口、200%缩放；菜单不出屏，主操作可达。移动设计是明确的适配方案，不伪称竞品实测。
7. **追踪关系**：每个画板/变体标CR-ID、组件来源、状态、竞品证据。旧实例按差异表迁移，不仅重命名图层；验收后记录真实节点ID与截图。

本阶段没有打开或修改Figma，因此不提供虚构节点、完成率或“设计已同步”结论。

## 8. 第二阶段对照表与实施顺序

逐项表模板见[对照与验收矩阵](evidence/2026-10-29-creation/parity-matrix.csv)。所有“当前实现”栏均为未检查，这是用户要求的阶段隔离，不代表缺失。

对照时分别记录五类结果：一致、部分一致、缺失、项目独有、竞品未知。一个功能的存在不等于视觉、交互、命名和异常处理都一致；必须分别判断。将每项差异关联到共享组件、设计节点和验收证据，避免每页独立补丁。

执行顺序：核对并行工作区与文档约束 → 读取实际路由/组件和页面 → 建立差异与命名映射 → 更新唯一来源设计及其PRD/Plan → 修改Figma组件/变量/实例和原型 → 按共享职责落实代码 → 页面逐项复验。涉及公共样式时先评估所有使用者；真实业务能力不足时记录合同缺口，不用静态按钮冒充完成。
