# 团队创作与成员管理设计

技术设计；确认等级沿原来源。需求、PRD、Plan 独立维护，实施状态只见 [BACKLOG](../../BACKLOG.md)。

## 1. 摘要

按有效团队资格管理成员、邀请、交接和创作空间。

本文采用设计、用户故事与测试场景结构。原始需求、PRD 和 Plan 独立维护；当前实施进度、剩余工作及阻塞项统一见 [BACKLOG](../../BACKLOG.md)。

## 2. 参与者

使用者与参与职责：团队成员与团队管理员。维护职责及确认人沿下方原来源记录；未给出姓名的，不补造人员或排期。

## 3. 背景

原始需求：[02-用户系统需求](../requirement/02-用户系统需求.md)。关联需求与验收：[01-用户系统](../prd/01-用户系统.md)。本文维护技术合同；相关实施步骤与证据见 Plan，状态与调度见 [BACKLOG](../../BACKLOG.md)。

## 4. 目标

按有效团队资格管理成员、邀请、交接和创作空间。目标的规则、量化条件与非目标沿需求原文及下方已确认设计，不增加未经确认的指标。

## 5. 使用场景

参与者为团队成员与团队管理员；在下方定义的输入、对象状态、权限和环境条件具备时执行相应操作。各故事按其独立前置条件核对，不能把测试夹具当成真实业务条件。

## 6. 价值

团队成员变化不改写全局身份，失去资格后隔离私有状态。

## 7. 方案

### 7.1 Global Constraints

- 前置01与T-USER-09，T-USER-10邀请端口复用；团队名称2～50字符；未归档创建≤5、加入≤20、每团队成员active+suspended≤100、pending邀请≤100。
- archived只读；suspended只由平台恢复原状态；governance_blocked在接管成功后清除。
- 邀请48小时，提案48小时；最后可用团队管理员必须交接；被移除/暂停不能用旧邀请复活。
- 只修改当前团队关系，作品归属不因退出/移除变化；执行[总览](01-用户系统总体设计.md)共同检查点。
