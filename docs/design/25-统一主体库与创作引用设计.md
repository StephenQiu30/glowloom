# 统一主体库与创作引用设计

依据：[主体需求12](../requirement/12-主体功能对齐需求.md) SUB-001～013；外部事实：[即梦主体研究09](../research/09-即梦主体功能与需求基线.md)。用户已明确采用即梦方式，即当前空间内跨项目统一主体库，并追加要求功能与设计全量一致、智能配音使用火山引擎豆包。设计目标与已实现状态分开；状态只见 [BACKLOG](../../BACKLOG.md)。

## 1. 摘要

将主体从「先选项目、再选角色/场景/物品、详情后再编辑」重构成独立的主体库。主体保存名称、描述、主参考、补充参考与可选音色；通过 `@` 在创作中复用，并固定主体和媒体版本。页面、Figma、API领域名统一使用 Subject／主体；Bible继续承担剧本角色、造型、场景、物品的既有职责，不做全仓字符串替换。

## 2. 参与者

登录创作者在当前创作空间管理主体，在有权写入的项目中引用主体。当前空间授权由既有 creation_scope 解析器负责；项目授权由 workspace 负责；媒体资格与对象读取由 media 负责；主体负责内容、版本、采纳绑定及生命周期。供应商负责实际生成，不把绑定音色视为已生成声音。具体维护人未指定。

## 3. 背景

本次在独立竞品基线形成后检查现有源码，确认如下差异；源码存在不等于运行验收。

| 领域 | 当前来源 | 目标变化 |
| --- | --- | --- |
| 主体库 | `frontend/src/app/subjects/_components/subjects-page.tsx`，`components/subjects/subject-list.tsx`；项目+三分类，分页后本地搜索，逐条GET详情 | 当前空间库、服务端全库查询、充分摘要、直接设置 |

## 4. 目标

1. 入口不要求项目或分类；完整的卡片→设置→保存→@引用路径与即梦已观察行为一致。
2. 查询先筛选排序再分页；错误、无权限与成功空结果区分。
3. 所有写入有明确归属、CAS版本和永久幂等，完整设置原子发布，未知结果不创建重复主体。
4. 旧主体身份、版本、剧本和提示词引用仍可读取；新旧来源不靠名称合并或猜测。
5. Figma可编辑稿和可点击流程覆盖桌面、390手机及关键状态；工程不可用能力明确说明，供应商验证独立记录。

## 5. 使用场景

| 故事 ID | 描述 | 来源与确认条件 |
| --- | --- | --- |

| US-SUB-04 | 作为项目创作者，希望通过@引用主体，以便保持身份和素材版本 | SUB-007；候选含创建入口、原子标签、持久ID/版本、授权重验和模型能力反馈 |

## 6. 价值

去掉项目和类别前置、详情再编辑等额外步骤；主体内容和素材来源分开，避免把普通图片收藏当主体收藏。原子保存消除「名字已经创建而主图尚未保存」的半完成体验；引用冻结版本让后续主体修改不悄悄改变已提交任务。

## 7. 方案

### 7.1 命名与页面

导航及页面名用「主体」；首张卡片为「新建主体」；@候选入口为「创建主体」；新建和编辑弹窗都为「设置主体」。字段为「参考主体」「名称」「描述」；已选主素材标为「主参考图」或视频参考，音色动作为「添加音色」「上传音色」「智能配音」。不再暴露角色/场景/物品分类、草稿/已确认、版本详情和恢复作为主体库主路径。

沿用全局ProductHeader、Geist、shadcn/Radix、Lucide和语义token；不复制即梦品牌、会员/营销或局部色板。筛选、时间、排序进入共享顶栏的页面工具槽；搜索沿共享公共操作组，作用于当前空间完整主体库。主区为新建卡及主体卡，封面保留原始比例和合理裁切，显示名称、类型标识及修改相对时间；更多菜单含设置、下载、收藏/取消收藏、删除。

弹窗桌面最大560px、内容内部可滚动，390px视口左右16px；关闭与保存始终可达。桌面控件沿全局36px，手机命中44px。新建/编辑共用表单：参考区域→音色→名称→描述→保存。名称最多20个UTF-16代码单元（与已观察maxlength及浏览器计数一致，属于项目精确合同），trim后非空；描述沿已有输入预算，不宣称即梦同上限。

### 7.2 媒体与音色

主参考必填，允许真实就绪图片或视频；初次从资产选择可切图片/视频。图片主参考可添加有序补充图片；补充项使用独立ID和position，不占用旧front/side等固定用途。图片/视频/音频格式及大小沿media现有真实接入预算；参考总量另作工程请求预算，不标成即梦实测上限。

主体专用来源接口先授权当前目标空间，再由服务器解析本人个人空间，复用media完整查询、预览和上传；浏览器不得指定源owner或切换全局空间绕过校验。来源查询合并本人个人素材和当前空间内本人发起的生成结果；由提交/报价/确认回执证明发起者，不以执行确认者冒充。图片/视频、搜索、收藏及真实超清条件在全局计数和稳定分页之前执行；响应携带当前actor/scope及可判别来源，生成项保留真实project_id。只读归档项目与原有读取授权保持一致；删除、回收站、非就绪或他人发起记录不进入候选。超清取实际upscale/super_resolution执行来源，不按像素尺寸猜测。重复asset身份跨来源冲突须明确拒绝，metadata行ID与asset ID不得混用。

音色可选，区分正式音频样本和已配置目录音色。添加菜单有上传音色及智能配音；加载时保存不可用，成功后可播放/移除，失败时保留表单并可重试/移除。没有真实支持的智能配音执行能力时，显示明确不可用原因，不能点后静默、返回静态音频或把绑定目录音色称为生成成功。该缺口不因Figma演示产物而消失。

### 7.3 领域与所有权

新增内聚 `subject` 域，`adapter → application → domain`。主体属于 `owner_scope_id`，以 `creation_scope` 权威解析当前用户、空间、读写权限和物理范围。每次读取、写入和幂等回放先进行当前授权；跨空间返回不可见。项目只是引用消费方，不为新建主体暗建项目。

主体头保存稳定ID、owner_scope_id、revision、current_version_id、created_by/created_at/updated_at/deleted_at；不可变版本保存schema版本、名称、描述、主参考和有序补充、音色事实、内容SHA及前版本。收藏是actor偏好，独立于共享内容版本；主图/名称/描述/引用任意变化产生新版本。

客户端只提交正式asset ID、参考项身份/顺序和音色选择，不接收自造SHA、对象地址或已就绪声明。媒体所有者证明资格并冻结原始/派生版本。主体采纳后只授予对**已绑定特定媒体**的使用，不授予浏览源个人库。媒体原owner保持不变；新主体历史引用须加入全局purge保护。团队绑定的先例是现有TeamAvatarAccess，但不能把头像专用校验直接用于通用主体。

跨项目生成必须通过明确的Subject绑定授权切点，或受控物化到目标项目；普通媒体接口的同项目约束不放宽。具体切点在实现前按实际调用链确定，必须覆盖草稿保存、报价、确认、worker和对象读取，不能只让前端插入成功。

### 7.4 设置命令、查询与管理

一次设置命令包含expected_revision、名称、描述、主参考、有序补充和可选音色，永久Idempotency-Key绑定actor+scope+action+完整请求哈希。在同一事务中验证所有依赖并发布版本。重试同键返回原回执；同键异体409；回放不绕过当前权限。失败不产生半主体。上传可以先独立完成，保存失败不删除已上传正式资产。

查询合同：q、favorite、created/updated时间字段、inclusive开始与exclusive结束时间、updated_desc/updated_asc/created_desc/created_asc、page/page_size。时间快捷项全部/最近一周/一个月/三个月换算为实际范围；UI时区为用户时区，服务端UTC。服务端先过滤再按(time,id)稳定排序，最后选择有界offset分页；主体UI不显示分页器，固定20条内部批次，底部IntersectionObserver（threshold 0.2）可见时追加，首批或查询变化重新读取第1批并取消旧请求；观察器使用视口相交裁剪，适用于product-main及引用弹窗滚动容器。按ID去重，空批次停止自动加载，重复批次只去重展示，仍按total边界递增请求。追加失败保留已有卡片并提供原批重试，禁止重复并发；保存/删除/收藏后刷新首批，避免旧顺序或版本残留。并发增删期间页内容可能移动，不宣称查询快照或游标一致性。

批量按明确选择的ID+revision执行，有界请求、逐项授权及结果。零项禁用；失败项保留选择并显示原因；不能把循环请求的部分成功提示成全部成功。导出属于项目格式决定：可审计manifest与经授权的真实媒体附件，不暴露存储键、短时URL或供应商凭据；即梦下载包格式尚未验证，不声称格式兼容。

### 7.5 删除与兼容

新Subject删除在产品中不可恢复，不提供回收站或恢复动作；实现保留不可变历史及媒体pin，不物理清理用户内容。删除确认说明「主体删除后无法恢复，关联的历史作品将无法重新编辑」，含明确目标；删除后旧已产出结果仍保留，但重新编辑/引用必须检查主体状态。UI文案与实际行为必须同时落地，未实现时不复制虚假警告。

旧Bible身份、内容、长名称、SHA、确认/恢复/剧本关系原样保留。使用有来源的映射或适配将旧条目带入统一库，不能按同名合并、随机生成新身份、截断长名称或重算覆盖旧历史。旧提示词ID+version沿既有resolver读取；新Subject引用有可判别来源及新schema版本，不能把旧ID当新表ID盲目重解释。部署仅加结构；禁止对已有业务库重放schema.sql。实际迁移先清点和备份，由明确迁移流程执行。

依据SUB-015，主体主页不展示「项目历史主体」入口；`/subjects/history`及旧项目入口继续保留原项目/三类型/详情/版本/恢复合同；当前空间新主体主路径保持无项目或分类前置。旧路由继续支持既有链接，不等于自动转入统一域。显式导入必须有永久来源映射和完整长名称/造型/音色转换；不能复用旧entry UUID创建新Subject，否则新域已知身份会阻断旧版本resolver回退。

### 7.6 引用和能力

@候选直接读取当前空间主体摘要，展示缩略图和名称，并提供创建主体；选择后插入原子引用。引用保存稳定主体ID+不可变version ID，以及服务器派生的描述和媒体身份/版本，不存预览URL。新建返回候选时可选中新主体，取消返回原光标位置；键盘方向键、回车、Escape与焦点由现有Command和Dialog管理。

既有草稿编译、source重验、报价和提交回执继续使用。主体内容修改不自动改变已固定的旧引用；用户显式更新版本。被删或撤权主体保留标签但标失效并阻断提交，正文不丢。模型不支持视频或音色时明确说明，不静默丢弃媒体后继续生成。供应商实际消费和视觉/声音一致性以授权真实样本单独验证。

正式采纳的每份媒体有独立binding ID与冻结owner、revision、原始SHA；草稿保存bindingId，报价及持久输入以subject_media记录该证明，worker只签发该正式输入的临时URL，并在签名前核对原始字节。普通media同项目授权不变。火山方舟视频omni_reference按官方content[]分别发送image_url、video_url、audio_url及reference_image/reference_video/reference_audio角色；帧模式不得混入全模态参考，其他协议不支持时拒绝，不能把声音编码成图片。此映射依赖模型发布合同允许的kind、数量与预算，不代表已真实调用供应商。协议依据：[火山官方Seedance说明](https://docs.volcengine.com/docs/ark/seedance-2-0?lang=zh)。

主体标签的语义role为subject；新正式binding在编译时按各物理kind展开成reference_image/reference_video/reference_audio，避免把附带音色也交给仅图片role。引用映射仍保留subject标签身份。旧Bible没有bindingId的快照保持原role及编译行为，不能因新展开规则改写旧永久请求。

### 7.8 豆包智能配音

供应商按SUB-012确定为豆包语音合成大模型2.0。采用[官方单向流式接口](https://docs.volcengine.com/docs/doubao-voice/unidirectional-streaming-text-to-speech-http?lang=zh)，新版语音API Key通过独立、固定语音服务地址调用；与火山方舟文本/图片/视频接入分开，不把方舟Key自动转发到语音域名。官方[语音Key说明](https://docs.volcengine.com/docs/DoubaoVoice/APIKeyUsage?lang=en)支持独立Key，无需在主体设置中暴露APPID或凭据。

复用现有catalog加密凭据和模型发布；接入保存与管理详情验证仍分开。主体入口没有项目，因此音色任务归当前actor/creation scope，不能暗建项目或通过client supplied owner选他人凭据。任务必须冻结模型、服务配置、凭据身份和真实speaker；短试听文本是项目选择，不宣称即梦使用同一文案或图像声纹推断。生成的是合成样本，不是用户真人声音复刻。

主体任务使用官方 `/tts/unidirectional/sse` 并要求实际 `code=20000000` 完整完成事件；共享普通HTTP适配仍按自身协议处理。依据[字节跳动官方调用示例](https://github.com/bytedance/agentkit-samples/blob/main/skills/byted-text-to-speech/scripts/text_to_speech.py)，不把普通HTTP EOF推定成Subject完成回执。非成功或截断音频不能进入正式产物。

无项目音色任务冻结正式release上游成本并记录实际usage，当前不创建项目预算预留；不虚构即梦的收费规则。凭据与release选择必须通过既有正式发布/验证门禁，连接保存不自动验证。provider并发及分钟限额与普通operation共用同一锁及统计；任务创建、开始提交、完整回执、成功/失败/未知写入同事务标准审计，不记录文本、密钥或音频字节。

永久幂等键及独立草稿意图将开始/恢复绑定到明确表单；加载期间禁保存，已有音色保留到新结果就绪。真实HTTP音频流完整接收、校验并由media所有者探测/导入就绪后，才能返回正式audio资产并供Subject设置原子采纳。不能伪造本地人工上传确认，也不能把provider临时URL当永久媒体。网络/进程未知不得自动重复收费调用；只读取原任务回执或明确未知状态。UI、数据库/worker、受控协议与真实供应商验证分别签收。

### 7.9 统一.env的TOS与历史读取

按SUB-013最新确认，所有配置仅从根 `.env` 读取；字段示例归 `.env.example`，真实文件不读取、不覆盖、不提交。不新增独立YML、JSON凭据或.local目录。`GLOWLOOM_OBJECT_STORAGE_PROVIDER=tos` 选择原生TOS SDK，公共连接字段复用 `ENDPOINT/BUCKET/REGION`，凭据复用 `ACCESS_KEY/SECRET_KEY`（均以 `GLOWLOOM_OBJECT_STORAGE_` 开头）。稳定 `PROFILE_ID` 和 `REVISION` 区分资源身份与配置版本；签名origin只允许现有合法规则。

provider未指定的旧MinIO五项配置保持兼容。显式新TOS配置时，旧资源由可选 `GLOWLOOM_OBJECT_STORAGE_LEGACY_*` 只读连接表达，不把旧裸key解释为新TOS。所有资源连接字段为空时，其余服务可启动，存储依赖入口明确未配置，不发云请求或收费生成。

配置加载不创建route或存在性事实。上传在首次接纳事务固定profile/revision，生成在报价事务固定operation工作目标；主参考、原始生成产物、波形/缩略图由同一位置台账接受。重试/历史读取始终使用已保存位置，不能跟随当前default。旧对象迁移依真实来源证明；无legacy首次部署以受锁保护的实际空存量证明分支处理，不能造MinIO记录。结构扩展、位置回填/finalize、桶验证、部署接受和CAS激活分别保留真实证据。

缺真实凭据不阻塞上述代码、迁移和受控测试。供应商/真实TOS验证和已完成的隔离测试分开签收；不可用提示本身不能关闭AC-SUB-15。
