## 7. 方案

### 7.1 范围与规则

- 当前工程标识统一使用Glowloom（展示）或glowloom（机器标识）；环境变量统一为GLOWLOOM_*，旧LV_*仅作为过渡期输入别名。无关外部服务账号和凭据不因品牌更名而改值。
- 现有项目、主画布、素材和用户标识不变。已发布提示词基线ID保持稳定，更名不让用户自定义模板变为过期。
- 当前本地使用glowloom数据库、glowloom_app授权角色、glowloom-local工作流命名空间及glowloom-media对象桶，容器卷使用glowloom前缀。
- 数据库角色采用原OID重命名并保留授权。已有数据库采用名称迁移，禁止用空库schema覆盖；原有资源在校验完整后切换配置。
- 历史审计、财务账本、已执行工作流和已导出的文件是保留事实，不能通过品牌替换批量改写私有正文或删除历史。旧资源只作迁移回退及历史档案，当前服务使用新命名；不伪称不可重命名资源已原地更名。
- 事件生产者与消费者一起切换；先核验在途工作、Outbox与所有分区消费位点。只迁移确有必要的未投递工作，不重放历史事件；infra.processed_event的逻辑消费者名不等于Kafka group，不随品牌替换。
- 名称修订不授权Git历史改写、提交、推送或生产发布。并行代码修改保留。

原命名任务按 ST-GL-01 追踪，边界与原执行清单保持一致。

### 7.2 ST-GL-01：统一名称并保持原有资源与历史事实

**故事 ID 与标题：** ST-GL-01；统一名称并保持原有资源与历史事实。此 ID 仅用于追踪原命名任务，不新增功能范围。

**描述：** 作为项目使用者，希望项目使用织光／Glowloom名称并继续访问原账号、项目、画布与素材，以便工程名称统一且已有工作可继续。

**来源与设计：** 用户2026-10-21命名要求及本节原《20-Glowloom命名统一与数据迁移实施计划》的范围与规则。

**讨论：** 配置按下节迁移为 GLOWLOOM_*；用户/项目/画布/素材ID及已发布提示词基线ID保留；历史审计、账本、已执行工作流和导出文件不批量改写。原执行步骤、兼容合同及回退边界继续适用。

**确认条件：** 工程与新写入使用当前名称；原资源身份、OID/权限及完整性保持；已发布格式按原精确指纹兼容；切换后的健康和画布操作按原真实记录判断，不把空清理运行当作已清理业务内容。

**追踪：** [CASE-GL-01](#81-case-gl-01命名切换后的完整性与真实画布操作)；实施状态及原完成清单见 [BACKLOG](../../BACKLOG.md)。

### 7.3 配置键迁移合同（2026-10-21）

用户追加确认：历史 `LV_*` 配置键统一为 `GLOWLOOM_*`。仅修改键名，凭据值、权限及注册策略不因此改变；第三方 `SMTP_*` 等标准接口保持原名。

后端读取优先级为：新键环境变量 → 新键配置文件 → 旧键环境变量 → 旧键配置文件 → 默认值。显式配置为空的新键仍具优先权，不能重新启用旧凭据；`GLOWLOOM_ENV_FILE` 同样优先于 `LV_ENV_FILE`。前端 Origin 和后端代理、Compose 与维护命令边界使用同样的新键优先原则。示例、测试、CI 与运行说明使用新键。

已有部署可先更新代码，再逐键迁移私有配置；迁移不得打印或提交凭据。回退时仅恢复对应键名和原值，不重建库、对象桶或身份密钥。旧键仅用于当前过渡兼容，不新增第二套配置模型。自定义YAML凭据引用中的环境变量名应与私有环境键同步迁移；兼容读取不改写任意凭据引用或第三方字段。

## 8. 实施与验收

### 8.1 CASE-GL-01：命名切换后的完整性与真实画布操作

**场景 ID 与名称：** CASE-GL-01；命名切换后的完整性与真实画布操作。

**目标：** 关联 [ST-GL-01](#72-st-gl-01统一名称并保持原有资源与历史事实)，核对命名统一没有改变原数据、归属、访问权限和历史事实。

**前置条件：** 采用本节原切换记录的已核验资源、停止应用写入窗口、无源库活动会话及授权角色；仅在原已授权环境与临时验收画布范围内执行。原项目、用户和素材保持保护。

**角色：** 资源切换由原工程/运行职责执行；画布操作沿原登录和授权，不绕过权限。

**步骤与结果：** ①按原保护清单核对数据库/角色OID、权限、行数与聚合摘要；②核对对象数量、字节、ETag及元数据，Kafka分区消费位点与Outbox，以及工作流历史保留；③服务健康后用临时画布执行创建、改名、打开、归档、删除和恢复，核对原ID及30天期限；④项目清理模式只安装原计划，原空运行不能推定已执行到期内容清理。

**例外：** 沿原目标资源已存在、源库活动会话、在途工作未排空、身份或完整性不一致等拒绝条件；不泛化旧格式兼容，不改写历史账本或删除回退资源。

**证据：** 本节保留原本地切换、后端Race、前端门禁、真实Chrome和worker记录及未覆盖边界。本次只整理文档，未重新运行这些检查，也未执行迁移、清理或发布。
