# 平台用户管理设计

## 1. 摘要

查询全站账号目录并执行受保护的治理、审计及受控导出。

## 2. 参与者

使用者与参与职责：具有独立平台职责的管理员。维护职责及确认人沿下方原来源记录；未给出姓名的，不补造人员或排期。

## 3. 背景

原始需求：[02-用户系统需求](../requirement/02-用户系统需求.md)。关联需求与验收：[01-用户系统](../prd/01-用户系统.md)。本文维护技术合同；相关实施步骤与证据见 Plan，状态与调度见 [BACKLOG](../../BACKLOG.md)。

## 4. 目标

查询全站账号目录并执行受保护的治理、审计及受控导出。目标的规则、量化条件与非目标沿需求原文及下方已确认设计，不增加未经确认的指标。

## 5. 使用场景

参与者为具有独立平台职责的管理员；在下方定义的输入、对象状态、权限和环境条件具备时执行相应操作。各故事按其独立前置条件核对，不能把测试夹具当成真实业务条件。

## 6. 价值

平台身份与内容访问分离，最后管理员和敏感操作得到保护。

## 7. 方案

### 7.1 Global Constraints

- 前置01；至少保留一个active且verified的平台管理员，临时锁定不影响治理资格计数。
- 敏感动作5分钟复验、原因5～500字符、expected_revision；旧团队管理员不能自动获得平台权限。
- 分页20/最大100、搜索100字符；导出最大10000行、完成后15分钟有效，生成/下载均重查当前权限。
- 各动作通知/审计同事务，通知故障不回滚已提交授权变化；遵守[总览](01-用户系统总体设计.md)检查点。

### 7.6 DataTable 批量管理草案（2026-10-25，待评审）

- 复用现有 `frontend/src/components/canvas/runtime/components/account/list/data-table.tsx` 的 shadcn Table / Checkbox 与受控选择、记录 ID、选中 revision 快照。现有组件并不等于批量治理接口已完成。
- 表头全选仅选当前页，明确选中数量与半选状态；翻页、筛选、搜索、每页条数变化清空选择，排序按 ID 保留当前页选择。刷新不能静默升级已选快照。
- 用户批量启用、禁用、撤销会话与删除保持独立动作；禁止把角色提权合并进普通批量动作。服务端逐项核对 allowed_actions、状态与版本。禁用和删除确认仅显示可执行数量与跳过摘要，逐项原因放在结果中，零条可执行时禁用确认，不发送空批次。
- 禁用和删除使用 §7.7 的紧凑确认稿，不保留强制原因、密码输入和大表格。其他敏感动作的复验要求沿原合同。处理中锁定选择和重复提交；关闭弹窗不解释为撤销。结果区分成功、失败、未执行及结果未知；成功项移出选择，失败项重新读取和确认后再试；未知先查原操作结果。
- 手机保持 DataTable 选择模型，优先显示身份与状态，批量栏分行。勾选热区与主按钮 44 px，复选框标签、半选播报、关闭焦点恢复作为实施验收要求。

### 7.7 独立管理页面与精简账号操作（2026-10-27）

来源为需求02的同日用户原文。本节是设计稿优化，不代表管理员删除接口、业务校验或浏览器功能已实现。

| 页面 | 独立内容 | 不承载的操作 |
| --- | --- | --- |
| 用户管理 `/users` | 全局账号目录、账号邀请、平台角色、账号状态和安全、单项/批量删除 | 团队资料、成员关系、团队邀请、团队启停 |
| 团队管理 `/platform/teams` | 团队目录、管理员、成员数、团队状态、团队详情和邀请 | 禁用/删除全局账号、重置密码、平台角色授权 |

- 页面跳转使用同级导航；查询、翻页、勾选与批量结果按各自对象隔离。移除用户列表底部“平台团队管理”模块、团队列和详情团队摘要；共用 shadcn 组件与布局，不共用业务表单或动作处理器。
- 用户详情补充“删除账号”，选中后的批量栏补充“删除账号”。普通禁用为中性按钮，删除使用 destructive 语义；确认只展示对象/数量、影响和两个按钮。禁用后可重新启用，删除提案为不可自助恢复的软删除，不承诺物理擦除。
- 示例批量选中5项：禁用2项、跳过当前账号/已禁用/已注销3项；删除3项、跳过当前账号/已注销2项。数量必须由实际可执行结果计算，不能硬编码。最后平台管理员及删除时尚未交接的最后团队管理员应返回明确阻止原因；禁用仍沿 FR-USER-12 的团队治理冻结合同。
- 普通禁用不强制填写原因或再次输入密码，是本轮交互提案；现有 §7.1 原因和5分钟复验以及接口校验尚未因此改变。实施时必须同步明确服务端审计原因和适用复验策略，不能只删控件。
- 桌面列表沿现有 DataTable，手机保留身份/状态紧凑列。弹窗采用 Auto Layout 居中、内容自适应高度、左右安全边距；删除/禁用稿不再依赖固定顶部偏移。实际焦点圈、键盘关闭/恢复、异步播报和读取错误重试仍需实现后浏览器验收。

## 2026-10-27 实施确认后的接口与职责边界

依据需求02的同日实施确认，第7.7节已进入代码范围。前文“普通禁用仍要求原因和近期密码复验”的合同，对 `disable` 和新增 `delete` 两种动作由本节替代，其他动作不变。

- `POST /api/platform/users/{id}/delete`：仅接收字符串 `expected_revision`，必须携带原始 UUID `Idempotency-Key`；204表示账号软删除事务提交，409表示版本或职责冲突。当前平台权限、账号版本、最后管理员、团队交接、身份及成员访问撤销、审计、通知入队和回执同事务完成。通知入队不代表送达。
- 普通禁用和删除省略原因时，审计分别记录 `platform account disable` / `platform account delete`；免额外密码复验不免会话、平台权限、Origin/CSRF、CAS、审计或回执。本人注销沿原验证流程。
- 目录详情新增可选 `blocked_actions`，返回当前账号、已删除、最后管理员、待交接等原因码；页面仅显示必要说明，不根据成员摘要自行推断删除资格。
- 用户页只挂载账号目录、账号邀请及平台授权业务组件。团队页单独读取团队目录、分页、选择、详情、团队邀请与启停。共同复用 DataTable、导航、Sheet 和批量执行界面，不共享业务表单或选择状态。团队写接口不提供幂等回执，因此结果未知时不提供“原请求重放”，需重新读取核对。
- 表格列按视口收敛，按钮组允许换行，确认框按视口居中且内容可滚动。读取失败在正文提供重试；暗色危险按钮使用语义色混合提高文字对比度。
