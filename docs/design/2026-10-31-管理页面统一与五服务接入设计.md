# 管理页面统一与五服务接入设计

依据：需求04 SRC-AI-32 与本次用户确认 CR-ADMIN-01；用户已选“一个页面、五个独立入口”，并要求设计和 Figma 先于代码。本文具体实现选择由实施者负责，不将建议追认为用户逐项指定。

## 1. 摘要

管理页面复用全站公共外壳、内容留白、页面标题与横向导航语言，AI 接入收敛为 OpenAI、DeepSeek、火山方舟、豆包语音、火山音乐五个入口。补齐 OpenAI 的预设、凭据、验证、模型发布、报价、冻结提交和结果处理。

## 2. 参与者

平台管理员管理用户、团队、服务、模型和设置；创作者消费已启用和已发布模型。用户确认产品范围，实施者负责设计、Figma、代码和分层验证。

## 3. 背景

五类管理页面已有共享 AdminWorkspace，但导航使用独立按钮组，内容内边距与普通页面不同；服务页面另写标题。项目已有 PageHeading、PageHeader、主题 token、Dialog/Sheet/DataTable。OpenAI 已有基础驱动及增量 SQL，但发布供应商白名单与冻结提交分支遗漏；候选目录含已退出服务的旧模型。调研依据见 research/2026-10-31-AI服务接入范围与即梦风格调研.md；模型与协议以 OpenAI 官方当前文档重新核验。

## 4. 目标

所有管理页面：用户、团队、服务、模型、平台设置，统一布局、导航、标题、按钮、输入、表格、分页与弹层。服务创建弹窗只展示五类；已有其他服务记录和任务保留可管理性。五类鉴权独立，秘密只在服务端保存。OpenAI 新目录采用官方当前可用文本与图片模型，文本走 Responses、图片走 Images API；不增加音视频、实时会话或工具执行能力。

## 5. 使用场景

管理员在管理导航切换页面，保留共享外壳；在服务页选择五类服务之一，填写对应凭据，跨能力分类选择模型后保存，详情中显式验证与启用。模型管理员可按相同 release 合同发布 OpenAI 模型；创作者报价与提交引用冻结发布版本，凭据轮换不能篡改既有操作。

## 6. 价值

复用全站组件减少管理页面的视觉割裂；明确火山三个产品的凭据边界；避免“接入选项存在但无法正式创作”的断链。

## 7. 方案

### 7.1 已确认与技术选择

用户已确认单页五入口、所有管理页面一致、先 Figma 后代码。保留一页五入口优于拆分管理页，因为当前规模只需切换表单字段。技术沿用 Go 模块化架构、Next.js 16、React19、shadcn、Geist 和已有语义 token，不增加 UI 库或网关。

### 7.2 统一页面

AdminWorkspace 使用与 workspace-page 相同 layout-content-x/y。AdminNavigation 仍是语义链接导航，用 aria-current、水平滚动和底部选中线表达切换；不是伪装成标签页的路由控件。手机触达区域至少44px，不折成多行按钮墙。标题复用全站 PageHeader（如其样式缺失则修复公共类），24px/32px、500字重，说明14px；动作同排可换行。服务页迁移到相同 AdminHeading 封装。表格、分页、Badge、Button、Dialog、Sheet 继续复用现有基础组件，不逐页覆盖主题。共享变化自然作用于五页，保留特定业务筛选和权限。

### 7.3 五入口

接入选项顺序 OpenAI、DeepSeek、火山方舟、豆包语音、火山音乐。过滤的是新建入口，预设管理与历史连接不删除。重试中的原请求保留原目标与回执，不因过滤丢失恢复路径。凭据：前三者各自 API Key、语音 API Key、音乐 AK/SK；非秘密资源ID属于模型参数。保存完成关闭弹窗、刷新列表、还原焦点；模型验证不随保存自动执行，未知结果仅查原请求。配置只显示已配置/未配置。

### 7.4 OpenAI 完整链路

新文本候选采用官方当前文本模型，单次无工具 Responses，store=false、stream=false；显式适配 input、max_output_tokens、typed output 和 input/output token 用量。只接受 completed 且有输出文本；拒绝、不完整、失败和传输未知不伪造成功，不自动重发。图片候选使用当前 GPT Image，单张文生图；不发送 GPT Image 不支持的 DALL·E response_format 或 seed、水印参数。旧候选快照保持可解释，旧模型调用结果按真实上游处理，不伪称仍可用。

发布验证、冻结版本选择、只读模型发现、参数白名单和接入激活均核对 OpenAI 路径；新模型不能靠导入自动启用。沿用报价、余额、请求去重、私有制品与审计合同，不重建业务流水线。模型增量 SQL 必须幂等且不改已有预设身份与归档状态。

### 7.5 故事与例外

US-ADMIN-01：管理员在五页看到相同布局与控件；手机键盘能触达全部链接，当前页有可访问标识。US-AI-32：管理员通过五个独立入口接入，旧服务仍能管理；无权限不能读写。US-OAI-01：管理员保存、验证、启用和发布 OpenAI 后创作可用；未知结果不重发、凭据更换证据失效、报价后版本变更仍使用冻结版本。以上验收映射至对应 Plan。

## 8. 实施与验收

先完成 Figma 可编辑五页与五入口、详情验证、手机和浅色实例，复用现有侧栏及账号组件，再实现产品代码。验证公共布局语义与五入口排序/过滤/恢复，OpenAI 请求/结果/用量/拒绝/错误与独立凭据；发布和冻结提交用隔离数据库测试。执行对应前端、Go质量门禁和浏览器页面检查。真实收费调用不是默认测试，受控测试不能替代真实账号验收；未执行据实记录。具体步骤与证据见 ../plan/2026-10-31-管理页面统一与五服务接入计划.md，进度仅维护 BACKLOG。

### CR-ADMIN-02 对第7.2节导航规则的替代

管理导航采用全站胶囊选中语言，通过既有 PageToolbar navigation 槽与账号工具栏同排，正文不重复导航，不再采用本稿此前的底部选中线。扫描普通页面后，同步迁移个人空间的作品/收藏/画布、历史主体类型主导航；资产、探索、主体已使用共享顶栏。Dialog中的模型分类及详情标签是局部操作，保留在原上下文。窄屏复用现有共享页头的可滚动导航行及44px触达，不为了桌面同排压缩账号操作。
