# 创作一致性与公共组件设计

依据：[需求16](../requirement/16-创作对齐即梦与全站公共组件需求.md)、[调研12](../research/12-即梦创作完整需求分析.md)。用户已确认研究后按设计落地；竞品未知项仍按 U01–U10 保留。实施状态只见 [BACKLOG](../../BACKLOG.md)。

## 1. 摘要

以即梦真实页面观察建立创作目标，统一创作命名、类型与模式分层、草稿生命周期、参考及参数交互，并收敛普通页面的公共账号区。完整范围为 CR-001–CR-070，不用已有实现反向缩减需求。

## 2. 参与者

使用者为游客、已登录创作者及空间成员；产品维护范围，设计维护组件，工程维护可执行合同。排期与认领只在 BACKLOG。

## 3. 背景

独立调研在源码审查之前完成。当前 Header 的资产分支包含通知、积分、会员与头像，其他路由包含独立主题按钮与64px头像占位，两套布局造成用户所述差异。首页列出七类入口，但仅图片和视频进入真实生成合同。菜单可见不等于能力可用。

## 4. 目标

70项均有事实、差异、设计归属及验收；普通页面共享一套账号区；命名与生成/画布层级一致；类型、模型、模式及参数不混层；切换不丢失其他类型草稿；不可用能力不伪装成功。

## 5. 使用场景

- 创作者在创作、探索、资产、主体、账号和管理页切换，账号入口与弹层位置稳定。
- 游客打开搜索或主题菜单，登录后主题入口归入账号菜单。
- 用户在图片、视频及其他创作类型之间切换，分别恢复对应上下文。
- 资产选择批量操作时保留页面动作，退出后恢复公共账号入口。

## 6. 价值

减少同一操作在不同页面的视觉和位置变化，避免共享提示词污染不同创作任务，并让用户分清可执行能力与尚未开放的能力。

## 7. 方案

### 7.1 来源与责任

逐项规则以[70项矩阵](../research/evidence/2026-10-29-creation/parity-matrix.csv)和调研12为准。共享外壳依赖[设计09](09-统一顶栏与阶段入口设计.md)，本设计覆盖其账号区组合的旧规则；项目、模型授权、生成任务沿既有合同，不能硬编码即梦专有模型为可执行模型。

### 7.2 公共账号区

新增 ProductAccountActions 单一组件，所有普通路由使用同一 ProductAccountActions；2026-10-30按下述导航修订覆盖原整体 outline 组合，顺序为通知、积分、开会员、AccountMenu。账号头像及菜单复用资产页已有实现，不新增复制品。会员入口仅桌面较宽时展示；窄屏保留通知、积分和账号，44px触达，极窄屏积分仍可从账号菜单进入。积分仅展示真实服务状态，不构造余额或促销。

登录用户主题仍在 AccountMenu；游客保留独立 ThemeToggle 并与通知、登录同组。ProductHeaderActions 只决定搜索及页面工具排列，assetLayout 不再决定账号样式。data-account-actions 为跨路由语义；资产批量状态沿既有规则隐藏该组。普通 replace-base 必须卸载公共弹层与快捷键，保留页面动作槽。

Figma 沿现有 Header 组件 620:24416 更新四个桌面/手机、登录/游客变体，公共账号区采用嵌套组件；现有页面实例传播更新。探索一级分类、资产来源标签等页面内容保留独立槽位。画布沉浸式工具栏仍沿独立合同。

### 7.3 命名及能力

页面正式名统一为“创作”，内部稳定路由 home 不需迁移；Figma 首页节点使用实际存在的1361:26。七类正式名称沿调研12。未开放类型需明确说明，不能以可点击提交假装有对应供应商。实现能力扩展须同时覆盖参数schema、权限、参考校验、报价/受理、任务恢复、结果及失败，不能仅增加菜单。

### 7.4 后续创作合同

按类型隔离结构化草稿及引用；actor/space切换隔离私有内容。图片/视频模型和参数只来自平台已启用目录。高级视频模式在切换模型/参数时显示可理解的变更反馈。音乐、音频、数字人、动作模仿分别有独立输入与校验，不能沿用同一文本框伪造完成。完整状态设计和真实服务可达证据按矩阵逐项接受。

### 7.5 创作类型草稿隔离

来源 CR-014/016/027，Figma [八态设计](https://www.figma.com/design/uLqmeRWuQuzfrp9xOYg6FT?node-id=3171-60732)，先于代码修改。

页面内由账号/空间拥有草稿集合；七种类型和画布想法各有独立结构化PromptDraft。切换类型仅选择目标草稿，不把当前正文、引用、modelVersion、mode、params带入目标。首次进入为空；返回恢复原对象的完整快照。项目工作区沿actor/space/project/type身份和已有服务端draftID，必须保存确认后才能切换；迟到回调在作用域卸载后失效。

页面内恢复用三段contextKey：actor/space/home-input:type；旧home-input只作为图片的历史候选。恢复仍走branchJournal的身份/空间权限确认；当前branchJournal是内存存储，整页刷新不会保留记录，刷新/跨设备恢复仍待实现。页面内恢复仅恢复纯文字，不恢复未经重新校验的引用、模型设置或未决提交。候选只显示于对应类型，明确点击才替换；用户开始新输入后隐藏旧候选。恢复读取与写入失败保留现有编辑内容，旧账号/空间的迟到响应不影响新上下文。退出/权限清理沿现有journal，不另建localStorage存储。

### 7.6 七类专属输入与可执行范围

先修改 Figma [七类桌面与手机表单](https://www.figma.com/design/uLqmeRWuQuzfrp9xOYg6FT?node-id=3179-56558)，再修改代码。独立输入区共享 InputGroup/Field/Button/Select；业务字段不硬合并：

| 类型 | 输入结构与代码合同 |
| --- | --- |
| Agent 模式 | 目标文本、参考、技能/偏好入口；首页独立会话未接通时明确提示，画布助手保留原所有权，不将普通文本生成改名为 Agent |
| 图片生成 | 文本与图片/主体引用；比例、清晰度、数量由已发布模型 schema 决定，引用本身可作为进入项目的输入 |
| 视频生成 | 文本及角色明确的参考；现有首尾帧/全能参考按模型支持；时长以秒显示，传输仍使用毫秒，slider 与数值框同步，不扩张供应商范围 |
| 音乐生成 | 描述或歌词、歌曲/纯音乐、显式秒数；火山 v5.0 不伪造智能时长字段，不把朗读替代音乐 |
| 音频生成 | 接入真实 audio.generate/text2audio，文本朗读无普通参考按钮与@引用；音色、语速、音量来自选定模型；没有音色目录时只提供模型配置的默认音色，已有草稿自定义音色标为“已保存音色”，不要求普通用户输入内部音色ID；模型未配置时继续可编辑且不能报价；不自动追加适用于视觉创作的全局提示词后缀 |
| 数字人 | 角色图片 + 驱动音频、可选动作描述；火山 OmniHuman 不接受台词直接替代音频，语音合成另走音频创作；动作描述禁止泄漏至其他类型 |
| 动作模仿 | 角色图片和动作视频双槽；不提供可编辑文本提示词；火山动作模仿 2.0 固定 720p/25fps，是否裁去首秒单独保存 |

未开放服务的参数只保存本页草稿，不向既有生成接口发送未知字段；页面内恢复仍遵循7.5的文字边界。所有类型继续沿原项目、身份、幂等报价、任务查询和恢复合同；没有供应商实测证据的能力不得标记已验收。

### 7.7 缺失供应商协议的接入依据

按用户补充授权完成[官方接口调研14](../research/14-音乐数字人与动作模仿供应商接口调研.md)。火山音乐采用独立音乐 Action 与 QuerySong；OmniHuman 与动作模仿采用各自视觉异步任务协议。不得把三者转换为现有 Ark 视频或 TTS 并宣称等价。

后续适配必须在当前发布目录、输入schema、引用授权、报价冻结、受理/未知结果恢复和结果归档链路中闭环：数字人图片+音频、动作模仿图片+视频分别限制输入；音乐歌词/描述与纯音乐时长分开。已知公开版本/req_key差异需在管理侧固定确认，不能由普通创作页任意填入技术标识。没有配置可用release时展示无模型，不能嵌入演示模型。申请开通与真实费用验收保持独立。

### 7.8 火山三类可执行合同

Figma：[三类提交到归档状态](https://www.figma.com/design/uLqmeRWuQuzfrp9xOYg6FT?node-id=3187-59172)，以及七类表单中对应桌面/手机实例。正式代码使用目录过滤与既有任务详情，不以入口可见或原型状态作为真实生成证据。

- 音乐采用 `volcengine_music`，AK/SK 签名，`GenSongForTime` / `GenBGMForTime` + `QuerySong`，显式 v5.0。歌曲描述/歌词二选一；含中文的歌曲输入保守限制 5–700 字符，其他输入 5–2000；纯音乐 30–120 秒、歌曲 30–240 秒。纯音乐传单段 `inst` 与用户秒数，避免正文时长覆盖外层 Duration。仅保留此版本生效的参数。
- 数字人采用 `volcengine_avatar`，API Key、`jimeng_realman_avatar_picture_omni_v15`、`submit_task/get_result`。角色图片 + 少于 60 秒音频；可选动作说明不超过 300 字；分辨率 720/1080、快速模式。台词需先生成或上传音频，不能暗中拼接未经确认的 TTS 调用。
- 动作模仿采用 `volcengine_motion`，API Key、`jimeng_dreamactor_m20_gen_video`、`submit_task_v2/get_result_v2`。角色图片 + 不超过 30 秒视频；无提示词/分辨率/时长参数，仅裁去首秒开关。素材类型、尺寸、大小和时长在报价时依据服务端探测事实校验。
- 三类独立模式为 `music_song/music_instrumental/avatar/motion`，复用 `audio.generate/video.generate`，不混入朗读和普通视频的模型菜单。旧草稿专属参数转换为实际 schema；账号/空间/项目/类型保存边界保持。
- 候选创建仅保存加密凭据与未启用模型，必须逐模式真实试运行、结果归档与现有模型发布审核后启用。音乐的 AK/SK 与视觉 API Key 分开录入；只读连接检测不能证明付费生成可用。
- 提交超时不自动重发；有 TaskID 只查原任务，无 TaskID 保留未知等待核对。失败不暴露残留输出；无法确定供应商费用时转核对并保留冻结，不宣称零消费或自动退款。
- 音乐结果只接受文档域名 `v1`–`v50-default.douyinvod.com`，下载后本地转为并探测 MP3；小数秒原值保留，平台毫秒向上取整。视觉结果域名未有官方固定清单，仅接受已认证查询返回的 HTTPS 公网域名；安全下载器固定该 origin、DNS 公网地址与连接，阻止私网和跨源重定向，不携带 API 凭据。
- 供应商成本上限与平台价格分开。候选按官方单价与最大时长预留保守预算，实际费用不能由请求时长或媒体时长伪装成供应商已出账。数字人/动作预计时长读取引用素材事实，禁止客户端伪造 duration_ms。

精确字段、限制与官方矛盾见[音乐协议](../research/evidence/2026-10-29-creation/volcengine-music-protocol.md)、[视觉协议](../research/evidence/2026-10-29-creation/volcengine-visual-protocol.md)。Agent 独立会话、高级视频编辑、即梦智能时长与音频扩展模式仍须各自设计和协议，不能被三类接入隐式替代。

### Seed-Audio 全能配音合同（2026-10-29）

来源：`../research/evidence/2026-10-29-creation/volcengine-omni-audio-protocol.md`。Figma 可编辑节点 `3211:63326`、`3211:63408`、`3211:63490`、`3211:63572`，桌面/移动共享现有组件；实例属性与文字均回读。

音频保留文本朗读，新增独立 `omni_audio` 模式，模型 `seed-audio-1.0`，POST `/api/v3/tts/create`。自然语言最多3000字符描述角色台词、环境音和时间段；最长120秒，不提供虚假的硬时长控制。引用最多3条音频（每条≤30秒、≤10MB）或1张图片（≤10MB），禁止混用，素材事实由服务端校验。引用通过稳定ID编译成当前物理顺序的 `@音频N`，不沿用删除后的旧编号。固定MP3/24000，开放语速、音量、音调、字幕开关。字幕保存句/字毫秒时间，允许查看与导出；缺失字幕不得伪造。

报价按最大120秒预留，实际使用 `original_duration` 计费，保留原始小数秒收据；不得按后处理时长或每次整分钟计费。超时结果未确认时保留原请求，不自动重发。模型必须经过真实模式验证才能启用，不能靠预设导入自动激活。官方收费与平台积分规则分开。音色注册、收藏、公共音色目录独立验收，素材上传不能冒充音色训练。


### 项目 Agent 单图执行合同（2026-10-29）

Figma 节点 `3217:60567`、`3217:60772`、`3217:60925`、`3217:61078`、`3217:61231`：会话、规划报价、图片方案确认、执行恢复、完成。首个可执行范围为图片创作，会话按项目和当前账号私有保存，刷新可恢复。规划器使用受限 JSON 方案（reply 或 generate_image），服务端严格解析和白名单执行，不能把普通文本聊天冒充任意工具 Agent。无需供应商原生 function-call；运行策略版本写入冻结提示与会话，不接受浏览器上传可信历史、工具结果或任意工具名。

每轮最多一次规划、单张图片和一次总结。规划、图片、总结分别复用正式 operation 报价/确认/余额/归档链路；模型输出不能授权付费。每个阶段持久化同一个请求 UUID，断线重放不得重复生成。只有 completed 且审核通过的图片结果才可反馈总结；unknown/manual/reconciling 保留原任务并暂停。用户可停止后续阶段，已开始的供应商任务仍按真实状态处理。会话读取只读，显式 advance 恢复执行。选择的模型和参数冻结至当前轮，工具不能改项目、供应商、URL、价格或参数。

该边界不承诺视频工具、浏览器、代码执行、多工具并行或自动花费总预算；这些能力需要另行扩展已验证工具合同。直接回答无需图片阶段。会话历史使用已落库事实，每次模型调用保持可审计和计费；总结不声称看过未经视觉模型读取的图片内容。

Agent 会话状态与当前阶段报价／确认使用同一数据库事务提交。Store 向转换回调显式提供绑定事务的 Operations，避免持有账号、项目、会话锁时通过另一连接申请同一把锁。会话锁与阶段操作 ID 保证重复确认返回原阶段结果；事务失败时会话、报价和预留同时回滚。

### 音色库与数字人文本驱动补充（2026-10-29）

来源：需求16；设计29；PRD16；实施计划25。Figma `3252:64030` 已先于代码建立并回读：音色库、创建、异常、数字人两阶段和390px。系统音色来自火山官方2.0列表；用户参考音色按项目与创建者隔离保存名称、素材ID及修订、授权确认和收藏，无需可用模型。参考音频必须就绪、审核通过、≤30秒且≤10MB；不把保存素材称为训练。创建使用稳定请求ID，重放相同请求返回原记录，不同输入冲突；变更带修订，删除不删除源素材。系统音色不虚构试听文件。数字人文本驱动复用独立音频草稿、报价、确认与任务结果，用户试听后显式采用音频，再单独确认数字人报价；台词不得直接提交OmniHuman。验收包括真实数据库权限、幂等、并发修订，以及浏览器保存/收藏/刷新/引用与类型往返。

音色属性采用性别、年龄、语言、声音特点四类枚举；未知信息显示“未标注”，不根据名称猜测。保存回执未知时按账号和项目保存原请求及源素材摘要，重开后只恢复同一请求。首页服务端草稿指针按账号、空间、项目和七类创作隔离；数字人配音指针再绑定视频草稿，不与普通音频共用。只记草稿ID，服务端仍核验当前权限。无模型时继续显示已保存模式。业务库外键随所属账号、项目或源素材清理，普通删除音色不删除素材；增量在事务中先按固定顺序取得父表锁，锁忙立即失败，避免迁移与业务读写形成等待环。
