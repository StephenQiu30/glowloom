# 导演台一致性与实现整理设计

状态：专项设计。依据：[REQ-DIRECTOR-20261029](../requirement/17-导演台对齐与实现整理需求.md)、[DIR-001～035 需求基线](../research/13-即梦导演台完整需求分析.md)。用户已确认“消化 BeefTV 实现并整理为当前项目实现”，不是整体搬运。

## 1. 摘要

将画布导演台收敛为静态构图与动态预演两个独立工作区，统一即梦命名和主要交互。保留 Glowloom 的项目/资产授权、Yjs 权威保存及现有组件规范，按职责整理 BeefTV 的核心实现。以可重新打开的场景、可解码的真实输出和可追溯回写为接受标准。

## 2. 参与者

使用者为有项目读写权限的创作者与团队协作者；只读访客可观察既有内容。需求确认人为用户；技术和设计责任按本专项执行，不补造人员姓名。

## 3. 背景

第一阶段已独立观察即梦并保存证据。第二阶段检查显示，当前工作区有并行新增的 `canvas/director/` 基础实现：真实 Three 场景、变换、关键帧采样、机位预览与 CAS 保存已存在，但 mode 仅切换同一场景；三类资产页为物体/机位/灯光，与来源的角色/物体/背景/机位不同。当前文件仍可能被另一聊天修改，[差异审查](../research/evidence/2026-10-29-director/implementation-gap-audit.md)是带时间和文件 hash 的快照，不是最终接受。

既有协作架构以 [Yjs设计](17-画布Yjs协作编辑设计.md)为约束：不新增第二套 OT、全局状态或独立远端写接口；真实权限与保存回执继续由业务层确认。本文收敛设计27中导演台内部的目标合同；画布其他功能仍由设计27维护。

## 4. 目标

- DIR-001～035 全部进入差异矩阵，区别“已有数据字段”“运行实现”“浏览器通过”和“尚未验证”。
- 两工作区复制/冻结、动作/关键帧/运镜/分镜与输出回写有独立、可测试的业务语义。
- 更新原导演台 Figma 稿及所需非空/弹窗/异常状态，保持原生可编辑层与组件规范。
- 新增能力按 Glowloom 模块职责组织；只保留必要 Three/媒体依赖，不引入 BeefTV 的 AntD、全局 store、AI 服务、品牌或完整 workbench。

| ------------------ | ---------------------------------------------------------- | ------------------ | --------------------------------------------------- |

## 6. 价值

把三维构图与运动设计接入创作画布，减少在外部工具中来回导出、上传和重建镜头的工作。沿用成熟渲染/轨迹逻辑，减少重新发明基础能力的成本；依项目合同重新组织后，权限、保存和素材引用可持续维护。

## 7. 方案

### 7.1 产品与命名

画布入口为“导演台”；编辑器为“3D导演台”；顶栏中央“静态预演 / 动态预演”；资产栏“角色 / 物体 / 背景 / 机位”；右侧“对象 / 属性”；机位与注视点分别编辑。环境和主光/补光/轮廓光归无对象选中时的属性，不占用一级资产标签。

静态场景展示对象/姿势属性；动态场景展示动作/关键帧、底部时间轴与分镜编排。输出统一“拍摄 / 镜头素材 / 导出视频 / 添加到画布”。不得向用户展示 `view.phase` 等内部状态枚举；保存状态必须映射为中文且符合真实回执。

### 7.2 分层与职责

| 当前归属                                  | 整理后的职责                                                              | 不引入的内容                             |
| ----------------------------------------- | ------------------------------------------------------------------------- | ---------------------------------------- |
| `components/canvas/director/`             | 编辑器界面、局部编辑状态、场景命令/采样、Three 运行时、资源和输出生命周期 | 独立页面应用、AntD、第二份全局业务 store |
| 现有 `canvas/yjs-live-session` 与节点集成 | 合法目标校验、epoch/CAS、单次事务、回执与协作                             | 绕过权威校验的 localStorage 成功状态     |
| 后端 canvas domain                        | 版本化场景、字段/引用/容量校验、复制与清理                                | UI/Three 运行对象、浏览器地址            |
| 当前项目资产与上传模块                    | 资源权限、版本、模型/动作/背景来源、产物落库                              | 私有资源下载器、未经验证的上游 API       |
| 现有媒体任务能力                          | 实际可用的视频编码/进度/失败与资产关联                                    | 文件后缀假装编码成功、无产物的假完成     |

只在出现真实消费者时拆出职责文件，不预建空适配层。视口和导出低频模块按需加载；播放和拖拽瞬时状态不触发整页存储更新。

### 7.3 场景合同演进（设计决定，实施前需契约测试）

现有 `node_type=director`、`node_action=tool` 与 `config.director` 保留；显示名更新不改节点身份。版本1当前单工作区需要显式兼容读取；版本2将场景内容拆成静态与动态工作区，顶层保留场景身份、活动工作区和输出关联。

- 旧稿无动画数据且 mode 缺省/静态时，完整迁入静态，动态创建默认空场景；旧稿 mode 为动态时，完整迁入动态，静态创建默认空场景。旧稿虽处于静态 mode 但仍含关键帧、动作片段或骨骼轨道时，完整动画数据迁入动态，静态由零帧求值生成，活动工作区保持静态。迁移需区分零时刻的既有变换与第一关键帧，未识别字段拒绝静默丢弃；不得因 mode 隐藏而清除旧动画。
- 各工作区内对象与机位保持稳定 ID；跨工作区同步保留引用映射。静态→动态保留原动态片段、关键帧和分镜，缺失被引用角色时拒绝覆盖；复制布局时移除静态 pose。动态→静态通过当前帧统一求值冻结 pose/transform/camera，移除动画轨道。
- 编辑前后必须通过同一 schema 校验；前后端版本、复制/删除资源引用、API 生成和历史文档恢复同时更新，禁止只用前端类型断言塞入未校验字段。
- 数值使用有限值；位置米、旋转内部明确弧度、界面度、时间内部秒与帧显式转换。各轨道独立处理，不把一处位置关键帧隐式覆盖旋转/缩放。
- 现有画幅 enum 的 `21:9` 不能冒充 `2.39:1`；添加精确值并核对渲染/输出比例及兼容验证。
- 场景不保存 Three 对象、临时 URL、授权 URL、hover、每帧播放求值或面板动画状态。

### 7.4 BeefTV 整理策略

基线固定为 MIT 提交 `2327ee2d80282b10dd8bef0f26b48990d46f5c3b`；记录原路径、版本、改写职责与测试来源，保留 MIT 版权。最新 main 的新增代码采用不同许可，不无差别合入。Quaternius 模型只使用已核验来源声明的 Standard CC0 资产；动作资源另核来源。

整理单元按具体问题选择：

- `director-scene` 的独立轨道采样、Quaternion slerp；改用本项目 DTO/单位/限制。
- `director-actor-paths` / `director-camera-paths` 的路径采样、重定时；接入即梦式预览确认流程。
- `director-camera-binding` 的绑定/解绑构图稳定、目标删除清引用；使用项目稳定 ID。
- `director-gesture-transaction` 的 begin/update/commit/cancel 收敛；最终通过当前 CAS 形成一笔撤销。
- `director-resources` / `director-recovery` 的共享资源释放、加载过期与 WebGL 恢复。
- `director-save` / `director-session` 的 revision/异步身份语义；不沿用它的持久化实现，映射当前 Yjs 回执和项目 scope。
- 截图与视频的状态恢复逻辑可参考；MediaRecorder 与确定性逐帧输出分别验收，不能承诺互等。

每个单元先写行为测试，再整理代码，不能以机械改名或删许可证替代架构适配。即梦发布包只用于需求证据，绝不导入产品。

### 7.5 保存、权限与输出

场景仍经现有 Yjs 权威通道保存。一次编辑以 epoch 与原场景摘要为前提，协作者改动时保留待提交稿并明确冲突。工作区独立撤销不能意外撤销画布其他节点；版本恢复和节点删除后丢弃过期异步回调。

本地草稿需要项目/画布/节点/账号/基线版本隔离、容量治理、退出 flush 和可恢复提示；保存成功仅以服务确认判定。竞品的 64MiB/50条/500ms 是观察值，项目采用前需容量验证，不直接作为性能承诺。

输出四步独立：渲染 → 持久化资产 → 镜头素材记录 → 用户选择添加到画布。任何失败保持可重试状态，不产生假 asset ID；回写时再核验项目、源节点、epoch 和权限，避免迟到结果覆盖新状态。清理编辑辅助后截图/录制，结束恢复原 renderer/视角/选择/播放状态。

文字生成动作只有真正接入可用服务才开放提交；无服务时说明不可用，不以预设动作或空片段返回“生成成功”。预设数量与可再分发素材必须以真实资源为准，不伪造 742 项目录。

Figma 对应节点：[静态空场景](https://www.figma.com/design/uLqmeRWuQuzfrp9xOYg6FT?node-id=3093-47908)、[动态空场景](https://www.figma.com/design/uLqmeRWuQuzfrp9xOYg6FT?node-id=3093-47499)、[非空动作、关键帧与分镜](https://www.figma.com/design/uLqmeRWuQuzfrp9xOYg6FT?node-id=3116-49794)。状态、图层、原型连接、截图复核及未覆盖项见[设计证据报告](../research/evidence/2026-10-29-director/figma-report.md)。

原静态/动态空态稿原位收敛，补非空角色姿势、机位、时间轴、动作/运镜、模式覆盖、草稿恢复、镜头素材、导出和异常状态。所有文本、按钮、面板与轨道为原生可编辑层；场景内容图仅作内容资产，不以整页截图代替设计。

遵循项目 Geist、shadcn/Radix、Lucide 和设计 token；尺寸依据实际来源再适配项目，不机械复制屏幕像素。窄屏优先保持视口与主动作可达，资产/属性收起为可恢复面板；移动端复杂骨骼操作的完整支持不在未经验证时宣称。

键盘以焦点范围分派：输入框/中文输入优先原生；视口 QWE/ASD、IJKL、0～3、G；时间轴方向键与播放；弹窗关闭后返回触发按钮。失焦清空按键，避免持续移动。
