# 探索发现与创作转化设计

文档性质：产品与技术设计评审稿。来源：[需求15](../requirement/15-探索对齐即梦需求.md) EX-REQ-01～07；外部依据：[调研11](../research/11-即梦探索完整需求分析.md)。唯一对应 [PRD15](../prd/15-探索发现与创作转化.md)，执行由 [Plan24](../plan/24-探索一致性改造Agent执行计划.md)承接。当前实施状态、优先级与调度只见 [BACKLOG](../../BACKLOG.md)。

## 1. 摘要

将探索定义为“发现公开内容，并带着正确的上下文进入创作”的产品入口。作品、技能、活动各自保留独立的信息结构和后续动作，以共享顶栏连接发现、搜索、详情、复用和发布。

本专项交付目标是完整闭环：用户能找到内容、理解内容、执行真实可用的复用或参与动作，并得到可确认的结果。不能仅以页面相似、按钮齐全或术语替换作为完成依据。本轮产出设计合同、PRD和执行计划；没有审计当前功能实现，也没有修改 Figma 或代码。

## 4. 目标

1. 分类、场景、媒体、搜索类型、发布分类具有稳定且不混淆的含义。
2. 桌面一级导航与头像始终同行，空间不足时分类局部滚动；详情和返回不丢失合理上下文。
3. 做同款、用作参考图、复制项目、添加技能、收藏、关注、发布各自有真实结果和失败恢复。
4. 每条来源需求都有设计、PRD验收和执行工作包，完整范围没有静默遗漏。

接受指标：来源覆盖率=有明确处置及验收归属的 EX-FR/EX-NFR 数÷50；目标为50/50。产品接受率=实测通过的必需验收场景÷22；目标为22/22，受条件限制项不能计通过。生产使用指标只定义口径，未获取基线前不承诺提升幅度或发布日期，见PRD15。

## 6. 价值

探索减少的是“看到结果后无法理解或继续使用”的断点。分类负责找到内容，详情负责理解素材和条件，复用动作负责交给正确的创作对象，服务端回执负责确认操作确实发生。

统一顶栏减少重复导航和页面间的操作位置变化；统一术语避免把收藏误认为下载、把添加技能误认为执行生成、把查看公开画布误认为获得原项目编辑权。完整价值依赖真实内容供给和写入能力，只有原型时不能宣称已经交付这些价值。

## 7. 方案

### 7.1 信息架构与命名合同

用户明确的导航方向属于已确认要求；下表依据竞品观察转为本稿目标规范，具体枚举与存量映射在实现审计后固定，不声称已有相同数据库或API。

| 一级类别/频道 | 二级内容                                                                                                       | 目标呈现                               |
| ------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| 短剧漫剧      | 短剧作品、漫剧作品                                                                                             | 以作品能力决定卡片；已观察短剧网格     |
| 影视作品      | 短片作品、音乐MV、视觉设定                                                                                     | 短片与图片分别呈现，不以一级名推断媒体 |
| 动画动漫      | 动画影片、视觉设定                                                                                             | 同上                                   |
| 广告营销      | 品牌广告、社媒营销                                                                                             | 按场景与内容能力呈现                   |
| 平面设计      | 海报、品牌设计                                                                                                 | 已观察海报瀑布流                       |
| 电商          | 电商头图、商品展示                                                                                             | 具体卡片矩阵须补证                     |
| 其他          | 灵感、短片                                                                                                     | 不用“其他”承载未接入能力假数据         |
| 技能          | 热门推荐、影视短片、电商、商业广告、通用创作、平面设计、社媒营销、娱乐、动漫游戏、大师风格复刻、专业运镜、发现 | 独立技能目录                           |
| 活动          | 当前活动、可展开的历史活动                                                                                     | 不沿用作品场景栏                       |

浏览导航为单选；跨作品分类重置首场景，重复选择当前分类保留当前场景。技能分类状态和作品场景分开存放；切换频道立即解除上一频道查询及详情状态，不能用迟到结果覆盖当前集合。

搜索类型为“灵感、技能、短片”；发布分类为“品牌广告、短片作品、剧集作品、音乐MV、动画影片、其他”。发布的剧集作品如何映射浏览的短剧/漫剧，按D04收敛，不能直接拿标签字符串相等当分类关联。

目标术语固定为：探索、作品、分类、场景、媒体类型、做同款、用作参考图、查看创作过程、查看短剧画布、复制项目、技能、添加技能、活动、发布短片。对应英文标识可分 ExploreCategory/ExploreScene/ExploreWork/ExploreSkill/ExploreActivity/ExploreSearchType/PublishCategory 命名空间；不强制重命名已有稳定资源ID。

本专项目标作品流采用追加加载与明确末尾，取代设计09对探索应用统一12/24/48分页的旧目标；其他数据页面的分页合同不变。若服务仅有页码接口，可以适配追加读取，但必须有稳定顺序、去重、终止条件与失败重试，不能只把分页按钮隐藏。

### 7.2 页面结构与共享顶栏

```text
侧栏 │ 一级分类及频道（可收缩、横向滚动） │ 搜索/公共操作/头像
     │ 当前分类的场景标签                │ 发布短片（能力允许时）
     │ 作品流 / 技能目录 / 活动列表
```

- 一级分类使用设计09的 navigation 槽，账号、主题和消息由公共操作组持有；页面只持有频道、筛选、查询、列表和详情状态，不复制账号组件。
- 桌面在同一 Grid/Flex 行分配空间。布局等价于 `minmax(0,1fr) auto`，导航区域 `min-width:0`，操作区不收缩；分类按钮不换行，溢出仅发生在分类区域。箭头按真实滚动边界显示，键盘选中的项目进入可见区。
- 二级场景在内容工具行，与有条件显示的发布按钮同排；活动频道撤掉无关场景。顶栏与二级行由同一滚动结构计算吸顶偏移，不叠加重复页标题或空白占位。
- 搜索目标提案：探索及其结果页采用行内搜索，公共组仍由共享壳拥有；其他页面保持原搜索弹窗。D01须明确该范围的展示模式、快捷键和焦点合同并回写设计09后，才实现切换；任何时候一个快捷键只触发一个搜索入口。此为目标提案，不是已获确认的全站改动。
- 桌面验收中心线差≤1 CSS px，分类容器不得侵占账号区；1869与1280宽度分别验证搜索收起/展开。不能从这两个尺寸推断完整移动端行为。
- 移动候选方案沿共享壳的导航/账号首行、页面工具次行、触控目标至少44px和无整页横向溢出规则；320/390验证为本项目适配，不冒称即梦手机一致性。
- 色彩、字体、控件继续从全局来源取值；Figma必须同时输出与即梦相同状态下的几何/密度/交互差异。D02未收敛的字体、组件与原站外观差异不能标为像素完全一致，也不能由探索单独改全局品牌体系。

### 7.3 内容与动作合同

| 对象      | 最少业务信息                                                            | 动作与权限                                                              |
| --------- | ----------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 公开作品  | 稳定ID、类型、分类/场景、封面与比例、作者、发布状态、可读详情、允许动作 | 列表/详情只读取允许公开的内容；可看封面不等于可读原始参考、提示词或过程 |
| 短片      | 作品信息、媒体与时长、过程关联（可选）                                  | 播放与作品切换；过程存在且可读才展示入口                                |
| 技能定义  | 稳定ID、版本、作者、描述、技能正文、分类、允许动作                      | 定义与“用户已添加关系”分离；添加成功必须可在目标入口读回                |
| 活动      | ID、状态、起止时间、规则、合法链接、作品集合                            | 当前/历史、全部/获奖及排序；投稿动作必须符合真实活动状态                |
| 收藏/关注 | 用户、对象类型与ID、当前关系                                            | 按当前身份写入；列表与详情共享关系事实，不以计数增减代替确认            |
| 发布记录  | 发起人、视频、封面、标题、发布分类、简介、下载许可、结果状态            | 发布是从私有来源形成公开记录的显式动作，不改变原始生成任务归属          |

接口具体路径、存储表和包位置由T-EX-00审计决定；上表不代表需要为每个对象新建微服务。所需语义合同为：目录/作品查询、作品详情、关系读取与设置、技能目录与添加、活动及作品查询、发布提交与结果查询。沿现有 OpenAPI、鉴权、错误体系和幂等约定扩展；不得凭本文造出与真实后端无关的客户端假接口。

查询必须明确关键词、类别/场景/类型、排序及游标的有效组合。公开查询缓存与用户关系缓存分离，私有缓存至少区分账号及适用空间。失权/下架应撤销详情和复用资格；404、无权、空集合、网络失败在产品层分别表达。

各展示面的最小内容合同如下；缺失值不能补造，允许动作以服务端能力为准。

| 展示面 / 来源                | 必需信息与交互                                                                                                                    | 缺失及异常规则                                                                                                                           |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| 列表及滚动 / FR08～11、NFR10 | 短剧卡片展示封面、时长、标题、作者及可用过程入口；图片保留比例和作者/收藏入口；长列表提供回到顶部；图片懒加载、预留比例、追加去重 | 缺封面用中性占位；未知时长/作者不伪造；返回复用有效查询结果，过期数据可后台校验，不重复追加                                              |
| 图片详情 / FR12～13          | 作者、关注/收藏、标题/日期、AI生成标识、允许公开的提示词、参考、模型和比例；当前集合前后项                                        | 非必需字段缺失时省略或标明未提供；模型/参考缺失时明确复用限制；不把未知来源标为AI生成                                                    |
| 短片查看器 / FR16～17        | 标题、作者、关注/收藏、更多入口；播放/暂停、进度、音量、清晰度、清屏与作品切换                                                    | 清晰度来自实际媒体清单；只有单一质量时如实呈现；播放失败可重试，切换/离屏停止旧播放，不自动有声播放；更多菜单项目先按D07核定，不加空按钮 |
| 技能卡片及详情 / FR22～24    | 封面、名称、作者、说明、真实统计、添加；详情含发布时间、使用次数、收藏、描述及技能正文                                            | 未提供统计不展示假零；正文无权或失效时说明，添加与收藏不是同一关系                                                                       |
| 活动卡片与详情 / FR26～29    | 封面、标题、状态/倒计时、可选奖励及人数；历史可展开/收起并回到顶部；详情含起止时间、规则、链接与作品                              | 历史展开状态可恢复；规则和人数来自真实数据；无获奖结果不等于活动读取失败                                                                 |
| 搜索卡片 / FR33              | 灵感卡片具有作者、收藏、做同款、参考追加；组内容按真实分组提供“查看全部”                                                          | D07先核定组内浏览合同；无分组时不显示组入口；动作与详情保持同一权限和数据                                                                |

页面在返回列表时恢复分类、场景、关键词、结果类型及可用滚动位置；来源集合不可恢复时回到明确默认入口。关闭详情释放播放器与临时媒体对象，焦点回到仍存在的触发项，否则回到列表标题/父入口。以上恢复、性能及媒体策略是本项目规则，不冒称竞品内部实现已证实。

### 7.4 从发现到创作

| 查看创作过程 | 可公开的过程快照/只读引用                    | 明确只读，可查看授权节点；关闭回到作品                   | 向浏览者开放原作者编辑权限、泄露私有节点                     |
| 复制项目     | 来源快照版本、目标空间/项目上下文、显式命令  | 独立可编辑副本可重新读取，原项目不变                     | 仅toast成功、共享可写身份、漏掉必要素材授权                  |
| 添加技能     | 技能ID/版本与目标用户/空间                   | 关系被接受，目标创作选择器可读回；重复添加结果确定       | 将正文复制到输入框冒充添加，或在添加时自动执行技能           |

已有草稿冲突采用“保留当前草稿，明确选择替换或另建”的候选交互；参考追加不替换正文。模型不能映射时保留可迁移内容并提示选择本平台可用模型，生成参数只来自真实能力。登录只恢复操作上下文，不自动补发生成或发布命令。

### 7.5 状态与恢复

| 状态机         | 转移与界面规则                                                                                                                  |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 列表读取       | 初次加载 → 有数据/已确认空/失败；有数据 → 加载更多 → 追加/末尾/追加失败。刷新保留旧内容；筛选变化隔离旧请求；失败不能伪装空集合 |
| 详情           | 打开 → 加载 → 可读/不可用/无权/失败。当前列表、关键词及滚动位置有可恢复上下文；直接深链无来源时返回探索默认入口                 |
| 关系及技能写入 | 稳定状态 → 提交中 → 已确认新状态/确定失败/结果未知。未知先查原结果，不换幂等身份重复写入；计数和关系统一更新                    |
| 发布编辑       | 编辑 → 上传/处理中 → 可提交 → 提交中 → 已受理/确定失败/结果未知。已受理不等于公开可见；若系统有审核，则审核是独立状态           |
| 项目复制       | 目标可写且来源可读 → 复制中 → 已接受副本/确定失败/结果未知；关闭面板不声称服务端撤回                                            |
| 身份切换       | 清除原身份的关系、私有草稿引用和权限结果；公开浏览内容可保留；重新验证后才恢复私有写入                                          |

表内异常恢复是本项目设计提案，不宣称即梦已实测采用相同内部状态。后端未提供查询/幂等能力时，该动作不能通过“重复提交即可”的方式接受。

发布表单按观察包含必填视频、封面、标题、分类，可选简介及下载开关。标题40汉字提示、简介500、最多2分类、默认允许下载是候选对齐值；**计数单位、视频格式/大小/时长、取帧、审核及默认下载策略必须由D04/D05确定为统一前后端合同**，不从界面提示直接猜服务端限制。

活动倒计时由明确时区的截止时间产生；评奖中、结束、获奖不是仅凭本机时钟猜出的同一状态。外部活动链接只跳转合法目标，不自动代用户投稿、接受条款或上传。

## 8. 实施与验收

技术接受依次验证：真实数据来源与权限 → 状态及命令合同 → Figma主流程与全状态 → 对应实现 → 正常/异常/跨端/存量验证。可以按已收敛的能力分批实施，但任何一批都要包含该能力的设计、实现和验证，不能以“全部前端完成”替代用户闭环。

桌面同行、追加查询不串流、复用不自动生成、只读与副本隔离、关系读回、发布结果可查询、旧数据可访问是不可省略的接受条件。具体产品期望见PRD15，步骤与证据模板见Plan24；真实供应商生成、公开发布与生产迁移不由文档产出自动授权。
