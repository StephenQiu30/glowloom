## 7. 方案

### 7.1 组件整合方式

来源：原设计《11-画布迁移实施方案》第3节。

按视口、节点、连线、分组、编辑器和页面控件组织组件，共享媒体和富文本能力继续由既有组件提供。交互计算与业务请求分离，所有图变更经同一编辑命令和保存链路处理。实现前检查当前能力及缺口，已满足设计的行为保留并回归；差异按设计10第7.27节修正。

### 7.2 模块与实现职责

来源：原设计《11-画布迁移实施方案》第4节。

画布页面模块位于 `frontend/src/app/canvas/`，跨页面媒体、编辑器及基础控件沿现有共享目录复用。

| 模块         | 实现方式                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------ |
| 视口         | 统一坐标转换、指针锚点缩放、平移、可见范围和输入隔离；高频预览按帧更新                     |
| 节点与连线   | 节点外壳复用媒体和文本内容；端口、曲线和命中共用锚点计算；图引用通过正式合同校验           |
| 分组与选择   | 框选和多选基于全图几何；整体移动保持相对位置；打组、解组和复制沿原子编辑事务处理           |
| 操作与浮层   | 工具栏按当前选择显示；节点参数、引用和创建菜单复用现有浮层组件，按统一屏幕坐标避让         |
| 素材处理     | 上传、替换、下载使用正式授权接口；裁剪、拆图及缩放输出为新素材，失败保留原素材和已完成回执 |
| 编辑器与生成 | 正文和提示词复用富文本底座；参考绑定、模型、报价和生成沿现有会话及服务合同                 |
| 历史与保存   | 手势完成形成一次编辑；提交保留原幂等键、版本和恢复上下文，迟到回执不覆盖新输入             |

蒙版、AI超分、多角度、反推、批量运行和版本服务仅在相应正式合同可用后提供操作，不通过占位按钮声明能力已完成。

### 7.3 数据与失败路径

来源：原设计《11-画布迁移实施方案》第5节。

1. `Canvas`、`Node`、`API.Edge`及`commandBatch`继续是目标编辑与保存边界。组件使用统一节点、父子关系和文档结构，不另建长期同步的业务图。
2. 节点UUID、素材`ref_id`、项目与账号范围不从预览URL反推。未完成上传不能成为已保存可用素材；复制重建节点身份，同时正确重映射内部引用。
3. 一次拖动、尺寸变化、分组、拆图或批量插入形成明确编辑事务。指针预览按帧更新，不逐事件请求服务端；Escape/失焦/取消恢复完整交互状态。
4. 保存中冻结载荷与幂等键。后续编辑排队，迟到回执不能覆盖新输入；超时查原回执，冲突保留本地分支，撤权或切换身份停止原私有请求。
5. 生成引用和引用线先经真实合同校验。仅布局操作不推进生成意图、不触发付费调用；确认生成沿用现有报价与提交槽位。
6. 新增正式接口时先更新Go所有者合同，再用`pnpm api:generate`生成客户端；不手改`frontend/src/api/`，统一通过生成客户端访问接口。
7. 旧图读取、编辑和保存往返必须保留未知或受保护数据；不以过滤不支持节点后另存规避兼容问题。
