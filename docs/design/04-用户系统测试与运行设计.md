### 7.1 邮件与后台任务运行合同

配置：可信 public origin、邮件通道/发件域、供应商回调签名、摘要及载荷密钥 ID、预算、并行哈希上限、管理员引导身份、告警目标。缺安全密钥拒绝启动相关能力；缺邮件配置可保留已验证账号登录，禁用注册/恢复发信入口并返回明确服务状态。不能输出配置值或把秘密下发浏览器。

邮件领取用限时 lease 与可重入事件 ID。建议每批20条、lease60秒、最多5次尝试（初次及30秒/2分钟/5分钟/15分钟退避），抖动±20%，任务过期立即结束；这些是运行建议，调优需更新接受值。供应商超时保留“结果未知”，幂等重试/查询回执，禁止直接声称送达。事件不重复改授权；回调先验签再去重，乱序回调不能把 delivered 退成 submitted。载荷投递后清除；重发生成新受限证明。

指标不以邮箱/user_id作标签。记录队列年龄、失败分类、受理/提交/送达计数、401/403/409、哈希耗时、DB锁等待、撤权拦截与清理重试。安全事件使用安全的 action/result 和最小 diff。告警目标未定不算“告警已交付”。

### 8.3 测试与生成命令约定

在 backend 运行 `go test ./tests/identity ./tests/workspace ./tests/app -count=1`；仅已创建的测试包可运行。任务提供更小的 `-run` 子集，红阶段必须观察与预期一致的失败，编译错误仅限新接口尚未定义阶段；绿阶段不能忽略 Skip。Go 修改完成后按 PROJECT 执行 gofmt/goimports、go vet、golangci-lint、go test -race、govulncheck，记录未可用的工具，不用下载最新版掩盖基线不明。

前端任务在 frontend 运行指定 `pnpm exec vitest run <file>`；完成切片后运行 `pnpm exec eslint .`、`pnpm exec prettier --check .`、`pnpm exec next typegen`、`pnpm exec tsc --noEmit`、`pnpm exec next build`。运行浏览器时不真实付费生成。

契约生成入口为纯声明的 `frontend/openapi2ts.config.ts`，使用 @umijs/openapi 官方配置项和原始模板。前端执行 `pnpm api:generate`，由独立的 `api:schema` 命令使用固定 swag 版本从后端 Handler/DTO 注解导出 Swagger 到 `node_modules/.cache/openapi/swagger.json`，随后运行官方 openapi2ts 与项目 Prettier，统一生成到 `src/api/`。按 Swagger 标签组织文件，未标标签的身份操作放入 `identity.ts`；同名 DTO 通过官方 hook 保留模块名，使用 `API` 类型命名空间。配置加载无外部命令、文件写入或进程目录切换；不复制修改工具模板，不新增 backend/docs 或在线 Swagger。`pnpm api:check` 独立核对逐文件重现、全部 operationId 和旧分散目录清理；后端 `public_contract_test.go` 独立验证规范与实际路由双向一致。生成文件与对应 DTO 同批评审，禁止手改。

生成函数经 `requestLibPath` 导入 `src/lib/request.ts` 中的 Axios 封装，使用 AxiosRequestConfig 配置。请求拦截器补充幂等键并处理 FormData，响应错误保留后端 code/status/meta，取消保持 Axios 取消语义；普通响应返回原始 payload。认证文案与会话校验保留在 `components/auth/contracts.ts`，不使公共传输层反向依赖组件。下载传入 options 时显式给出 `responseType: "blob"`，遵循锁定版本原始模板的 options 优先规则。依据：[OpenAPI 官方说明](https://github.com/chenshuai2144/openapi2typescript#usage)、[Umi 请求文档](https://umijs.org/docs/max/request/)、[Axios 实例](https://axios-http.com/docs/instance)。

### 8.4 发布、迁移与恢复

1. 预检：冻结待迁移清单、逐资源拥有者、已核验邮箱、团队映射、初始平台管理员、当前版本和备份；缺项隔离并阻止相关用户切换。
2. 扩展：先增表/可空列/索引，空库 schema 与增量分别测试；大表索引和锁窗口单独评估，不直接对业务库重放 schema.sql。
3. 回填：按稳定 ID 分批、可续办，检查 FK、唯一邮箱与统计；不猜归属、不合并重名账号，旧管理员仅映射已核实团队管理职责。
4. 切换：维护窗口阻止旧身份写入，关闭旧认证/管理入口，启用新合同和所有范围消费者，同时失效旧会话；HTTP/worker/download同一授权版本，不能仅切前端。
5. 冒烟：两账号两团队正反例、平台治理无作品权、改密恢复、旧会话被拒、真实测试邮箱。先满足P0再开放注册，P1仍在完整计划。
6. 收缩：证明旧字段/入口无消费者后另批删除；只改命名不会完成迁移。生产数据操作需要用户明确指定环境和授权，计划本身不授权执行。

回退点：切换前可停回填、继续兼容旧服务；切换后禁止回退到单 org/role 授权版本。先关闭新写入，修复当前版本或恢复兼容快照并重放切换后必要变化。恢复隔离库中验证撤权日志、team治理冻结、会话全局失效；无法证明安全状态完整就保持外部访问关闭。恢复前后对照 ID/拥有者/成员资格、事件序号与时间窗口，恢复须保留账号软删除标记与撤权状态。

SMTP 已确认并完成管理员真实收信验证；条款正式发布/业务限额与质量目标/恢复支持/其他记录保留期限/告警目标仍以 SRS 第9节为待决入口。未决项只阻塞依赖它的公开执行；可使用 fake 通道、纯领域测试和现有库可回滚事务完成不依赖它的工程验证。用户已接受即时软删除、资料与资源保留和邮箱占位；不设置冷静期、自助恢复或物理清理任务。

### 8.7 已实现的运维入口

`glowloom identity` 提供 `bind-start --login-name … --email … [--platform-admin]`、`mail-run --operation …`、`bind-complete --operation … [--platform-admin]`。命令来自唯一入口 `backend/cmd/glowloom`，不另建身份二进制。该子命令不创建环境、不自动迁移 schema、不启动服务，也不开放注册。完成验证要求交互终端隐藏输入，不接受命令行验证码。

所有身份密钥仅通过 `.env` 注入运行环境，不再配置文件路径或挂载 `.local/identity/`。`GLOWLOOM_IDENTITY_KEY` 保存身份凭据材料的 JSON，HMAC 与 AES 密钥独立随机生成；迁移时保留已有材料，避免影响已存摘要及加密邮件载荷。`.env` 不提交，密钥不进入浏览器、日志或报告。条款版本及来源/全局发信预算通过 `GLOWLOOM_IDENTITY_TERMS_VERSION`、`GLOWLOOM_IDENTITY_MAIL_SOURCE_HOURLY_LIMIT`、`GLOWLOOM_IDENTITY_MAIL_GLOBAL_HOURLY_LIMIT` 显式配置；缺条款只关闭注册，缺预算关闭邮件申请，已验证登录不依赖这些配置。SMTP 复用既有 `SMTP_*` 名称及 TLS 配置。submitted 仅代表 SMTP 接受，真实收信需独立证据。

### 8.10 精确真实测试与清理

- PG：清空其他`GLOWLOOM_TEST_*`，只受控注入`GLOWLOOM_TEST_SESSION_V2_PG_ACTUAL=reviewed-exact-fixtures`与`GLOWLOOM_TEST_SESSION_V2_PG_DSN`，运行`go test -race -count=1 -json ./tests/identity -run '^TestSessionV2ActualPostgresCompetition$'`。三场景为refresh_refresh、revoke_refresh、refresh_revoke；两个独占现有连接，观察实际PG阻塞边后提交，不以延时猜测竞争。fixture只有随机UUID creator/org/scope/sid；清理以marker和UUID核验后按security_event→refresh→session→scope→user→org顺序事务删除，独立有界context，协程先退出再清理，最后精确残留必须0。controller独立核对既有8表指纹/行数不变。无真实账号写入、SMTP、settings写或全局cleanup。
- Redis：只受控注入`GLOWLOOM_TEST_SESSION_V2_REDIS_ACTUAL=reviewed-exact-keys`与`GLOWLOOM_TEST_SESSION_V2_REDIS_URL`，运行`go test -race -count=1 -json ./tests/identity -run '^TestSessionV2ActualRedisLua$'`。仅两随机sid/source的8键清单，检查Lua来源桶隔离、sid预算、租约owner/过期、receipt/revoked读取与绝对毫秒PXAT；独立cleanup仅DEL该清单并确认残留0。专属键主动PEXPIREAT与种预算是可控边界，不声称自然等待或共享实例故障；禁SCAN/FLUSH/CONFIG/停实例。
- 无opt-in的Skip不是实际通过。进程强杀/主机故障不能保证自动cleanup，保留已记录的精确UUID/key清单进行受控核对；不得扩大为全库清理。PG竞争中的本地codec/coordinator及拒绝cache写入是适配器模拟，不能冒充真实Redis停机恢复。

### 8.11 浏览器、性能与恢复验收

使用实际浏览器验证自然续期、同设备与原期限保持、纯定时器不推进用户活跃时间。只采集脱敏状态与时延，不采集 Cookie、JWT、密码或请求正文。记录样本量、负载、前后台状态及 p95 算法；注入时钟、单次成功和 warm 恢复不能替代自然周期或容量证明。

覆盖被动失效、主动退出、同账号新会话恢复、不同账号或范围拒绝、跨标签、存储拒绝及事务中止、迟到回调、撤权与恢复竞争。业务输入只能在当前身份和权限确认后显式恢复；禁止自动重复生成、发布或删除。

故障注入只作用已授权的测试范围，不能中断共享依赖。实际运行挂载、密钥和证据目录须先核对使用关系，不能作为旧测试缓存自动清理。结果及未覆盖边界记录在[会话实施计划](../plan/08-无感登录与会话续期实施计划.md)。
