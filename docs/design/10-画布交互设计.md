# 画布交互设计

## 1. 摘要

画布用于组织和编辑文本、图片、视频、音频及分组。交互组件负责编辑体验；正式项目画布必须把节点和关系保存到数据库，重开后恢复已确认内容。文件导出不能代替项目保存。

本文是基于原始需求的目标设计，不是对现有代码可靠性的背书。2026-10-22 用户要求按原始需求整理设计，删除冗余方案；实现是否满足本设计必须另行验证。

## 2. 参与者

创作者编辑素材；画布前端负责交互与未确认状态；数据服务负责持久化、授权和图约束。具体负责人及实施状态见 [BACKLOG](../../BACKLOG.md)。

## 3. 背景

依据 [需求06](../requirement/06-画布组件迁入与定制需求.md) 的最新确认：先采用参考项目的画布编辑与素材体验，独立组件先行，业务接线后续进行；不引入其 AI、助手、提示词库、远程插件或 Agent。用户随后明确要求设计节点入库和后端接口，不能因此把其他业务一起接回。

[需求08](../requirement/08-画布数据库持久化与DAG需求.md)规定持久化；[需求09](../requirement/09-画布WebSocket实时同步需求.md)规定唯一 WebSocket 保存；[需求10](../requirement/10-画布OT协同一致性需求.md)规定并发转换。它们是后续接线的验收依据，不因组件独立而被取消。

参考项目仅提供交互参考和组件来源，不决定 Glowloom 的数据库、权限或服务接口。旧迁移步骤、竞品功能全集和旧组件文件名不再作为当前设计。

## 4. 目标

- 节点操作、分组、连线、文本和素材编辑形成完整闭环，取消操作不产生多余节点。
- 数据库保存全部正式内容；读取失败不显示成可写空画布；保存失败不能误报成功。
- 独立组件和项目宿主职责明确，只接入完成当前画布所必要的服务。

不新增执行引擎、插件平台、多人光标或另一套知识库；生成、任务和计费不属于本次画布编辑范围。

## 5. 使用场景

| 场景                   | 用户结果                                                         |
| ---------------------- | ---------------------------------------------------------------- |
| 添加文本或导入素材     | 节点出现在可见位置；上传和保存状态明确，失败可重试或取消         |
| 拖动、缩放、框选和分组 | 节点与连线一起更新；松手完成一次编辑，取消恢复手势前状态         |
| 编辑、替换和裁剪图片   | 原节点身份和关系保留；新文件保存成功后才确认替换                 |
| 关闭重开或换设备       | 从项目读取数据库已确认状态，恢复相同内容与关系                   |
| 临时断线               | 页面中保留有界未确认操作，显示未保存；不承诺刷新后恢复未送达内容 |

## 6. 价值

用户能区分“眼前已改动”和“服务器已保存”，素材处理不破坏画布结构，后续开发有稳定的编辑边界。

## 7. 方案

### 7.1 组件与宿主职责

组件接收已验证的展示模型、编辑权限、保存状态及提交回调；输出明确的编辑意图。宿主负责项目身份、加载、媒体上传和读取、唯一提交队列、服务端回执与错误恢复。组件不持有数据库凭据，也不自行建立第二条保存路径。

独立使用可以通过用户主动导入、导出文件保留内容，页面明确文件保存边界。正式项目中的导入必须转为新增节点/关系操作，不能整图覆盖数据库。浏览器持久缓存不参与正式画布恢复。

### 7.2 节点与素材

首轮支持文本、图片、视频、音频和分组。文本保留正文与标题；媒体节点持稳定素材身份；分组保留成员关系。详细字段与派生值归属只在[数据与接口设计](14-画布数据与接口设计.md#72-节点字段与数据归属)维护。

本地导入、粘贴和拖放先产生可取消的上传占位，上传成功取得素材身份后提交节点。上传失败不得生成伪素材引用；离开、取消或切换项目后的迟到结果不能插入另一个画布。重复点击重试复用同一上传请求身份。

图片裁剪、像素缩放及替换产生新素材，再提交同一节点的素材替换操作；拆分产生多个新节点。对象存储上传与图提交不假装跨服务原子：上传成功而图保存失败时保留真实素材回执，可重试图提交，不自动删除素材。

### 7.3 手势与编辑边界

- 世界坐标定义节点位置和连线端点；屏幕坐标只用于菜单与操作条。缩放不改变节点存储坐标。
- 一次拖动由一个指针持有，预览在内存更新；结束时提交最终位置，取消或捕获丢失时结束手势并恢复预览。网络回执不控制指针释放。
- 分组移动提交组和全部受影响成员的最终世界坐标；入组、出组保持视觉位置。分组不能形成父子环。
- 连线为可视标注，不自动成为生成输入。禁止自连和同语义重复线；取消连线不留下孤立节点。
- 文字输入、选择、IME、菜单导航及滚动不触发画布快捷键。浮层有焦点与关闭规则，短屏可滚动，不改变画布视口。
- 选中、悬停、拖动预览属于当前会话；个人平移缩放不能被他人操作覆盖。服务端个人视图恢复不是首轮必要能力，默认按内容适配视口。

### 7.4 保存与失败呈现

连接状态与保存状态分别展示。编辑提交后显示未保存/待确认，只有当前所有编辑均获得持久接受、且对应权威变化已应用后显示已保存。拒绝要显示可操作原因；未知结果先查证原请求。

首次未授权、明确失权、未知文档结构或无法安全恢复时暂停编辑。临时断线且最近确认可写、基线可协调时可继续页面内编辑；队列达到上限暂停新编辑并提示。离开页面前提示仍有未确认内容，不以浏览器后台发送保证保存。

恢复与消息合同见[实时通道设计](15-画布WebSocket实时通道设计.md)；并发和撤销见[OT设计](17-画布OT处理设计.md)。正式项目撤销不能使用整份旧快照覆盖他人修改。

### 7.5 历史内容保护

新组件不能解释的历史节点、配置和关系必须保留，提供明确只读展示或阻止整份画布编辑；不得过滤后再保存剩余节点。生成节点、输入版本及历史结果继续由原所属业务管理，本轮不新增其编辑入口。

### 7.6 需求与故事追踪

保留已有故事身份，范围按最新确认解释；旧生成/提示词交互仅是历史要求，不作为首轮组件前置。

## 8. 实施与验收

[PRD05](../prd/05-画布编辑与素材.md)定义组件交付；[PRD07](../prd/07-画布数据库持久化与DAG.md)定义保存与恢复。旧验证记录保留在[计划13](../plan/13-画布编辑与素材实施计划.md)和[历史验证记录14](../plan/14-画布交互历史验证记录.md)，不证明新设计或新组件已接受。

组件验收覆盖五类节点、图片处理、分组、连线、手势取消、中文输入、键盘、窄屏和文件往返。接线验收必须另用真实数据库、正式身份和独立浏览器验证上传→编辑→持久确认→重开，并核对节点 ID、正文、布局、素材 ID 和关系。实现、性能、恢复、生产可用性分别给证据，不能由设计文档推出稳定性结论。
