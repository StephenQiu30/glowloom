# 画布WebSocket实时通道设计

## 1. 摘要

画布编辑只通过一条WebSocket提交队列发送，持久回执和权威变化也通过该连接交付。连接、授权和保存是三个独立状态，心跳不能代替数据库确认。

2026-10-22按原始需求重整为目标协议；不以旧客户端、现有socket实现或旧测试结果证明可靠。下面的报文是待实现与验证的合同，不是当前接口说明。

## 2. 参与者

画布客户端、身份与项目权限服务、画布提交服务。数据库与事务由设计14负责，操作转换由设计17负责；通道不再定义第二套保存逻辑。

## 3. 背景

[需求09](../requirement/09-画布WebSocket实时同步需求.md)明确要求编辑上行、回执和变化下行都走WebSocket，拒绝HTTP保存兜底或独立定时保存器。其FR-SYNC-01～03、BR-SYNC-01～06和AC-SYNC-01～04是本设计依据。

持久状态与原请求查证依赖[数据与接口设计14](14-画布数据与接口设计.md)；并发意图及撤销依赖[OT设计17](17-画布OT处理设计.md)。通信组件沿需求09保留的用户选择使用`coder/websocket`，仅承担协议和连接；库选择不决定业务保存、授权与恢复语义。无需增加房间服务、在线头像或邀请功能。

## 4. 目标

有权限的客户端按数据库接受顺序收到完整变化；初始化、丢ACK、重复消息、应用重启和重连都不产生重复编辑或假保存。短暂断线不打断手势所有权，明确失权必须停止编辑与新私有消息。

## 5. 使用场景

正常编辑在数据库提交后确认；另一端自动看到变化。网络断开时本页保留有界内存操作，重连先核实原请求，再补齐历史。恢复不足时保留本页意图供对照，不能用旧整图覆盖新快照。

## 6. 价值

用户可以判断内容是否真正保存，并在不刷新丢失本页修改的前提下处理连接故障。消息送达与并发正确性分别验证，互不冒充。

## 7. 方案

### 7.1 连接与身份

入口为`/api/canvases/{canvas_id}/live`；生产采用WSS，开发与生产使用同一业务语义。校验会话、Origin及当前空间/项目权限；凭据不进入URL或日志。首包join携带协议版本、client_id、当前空间和CSRF证明、last_revision；具体身份材料沿用户系统合同，不另建登录机制。

protocol_version用于报文兼容，operation_version用于操作语义，schema_version用于快照结构，三者分别校验。不支持的版本返回明确错误及受支持版本，不能降级为不安全的旧保存入口。各版本值在实现契约中统一注册；本文示例版本1是目标规范版本，不表示与现有版本1或2可直接兼容。上线须完成显式协商与切换测试。

本次报文合同采用protocol_version=3、operation_version=1、schema_version=1，三个常量集中定义；join必须显式携带client_id和字符串last_revision。协议1、2不再接收编辑，unsupported_protocol_version返回supported_versions=[3]及retryable=false。新协议仅允许按原body查证已存在的旧OT回执（旧body不含client_id、revision为数字），不执行旧请求；client_id不作为账号或权限凭据。HTTP画布快照及生命周期revision同步使用十进制字符串，持久历史的内部表示不因传输升级重写。

首次授权成功并完成同步后才可编辑。每次提交和投递私有变化前重新核对权限；归档变为只读，撤权停止新推送。授权结果不得在长连接内永久缓存。撤权后已被合法接收的数据无法由服务端收回，但后续私有消息不能继续发送。

### 7.2 消息合同

所有revision均为十进制字符串；空基线用`"0"`。document_id由连接绑定，客户端不能在消息中切换目标。

| 方向与消息              | 必要字段                                                         | 语义                                                                    |
| ----------------------- | ---------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 客户端join              | protocol_version、client_id、scope_id、csrf_token、last_revision | 加入明确文档，申请完整快照或从已确认版本续接                            |
| 服务端snapshot          | document、revision、permissions                                  | 同版本完整状态；不等于同步已结束                                        |
| 服务端changes           | from_revision、to_revision、changes[]                            | 每项含revision、actor_id、op_id、规范操作及重建所需effects；必须连续    |
| 服务端ready             | revision、actor_id、permissions                                  | 该连接已交付到此版本；允许在权限范围内开始发送                          |
| 客户端submit            | op_id、body                                                      | body含client_id、operation_version、base_revision、operations或undo_of  |
| 客户端resolve           | op_id、原body                                                    | 查询原请求；不执行，不修改body、不生成新ID                              |
| 服务端ack               | op_id、receipt                                                   | receipt为accepted+revision或rejected+code；持久回执，不是收到消息的通知 |
| 服务端receipt_not_found | op_id                                                            | 暂无回执，不是确定失败                                                  |
| 服务端heartbeat         | revision、permissions                                            | 保活及差距检测，不携带保存成功推断                                      |
| 服务端resync_required   | revision、code                                                   | 连续历史无法满足，停止发送并安全重建                                    |
| 服务端error             | code、op_id（若可识别）、retryable                               | 协议/权限/容量/依赖错误；可重试不等于可以更换请求身份                   |

目标提交示例：

```json
{
  "type": "submit",
  "op_id": "44444444-4444-4444-8444-444444444444",
  "body": {
    "client_id": "55555555-5555-4555-8555-555555555555",
    "operation_version": 1,
    "base_revision": "12",
    "operations": [
      {
        "type": "set",
        "node_id": "33333333-3333-4333-8333-333333333333",
        "path": ["position"],
        "value": { "x": 160, "y": 100 }
      }
    ]
  }
}
```

目标接受回执：

```json
{
  "type": "ack",
  "op_id": "44444444-4444-4444-8444-444444444444",
  "receipt": { "status": "accepted", "revision": "13" }
}
```

拒绝回执保留同一op_id，receipt为`{"status":"rejected","code":"invalid_graph"}`。ACK与changes可能先后不同；两者按op_id、revision核对，不重复应用自己的操作。缺字段或身份不匹配不得猜测为已保存。

### 7.3 初始化与增量连续性

先注册变化唤醒，再取得一致快照R；从数据库日志读取R之后的连续变化，交付到已核实水位H后发送ready(H)。通知只是唤醒线索，不是日志；每次排空和心跳均重新核对权威revision，避免注册/读取窗口丢失修改。

客户端接收revision小于等于已确认版本时去重；大于下一连续版本时请求补齐，不跳过缺口。一次变化只能应用一次。不能把HTTP快照R和另一版本的节点列表、权限缓存或无序推送拼成新图。

重连携带last_revision；有连续历史则发送changes和ready，否则发送resync_required并进入安全重建。快照必须包含已确认版本，不能用旧快照覆盖新基线。慢客户端不能通过无界缓冲追赶；关闭连接后靠数据库历史恢复。

### 7.4 保存队列与状态

采用设计17的B（确认基线）、P（唯一在途批次）、Q（后续内存意图）。一个文档会话只能有一个P；其他修改进入有界Q。手势完成产生编辑批次，指针释放不等待ACK。文本以编辑事务合并未发送输入；不设独立周期保存器。

“已保存”要求P与Q均空、所有接受回执对应的规范变化已应用。仅socket已连接、心跳revision增加或另一个用户有提交，均不能清空本地未确认状态。

| 状态/事件                        | 编辑与发送规则                                         |
| -------------------------------- | ------------------------------------------------------ |
| 首次连接、未完成授权或基线       | 不编辑、不发送                                         |
| 已ready且可写                    | 编辑并经唯一队列发送                                   |
| 临时断线，最近可写且基线可协调   | 允许有界页面内编辑，暂停发送；展示未保存/待确认        |
| 明确只读、撤权、身份切换         | 停止新编辑与发送；清理旧账号订阅，不将旧队列发往新身份 |
| 未知结构、历史不足、队列达到上限 | 暂停新编辑并说明原因；保留可解释的本页内容             |

### 7.5 未知结果、心跳与重建

断线或ACK超时后，P的原ID和body冻结。重连先重新授权并resolve(P)：accepted则核对包含该revision的历史/快照；rejected则终止P并重算后续意图；receipt_not_found则在ready且可写后用原ID/body重送，仍由服务端幂等与历史校验决定结果。

健康连接也可能丢ACK，因此心跳触发未决请求查证，不触发新的保存请求。拿到新快照不能据此断定P已接受或丢弃；必须核对原回执。若无法取得足够历史，保留本页意图并显示需要处理的冲突，用户重新编辑后才生成新ID。

建议心跳间隔5秒、连续3次未响应判定断线；重连使用有抖动的指数退避并设上限，身份错误停止自动重连。具体参数需在部署环境验证，是本次建议而非可用性承诺。

### 7.6 背压与资源边界

建议每连接上行消息不超过1MiB，本页待确认操作序列化总量不超过1MiB；服务端下行队列按条数及字节双限额，超限断开并要求补齐。完整文档JSON上限8MiB、下行单消息上限16MiB，与设计14的提交准入使用同一字节口径。快照超出预算时返回canvas_capacity_exceeded，不截断节点或静默漏发。图容量和消息预算必须一起验证，不允许“2000节点合法但永远无法加载”的组合。

提交、join、授权、数据库操作均有独立超时与取消；关闭页面或切换文档释放连接、计时器和订阅。超时后结果仍可能未知，按原请求查证。日志仅含关联ID、revision和错误类别。

首轮不新增跨实例消息平台。无论实际部署一台还是多台应用，持久顺序和补齐都来自同一权威数据库；若部署多实例，必须验证另一实例上的提交可通过版本检查补齐。不能用单机内存广播通过来宣称多实例实时SLO。
