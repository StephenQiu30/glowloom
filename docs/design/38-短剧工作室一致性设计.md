# 短剧工作室一致性设计

依据 [需求23](../requirement/23-短剧工作室对齐即梦需求.md)。交互目标已明确，依赖真实生成的行为以运行验收确定。

## 1. 摘要

短剧制作由来源/创作要求、剧本分集、制作资产、分镜与生成规划、视频/声音制作、采用、时间线和交付构成。工作室首页接收目标；项目内以可审阅的阶段产物和真实素材推进，允许人工接管、局部修改和从原任务恢复。

整体调用关系见[设计32 §7.0](32-完整创作AgentHarness与Skill多Agent架构设计.md#70-整体方案与完整调用路径)，本设计§7.3～7.6定义业务对象，§7.7给出贯穿流程，§7.8定义局部重做，§7.9给出可靠生产与版本化交付。两者是同一完整方案的执行与内容两面。

## 2. 参与者

编剧导入或创作剧本；项目成员制作资产、编辑分镜与生成；浏览者从精选作品查看获授权的只读画布；组织管理员控制供应商及模型可用性。

## 3. 背景

下段及§7原对照表保留2026-11-06入口设计时的基线，不表示今日仍无工作室/分镜实现。2026-11-12源码复核已确认项目五阶段、剧本/分集/结构编辑、Bible丰富模型、批量任务和真实渲染/工程导出，当前差距是生产身份及自动串联，见§7.3～7.6及[调研报告](../research/2026-11-12-短剧制作平台源码与发行包对照调研.md)。源码存在不等于当前部署或真实供应商接受。

短剧和普通画布共享项目及主画布服务。资产页已有 `short_drama` 分类、模板、权限和写入回执。独立的 `/storyboard` 只有占位状态。剧本模块有来源、文件导入、剧集结构、版本和确认接口，项目主体接口可提供资产引用。导演台和时间线已有画布实现，需要核对短剧内上下文及回填。

## 4. 目标

使用「短剧工作室」「短剧画布」「制作资产库」「分集视频」「故事板助手」等已观察名称。短剧项目的创建、打开、分集切换和返回共享项目身份。设计、接口、真实数据与运行状态能逐项追溯到需求。

## 5. 使用场景

- 创作者有剧本、只有创意、已有成片或直接进入画布时，分别走上传剧本、剧本创作、转绘或短剧画布。
- 项目成员在资产库准备角色和场景，进入分集视频选择一集，在编辑器查看片段、引用素材、预演和生成。
- 访问者查看公开示例。进入本人工作区编辑须显式复制，并核对权限和副本结果。

## 6. 价值

统一创作入口与项目归属，可通过「我的短剧」找回进行中的项目。制作资产可在画布、剧集和分镜复用，减少重复上传和选错项目的情况。

### 7.1 项目内交接

- `/short-drama/:projectID` 打开同一项目的剧本、剧本创作、制作资产库、分镜及转绘与后期。首页按创作方式创建短剧项目后定位对应阶段，短剧卡片可重新进入项目。主画布仍由原画布路由和协作服务持有。
- 文本使用现有剧本来源接口写入草稿。TXT/DOCX 原件先作为项目文档上传，再交给剧本解析任务。保存、上传和解析各持有自己的请求键；解析受理不明时重放原请求，保留已确认的上传结果。文件解析结果、取消、重试与核对使用任务回执。
- 剧本创作沿用项目 Agent 的真实模型目录、预算、提交和历史。用户显式选用完成回复，再确认正文和权利后写入草稿。分集候选沿用标题规则与完整范围确认。正式采纳后，片段结构可以按正文行建立、手工编辑和确认；助手建议仅应用到选定集和片段的本地草稿，保存时沿用版本校验。
- 制作资产库使用同一项目的媒资和角色、场景、道具实体。片段内容可以带入视频生成，媒体可通过生成器的引用入口使用。转绘当前通过模型声明的视频参考能力制作新版本，风格和市场作为创作要求，比例以选中模型支持的配置为准。结果保存在同项目中，可在短剧画布时间线编排与导出。
- 独立的视频转绘语义、逐镜输出绑定与合成全集、精选只读画布、智能预演、片段重拍、超分和拉片需要独立的权限、输入输出及恢复合同。正式开放时分别验收。

### 7.2 多媒体与风格输入合同

依据SRC-STUDIO-17/18，工作室的参考区提供上传菜单、可复用素材选择与已选卡片。上传沿用现有个人库确认、权限和幂等合同；创建项目回执成功后，把已选个人条目以冻结版本经现有transfer复制到项目，读取逐项成功的目标媒体身份及revision后组装PromptDraft。复制前及完成后都复核个人条目与媒体revision，最多8个并行读取；复制期间版本变化时不采用新内容，已受理的任务记录保留。复制失败或结果不明阻断发送并保留原命令重试；身份/空间切换取消旧请求和清空私有选择。小说文档读取真实TXT/DOCX正文，视频读取实际字节抽取带时间戳的采样帧，输出限制与模型能力先校验，不静默截断或声称完整音轨理解。链接导入后端处理时限5分钟，BFF仅该POST路由等待310秒并保留浏览器取消信号，其他JSON接口仍为10秒；客户端保留原URL/永久键并处理未知回执。链接只有解析入库回执成功才成为媒体引用，未配置/不支持时保留明确失败，不直接以URL冒充视频。

风格库复用workspace.style_preset的数据归属和引用语义，新增独立的授权library读写接口，不扩大原安全摘要接口。官方条目只读；本人条目按org/scope/actor持有，新增revision及分类，搜索和分页在服务端执行。创建/更新/软删除使用幂等键、CAS、事务审计和持久回执；被项目绑定的条目不能静默删除。参考图逐项校验真实个人媒资，第一张封面。选择读取详情并冻结本次描述与图像，后续编辑风格不会悄悄改写已组成的输入。此按次风格输入不改项目既定style_type/subtype。分析风格复用现有Agent模型/预算/提交合同，回复由用户明确采用，禁止自动付费和伪造成功。

新增存储合同包含 `workspace.style_preset.owner_user_id/library_category/revision`、风格命令回执与历史参考 pin 关系；私有风格不进入旧的项目风格摘要和复制读取。`media.upload_request.source_kind` 只允许 `local/video_link`，默认 `local`；可信链接管线通过服务端字段写入 `video_link`，外部JSON和multipart不能声明来源。永久回执同时核对来源，防止本地同名上传冒充链接解析。目录校验使用既有 canonical library projection，不能要求每个上传素材都先有实体 `library_item`。存量数据库须由结构所有者先补列、约束、索引和最小授权，再启动新二进制；完整空库结构不得直接重放到已有业务库。

补充[多媒体参考与风格库原型区](https://www.figma.com/design/uLqmeRWuQuzfrp9xOYg6FT/Glowloom?node-id=3642-114436)复用既有Input/Textarea/Button/Checkbox与语义变量，包含风格目录、桌面双栏/手机单列编辑、添加来源菜单、链接、复制等待/失败、资产选择、预览、分析和删除状态。卡片为示例数据，字体和真实业务目录仍按各自验收记录核对。

### 7.3 生产身份、候选版本与采用关系

来源：[需求23 SRC-STUDIO-19/FR-STUDIO-01～12](../requirement/23-短剧工作室对齐即梦需求.md#src-studio-19)。本节至§7.6为2026-11-12能力补齐评审稿，仅文档，不改变既有领域权威或授权执行代码。外部事实与许可保留在调研报告，不作为产品命名。

现有剧本结构行承载scene/action/dialogue等文本与来源，不直接扩充成同时承载导演台、供应商任务和剪辑的一张万能记录。需要稳定的生产镜头与关联，具体存储布局在实施前依据现有领域确定，不预建新服务或平行任务引擎。

| 对象/关系 | 核心合同 | 所有权与边界 |
| --- | --- | --- |
| 来源/剧本/分集版本 | 项目、原件与范围定位、已采用版本、权利及改编约束 | 现有script服务；批次候选未完整写入不替换正式版本 |
| 生产镜头及修订 | 稳定镜头ID、集、顺序、来源结构引用/版本、内容/对白、景别/机位/运动、目标时长与连续性 | 短剧制作业务；重排不换ID；更新CAS，不以内容字符串识别镜头 |
| 模型生成单元 | 覆盖哪些镜头/区间、固定参考/造型/声音、模型能力与参数、输出要求 | 生成规划属于业务提案；一个单元可含多个镜头，一个镜头可多单元，不将其等同provider request |
| 生成operation/attempt | 原报价、预算、提交身份、供应商请求/句柄及逐项结果 | 现有operation/batch与资金服务；恢复查原记录，新尝试需重新准入 |
| 候选take与采用 | 生成来源、覆盖镜头/区间、真实asset/内容版本、验证；当前采用和历史采用回执 | 复用媒体身份，增加业务关联；成功不自动覆盖采用；比较、重拍和切换保留历史 |
| 时间线片段/版本 | 采用take、源裁切与目标起止、速度/过渡/音量/cue、画幅/fps | 现有时间线/Yjs权威；保持回到镜头关联；人工编辑不得被自动装配静默覆盖 |
| 交付及检查 | 固定时间线/输入版本、目标格式、缺项策略、原export task/产物及检查结果 | 现有mediatool/export/媒体；工程包导出与目标软件实际导入分开接受 |

`onShot(item.content)`式交接需替换为带项目/集/来源结构版本/生产镜头/生成单元的正式上下文引用，生成器回传候选take及原operation，业务采用回执再绑定镜头。提示词只是其中一个字段。跳转、刷新和再次选择素材后关联仍在，过期版本明确冲突。3D导演台继续持有自己的场景/机位/时间轴，通过正式输出引用关联制作镜头，不强制合并实体。

### 7.4 阶段产物、制作依赖与批量推进

主Agent按[设计32](32-完整创作AgentHarness与Skill多Agent架构设计.md)管理目标、任务书、主子会话、Skill、MCP、根预算与持久等待；本设计只定义短剧内容合同。角色不是固定服务数量：编剧、美术、分镜/连续性、声音、剪辑可按输入范围委派，简单任务可直接调用正式工具，独立审查不能取得被审对象的额外写权限。

阶段产物分别为创作要求/剧本、分集计划、制作资产计划、故事板、模型生成计划、声音/cue计划、时间线提案和交付报告。每份候选有类型/schema版本、项目/集/镜头范围、来源修订、确切引用、必要字段、验证与作者/运行来源。方法Skill不兼任正式存储；候选可审查、局部修改，正式采用走Go权限及CAS。超长结果可分批写候选，全部通过后原子采用；拒绝clear-first再逐批写正式整体。

| 依赖阶段 | 就绪条件 | 失败/变更处理 |
| --- | --- | --- |
| 资产提取→资产制作 | 已采用剧本范围和实体映射；角色/场景/道具别名不混淆 | 无依据的实体候选待确认，不自动合并重名角色 |
| 参考制作→视频单元 | 固定Bible/造型/参考版本，媒体真实归档可用且已采用 | 未完成参考不能与依赖视频一起盲目收费；失败阻断必要下游，其他独立项继续 |
| 视频/声音批次→采用 | 每项有原请求、真实asset及验证回执 | 显示成功/失败/未知/取消和费用；未知查原任务，不“重新开始整集” |
| 采用→剪辑 | 要求范围的take/声音/cue已就绪，或明确进入部分预览策略 | 缺项列表与空洞可见；部分可用不等于全集完成 |
| 时间线→交付 | 固定可读取版本、输入引用、输出策略、预算/授权和完整性要求 | 人工修改导致版本冲突，创建可审阅新提案而非覆盖 |

按集、选中镜头或明确生成单元组成批次，复用现有batch容量/领取/供应商暂停策略；逐项报价和总授权冻结，依赖变化使旧提案失效。执行/归档/绑定可自动接续，采用仅限用户显式选择或事前授权的确定范围，不能由LLM自称“质量合格”扩大收费。终态汇合记录要求的完成策略（全成功/可部分预览/遇必需项失败阻断），再持久登记后续工作，由设计32统一准入。页面断开、通知早到/丢失不影响原任务核对；用户新输入、审批及Stop优先级沿原执行控制。

### 7.5 连续性、声音与时间线交付

连续性由已采用Bible与相邻镜头的入口/出口共同表达：角色造型、时空/光线、道具持有、站位/朝向/视线、动作状态和延续声音。审查保留镜头/素材版本、输入覆盖、观察依据、问题级别和人工决定。结构检查、真实媒体探测和模型审查分开；3帧视觉投影不能冒称听过音轨或逐帧看过成片，模型选择按实际理解能力。

对白保留台词/说话角色/情绪、声音绑定与版本，生成的音频保留原任务及采用。音频和字幕cue有权威文本来源、时间单位、入出点和对齐依据（人工、模型或已启用转写），时间线明确源音保留/静音/替换/混合、音量、裁切补齐与淡入淡出。字幕修订不重做无关视频。现有文字数字人已有配音试听采用后再确认视频的手动流程；Agent组合只接续相同正式合同，不将音色/台词直接塞给只支持驱动音频的视频接口。

自动装配生成时间线候选，引用采用take的精确内容版本与源区间，指定画幅、fps/时基、排序/重叠/过渡、声音/cue策略。使用现有timeline命令、真实FFmpeg worker和工程归档；不能新建另一个只拼URL的合成路径。检测缺镜、不可读输入、时长不足、非预期空洞/重叠、流布局和字幕范围；按真实FFmpeg约束归一。人工改变时间线后重装配需新候选及CAS，不覆盖新增片段。

交付由设计32 §7.14的确定性复合操作编排现有动作：固定/提交时间线→受理原渲染任务→归档并验证结果→绑定/登记产物→受理工程/媒体包导出→完整性检查。每步使用原业务身份、依赖版本与回执；重开只核对或补缺失步骤。已完成渲染不因绑定/工程导出失败重做，供应商生成未知也不因交付超时而重发。Stop后不新增导出，已产出媒体仍保留。

完整交付需证明要求镜头覆盖、可解码、时长/画幅/fps、所要求音轨/字幕/工程文件及资产可读；音画内容、连续性/节奏由明确范围的检查和人工接受补足。允许部分输出时显示“部分预览/部分导出”与缺项，不能默认为全集完成。FCPXML/XMEML/剪映文件生成成功不代表目标软件实际导入通过。

### 7.6 局部重做、权限与接受边界

依赖图只保存真实关联：来源/剧本→集/镜头→生成单元→take/采用→时间线clip/声音cue→交付。更改某角色造型时展示受影响镜头与采用/时间线，允许保留旧版本；更改一个字幕文本不触发全片重新生成。现有 script 影响服务返回集级 `AffectedEpisode`；Bible 角色/造型影响当前只返回计数（sha256/修订/行数/别名），没有集或镜头身份。扩展镜头级计算前不得猜测、删除或把所有历史素材标废。

普通写入沿项目/空间权限、CAS及永久回执，收费沿operation/资金服务；Agent及MCP不能绕过。不同子Agent产物冲突交主Agent形成新候选，不让最后返回者覆盖。重试、撤权、Stop、失owner和迟到结果的执行语义沿设计32；短剧域补充镜头/采用/时间线版本校验和逐项完整性。

验收分别覆盖结构/策略合同、真实Pi及隔离数据库/受控供应商的故障恢复、真实媒体渲染/工程文件、获准真实供应商与目标编辑器。前两层不能冒称模型质量或整剧接受。本轮没有执行上述工程验证；接受ID见PRD24新增表，实施组织见Plan33，状态仅BACKLOG。

#### 7.7.2 自动推进与人工接管

每一步自动推进前检查：依赖采用版本一致、所需输入真实可用、执行能力可用、控制允许、费用/权限仍在批准范围、任务书未过截止、没有待决冲突。条件不足进入有原因的等待，按原任务/采用回执查询；不让模型反复询问状态消耗预算。

**人工修订的业务围栏**：人工修订或采用变更在Go领域事务内记录新生产修订及受影响范围失效事实；正式生成/采用/时间线写入受理时，必须在相同准入事务或相同串行化边界下校验期望生产修订、引用版本和失效事实。不能仅依赖Agent收到通知才停止旧计划。两者竞争时，先受理的旧任务作为已在途核对并保存旧版本候选；修订先提交时，旧计划请求即使通知尚未送达也必须拒绝新收费/写入。原领域没有可验证的围栏时，自动生产不能开放；跨领域引用按固定采用快照和受控准入串行化，不声称数据库外部系统共享原子事务。

用户面板从一致快照/事件展示根目标、阶段、真实主子任务、采用版本、调用/批次、逐项成功/未知/失败、等待原因、预算/费用和产物。用户可查看计划、批准/驳回、采用、修改、停止或处理缺项；“重试”必须区分查询原任务、补齐归档、恢复后续和明确新尝试，不能一个按钮统一再生成。

人工编辑采用产物时，先记录正式业务修订，再形成影响预览。受影响分支停止**新**下游动作，已受理外部任务只收原回执；迟到结果按原输入版本保存为历史候选，不能写成当前采用。用户恢复执行时重新核对影响/授权，未受影响分支可复用。暂停/Stop、撤权和恢复执行段的细节沿设计32，不以改一段提示词热修改子Agent在途任务书。

读任务不启动模型；页面离开仅断订阅。恢复页面能查看原root/阶段/版本、失败和未决收费，不要求重新提交目标。数据删除/取消与停止执行分开；正在引用的素材沿原媒体引用保护/保留策略处理，不为清理候选破坏当前工程或账单依据。

### 7.8 局部重做的完整流程

#### 7.8.1 影响预览与受控重做

1. **捕获变化**：读取旧采用版本与新候选/人工修订，记录变化字段、资源身份及来源；不直接删除旧输出。
2. **计算影响**：沿真实依赖边定位生成单元、take采用、cue、clip及交付；区分必须重做、只需复查、保持复用。一个生成单元覆盖多个镜头时展示整单元影响，不能假称能只重生内部一帧。
3. **预览与批准**：展示理由、受影响/不受影响清单、可复用素材、追加费用和计划修订。用户可保留旧采用、只接受部分修订或授权重做；报价和输入变化后的旧批准不自动有效。
4. **固定新计划**：CAS确认当前采用/时间线版本未变，更新非终态root任务书/manifest的必要修订或建立唯一新段；原root已Stop或完成时新受理run，引用旧采用结果而不复活终态root；Go受理新的业务尝试。恢复原未知请求与“按新要求重做”使用不同意图，不能混用幂等键。
5. **只执行必要下游**：使用原依赖图和batch/worker，保留成功无关项；同一素材被多个镜头使用时逐项明确替换范围。原生成尚未知，先核对/收束，不以重做掩盖未决费用。
6. **重新采用与交付**：新结果核对原输入和当前计划，重新采用后生成时间线候选并检查连续性/时长/声音，重新渲染/导出仅针对变化版本。旧成片/工程仍保留历史身份，不覆盖为新版本。

#### 7.8.2 变化类型和传播边界

| 变化 | 必须计算的下游 | 可以复用/只复查的内容 |
| --- | --- | --- |
| 单集剧情/对白/分集范围 | 受影响镜头、台词音频/cue、生成覆盖、时间线/交付；可能改变时长 | 未引用改动来源的集/资产；是否影响视频依实际声音/口型合同判断 |
| 角色造型/场景/道具参考 | 引用该版本的图/视频单元、对应take/clip/交付 | 其他角色/场景及明确保留旧造型的镜头；声音无依赖不重做 |
| 单镜动作/构图/时长 | 覆盖该镜头的生成单元、裁剪/clip/cue及交付 | 邻镜入口/出口重新检查，只有真实连续性影响才扩展重做 |
| 更换已生成take | 采用映射、源裁切/片长、相关声音对齐、时间线与交付 | 不新调用视频模型；相邻镜连续性先复查 |
| 音色/配音或背景音乐 | 对应声音任务/cue/混音及交付，驱动口型视频若有真实依赖也纳入 | 不依赖该音轨的画面；改字幕错字不默认重生配音 |
| 字幕文字或时间 | 字幕cue、字幕烧录/封装或工程、对应交付 | 已采用视频/声音；若仅文案改动要求改对白须显式另选 |
| 剪辑区间/过渡/输出规格 | clip、合成/导出及格式检查 | 现有源素材满足质量/画幅要求时复用；不够时提出新生成，不静默收费 |

依赖不完整时明确报告“影响无法可靠确定”，先补引用或人工选择范围；不能假装精确局部，也不能默认全片重做。复查传播有去重和有界范围，回路/无进展进入待决定，不让“连续性更好”变成无限重生邻镜。

### 7.9 可靠生产与版本化交付的收紧

本节依据需求23 SRC-STUDIO-21，是前述制作合同的稳定性再评估，不代表已执行工程验证。通用动作/等待/资金/容量/灾后恢复以[设计32 §7.15](32-完整创作AgentHarness与Skill多Agent架构设计.md#715-稳定服务再评估与详细执行合同)为准。

#### 7.9.1 固定生产快照及交付身份

每次批准制作固定production revision及其采用输入快照，包含集/镜头/生成单元覆盖、Bible/造型/声音、参考媒体内容版本、模型/参数/报价、目标时长及缺项策略。快照是引用及必要参数，不复制另一份媒体或钱包。可独立复用输入分别固定版本；人工修订时标识受影响范围，不能因为一个root持有旧快照就永久允许新收费。

每次交付再固定timeline revision、采用take/cue清单、输出规格及必需清单，形成独立delivery身份及分步回执。新修改后的导出不得复用旧交付幂等身份；同一交付重试不得更改输入。已完成渲染可复用的条件是输入/参数内容身份一致且文件仍真实可读，不仅是“同一项目上次成功”。

#### 7.9.2 确定性生产步骤与版本竞争

准备故事板、准备参考草稿、提交收费生产、归档、采用、时间线刷新/重装配、渲染、绑定、工程导出分别保留正式操作。准备不偷偷生成；生成不偷偷采用；节点已显示成功不替代资源可读；归档失败只恢复原结果。受理新的收费/采用/时间线更新时，Go校验生产修订及失效事实，控制与计划变化的判断不能只在Agent完成。

人工编辑与自动提交竞争按正式领域串行化：旧操作先提交则后续归为原输入在途候选；人工修订先提交则拒绝旧计划新受理。Go事务内不等RPC。用户保留旧take时该采用版本仍可用于明确的旧方案，新方案不能默默继承它的完整通过结论。

对未改变的节点替换媒体，可按节点 id 做选择性刷新，但须校验真实关联、内容版本、所有权、时长/源裁切和人工编辑。只改变引用可用局部更新；改变故事节奏或时长需时间线候选和连续性复查。旧媒体更短、不覆盖原区间时不得截短凑合或覆盖其他clip，先显示冲突。共享生成单元改变要展示全部覆盖镜头，不能只按选中行生成。

#### 7.9.3 批量完成与成本收尾

整集batch逐项汇合，明确必需项、可选项、待人工采用与未知项；只有正式ready产物且采用符合规则才解锁相关下游。用户批准总预算不等于同意无限失败重生；重做预览有追加费用和剩余额度，未知原费用继续占用。逻辑分支、图片/视频operation与最终交付费用各归原资金身份，同一笔消费不因经过多个Agent/工具被多计。

业务root超截止/Stop后不继续新制作，但原上游请求和费用/归档可在各领域进行有限、可追踪的核对收尾；迟到素材留原候选，不绑定为当前采用。作品部分可用显示部分，不把root执行结束、batch终态或最终模型文本等同整集交付。

#### 7.9.4 局部重做与恢复接受

先完成一镜的来源→候选→采用→正式生成→归档→take绑定→时间线→成片/工程闭环，再用真实独立两镜验证并行/依赖，最后扩展整集。简单步骤由主Agent+确定性操作执行，专业子Agent只承担确有独立输入输出/审查价值的工作。实际接入外部服务通过同一Go出口；制作业务不依赖所有MCP连接或所有角色同时上线。

故障接受须覆盖：旧快照重试、新交付误用旧回执、同段提交未知、产物已归档未绑定、旧片段时长不够、渲染后人工改时间线、未知费用与Stop、恢复旧数据库后上游其实已收费。以确切输入/产物/费用回执证明局部恢复，不以新生成一个看似成功的文件掩盖重复消费。作品内容质量、完整音轨/字幕检查和目标编辑器导入仍单独接受。

## 8. 实施与验收

首个可用闭环从全局入口进入，读取当前用户的最近短剧和模板，创建或打开短剧画布，并到资产页管理全部。匿名只浏览公开页面，写操作走登录及当前空间授权。后续验收覆盖导入、生成、转绘、分镜助手和派生媒体。以 [PRD24](../prd/24-短剧工作室.md) 和 [Plan33](../plan/33-短剧工作室实施计划.md) 组织验收。
