# 模型销售定价与结算设计

从零设计评审稿。来源为[后台倍率和折扣需求 SRC-AI-49](../requirement/04-AI平台接入与预设管理需求.md#src-ai-49)、[号池 FR-POOL-09](../requirement/26-模型号池与多供应商路由需求.md)与[用户确认的积分规则 SRC-CREDIT-04](../requirement/21-模型商业计费与积分系统需求.md#src-credit-04)。线路资格、派发和原身份恢复由[设计40](40-模型号池与销售计费设计.md#pool-contract)持有。

产品验收见[PRD](../prd/27-模型销售定价与结算.md)，执行步骤见[Plan](../plan/36-模型销售定价与结算执行计划.md)。

## 1. 摘要

管理员为一个模型规格设置销售基准、常规倍率和折扣。系统同时显示采购参考、折前价和折后积分，发布后供各创作入口报价。每次确认固定用户能接受的最高扣费，实际命中渠道的采购成本独立核算。

## 2. 参与者

有定价权限的管理员可编辑、预览和发布。创作者或获授权的 Agent 可请求报价并在余额、预算内确认。账务人员依据供应商回执、账单和积分流水核对差额。服务端按付款空间校验读写权限。

## 3. 背景

即梦网页会随规格及账号权益展示单次积分。方舟 Seedance API 的 Token 回执提供采购计量依据。BeefTV 的报价模型分别表达已知金额、用量估算、预留额和未知项。设计采用这些区别来组织报价与账单。[外部研究 §4～5](../research/2026-11-13-模型号池与多供应商路由调研.md)

## 4. 目标

**已明确**　后台可调整倍率和折扣。按已经确认的商业规则，每人民币元折 10 积分，整单向上取整，足额才派发，扣费受确认上限约束。**建议**　首轮以模型和规格为定价范围，每个销售版本使用一项有效折扣。**待定**　倍率上下界、限免、会员优惠叠加以及视频固定秒销售价的开放范围。

## 5. 使用场景

| 来源 | 前置、角色与动作 | 确认条件 |
| --- | --- | --- |
| SRC-AI-49 | 管理员选定模型和模式，把常规倍率设为 1.5、销售优惠设为 8 折，选择示例输入预览。 | 预览可见折前、折后与适用版本。非法值保留草稿并指出字段。只有有权限的管理员可发布。AC-AI-44、AC-AI-45。 |
| US-POOL-01 | 创作者确认折后报价，随后管理员取消优惠或供给侧切换线路。 | 原任务按冻结的销售合同和用量结算。新报价采用新版本。AC-AI-46。 |
| US-POOL-03 | 视频已交付且用量回执缺失，账务人员核对原供应商账单。 | 交付与收费状态各自可读。补齐可归属用量后收敛原冻结，重复回执的资金效果为一次。AC-POOL-08。 |

## 6. 价值

管理员可以核算一次调价对用户积分和预计毛利的影响。创作者可在生成前看到整单预算。对账时能解释采购价差、优惠和超确认价由平台承担的金额。

## 7. 方案

### 7.1 管理员价格发布

对应 FR-AI-65。采购价与销售价版本的来源见 FR-AI-55、FR-AI-56。[原始价格规则](../requirement/04-AI平台接入与预设管理需求.md#src-ai-47)

模型价格页显示当前有效版本及适用规格。上半部分选择有来源、币种、单位和审核时间的渠道采购价。下半部分编辑对外销售基准、倍率和折扣。销售基准须引用确定的参考费率及汇率版本，换路后仍可复算。默认倍率 1，默认 10 折。产品界面输入 8 折时，服务端保存精确十进制 0.8。首轮建议接受正倍率、折数大于 0 且不超过 10，零价活动另议。

管理员用示例输入预览已知采购成本或区间、折前金额与积分、折后金额与积分、预计价差。预览和正式报价使用同一计价规则。保存草稿后显式发布，操作带所见版本。并发改价引发版本冲突时展示最新差异。发布形成不可变销售版本，审计记录操作者、前后值、适用规格和生效时间。取消优惠发布 10 折的新版本。修改前已出具且仍有效的报价使用其冻结版本，过期或输入变化则返回新报价。

### 7.2 计量、换算与上限

对应 FR-AI-66、FR-AI-67。先用所选合同的基准费率计算各计费项，按冻结汇率换算为人民币并合计。对整单乘常规倍率和一次折扣，再乘 10 向上取整。保存中间的精确金额以供审计。采购独立使用各次实际命中渠道的单位、用量、采购价及账单。

| 计量合同 | 提交前所需数据 | 结算依据 |
| --- | --- | --- |
| 确定单价，如按张、按次或已约定的计费秒数 | 合法数量、规格、可收费附加项及币种。 | 合同规定的实际交付量与收费证据。部分成功按可核实的计费项汇总。 |
| 按实际用量，如文本或方舟视频 Token | 模型版本、单价分档、计量上下界。视频预估考虑分辨率、帧率、输入/输出时长及适用的最低用量。 | 对应任务的计费 Token 及其来源。单位不同的备线必须能提供冻结销售合同所需的计量证据。 |
| 只能获得账单或用量暂缺 | 单独展示估算和可兑现的确认上限。无可承诺上限时显示待报价。 | 收到账单后核实其与原任务及销售计量的关系，证据不足继续待核对。 |

例：人民币基准 ¥7.56，常规倍率 1.5。折前 ¥11.34 为 114 积分，8 折后 ¥9.072 为 91 积分。若确认上限为 91、可信实际基准金额为 ¥6.00，则实际扣 72、释放 19。若实际基准为 ¥8.00，按同一规则算出 96 积分，用户最多扣 91，其余 5 积分的售价差额由平台承担。该差额与采购账单的币种和金额分别记录。上述数值为设计验算。

### 7.3 报价、确认与对账交接

对应 FR-POOL-09。创作入口提交付款空间、模型规格、规范化输入和约束，报价返回报价号、版本、折前与折后预计积分、最高积分、有效期。确认时重新校验权限、空间预算、输入摘要和报价有效期。余额与预算足够时，一次事务冻结确认上限、生成任务并登记可派发记录。同一付款方、确认键和内容重放取得原任务，异内容冲突。执行端只消费已提交的派发记录。[派发约定](40-模型号池与销售计费设计.md#pool-contract)

| 可核对的事实 | 资金动作 |
| --- | --- |
| 可信用量及终态已取得 | 按冻结销售版本重算，核销实际积分与确认上限中的较小值，释放余量。采购差额按实际渠道单列。 |
| 收到明确未受理且无费用的证明，任务已终止 | 释放原冻结并记原因。安全补尝试仍在途时，冻结保留至任务终态。 |
| 受理、用量或费用未知，或回执与账单冲突 | 留存原冻结、尝试号及待核对原因。迟到回执先按付款方、任务、尝试与原上游编号校验归属，再以同一结算身份处理。 |
| 重复、乱序或事后更正 | 原结算只生效一次。重复事件返回原结果，互相矛盾的证据进入人工核对。已落账的更正以关联原流水的调整记录表达，用户累计实扣仍受确认上限约束。 |

## 8. 实施与验收

以下场景未执行。每个场景保存报价版本、脱敏输入、计算明细和可核对的资金记录。

| 场景 | 前置、角色与操作 | 预期证据 |
| --- | --- | --- |
| AC-AI-44 | 管理员在草稿输入 1.5 倍、8 折并发布，另由普通用户提交同一改价请求，再并发提交一个旧版本草稿。 | 新价有唯一生效版本，越权和冲突均无新版本。管理员预览与同输入的创作端报价一致。 |
| AC-AI-45 | 使用 ¥7.56 样例，分别发布 8 折和 10 折，并重放原确认。 | 对应 91 和 114 积分，原单只冻结一次。倍率、折扣与采购基准可分别复算。 |
| AC-AI-46 | 确认 91 后调价并切换到等价渠道，用较低、较高和缺失用量分别测试。 | 检查 72 扣款及 19 释放、91 封顶及 5 差额、冻结待核对三个结果。采购记录指向各自实际上游。 |
| AC-POOL-08 | 两次并发确认争用仅足一单的余额。成功单收到重复结算、晚到回执或冲突账单。 | 余额始终非负，冻结一次，用户核销至多一次，能从账单追到原任务和流水。 |

实单接受时应闭合“报价 → 冻结 → 原任务回执及可用产物 → 采购账单 → 用户核销与余量释放”。供应商数据尚不完整的组合记录具体缺项，可用性待验证。
