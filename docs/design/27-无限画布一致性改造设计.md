# 无限画布一致性改造设计

文档性质：产品与工程设计评审稿。来源：[需求14](../requirement/14-无限画布对齐即梦需求.md) REQ-JC-001～007、[研究10](../research/10-即梦无限画布需求基线.md) JC-001～060，以及2026-10-28用户要求产出 design、专业 PRD 与执行计划的指令。

本设计是**一致性改造专项的统筹设计**，持有目标交互、跨域组合、设计交付与验收边界；不是第二套画布存储、主体或资产规范。对应唯一产品文件为[PRD14](../prd/14-无限画布一致性改造.md)，执行见[Plan23](../plan/23-无限画布一致性改造实施计划.md)。排期、优先级、状态与阻塞仅见 [BACKLOG](../../BACKLOG.md)。

## 1. 摘要

让创作者在同一画布中完成素材组织、带参考的文本与媒体创作、结果再利用和连续编辑，使入口、选中态、参考连接、生成器、分组与辅助面板的视觉和交互按即梦实页逐项一致。REQ-JC-007明确否定“套用现有视觉、只对齐操作”的方案；颜色、字体、尺寸、间距、圆角、图标及透明热区均须有对应证据。实施按“证据与差异核对 → 设计稿及合同收敛 → 功能链路 → 综合验收”推进。

本次形成目标方案与任务定义，不将尚未检查的现有代码写为缺失。真实生成、非空时间线、导演台内部和协作异常等未证实部分必须补证；采用项目自主规则时显式记录，不能声称是即梦原行为。

## 4. 目标

1. 每个 JC 编号都有目标规则、差异处置、设计归属、任务和验收；无静默遗漏。
2. 创作者能完成“导入或编辑 → 引用 → 配置 → 生成 → 采用 → 重开继续”的真实闭环。
3. 节点内容、引用身份、资源可用性、生成任务、保存状态和访问权限分别表达；不以局部界面成功代替业务成功。
4. 新设计完整覆盖桌面、窄窗口、手机可达性、键盘、空/加载/失败/只读与恢复状态。
5. 保留存量内容与已接受架构；只有经核验的差异需要修改，不以全量重写作为一致性的前提。

不在本专项扩展支付系统、新供应商接入平台、独立三维引擎或新协作协议。时间线、导演台和AI对话仍在完整范围内；内部能力缺少证据或服务合同的，按独立退出条件处理，不把不可用入口当作完成。

## 5. 使用场景

| 场景           | 角色/前置                    | 主路径                                            | 异常关注                               |
| -------------- | ---------------------------- | ------------------------------------------------- | -------------------------------------- |
| 整理创意       | 有画布写权限，已有文本或素材 | 新建 → 编辑 → 多选/分组 → 查找定位                | 长文、混选、只读、撤销、未确认保存     |
| 参考生成       | 有合法素材与可用模型         | 连接/添加参考 → 配置 → 查看提交条件 → 提交 → 采用 | 空主体、引用失效、参数不支持、结果未知 |
| 稳定主体复用   | 当前空间有主体，目标项目可写 | 导入固定主体版本 → 引用主/辅媒体或音色 → 生成     | 无权媒体、删除版本、跨空间、音色不支持 |
| 继续创作       | 当前用户可读已有任务或作品   | 搜索/历史 → 定位或显式回填 → 修改 → 新任务        | 切换账号、任务失败、节点已删除         |
| 剪辑与镜头设计 | 合法素材，相关服务可用       | 时间线/导演台 → 编辑 → 导出/回写                  | 非空状态、取消、缺失资源、不支持格式   |
| 协作与恢复     | 两个授权账号，三个客户端     | 同时编辑 → 暂时断线 → 回执查证 → 继续             | 并发删除、IME、拒绝、撤权、旧客户端    |

故事与验收的完整定义由 PRD14 持有；此表不复制其确认条件。

## 6. 价值

素材选择、正文、参考、生成和结果采用位于连续工作流内，减少跨页重找内容与重复配置。稳定版本及真实任务身份让“重新生成”可以解释；保存与连接分开反馈，减少以为已保存却丢失内容的风险。熟悉即梦的用户可以复用操作习惯，同时继续使用织光已配置的模型、主体和资产。

上述价值为产品目标，尚未采集操作耗时或用户转化数据；不提供虚构提升比例。

## 7. 方案

### 7.1 规则分级与差异处理

- **已确认**：用户要求先分析、再核对、先设计后代码，并通过REQ-JC-007要求与即梦完全一致。领域约束继续有效；与此冲突的旧画布视觉规则由本次实页测量纠正。
- **观察依据**：研究10中实际菜单与行为；只适用于记录条件。
- **本次设计建议**：以下 `DEC-CJC-*` 是可执行目标方案，不是即梦实测结论，也不标为用户已逐项接受。
- **补证项**：未观察且会改变业务含义的流程，通过 Plan23 的补证任务解决；不阻塞无关已确定任务。

差异结果只能为“复用已满足、行为调整、视觉调整、补齐能力、领域合同变更、待证据决策”。“代码里找到组件”不足以选择复用已满足，必须关联运行证据。

### 7.3 关键状态与操作合同

| 维度 | 状态                                                       | 允许操作及反馈                                                     |
| ---- | ---------------------------------------------------------- | ------------------------------------------------------------------ |
| 交互 | 未选中/单选/多选/正文编辑/展开                             | 快捷键、操作条和焦点按状态切换；切换不提交生成                     |
| 资源 | 未添加/上传中/处理中/就绪/失败/失权                        | 只有就绪且获授权素材可作为生成输入；失败保留可重试/移除路径        |
| 草稿 | 可编辑/不完整/存在失效项                                   | 可继续修正，不隐藏具体错误；切节点、展开折叠保留当前会话内容       |
| 任务 | 待确认/已提交/排队/执行/成功/失败/取消请求/已取消/结果未知 | 查询和重连复用任务身份；取消请求不等于供应商已取消；未知结果先查证 |
| 保存 | 未保存/待确认/已保存/拒绝/需恢复                           | 新输入、上传和恢复未结束时不能被旧ACK标成已保存                    |
| 连接 | 连接中/已连接/重连/不可用                                  | 与保存分开；断线有界保留本页内容，按已有队列规则限制新写           |
| 权限 | 可写/只读/失效                                             | 只读保留获授权浏览；撤权后停止写入并清理私人缓存                   |

参考完整性按四步判断：目标允许该来源类型 → 来源仍存在且可访问 → 来源有就绪的固定版本素材 → 所选模型可以消费。第一步通过不意味着后三步通过。两行已观察的后接矩阵沿研究10使用；其余组合不能默认全允许或全禁止，应在能力合同中逐项确定。

```mermaid
flowchart LR
    A[节点与草稿编辑] --> B[类型及字段校验]
    B --> C[引用版本与授权校验]
    C --> D[真实模型能力与计费说明]
    D --> E[提交固定输入]
    E --> F[稳定任务身份]
    F --> G[执行状态与结果]
    G --> H[用户采用结果]
    H --> I[画布权威接受与持久回执]
    I --> A
```

#### 7.4.1 同节点生成输入与结果分离

按REQ-JC-007全量一致要求，文本/图片/视频/音频的同一可见节点同时拥有结果区和生成输入区。四类resource节点保持原ID和node_type/node_action，在既有`config.draft.composer`保存生成输入；正文仍为`config.rich_text/text`，媒体仍为`media_ref`。不把结果正文当提示词，不为每个节点另建workspace.prompt_draft，不静默转换资源节点类型。

该增量复用现有Draft/InputRevision/node_input快照与canvas_input合同：首次输入由服务器分配input_revision=1；输入内容、模型、参考、参数变化推进输入版本；布局、节点名称、背景及结果采用不推进。已有image_generation/video_generation继续按同一合同工作。资源节点仅接受结构化composer，不能混填旧prompt字段；固定参考编号不可回退，删除/撤销/恢复保留来源及授权检查。

生成前宿主等待既有Yjs队列完成、读取与确认contentRevision一致的权威DTO，并检查账号/项目/画布/节点、epoch、输入法/手势/上传/恢复/只读状态。返回当前canvas_revision和input_revision，禁止使用本地预测值或把Yjs epoch当submission epoch。正式RichGeneration复用保存来源、报价、确认、任务恢复与采用；失权、离线、结果未知和切换目标不能自动再次提交。文本/媒体结果必须通过现有正式资源接口回写正确节点，不能把任务受理当作生成完成。
后接创建的点击与拖拽必须分离：点击端口或键盘激活先打开七项创建菜单，不被端口后方节点误判为拖线落点；新节点放在来源相应侧，不能以端口为中心覆盖来源。拖到空白再创建仍以释放坐标为中心。来源实测空图片320×320、一次后接的水平间隙约61世界单位（[取证](../research/evidence/2026-10-28-canvas-implementation/advanced-source/connected-placement.json)）；织光采用60世界单位、节点中心对齐作为当前实现规则，纵向自动避让尚无充分源端证据，不冒充已像素一致。已存在节点、已加载素材的原比例不因默认值变更而迁移。

打开尚无composer的资源节点时，空编辑器初始化不是内容变更，不自动写空draft或新增撤销步骤；语义基线为emptyPromptDraft，实际输入才写入。打开生成器只waitForNode等待新节点接受，不flush；报价前flush可显式物化空输入并等待权威版本。无draft与节点已删除必须区分；撤销恢复无draft的既存节点不能误报协作者冲突，真实未提交内容及删除仍按恢复合同保留。

#### 7.4.2 时间线画幅意图与实际渲染尺寸

来源为[高级工具实测](../research/evidence/2026-10-28-canvas-implementation/advanced-parity-contracts.md)。时间线选择器完整保留 `auto`、`2.35:1`、`21:9`、`1.85:1`、`16:9`、`3:2`、`4:3`、`1:1`、`3:4`、`2:3`、`9:16`。显式画幅贯穿配置保存、刷新回读、预览、FFmpeg 渲染和产物 probe；编码尺寸保持偶数像素，沿用织光短边1080的编码规格等比计算（例如2.35:1为2538×1080、3:4为1080×1440；此规则不冒充即梦默认清晰度），不能将所有横屏比例当作16:9。

`auto` 表示尚待解析的画幅意图，不能默认映射16:9并声称与源一致。源端非空素材插入后的自动取向、切换首素材、无画面仅音轨规则尚待取证；在该合同落实前，保存允许保留意图，导出必须要求解析后的实际画幅，不能伪造自动结果。前端选择器区分用户所选意图和解析后的实际尺寸。完整退出条件仍包括非空源行为取证与正式时间线宿主，单独放开枚举不计为全量一致。
#### 7.4.3 时间线正式节点与编辑会话

预览授权地址仅用于当前身份、项目、画布和节点会话；媒体加载并发上限为6。按服务端最早到期时间提前刷新，组件卸载、身份/空间切换、素材集合变化立即取消旧请求和定时器，迟到响应不得回填。刷新失败移除对应过期地址并提供明确的重新读取入口，不能无限自动重试或以旧签名继续播放。该规则属于织光媒体授权合同，不推断即梦内部签名实现。

时间线使用已存在的 `node_type=timeline`、`node_action=tool`、`config.timeline`，复用Yjs原子保存和Go权威图验证，不创建私有浏览器工程。节点卡片展示当前工程预览/播放及进入全屏入口；全屏包含素材、预览、轨道三分区，缩放仅影响视图。新建配置保留auto意图、30fps与一条视频主视觉轨；空态16:9预览已获源端尺寸证据，不能推断为非空auto规则。

现有轨道合同要求同轨clip.kind与track.kind一致，故图片/视频/音频使用对应分型轨道；主视觉混轨规则仍需源端非空证据及后端同时扩展。任何拖动、修剪、分割必须同步维护start_ms/duration_ms/source_start_ms与固定媒体身份；锁定轨不允许剪辑改变，隐藏/静音参与预览和导出，吸附为明确可切换的编辑规则。每次修改以调用者基线和当前画布配置比较，远端已变化则拒绝覆盖并保留可恢复编辑；关闭不清除尚未确认修改。

导出必须等待画布已接受版本并读取权威revision，冻结输入后创建已有media-export任务；任务状态、重试、取消、真实产物预览、审核及下载均走现有API。现有可用格式MP4/M4A/SRT仅代表这些格式的实施边界；源菜单的工程格式仍须各自实现/解析/导入验证，不以下载同一MP4更换扩展名或禁用菜单作为交付。后续实现均沿这一真实服务合同扩展。
#### 7.4.4 主体正式节点与固定版本来源

主体使用独立的 `node_type=subject`、`node_action=resource`，配置为 `config.subject={version:1,subject_id?:UUID,version_id?:UUID}`；两个ID同时缺省为空主体，同时存在为统一主体库固定版本。`version_id` 是不可变版本UUID，不能使用主体头部CAS `revision` 替代。空主体可保存、移动、重命名和撤销，但不能充当生成素材；不伪装成普通图片节点，不通过URL或名称推断来源。未知字段、单侧ID、零UUID、非法版本和主体配置混入其他节点类型一律拒绝。

工具栏创建空主体；单选导入原子填充同一节点并以所选版本名称更名；多选导入先填充当前节点，其余建立独立主体节点，作为一次Yjs事务接受和撤销。移除主媒体清除整个固定版本绑定，恢复空主体，不隐式删除或修改统一库。节点标题与说明属于画布呈现；库主辅媒体/音色变更继续走设计25所有者接口，生成引用通过现有固定版本解析和binding证明展开。

每次Yjs投影保存均重新校验候选图与中间节点的主体来源，包括未改变或复用的固定绑定；统一主体所有者验证当前会话、空间、项目、固定版本及每项主/辅/音色媒体绑定。删除、撤权、跨空间、错误版本或失效媒体拒绝整笔保存，不缓存曾经授权作为当前许可；报价与执行沿既有主体binding链再次验证。复制节点保留固定版本但重新授权；跨项目复制仅允许既有复制所有者证明同一空间与源/目标权限后保留同一固定版本，不创建重复主体、不把主体媒体转为普通项目资产。缺少证明的复制失败关闭，不能静默清空绑定。

画布局部编辑使用可选 `config.subject.local={description,primary?,references,voice?}` 完整覆盖内容；媒体项为 `{asset_id,asset_revision,kind,binding_id?}`，音色为 `{name,media}`。主媒体限图/视频，辅助媒体限图片，音色限音频；不保存URL或客户端自报就绪。首次编辑已导入主体时物化该固定版本，保留原pin供既有binding授权；新选媒体只允许当前项目正式媒体，原pin媒体必须匹配其不可变binding。空节点可保存局部说明；清除主媒体恢复完整空态。修改、添加、移除、重命名音色均只写画布，不能静默更新主体库。

主体节点采用服务端派生 `input_revision` 标识可引用内容；新建为1，标题或主体配置变化单次递增，布局不递增，恢复不得复用旧修订。局部主体生成使用独立 `kind=canvas_subject`，`sourceId=node_id`、`sourceVersion=input_revision`，带当时说明与主/辅/音色的展开事实。保存、报价与确认均重读当前项目中的同一主体节点、精确修订和媒体授权；未保存、空主媒体、已删除或内容变化的来源拒绝。纯库pin沿既有subject来源。不能把局部编辑内容继续伪装成旧统一库版本。

画布添加采用现有referenceSelection蒙层直接点选合法媒体节点，Escape取消并回到编辑器；冻结、目标删除或epoch变更关闭选择，不创建参考连线。智能配音复用统一主体的正式语音任务；成功个人音频通过媒体所有者的永久幂等转移命令复制到当前项目，验证任务、逐项结果和项目preview后才加入局部音色。转移不重复合成、不暗建或改写库主体；未知任务恢复原键，未就绪/失权/迟到结果不写回节点。

局部媒体跨项目复制时，普通项目asset_id通过已验证的复制映射重建，复制资产revision从1开始；原统一库binding保留并重新授权。节点input_revision重建为1，库不会产生重复主体。

验收包括空/绑定配置往返、原子单/多导入与清除、重复/复制身份、刷新及两端固定版本、未修改绑定的撤权保存拒绝、跨空间/错误版本/删除/媒体失效拒绝及报价/执行复核。画布节点消费实现不代表主体媒体编辑、音色、全部来源入口或真实供应商生成已全量验收。

主体连线补充（JC-028～030）：正式边采用fromPortId=subject、toPortId=reference_subjects、purpose=REFERENCE_SUBJECT、binding=NODE_VALUE，仅允许image/video/audio目标；同源同目标重复边拒绝。空主体仍可保存节点与边，但不产生有效参考条目。非空边由权威GenerationInput派生不可变引用，原composer草稿不被重写：local使用node/input_revision及主辅音色固定媒体；纯库pin在node_input冻结subject_id/version_id，quote/confirm锁内由统一主体owner展开该固定版本并重新授权，不能信任客户端填充。引用ID由边身份确定，按边order/ID稳定排序并分配独立主体标签；删除/清空/重连及源内容改动推进目标input_revision，位置不推进。先全图推进主体input_revision，再冻结下游，禁止数组排序导致新内容套旧版本。连线创建的节点与边同一Yjs编辑接受，删除/撤销恢复使用既有事务和个人history。菜单、摘要和预览不能将空边当可执行来源。
#### 7.4.5 画布助手会话与真实执行

画布助手的会话归属为当前用户、项目和画布三元组；不使用管理员试验接口，也不把画布本地数组当服务。新增 `canvas.assistant_session` 保存会话标题、修订和有序轮次，每轮绑定同一用户在同一项目中的正式提示词草稿。创建草稿与绑定成功后才显示发送编辑器。执行复用正式提示词编译、报价确认、operation任务、取消及结果审核。当前轮通过正式submission恢复未知状态；开始下一轮前服务端锁会话并冻结上一轮实际operation，禁止未完成、报价待确认或未知请求被静默跳过。

会话命令使用稳定UUID与期望修订，相同绑定重试不重复轮次。会话私有，协作者不能读取他人会话；每次访问重新授权画布和项目，切换上下文取消前端请求。会话不进入Yjs文档，不参加画布撤销，也不随项目复制泄露。侧栏初始宽度400px，可在320px至视口允许宽度间调整，窄屏使用全部可用宽度。

助手展示使用独立 `presentation="assistant"`，仍归属于正式 `prompt_draft`，不得借用canvas owner。按 `advanced-source/assistant-panel.png/txt`：侧栏四边留12px、圆角24px、初始400px；标题为新会话，中央五个快捷入口为视频反解、创作分镜、全流程广告片导演、剧本开发、剧情短片；底部输入区为紧凑正文与 `+ / 使用技能 / @ / 发送` 工具行。模型和参数进入设置弹层，费用确认进入提交对话框；普通输入不展示reference_image等协议字段。快捷入口把对应创作请求写入当前可持久保存的草稿；它们不自动代表专业执行器已完成。剧本开发是来源首页快捷入口，不擅自扩为七技能目录的第八项。

打开助手自动恢复已有空会话或创建并绑定一个空草稿；未获得正式operation的会话视为空会话（仅键入文字或产生报价尚不算发出消息），新建入口显示“仅支持新建一个空会话”。服务端按当前用户与画布锁定并拒绝重复空会话；已经有正式任务后可新建。会话列表仍允许返回已有会话；未知响应重试沿用原身份，不额外创建。

七个来源技能保留为独立能力：视频反解、创作分镜、全流程广告片导演、剧情短片、电商套图、海报设计、品牌设计。普通文本讨论可使用正式文字模型；专业模式的分镜、图片组和视频执行必须有对应真实工具合同与产物验证，不能以提示词模板或菜单替代。来源证明空态目录、技能说明与入口，未证明工具内部执行协议。

续聊历史由已冻结operation的审核通过结果构造，区分用户输入和助手输出；超过输入容量时明确报错，不静默丢弃。参考复用prompt固定版本及授权。采用结果是独立显式操作，受当前画布/节点版本和权限检查；模型文本不自行执行画布命令。

助手工具执行分开记录 `skill` 和 `execution`。`discussion` 为文字讨论；`image` 仅用于海报设计和电商套图的正式图片生成，用户选择真实模型、数量和参数并确认报价，所有图片逐项审核、预览和采用。该合同证明图片产物链路，不证明源技能完整内部步骤。图片生成后的续聊把已审核产物转为重新授权的固定媒体参考，再回到文字输入；不得把图片结果伪造为文字回复。视频反解需能够接收真实视频的理解模型；分镜/广告片/剧情短片/品牌设计需要各自分镜、镜头、品牌产物的结构校验与工具执行合同，普通讨论或一次生成不能替代这些完整流程。

相机目录完整采样为7相机、7镜头、5焦距、4光圈，包含自动；每组单选、左右循环、全部重置至自动，默认可确认。配色27个预设各8色，单选、全部重置；风格10项、初始复古对称美学、循环切换；运镜20项、初始无选中且不能确认、单选、清空。来源画面预览不直接复制；实现须使用有授权的独立替代视觉并披露视觉差异。自定义配色保存名称和颜色，提供色号、色相/饱和度/亮度、增删及取色；从图片取色读取用户明确选择的本地图片并产生真实颜色，不生成虚假采样。自定义颜色上限16为项目输入容量决策，非源限制实测。

正式结构为版本1的闭合CinemaKit设置（camera/palette/style/motion）；独立节点恰含一种设置，目标image/video可含对应多种本地设置。图引用与目标本地同类设置不能歧义叠加；替换/清除必须以一笔图事务更新相应边和本地设置。所选目录ID、精确自定义色值都参加保存和撤销。

本项目生成决策（不是对源内部实现的推断）：Canvas authoritative projection从目标本地设置和实际入边解析有效CinemaKit，校验来源节点/类别/能力；把完整设置、源node UUID与设置内容hash写入不可变生成input snapshot。上游设置、连接、清除或目标设置变更均增加下游input_revision，使旧报价拒绝确认；单纯移动或改名不使视觉意图变更。PromptDraft接受此受限typed意图，hash与operation.editor_draft冻结它，编译器将闭合目录语义转成可审查视觉约束传入真实provider prompt；用户正文不被UI改写，不向模型参数表塞不存在的camera字段。此策略不宣称供应商原生支持镜头参数，也不保证生成效果。非图片/视频模型、错误类型或无模型仍在正式预检拒绝；供应商是否遵循设置需要逐项真实产物验收。
#### 7.4.12 普通组与堆叠容器

来源为advanced-source/group-{created,layout,background}及stack-{created,gallery,actions}：两者均创建独立容器节点、保留原成员。复用既有 `node_type=group` 和 `parent_id` 父树，新增严格 `config.container={version:1,kind:group|stack,background:none|cyan|blue|purple|orange|yellow}`。缺少container的存量group仍为普通组；collapsed不代表stack，也不能按collapsed推断堆叠。stack在可访问名称、搜索分类、卡片与操作中明确为“堆叠”。其成员隐藏仅是视图派生，不删除节点、媒体、边或已保存绝对坐标。

编组/堆叠仅包住选中的顶层根，保留嵌套容器结构，不展开后丢弃原组；选中父子时子节点只归属一次。解除容器只删除该容器并将直接成员提升到其原父级，保留所有成员几何与边；容器移动一次平移所有后代。删除容器时显式递归删除后代并清理相关边，撤销恢复完整父树/几何/边。复制复用正式剪贴板递归捕获与ID映射，容器kind/背景随配置保存，外部父关系不继承，禁止循环或不存在父节点。

普通组可重命名、解除编组、宫格/智能布局、六种背景、下载；布局作用于直接成员及其后代的整体平移，并重新包围容器，不依赖workflow.enabled。堆叠显示真实成员卡片、数量、打开画廊、解除堆叠、下载；画廊展示原内容与身份，不克隆持久节点或自动发起生成。所有容器编辑沿现有正式Yjs事务与接受回执，冻结/只读/未知保存状态不得绕过。

分镜成功态没有可用源图片证据，暂仅显示已确认的前提说明：仅图片、最多49个、至少一张可用图片；空图禁用理由为“所选节点均无可用图片”。不得用普通宫格伪装分镜生成。容器下载复用正式媒体/文本下载权限，不能合成假媒体URL或把不支持类型静默标成功。

多选后接使用选区右侧入口，按所有来源的共同能力展示七项类型菜单；确认后只新增一个目标并同时建立所有来源边，一次Yjs变更/撤销，不允许部分成功。[来源实测](../research/evidence/2026-10-28-canvas-implementation/advanced-source/multi-connected-create.txt)为两文本→图片，5节点0边→6节点2边，CmdZ回5节点0边。工具条依次为数量、堆叠、编组下拉、布局下拉、下载，标签与后接独立定位；复制/删除沿右键与快捷键保留。容器与多选下载复用同一授权原件/Markdown路径；当前为逐文件发起，真实源批量包格式尚未取得成功证据，不能宣称ZIP一致。空文本来源批量下载只观察到“重试”失败，不推断成功产物。

#### 7.4.13 同项目跨画布保存与生成草稿复制

“保存到其他画布”使用当前项目内有写权限的正式目标文档。没有目标时允许在此项目通过正式createCanvas创建命名目标，原Idempotency-Key与名称保留至明确回执；未知结果只重试原创建，不另建项目或新请求。选区冻结包括组后代及内部边；任务、旧操作身份和私有预览URL不是新执行。源画布先完成保存，读取源与目标当前权限，目标选择后打开目标的正式Yjs编辑器，一次接受固定的新节点/边身份；新主体与生成输入由目标所有者分配新input_revision和不可变快照，源图保持不变。既有普通复制仍仅复制内容；跨画布保存成功必须以目标接受回执及重新GET读回对应新身份为准。

转移意图只在当前页面会话内存中保留，绑定session/actor/scope/project和目标文档。切账号、切空间、刷新/关闭页面不能恢复私有快照；未知保存使用同一意图与节点身份查证，禁止再次生成副本。目标删除、失写权限、源失读权限或会话代次变化时拒绝未提交写入；已提交与未确认状态如实区分。进入目标后其个人撤销可回退整次粘贴。

同项目复制保持资产ID/资产版本、库subject_id/version_id及用户显式参考的固定来源，不把历史canvas_subject输入冒充新节点input_revision。选区内部主体边随新节点身份重映射，GenerationInput在目标接受后从新主体revision重新派生；外部边不复制。时间线/导演等活动node引用仅在选区内重映射，跨画布外部node引用明确拒绝，用户需一起选择来源；固定asset引用不受此限制。当前项目权限及每项主体/媒体绑定由目标Yjs原子保存重新校验。

跨项目整体复制仍由workspace复制任务、media映射与canvas专属copy owner协作。此前拒绝IsDraft是因为生成输入含固定来源与执行/模型身份，不能只重命名节点UUID就认为授权完成。扩展时必须先按来源种类定义资产/节点/主体版本重映射、目标模型权限、任务清除、快照重建及receipt重放；未验证的种类不得静默删除或沿用原项目身份。此安全边界不等于全量复制验收。

跨项目闭合草稿子集：正式text/image/video/audio resource节点的composer无手工固定参考时，保留正文、模型选择、模式、参数和标签墓碑；模型权限仍在目标报价时重新校验。引用只由同一冻结图内subject边派生：固定库pin经专属copy owner复核，局部主体项目媒体经media映射重建；所有目标生成节点input_revision从1开始，持久化GenerationInput快照，与源项目输入和任务身份独立。手工固定参考与旧image_generation/video_generation执行节点仍需要独立来源迁移合同，不能静默清空后复制。 工具箱来源proof仅由目标GenerationInput按重映射后的cinema_studio边重新编译，新source.node_id属于目标，设置hash和手工配色/参数值保留；正式node config不接受非空CinemaKit.Sources，draft composer不接受派生CinemaKit，不把旧输入快照回灌成可编辑配置。

撤销新建/跨画布保存以用户拥有的字段比较；权威接受时派生的referenceLabels、labelState和mention显示编号不构成协作者编辑，不能因此误拒绝整次撤销。正文、参数、媒体、位置等真实变化仍保护；新出现且不属于本事务的入/出连线或子成员也阻止删除，保留协作者依赖。一次复制的节点/内部边整组撤销，redo保持原目标身份并使用当前输入版本高水位；需要真实接受回执与刷新核对，不能只凭客户端数量。

#### 7.4.14 画布素材选择器与完整集合筛选

JC-052～054 来源为研究10 E22。一级资产/主体/画布是不同授权查询来源，二级图片/视频/音频/文档是媒体类型；不把当前页数组过滤伪装完整库查询。现有ProjectAssetDialog所有调用者保留onAdd的项目AssetSummary合同、allowedKinds与单选/多选上限，确认前逐项重新授权并核对项目、媒体ID/kind/revision，scope/session切换或卸载取消迟到结果。

项目资产读取复用media/library的project scope、ready/passed/未回收过滤、服务端search与page/total；扩展created_from/created_before为创建时间半开区间、origin为upload/generated/system，图片专有resolutions与ratios为闭合多选OR，同类与异类筛选AND，先筛完整授权集合再count/order/page。分辨率沿现有历史媒体事实口径，真实图片长边1024/2048/4096/8192分别1K/2K/4K/8K（无元数据不命中）；比例按真实宽高精确交叉乘积比较8个已证比例，不根据文件名猜测，亦不把超清与高像素等同。个人收藏当前由个人库所有，项目库收藏与生成超清process事实缺少正式合同，项目picker必须说明不可用，禁止写入共享favorite冒充个人收藏。

规格筛选使用既有Checkbox多选：分辨率与比例各显示已选数量、可独立清空，筛选按钮显示来源与规格总数，并可清除全部条件。同组多选以逗号枚举交给正式查询OR，不过滤当前页；切到视频/音频/文档/模型时清除图片规格，切回图片保持已清除状态，通用时间/来源条件保留。每次条件变化从第一页重新读取，跨页已选素材继续保留。

主体列表由统一subject域的当前身份/空间API负责，不把Bible旧身份投影伪装统一主体；保留旧onSubject调用者，新增onUnifiedSubject消费统一主体。确认重新读取getSubjectVersion并验证当前scope与固定subject/version，创建正式subject节点而不拷贝成图片；选择器打开时捕获私有document epoch，scope/session/project切换、卸载或历史恢复后拒绝迟到确认，getter不进入持久DTO。画布列表复用当前空间授权canvas catalogue及其真实search/time/favorite游标，浏览不暗示能够把整张画布导入；画布引用/导入成功语义仍待来源证据与正式写入合同。文档可按真实媒体库列出，当前ProjectAssetDialog只浏览并明确说明文档解析/添加未接入，不调用onAdd执行文档写入，不改扩展名或转伪图片。新增筛选仅作用其支持来源，不向音频/文档强加图片条件；切换来源/类型重置不适用查询与页码，加载、空态、失败/重试、清除条件均可见。

#### 7.4.15 节点统计与项目信息（JC-002）

#### 7.5.1 完全一致的视觉验收合同

### 7.8 流星连线（REQ-JC-008）

依据用户双图纠正与实际页面的独立 canvas-connection-flow-layer：创建预览为连续细蓝贝塞尔线，不能使用粗灰虚线。沿用输出右侧中点到输入左侧中点的几何与吸附规则；从输入端反向拖动时，数据流仍保持输出→输入。待创建弹层使用同一预览组件，Escape 关闭即移除。

精确动效合同（REQ-JC-009）：来源为当前源页加载的 `octo-canvas-rendering.3800953894.js` 与 `canvas-view.e4df37de47.js`，身份及公式见[算法审计](../research/evidence/2026-10-29-connection-calibration/source-algorithm-audit.md)。以下取代旧版2.8秒/12%透明尾/白色头的近似方案。

- 周期2600ms，共享动画帧时钟 `p=(t%2600)/2600`；新增连线采用当前相位，恢复动画不从头重启。
- 令世界坐标贝塞尔近似弧长为 L，流段长度 `S=clamp(0.55L,120,312)`，头 `H=p(L+S+72)`、尾 `T=H−S`，仅绘制 `[max(0,T),min(L,H)]`。末尾72世界单位为空窗，流段不环绕。
- 基线 #008EE5、SVG authored width 1px、opacity1，100%视图显示1px，选中不增粗。独立热区保持现有点击/右键能力。无关已连接边的低对比状态另沿现有选择合同。
- 暗色流段从尾至头使用13节点渐变：0% #008EE5、13% #018FE5、27% #14A7EC、41% #1CB1E5、52% #75CCB9、60% #D6B20A、68% #E29618、71% #E48120、75% #E29618、80% #D6B20A、85% #75CCB9、95% #18ACE9、100% #008EE5；256×1 RGBA8纹理，RGB线性插值取整、alpha255、GPU线性采样。
- 流段内位置 q=(d−T)/S，核心直径 `1+sin(πq)` CSS px，蓝色头尾收细，中部彩色变宽；不设置独立白头或透明度渐隐尾。
- 距核心外缘 g 的暗色辉光为 #008EE5，coverage=`0.22×exp(−0.5×(g/1.5)²)×(1−coreCoverage)`。核心以距离场及 `fwidth` 抗锯齿；预乘alpha输出、MAX合成，分段接缝不反复叠加变亮。不可用CSS多层阴影冒充同等亮度。
- 单源64等参数段、多源16段，累计欧氏弧长存Float32；路径与尾长随视图缩放，核心宽度与辉光sigma保持CSS像素。Backing canvas按DPR取整。
- 拖拽与待创建预览的基线位于彩色流光之上：实测preview处于renderer z4，flow host z3，形成蓝色脊线。SVG外层CSS视图缩放影响基线，不能只凭vector-effect或computed width声称任意缩放都固定1 CSS px；71%源帧以约0.71屏幕像素基线复算更接近原图。
- 一张共享WebGL层绘制活动连线，React不逐帧更新；几何变化、平移与缩放跟随实际视图。减少动态效果、页面隐藏、无活动线时取消绘制并清空；清理资源，WebGL不可用时保留静态基线。隐藏关系或取消预览不残留动画。

Figma以0/650/1300/1950/2600ms静态可编辑关键帧表达同一公式；100%是周期边界空窗。原生图层表达颜色与几何，不代表GPU抗锯齿/MAX合成已验证。亮度与时序须在同浏览器、DPR、缩放、曲线、背景和相位下对照，明确截图时刻误差及遮挡，不能承诺跨GPU逐像素相同。浅色源端使用独立CSS渐变与0.10/sigma1辉光；未标定浅色值前不得将暗色数值冒称浅色一致。

导演台内部的一致性目标、两工作区合同、命名与 参考实现 实现整理方式，由专项[设计30](30-导演台一致性与实现整理设计.md)统一定义，并通过 PRD17 / Plan26 展开。既有单场景 `mode` 方案不等同于完整静态/动态工作区，不据此关闭专项需求。

### 7.9 节点“+”连接入口（REQ-JC-010）

源端已加载1112.b5ee721939.js及canvas-view.e4df37de47.js与实际DOM/操作共同确定，证据见[入口审计](../research/evidence/2026-10-29-connection-entry/source-audit.md)。

- 逻辑端口盒为60×120世界单位，中心固定在节点侧边中点。圆环20、边框1、默认外距22；外侧热区40×80、与节点无间隙。chrome反缩放为1/max(有效zoom,0.5)，故zoom≥50%时这些尺寸为CSS像素，低于50%随画布缩小。

- 拖动中的曲线锚点从侧边中点向外4CSSpx，菜单pending预览回到侧边中点。两者都不随glyph位置改变；反向输入端保持数据流方向。Escape取消保持节点/边不变。

### 7.11 高级节点组合与异常保存合同

本节区分三类依据：**源页面实测**是当前账号实际操作；**源静态事实**是当前已加载资源中的能力与保存分支；**本项目待验状态**是实现与验收合同，不作为即梦界面文案或端到端恢复已一致的证据。图稿沿原多选总板 `3153:57117` 扩展，不替换原01～07。

#### 7.11.1 能力、资源就绪与领域连接

源页面本轮实测空图片后接：文本、图片、视频、音频可用；时间线禁用，原因为“素材信息仍在加载中，请稍后重试。”；主体禁用，原因为“没有可用的就绪资源”；导演台禁用，原因为“无法连接这些节点”。这些结论仅适用于当前空图片、账号及模型状态，不能推广为所有图片或混合来源能力。原因通过提示/可访问描述表达，不新增占满菜单的说明行。

高级组合必须冻结完整来源集合；来源类型可连接不等于资源已就绪。所有参与领域操作的来源均须具有可用资源、合法身份与当前用途权限；图片/视频/音频等资源状态、模型允许类型、总量与分类型容量共同决定候选。external/provenance、tool、file、timeline、subject、group/stack分别按实际能力处理，不能把不兼容成员悄悄剔除后只连接合法子集。

主体与时间线使用各自领域事务：主体写入完整且有效的 assignments，时间线写入可接纳的素材集合，不以普通 reference 裸边冒充素材已进入目标。候选阶段只显示临时预览；完整来源就绪并通过整体 admission 后，目标、领域绑定与关系作为一次提交接受，一次 undo/redo处理。任何 skipped、部分资源不就绪、用途/容量变化、重复或成环均整批拒绝，不留下新目标、半批边或孤立绑定。预览可用不保证释放时提交成功；释放时按最新权限、拓扑及资源状态再验证。

领域素材解析可能异步完成。开始时冻结来源身份、资源身份及内容版本，并记录目标内容和当前文档/epoch；取得权威素材信息后，必须再次核对全部来源仍存在且输入未变、既有目标未被删除或改写、会话范围及写权限仍有效。任一核对失败即放弃整个候选；迟到结果不能复活来源、覆盖目标新内容或向新会话写入。其他无关编辑保留，候选基于最新可接受图构造。完整候选发布前还须通过保存准入，包含上传中引用与完整服务文档投影校验；被拒绝时不得先展示成功目标或部分边。事务只发布一次，等待保存及读回确认失败不触发新的创建事务。这里的准入与领域校验是本项目实现合同，不能代替实际服务接受和异常浏览器验收。

| 其他异构来源→领域目标 | 源静态事实 / 本项目待验 | 全来源就绪、领域绑定及单次事务；未经真实操作不显示已验通过 |
| 一项非法导致整批失败 | 源静态事实；普通重复已有页面实测 | 所有来源保留，零新增关系；实际提示与操作恢复单独核验 |
| 来源/权限在手势中变化 | 本项目待验 | 取消或拒绝临时候选，不复活被删来源，不静默降级 |

#### 7.11.2 等待保存、未知结果与权限边界

本地候选已应用、write receipt、submitted/held或网络已连接均不等于已保存。顶栏只有在当前业务提交得到权威接受、已接受基线追赶完成且没有未决操作或待处理恢复时才显示“已保存”。源静态保存状态包含 blocked、unsaved、unknown_timeout、pending、saved；这些内部字段不直接成为用户文案，也不能据此伪造即梦异常截图。

本项目待验画面使用简短状态文案“等待保存”“连接已断开”“保存结果未确认”，明确标注为项目设计。画布中的临时边与引用可继续呈现未确认意图，但不能用绿色成功、已保存或新回执掩盖未知结果。断线与保存状态分别表达；不把未知提交当成失败后重新创建目标。

新增源页面异常实测：视频＋音频接时间线后本地图为10节点10边，撤销到9节点8边显示已保存且刷新保持；重做本地恢复10节点10边，随后发生 `write_scope_denied` 并停止编辑，刷新回9节点。源提示为“您的更改未保存，仅保留在此选项卡中。编辑已停止；刷新页面将放弃此更改并加载最新草稿。”[截图](../research/evidence/2026-10-29-advanced-connection/source-write-scope-denied.png)及[可访问文本](../research/evidence/2026-10-29-advanced-connection/source-write-scope-denied.txt)证实未保存状态与提示；计数及刷新结果来自同次连续操作记录。此例证明本地重做与权威持久化必须分开，不能记为重做保存通过，也不能据错误码推断权限失效的具体根因或推广全部异常UI文案。

| 情形 | 操作与恢复合同 |
| --- | --- |
| 等待 ACK | 保留原提交身份、载荷及后继依赖；等待权威接受，不能仅凭本地节点/边出现切换已保存 |
| 超时 / 丢 ACK / 查询暂不可用 | 按原身份查证或重试，结果未知不生成新提交 ID；保留本页未决意图，避免重复目标和重复边 |
| 重连 | 先核验同账号/范围的权限、协议与 epoch，再查原回执、追赶基线；成功后才继续依赖完整的后继操作 |
| 明确拒绝 / 批次部分非法 | 整批不接受；按已接受基线恢复，后继意图显式核对，不将半批成功留在共享图 |
| 失去写权限但仍可读 | 停止连接和提交；已有图可读，允许查看按现有合同保留的本页恢复内容，不把只读当作保存成功 |
| 失去读权限 / 切换账号或范围 | 立即停止接收和展示旧私有内容；不向新范围重放旧提交或恢复输入 |
| epoch变化 | 查清旧提交已接受事实，加载新基线；旧P/Q不得自动投到新文档，未接受意图需按当前权限显式处理 |

连接专用准入在UNKNOWN或原提交仍inFlight时拒绝新建连接意图，防止确认等待结束后通过第二次手势生成新的业务身份。15秒等待超时不等于原提交终止；原提交查证使用相同op_id及完整载荷，不能再次创建目标。普通编辑准入与排队合同保持独立。恢复连接准入必须以原提交被接受且已读回为依据，单元会话中“只提交一次”不替代浏览器故障注入验收。

普通画布本轮恢复合同扩展此前仅本页业务内存的范围：使用IndexedDB事务保存frozen update、原确认基线、snapshot、pending、intents、forms、textDrafts与recoverySources；origin/actor/scope/project/canvas隔离，记录身份含session与epoch。网络submit前必须成功落盘，存储不可用或单记录超16MiB时不发送，并显示本机草稿保存失败、请勿关闭页面；不保存Cookie、CSRF或认证回调。Web Locks独占原session租约，恢复前重新读取，不能抢占仍活跃窗口；其它待恢复session保持可发现，不静默删除。

重开先恢复原session身份，再使用原op_id/原载荷resolve；accepted后合并并清理已确认记录。NOT_FOUND保留可读恢复草稿，不盲目重发；用户显式恢复字段后才形成新业务操作。跨epoch先查旧操作，再归档旧来源并显示当前权威图；403/404清除本页可见内容，按隔离命名空间保留本机草稿，不向其它actor暴露。输入中内容持续保护，stop前尽力落盘，但强制终止、设备损坏或系统清理存储不承诺恢复。本合同不等于即梦全部journal/quarantine实现已经一致，也不借导演台私有稿代替普通画布恢复。

验收必须分开：存储helper保存→真实reload→读取/actor隔离，只证明存储层；真实业务创建同页resolve、跨登录恢复、权威hash读回各自独立接受。页面可见已保存图不替代重新加载后取得权威snapshot。源异常UI、权限变更、领域事务回滚、租约竞争与跨用户并发仍需分别实测，不能由静态图或存储层结果替代。

## 8. 实施与验收

技术验收要求：单一编辑会话、稳定对象身份、合法引用、服务端权威能力、幂等任务、迟到结果不覆盖新内容、正确权限、持久接受与保存反馈一致、个人撤销不撤销他人贡献，以及存量内容可读。

产品验收由 PRD14 的 AC-CJC-01～24定义；执行样例、任务依赖、文件责任、测试与迁移回退由 Plan23 持有。每个设计集合须提供正常、边界和异常交互说明；演示数据标为演示，真实资产、任务、余额和成员不伪造。
