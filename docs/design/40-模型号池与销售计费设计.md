# 模型号池与销售计费设计｜总体、接入与路由

从零设计评审稿。本文负责模型、渠道、凭据、派发、任务恢复与可用性证据。管理员售价、确认与结算由[设计41](41-模型销售定价与结算设计.md)负责。需求来源为 [SRC-POOL-01](../requirement/26-模型号池与多供应商路由需求.md#src-pool-01) 和 [SRC-POOL-02](../requirement/26-模型号池与多供应商路由需求.md#src-pool-02)。

产品验收见[PRD](../prd/26-模型号池接入与路由.md)，执行步骤见[Plan](../plan/35-模型号池接入与路由执行计划.md)。

## 1. 摘要

创作者选定模型和规格后，系统在同一授权范围内选择渠道和 Key。一次确认对应一个业务任务，后台可以有多次有界尝试。任何可能已被受理的请求都保留原身份，用于查原单、取回产物和核对费用。

## 2. 参与者

平台接入管理员维护供应商和凭据。创作者及获授权的 Agent 发起业务任务。值班人员按任务编号处理异常，账务人员读取脱敏采购与结算证据。创作者和 Agent 只能读取当前有权使用的模型和任务，Agent 还受原授权的模型、端点及预算限制。

## 3. 背景

OpenRouter、New API 提供端点筛选和分层选路的实例。CC Switch 区分网络可达与可调用，Magpie 按 Key 维护模型权限，BeefTV 的媒体任务展示了原请求恢复所需的身份和回执。以上作为设计取舍的外部依据，织光各条线路的可用性均待实测。[八个项目的调研](../research/2026-11-13-模型号池与多供应商路由调研.md)

## 4. 目标

**已明确**　服务当前创作项目，持续更新号池，在合格供应商或 Key 间无感路由，后台可调整倍率及折扣。开放充值销售、个人订阅账号共享、跨模型自动降级和复杂策略编排属于非目标。本文 §7 的选择策略、发布机制和恢复路径为评审建议。

## 5. 使用场景

| 来源故事 | 触发、权限与可观察结果 | 设计与验收 |
| --- | --- | --- |
| US-POOL-01 | 创作者在画布、工作室或对话选择同一精确规格。主路维护时，三个入口均取得模型、参数和报价不变的结果。固定端点的 Agent 只能使用该端点。 | §7.2～7.3，AC-POOL-02、AC-POOL-04 |
| US-POOL-02 | 接入管理员更新即将到期的 Key。发布前可检查新凭据验证结果和正在使用旧凭据的任务。发布后新单转移，旧单仍可按授权收尾。 | §7.1，AC-POOL-01、AC-POOL-07、AC-POOL-09 |
| US-POOL-03 | 值班人员按视频任务编号查到上游受理证据。账务人员能看到此单已交付、费用待核对并追踪原账单。 | §7.3～7.4，AC-POOL-06、AC-POOL-08、AC-POOL-10 |

## 6. 价值

创作者只需确认一次。管理员能定位故障属于一把 Key、共享账号还是整个渠道，保留其他合格供给。按同一时间窗观察终态业务成功率、安全切换挽回率和端到端 P95，并单列未知单，统计口径见[需求26 §5](../requirement/26-模型号池与多供应商路由需求.md)。

## 7. 方案

<a id="pool-publish"></a>

### 7.1 渠道、凭据和发布

对应 FR-POOL-01、FR-POOL-02、FR-POOL-03。后台“渠道与 Key”保存供应商、协议、允许的端点、地区、数据处理约束、真实配额归属。密钥写入后只返回掩码和版本引用。每个线路版本绑定对外模型、精确规格、上游型号、凭据能力证据、采购价版本及可用的查询/取消方式。

| 管理操作 | 生效条件和结果 |
| --- | --- |
| 新增、轮换 | 新 Key 从待验证开始。分别记录网络、鉴权、当前 Key 的模型授权和精确模式实测。地址可达只影响网络检查。未提供目录的供应商支持人工录入及验证。 |
| 手动或定时刷新 | 按凭据版本读取模型、能力和价目，保存来源、时间与差异供审核。超时或空目录保留上次观测并标记陈旧。明确撤权、到期或必要证据失效立即取消新单资格。读取期间身份变化时丢弃旧响应。 |
| 发布、回滚 | 管理员预览新增或失效规格、受影响渠道及在途任务数，按所见版本提交。整版生效，版本冲突返回新差异。回滚选用仍有效的历史配置生成新发布，执行端始终读取当前撤销状态。配置变更无需重启。 |
| 排空、紧急撤销 | 排空立即停止新单，允许已绑定任务查单或取回。撤销和新派发使用同一准入边界，撤销成功后各实例阻止后续凭据使用。此前已发出的请求保留原记录，无法继续查询的转人工。 |

<a id="pool-select"></a>

### 7.2 无感选路和共享额度

对应 FR-POOL-04、FR-POOL-05、FR-POOL-06、FR-POOL-07。每次派发依次执行以下操作。

1. 读取任务冻结的精确模型、规格、必需参数、授权、销售计量要求及采购预算。排除不支持参考素材角色、工具调用、地区或数据策略的线路。上游文件 ID 绑定账号时只在该身份范围使用。聚合商还须能够约束下一跳和付款来源。
2. 筛出已发布且证据有效的候选。建议先选主备层级、同级均分，再在渠道内轮询可用 Key。候选为空时返回可解释的不可用原因。固定端点授权将集合限制在该端点。
3. 跨执行实例统一占用凭据、共享账号和渠道的并发名额与适用额度。容量竞争失败时重新选择独立候选。原子取得本次派发权，记录尝试、采购版本、端点和凭据版本，再发出请求。结束时释放并发占用，已发生的用量计入其所属额度周期。
4. 区分故障范围。鉴权失效隔离 Key，共享余额耗尽阻断整个额度组，端点故障隔离线路。临时故障依供应商恢复时间冷却，再有限探测。撤权、欠费和模型下架须依据新的授权、余额或发布证据恢复。
5. 建议首发加一次安全补尝试，共用原始截止时间。计数涵盖上游收费提交，约束 SDK 和代理的自动重试。已尝试的候选从本笔排除。业务格式错误、内容拒绝和用户取消进入终止处理。

<a id="pool-recover"></a>

### 7.3 任务身份与恢复

对应 FR-POOL-07、FR-POOL-08。每笔保存业务任务号、尝试序号、请求摘要、原路身份和上游编号。分别记录交付状态和费用状态。下面的证据决定同一任务的下一步。

| 已知事实 | 下一步 |
| --- | --- |
| 尚未发出，或上游回执及该渠道合同共同证明未受理、无费用 | 可在授权、预算、次数和时间范围内换路。失败种类不允许换路时结束任务，向计费侧提供明确零费用依据。 |
| 已收到任务号、工具调用或流片段 | 按原身份查询、取消或取回结果。流中断显示已输出内容和中断状态，避免重复执行工具。上游不支持取消时记录用户已停止后续动作，继续核对在途事实。 |
| 发送后超时、回执丢失，或进程重启时无法判断是否已发出 | 进入待核对。依据原请求号、原渠道查询或供应商账单收敛。HTTP 状态码、查询暂未找到及客户端断线均不足以证明未受理。 |
| 已取得产物但归档失败或费用未知 | 用原任务取回并重试归档。已交付状态和待结算状态可同时存在。用户主动再生成须取得新的报价和确认。 |

<a id="pool-contract"></a>

### 7.4 模块交接与后台可见性

三个管理入口分别为“渠道与 Key”“模型与售价”“任务与对账”。一份任务事实可由同一服务内的不同职责共享，下表约定读写边界。

| 操作 | 提供方 → 消费方 | 交接内容与失败行为 |
| --- | --- | --- |
| 检查可售规格 | 接入 → 报价 | 精确规格、可选线路版本、计量覆盖与采购上限。无合格候选时返回原因。 |
| 确认后派发 | 计费 → 路由 | 业务任务号、付款方及授权范围、冻结成功凭据、输入摘要、确认上限、不可变销售版本和允许线路范围。同一任务至多有一个可能已受理的尝试。 |
| 回传用量及交付结果 | 执行 → 对账 | 任务号、尝试号、原上游编号、用量单位和来源、采购版本、账单引用、交付与费用状态。按任务和回执身份幂等登记。归属不明或证据冲突时保留核对状态。 |
| 查询任务 | 管理 / 用户只读 | FR-POOL-10 要求列表展示可用或不可用，详情显示阻断原因、冷却和生效版本。值班可查看脱敏尝试链、变更人及时间。用户仅看本人任务、费用与可执行动作。日志和导出排除秘密、完整提示词及私有素材 URL。 |

FR-POOL-09 的冻结、结算与更正由[设计41 §7](41-模型销售定价与结算设计.md#sale-contract)持有。**待定**　DEC-POOL-01 的首批模型和等价渠道、DEC-POOL-02 的调度参数与更新时限、DEC-POOL-03 的采购价差和数据范围，均须按具体模型确认。

## 8. 实施与验收

设计验收场景均未执行。以下复用需求26的场景 ID。受控故障用于验证边界，真实可用性另须留存渠道证据。

| 场景 | 前置与操作 | 预期及证据 |
| --- | --- | --- |
| AC-POOL-01、AC-POOL-09 | 管理员从空池发布一条线路，再并发刷新和轮换 Key，模拟一次发布冲突。 | 观察初次可售时点、冲突响应和执行端版本。失败刷新保留最后有效配置。 |
| AC-POOL-02、AC-POOL-03、AC-POOL-04 | 配置甲、乙渠道及共享限额的两把 Key，分别模拟单 Key 到期、共享限流和规格不兼容。 | 对比所有实际接收端。独立合格渠道可承接，固定端点授权和不合格规格均无越界发送。 |
| AC-POOL-05、AC-POOL-06 | 注入明确拒收、回执丢失、流中断、用户取消和执行端崩溃，再用原确认键恢复。 | 记录收费 POST 次数、原任务号与工具执行次数。未知受理零补发，安全补尝试受上限约束。 |
| AC-POOL-07、AC-POOL-10 | 视频受理后先排空再撤销，回滚配置。以管理员及普通用户分别检查详情。 | 原凭据只在授权期间收尾。回滚无法恢复撤销的凭据，用户读不到路由秘密。 |
| AC-POOL-08 | 乙线路成功时重复回调，再注入一次缺用量的成功结果。 | 用任务号比对产物、采购尝试和唯一用户流水。缺用量待核对。详见[结算验收](41-模型销售定价与结算设计.md#sale-check)。 |

每个准备开放的“模型 × 规格 × 渠道 × 凭据”须有脱敏请求、受理编号、有效结果、可验证用量、实际采购费用及用户结算记录。异步任务另验原身份取回和轮换收尾。同模型跨供应商开放须有两个合格组合以及可复核的安全切换。当前状态为待验证。
