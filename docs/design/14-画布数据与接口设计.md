# 画布数据与接口设计

## 1. 摘要

保存完整画布、Yjs协作状态及接受回执，提供业务读取投影、素材引用和历史恢复。Go负责项目权限、业务约束与持久接受。

## 2. 参与者

画布客户端、Yjs协作服务、Go业务服务、PostgreSQL及现有素材存储服务。

## 3. 背景

来源为[数据需求08](../requirement/08-画布数据库持久化与DAG需求.md)及[协作需求10](../requirement/10-画布协作编辑需求.md)。交互见[设计10](10-画布交互设计.md)，传输见[设计15](15-画布WebSocket实时通道设计.md)，协作见[设计17](17-画布Yjs协作编辑设计.md)。

## 4. 目标

所有已确认内容可在换设备、清理浏览器数据和服务重启后恢复；每次编辑有可查询的确定结果，图与引用始终符合当前权限及业务约束。

## 5. 使用场景

既有字段兼容约束：完整编辑器参数以版本化 `config.editor` 保存，包含模型/模式/参数值、可编辑元数据、媒体节点的富文本提示词及固定素材引用；不保存临时URL、加载状态或生成回执。现行Go适配以CAS保存编辑参数；目标Yjs模型保留相同字段和业务校验，但按可独立编辑属性合并，不能将整份JSON CAS覆盖作为Yjs并发语义。授权素材仍通过所属项目的素材查询及历史保留校验。空媒体节点可保存，`replace_media` 用显式empty标识区分空内容与固定素材，旧绑定必须匹配。连线保留端口、用途、顺序与NODE_VALUE/FILE_REFERENCE/RUN_OUTPUT绑定，`set_edge`以原连线整体CAS更新并保存可逆历史，服务端校验端口、来源、重复与业务依赖成环；视觉annotation允许形成环，不能与业务依赖DAG混同；历史业务关系不得被降级为普通连线。保存批次原子接受，读回完整重建；执行任务另按业务合同授权，不因保存参数触发生成。

打开项目画布、上传并引用素材、连续编辑、多端同步、查证未知提交、复制项目、浏览与恢复版本，以及生成结果回写。

## 6. 价值

画布内容、素材身份和任务来源保持一致，用户可以核实保存结果并继续创作。

## 7. 方案

### 7.1 文档身份与权威状态

文档具有稳定ID、项目归属、schema版本、协作epoch与接受修订号。修订号以十进制字符串跨语言传输。每个epoch只有一个有效写入通道。

持久保存Yjs二进制状态、增量与原始提交身份；业务读取使用同次接受产生的类型化投影。恢复从二进制基线与更新重建Y.Doc，JSON用于业务读取及导出。

#### 7.1.1 控制版本与持久记录建议

| 标识/记录                       | 语义及约束                                                                                                     |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| documentId / projectId          | 稳定身份和授权归属；不从客户端自由拼接跨项目引用                                                               |
| schemaVersion / protocolVersion | 内容与消息兼容边界；不兼容则拒写或只读，不删除未知字段后保存                                                   |
| epoch                           | 文档谱系；历史恢复/协议迁移时改变，普通断线与owner接管不改变                                                   |
| writerTerm                      | 数据库分配的单调所有权代次；接管递增，旧owner即使连接存活也拒写                                                |
| commitSeq                       | 服务端接受顺序；以字符串传输，唯一键(documentId, epoch, commitSeq)；不等同Yjs state vector或节点contentVersion |
| 二进制checkpoint与更新日志      | checkpoint明确到达的commitSeq及hash，后续日志按连续修订重建；与可视JSON投影同版本核对                          |
| 提交回执                        | 唯一(documentId, epoch, actorId, updateId)，固定原信封hash、accepted/rejected、接受版本或原因                  |
| 提交事件Outbox                  | 同事务保存已接受事件的身份与版本；投递可重试，消费者去重并能按日志补齐                                         |
| 业务投影/来源记录               | 节点、边、输入版本、对象删除身份及素材引用；仅接受事务更新，不独立反写Yjs                                      |

以上为逻辑记录。第二阶段DDL使用 `canvas.collab_document` 保存当前二进制及writerTerm/epoch/commitSeq/contentRevision、`canvas.collab_update` 保存原始接受增量、`canvas.collab_receipt` 保存绑定账号/页面/epoch/更新ID的原请求哈希与终态。脚本为 `backend/db/canvas_yjs_incremental.sql`，与空库schema对应；脚本存在不表示业务库已迁移。每次接受将完整当前状态持久化，当前不执行更新日志截断。权威状态是同一事务接受的二进制与投影这一对事实；二者不允许各自接受写入。读取接口若采用异步派生缓存，必须带其到达版本，不可把旧缓存当当前权威图。

### 7.2 节点字段与数据归属

节点按稳定ID保存类型、标题、位置、尺寸、层级、配置及内容。坐标为有限数值，尺寸为正值；位置和尺寸分别按完整字段组更新。分组成员、连线端点、输入依赖及来源关系使用稳定ID。

Tiptap正文使用共享富文本结构，业务投影保留段落、格式、引用提及和引用元数据。引用保存referenceId、assetId、绑定版本及来源；媒体使用稳定素材身份，临时展示URL由读取服务签发。

生成输入版本与节点布局分开管理；结果绑定发起时冻结的输入、引用和任务身份。个人视口、选中状态、在线光标及拖动预览按交互与协作设计管理。

#### 7.2.1 应用可控的客户端存储清单

| 内容/位置                                                     | 策略                                                                                                                                   |
| ------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 已接受Y.Doc、乐观Y.Doc、P/Q、富文本恢复意图、素材发布中的草稿 | 只驻留当前会话内存；不接入IDB、localStorage/sessionStorage或文件系统自动journal                                                        |
| 画布快照/历史/正文/引用读取响应                               | 私有业务响应使用`Cache-Control: no-store`；不注册到Service Worker/Cache API离线缓存，不使用持久化查询/状态缓存，页面预取也遵守同一边界 |
| 业务内容的日志、错误重放或遥测备份                            | 不记录完整正文、二进制载荷或将其落入浏览器日志队列；诊断只保留必要身份、版本、大小与错误码                                             |
| 登录态、静态资源、个人视图偏好                                | 沿既有合同；个人视图严格使用设计10白名单，不夹带节点属性、正文、权限或未决操作                                                         |
| 旧业务缓存                                                    | 入口禁止读回/上传；盘点键/库后定向退出或清理，不全量清除同源登录和其他模块数据                                                         |

内存查询缓存允许，但按账号、空间、项目、画布和epoch隔离；退出账号或失去访问权释放，页面恢复显示前重新校验身份。用户主动导出沿既有功能，不作为自动草稿恢复手段。该约束针对应用主动存储与可控响应策略，不宣称可以控制浏览器/操作系统的全部内部落盘行为。验证不能只禁用IDB后就判定符合需求。

### 7.3 图与引用约束

| 数据     | 接受规则                                           |
| -------- | -------------------------------------------------- |
| 标注连线 | 端点存在，按连线身份去重，可表达视觉环路           |
| 分组     | 成员存在，父子关系无环，删除与取消分组保持成员合法 |
| 执行依赖 | 输入端口与类型有效，依赖图无环                     |
| 素材引用 | 校验项目可见性、授权、素材身份与绑定版本           |
| 生成结果 | 保存输入版本及来源关系，结果回写保留后来编辑的输入 |
| 历史结构 | 完整保留类型、字段和引用；版本不兼容时提供只读读取 |

删除节点按关系语义清理其引用边，素材回收由素材服务管理。项目复制重新映射节点、关系和正文引用，并保持授权与来源可追溯。

### 7.4 接受与持久化

协作服务基于已接受状态构造隔离候选；Go验证当前身份、项目状态、schema、图和引用。接受时原子保存协作状态或增量、业务投影、修订号和回执，提交后广播。

提交由文档、epoch、提交ID、发起身份及载荷哈希确定。重复请求返回原结果；同身份不同载荷明确拒绝。结果未知时查询原提交；授权的权威查询明确返回未找到时原样重试，查询失败不等于未找到。失败与拒绝保持已接受状态完整。

单写者切换、进程重启和超时恢复需通过持久版本条件防止旧实例写入；跨服务接受调用以原提交身份幂等处理。拒绝后的客户端恢复规则见[设计17](17-画布Yjs协作编辑设计.md#73-合法接受与恢复)。

#### 7.4.1 可落地的接受时序

1. Go从认证会话确定actor与授权范围，计算不可变提交信封的服务端hash；查原回执。同身份不同hash拒绝，未知结果不换ID重新提交。
2. JS运行时基于(documentId, epoch, writerTerm, commitSeq)准备隔离候选，输出二进制、实际变化及规范投影；按设计17校验根/因果完整性与资源预算。较重的解码和图准备不长期占用数据库行锁。
3. Go开启短事务，锁定文档及需要串行化的权限/对象状态，复核幂等记录、writerTerm、epoch、expectedCommitSeq、当前权限与素材。撤权/归档操作使用相同锁顺序或权限版本条件，防止验证后撤权仍提交的时间窗口。
4. 基线不匹配时整笔退出，在最新状态重新准备原更新；不提交旧候选。合法时原子写增量/必要checkpoint、业务投影、引用历史、递增commitSeq、回执及Outbox。拒绝记录不写候选图，但基于图状态的确定拒绝也须复核相同基线/epoch及幂等身份；基线已变化须重新校验后决定，不能固化过期候选的拒绝。锁等待、owner变化和服务不可用等暂态故障不伪造确定拒绝。
5. 数据库commit成功后才允许发送accepted、安装房间新基线及对外广播。运行时安装失败不撤销已完成事务；停止该房间进一步接受并从持久状态重载，客户端按原ID查证。投递器重试Outbox，客户端按版本查漏；广播失败不把已保存数据变成未提交。

Go不解析一套平行Yjs语义；只信任受认证内部运行时从相同基线计算的候选，并独立执行业务授权与约束。禁止浏览器直接调用候选接受接口或自报projectionHash绕过验证。相同bytes的Yjs重复应用幂等，不等于业务副作用幂等；二者分别验证。

持久提交要求实际部署核验WAL及同步提交设置；关闭fsync或异步提交不能支撑同等“已保存”承诺。主库本地耐久不自动等于跨机房零丢失，复制、备份及RPO/RTO另行接受。[PostgreSQL同步/异步提交说明](https://www.postgresql.org/docs/current/wal-async-commit.html)是部署核对依据；锁策略参考[官方锁文档](https://www.postgresql.org/docs/current/explicit-locking.html)。

#### 7.4.2 并发合法性与系统回写

例如A基于版本s添加依赖X→Y，B同时添加Y→X，单独看都合法。先接受A后，B必须基于s+1重新构造并校验最终图，若成环则整笔拒绝。Yjs确定性收敛不能使非法DAG变合法。分组父子关系、删除后悬空边和资产越权同样验证。

生成服务提交带taskId、冻结输入版本、结果资产ID与目标节点身份的系统意图，转成Yjs候选后走同一接受事务；不在另一事务只改节点JSON。布局/新提示词保留，旧结果只能关联其原输入，节点已删除时按任务合同保存历史结果或明确拒绝绑定。接受/重放图变更不自动创建新任务或费用。

### 7.5 数据接口

HTTP提供项目与画布生命周期、快照读取、历史读取，以及素材上传、授权预览和下载。编辑、确认、远端变化与回执查证通过WebSocket传输。所有入口使用统一身份、项目归属与当前授权。

最终asset引用须先取得素材服务成功回执。沿共享提示词需求保留`pending_upload`占位能力：已由服务端校验账号/项目归属的uploadAttemptId、稳定bindingId及目标生命周期可作为类型明确的待上传占位进入权威图，不伪造assetId；占位保存正文位置与用户意图，不代表素材已存在或可生成。上传中的文件字节、派生图、blob URL与本地路径仅在有界内存。尚未建立合法上传身份的临时选择保留为本页意图，不提前写入不可验证占位。

独立编辑和合法占位可自动保存，只有依赖真实资产就绪的绑定转换/生成等待上传。仍有上传待办时可显示“草稿已保存，素材上传中”，不能显示所有输入与素材均完成的无条件“已保存”。重开先查原上传回执；成功则核对当前目标再转换占位，未完成且无原文件时要求重新选择，不承诺恢复本地字节。在尚未发送的意图层按依赖调度，不能重排已经封包的Yjs因果链。占位schema及授权合同须在字段清单和真实接受测试中落定，不把当前接口未支持描述成已实现。

上传失败显示待处理及重试/取消；取消未发送选择只移除暂存意图，取消已接受占位须提交合法新事务。重试复用已确认的素材身份，图绑定的原请求未知时先查证，不重复上传或绑定。上传完成前节点已删除、被替换、切项目或撤权时，迟到结果不得自动绑定或复活目标。临时孤立素材按现有素材回收合同处理，不能为补偿图失败直接删除他人仍引用的资产。异步结果始终核对会话、项目、画布和目标生命周期。

历史恢复、项目复制或服务任务即使由HTTP命令发起，实际图变化仍经统一授权和接受合同；它们不是客户端普通编辑的HTTP后备保存器。用户输入的标题/布局/正文等不得借“生命周期接口”绕过唯一WS编辑通道。

读取错误返回明确错误状态；归档、撤权或版本不兼容保留可解释的恢复入口。分页、报文大小及候选处理资源设定可配置上限。

### 7.6 历史、迁移与恢复

历史检查点保留二进制状态、schema、epoch、修订号及素材引用。历史查看提供只读快照；版本恢复经当前授权和引用校验，原子安装新epoch及其持久基线，保留旧epoch已接受记录与回执，并隔离恢复前的未确认编辑。旧请求只可在当前授权下查证其原结果；曾经accepted不代表被再次应用到新epoch。

存量转换保留原始只读快照，逐项核对节点、正文、格式、引用、关系与生成来源；转换可回读后按画布启用新epoch。旧客户端写入被版本门禁拒绝。备份、回退及故障恢复按真实数据演练验证。

### 7.7 检查点、保留与故障恢复

检查点在明确commitSeq生成并验证可回读后才能用于日志压缩；截断边界同时满足历史版本读取、幂等回执查证、备份和素材保留需求。纯压缩不能更换CRDT身份或epoch；改写历史因果身份的转换必须显式新epoch，并隔离未确认旧更新。回执不因日志压缩一起清除；若产品以后要求有限查证窗口，协议须先规定过期请求拒绝，不能清掉回执后把旧ID重新执行。

故障顺序必须可解释：commit前崩溃无接受；commit后ACK前崩溃能查到同一回执；commit后广播前崩溃由Outbox/追赶补齐；owner失联后的新term阻止旧写者；仅有Yjs状态或仅有投影的半笔写入不允许。数据库备份与对象存储恢复要核对稳定引用，不能拿仅JSON导出当完整协作恢复。

该方案的阈值、历史期限、检查点间隔、RPO/RTO与容量在部署接受前确定。当前既有CAS字段适配记录不作为这些Yjs运行保证已通过的证据。

### 附：Yjs 历史版本数据合同

`canvas.collab_version` 以 `(document_id, revision)` 唯一保存不可变业务快照及其对应 `epoch`、`writer_term`、`commit_seq`、二进制 `state`、`graph_hash`、操作者与原因。schema 版本随 `document_json` 保存，素材身份与引用随图保存；业务历史不代替完整数据库和对象存储备份。保存接受、恢复新 epoch、版本记录及回执处于同一数据库事务。纯因果变化不增加可见历史条目，其原日志与回执继续保留。

`canvas.collab_control_receipt` 用画布、账号、页面会话及命令 ID 定位历史恢复原结果，校验原请求哈希。恢复产生新 epoch 和递增业务 revision，保留当前名称、个人视口以及已分配引用编号的墓碑；不退回编号高水位。历史预览展示原快照，恢复时按当前授权重新校验素材与依赖。明确区分业务历史恢复与运维检查点压缩；本批不启用历史或回执清理。

### 全应用页面内存边界

依据用户新增确认，独立提示词、项目创建/复制、试运行、配置请求与旧画布工作流的业务恢复记录也退出浏览器持久存储。保留原请求ID和完整载荷仅用于当前页面内的查证/重试，账号/空间变更隔离并释放内存；刷新/关页不恢复未确认内容。旧IDB/Storage记录不读回、不上传，不以全量清空同源数据代替退出。登录Cookie、主题与设计10个人视图白名单保持既有用途。
