# 画布数据与接口设计

## 1. 摘要

画布数据库是已保存内容的唯一权威。节点、正文、布局、分组和连线作为一个画布聚合提交；授权、版本、合法性、操作记录和回执必须在同一事务边界内成立。媒体文件存对象存储，数据库保存稳定素材引用。

**2026-10-22：本文按原始需求重新整理，是目标规范。字段、消息和错误示例不表示现有代码已支持；现有实现须在后续逐项对照验证，不能反过来决定需求。** 本轮不执行代码修改、DDL或数据迁移。

## 2. 参与者

创作者编辑及重开画布；项目服务确定归属与权限；画布服务负责读取、编辑提交和恢复；素材服务管理文件与授权；前端呈现待确认状态。维护和实施进度见 [BACKLOG](../../BACKLOG.md)。

## 3. 背景

唯一原始依据为[需求08](../requirement/08-画布数据库持久化与DAG需求.md)：FR-DATA-01～05、DR-DATA-01～07、BR-DATA-01～10、AC-DATA-01～08。范围遵守[需求06最新确认](../requirement/06-画布组件迁入与定制需求.md)，项目生命周期遵守[需求07](../requirement/07-项目与画布创建原始需求.md)。

用户已明确节点入库、退出画布本地持久恢复、WebSocket唯一编辑提交及OT方向。具体表结构、操作字段、容量和保留规则是本文设计决策，不冒充用户逐项指定或生产接受。同步及OT各自只维护自身机制，不另设图状态、保存事务或权威接口。

## 4. 目标

1. 关闭页面、清除浏览器数据或换设备后，恢复全部已确认内容。
2. 重试一次业务效果；被拒绝或事务失败不留下部分节点、边或成功回执。
3. 保存合法、可解释的图；普通标注线不触发依赖执行或计费。
4. 未知历史数据不被静默删除，失败和结果不明均能准确呈现。

不新增独立画布微服务、图数据库、第二套素材服务、浏览器持久草稿、自动DAG执行器或通用插件协议。

## 5. 使用场景

| 场景                   | 必须得到的结果                                       |
| ---------------------- | ---------------------------------------------------- |
| 编辑后重开             | 数据库恢复同一节点身份、内容、布局、素材和关系       |
| 提交完成但回执丢失     | 原操作可查证；不换ID盲目重发，不重复创建             |
| 两端同时修改           | 在同一文档顺序下转换、校验和提交；合法兼容编辑保留   |
| 素材替换或图片处理     | 新素材就绪后原子改绑，节点及连线不变；失败保留原引用 |
| 未授权、归档、未知结构 | 拒绝相应写入，不以空图或裁剪字段后覆盖               |

## 6. 价值

创作内容不依赖浏览器缓存，保存结果可核实，前后端围绕同一数据与操作合同开发；是否稳定由故障和恢复验收证明。

## 7. 方案

### 7.1 服务边界与设计取舍

在项目既有应用服务和关系数据库边界内实现画布聚合，不因旧表或函数存在而默认满足合同。采用“当前状态表＋有序操作日志＋持久回执”：当前状态负责加载，日志负责有界补齐/转换，回执负责确认原请求。无需为首轮另建周期快照系统；数据库备份承担灾难恢复。

编辑唯一写入通道为 WebSocket，依据需求09的明确确认。HTTP负责读取、项目生命周期及素材传输，不提供整图PUT、逐节点旁路PATCH或HTTP保存兜底。历史HTTP写入口和后台回写都必须受同一应用提交边界约束，切换前逐项审计。

### 7.2 节点字段与数据归属

| 信息              | 权威持久字段（目标合同）                                                       | 归属与约束                                                                       |
| ----------------- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| 文档              | id、project_id、schema_version、revision、生命周期                             | UUID稳定；一项目一主画布；名称和归档沿项目，不双向独立维护                       |
| 全部节点          | id、node_type、title、x、y、width、height、z_index、parent_id、content_version | UUID不可随编辑改变；世界坐标有限数；尺寸为正；层级可确定；父节点必须为同画布分组 |
| 文本              | config.text、config.format、config.format_version                              | 正文是持久内容；空字符串合法；格式演进不能把未知结构改成空文本                   |
| 图片/视频/音频    | media_ref.asset_id、必要的不可变版本标识                                       | 指向已完成上传且可用于当前项目的真实素材；预览URL不作身份                        |
| 分组              | 类型、标题、布局；成员通过parent_id表示                                        | 单一归属，无父子循环；不用另存一份成员数组                                       |
| 连线              | id、edge_type、source_node_id、target_node_id、必要绑定                        | 首轮创建annotation；端点同画布、存在；稳定ID；唯一语义关系                       |
| 既有生成/工具内容 | 原类型版本化config、输入版本、结果来源                                         | 保留原完整结构与身份；首轮编辑组件不修改；不能由迟到结果覆盖新输入               |
| 素材元数据        | MIME、自然宽高、时长、对象存储定位                                             | 素材服务持久化；画布可按asset_id重新获取，避免节点重复维护权威值                 |
| 可重建展示值      | 曲线、包围盒、预览URL、渲染顺序                                                | 从持久字段或素材服务重建；不作为节点业务内容存第二份                             |
| 会话状态          | 选中、悬停、光标、拖动预览、未确认队列                                         | 仅内存；最终落点必须提交。个人视口暂为会话状态，重开适配内容，不写共享图         |

媒体DTO的media_ref映射到可约束的media_asset_id/media_version列；素材ID若已保证内容不可变，可不另造版本体系，否则版本不可省略。正文format首轮明确plain或受支持的markdown；未知格式只读保护。

节点类型使用版本化的封闭联合类型。新增类型必须先补完整字段、操作和验收清单；不是允许任意JSON进入config。历史未知类型或字段原样保留并只读保护；客户端不能把未知节点过滤掉后保存整图。后续若要求跨会话恢复个人视口，采用用户维度的服务端偏好，不借共享视口同步他人的平移缩放。

### 7.3 数据库模型与约束

以下是逻辑表设计，不是可以直接执行的迁移SQL；物理变更须在目标合同接受后另做存量差距核对。

| 逻辑表              | 关键列                                                                                                                                      | 主键、约束及索引                                                                                                    |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| canvas.document     | id、project_id、schema_version、revision、created_at、updated_at、deleted_at                                                                | 主键id；revision正数；项目归属外键；主画布唯一归属由项目合同保证                                                    |
| canvas.node         | document_id、id、node_type、title、config、media_asset_id、media_version、x/y/width/height、parent_id、z_index、content_version、deleted_at | 主键(document_id,id)；父节点复合外键；按document_id及有效状态读全图；素材引用可校验；有限数、正尺寸与字段schema校验 |
| canvas.edge         | document_id、id、edge_type、source_node_id、target_node_id、binding、deleted_at                                                             | 主键(document_id,id)；两个端点复合外键；有效语义键唯一；按document_id读取，按两端点查询删除影响                     |
| canvas.operation    | document_id、revision、actor_id、client_id、op_id、base_revision、operation_version、canonical_operations、effects、created_at              | 主键(document_id,revision)；同一接受操作唯一；保存规范操作与撤销必要前像，不记录临时媒体URL                         |
| canvas.save_receipt | actor_id、op_id、document_id、request_hash、status、result_revision、response、created_at                                                   | 主键(actor_id,op_id)；accepted/rejected终态；相同ID不同文档或body拒绝；用于请求查证                                 |

成员/端点“未软删除”、父子环、重复语义绑定、资产授权及DAG不能只靠外键：在持文档写锁的同一事务中校验最终候选图。软删除记录的重用/恢复须有明确操作，普通创建不复用旧ID。节点删除只处理节点和可编辑关系，不删除素材文件。

文档级revision表示接受顺序；节点content_version标识内容或素材变更，用于引用及迟到结果绑定。纯移动不改内容版本。revision建议使用64位整数，线上JSON用十进制字符串避免JavaScript精度损失；这是目标合同，实施时需显式版本化，不能直接混用旧数值DTO。

### 7.4 读取与HTTP接口

统一以`/api`为前缀，采用当前身份会话和空间/项目权限；服务端从文档反查归属，不信任客户端提交的project_id。无访问权限与不存在返回一致的不可访问结果，避免泄漏私有对象。私有响应不得进入公共缓存。

| 接口                                                 | 输入                                          | 输出与职责                                                                   |
| ---------------------------------------------------- | --------------------------------------------- | ---------------------------------------------------------------------------- |
| GET /projects/{project_id}/canvases                  | 项目身份                                      | 可访问画布摘要；项目主画布由项目生命周期创建，不在页面加载时重复创建         |
| GET /canvases/{canvas_id}                            | 文档身份                                      | 同一revision的完整快照、schema_version、权限及只读原因；失败不能返回伪造空图 |
| GET /canvases/{canvas_id}/live（升级WebSocket）      | 会话；首包join                                | 编辑、回执查证、连续变化；消息见设计15                                       |
| POST /projects/{project_id}/media/uploads            | Idempotency-Key、文件及素材服务要求的真实确认 | 稳定素材ID与状态；不能在画布层绕过上传服务校验或代用户伪造确认               |
| GET /projects/{project_id}/media/{asset_id}/preview  | 项目和素材ID                                  | 当前授权的展示信息；URL失效重新获取，不改节点引用                            |
| GET /projects/{project_id}/media/{asset_id}/download | 项目和素材ID                                  | 授权原件；下载与节点删除互不替代                                             |

画布重命名、归档和删除沿[项目生命周期设计13](13-项目与画布创建及一致性详细设计.md)，避免画布名和项目名出现两个独立写源。素材库选择需要先取得对当前项目有效的素材身份；条目ID、文件地址不能当作asset_id。

快照示意（目标DTO节选，未列字段并非可以删除）：

```json
{
  "id": "11111111-1111-4111-8111-111111111111",
  "project_id": "22222222-2222-4222-8222-222222222222",
  "schema_version": 1,
  "revision": "12",
  "permissions": { "read": true, "write": true },
  "read_only_reason": null,
  "nodes": [
    {
      "id": "33333333-3333-4333-8333-333333333333",
      "node_type": "text",
      "title": "想法",
      "config": {
        "text": "第一段正文",
        "format": "plain",
        "format_version": 1
      },
      "x": 100,
      "y": 80,
      "width": 320,
      "height": 200,
      "parent_id": null,
      "z_index": 0,

    }

```

数据库读取必须形成一致快照，不能分别查询后拼接不同时刻的文档、节点和边。HTTP预览加载不授予发送权限；WebSocket ready及最新授权决定正式提交权限，不能把两个来源的不同revision混成一份图。

### 7.5 编辑操作合同

一个提交包含op_id、client_id、operation_version、base_revision和operations；身份由会话确定。op_id为每次逻辑编辑新建的UUID，重试不变；client_id仅用于关联客户端，不授予权限。整个批次原子接受或拒绝。

| 操作语义             | 最小内容                                   | 约束与结果                                                           |
| -------------------- | ------------------------------------------ | -------------------------------------------------------------------- |
| create_node          | 完整类型化节点                             | 新UUID、有效内容、授权媒体、合法父节点；不接受服务端任务字段伪造     |
| set_node_fields      | node_id、有限字段补丁                      | 只改标题/布局/层级等允许字段；不支持任意JSON Patch或整节点覆盖       |
| edit_text            | node_id、文本操作                          | 以基准正文和明确位置单位生成OT操作；格式/引用规则见设计17            |
| replace_media        | node_id、expected_media_ref、new_media_ref | 同媒体类型、当前授权、比较旧绑定；保留节点和边身份，增加内容版本     |
| delete_node          | node_id                                    | 原子清理可编辑关联边与分组归属；有受保护依赖时明确拒绝或要求显式解除 |
| connect / disconnect | 稳定edge_id及端点/语义                     | 标注线不创建任务，不写生成输入；重复语义连接明确拒绝                 |
| group / ungroup      | 组ID、成员ID与需要的最终布局               | 原子维护父关系；取消分组保留成员世界坐标；组移动含成员最终位置       |
| undo                 | 目标已接受op_id                            | 只撤销本人贡献；受保护关系或历史不足时明确拒绝                       |

分组、拆图或批量导入若超过单批限制，不能拆成数次提交后谎称一个原子操作。应在操作前提示范围并由用户分批；已上传但未加入画布的素材仍归素材服务。后续如有“大批原子导入”需求，再单独设计，首轮不预建作业系统。

### 7.6 保存事务与幂等

1. 解析版本、大小和结构，验证会话；拒绝未知协议和非法操作，不执行任何外部副作用。
2. 开启事务，重新验证项目/画布读写权限与生命周期。串行化同一操作者op_id，并查询回执；同body回放原结果，不同body返回op_id_reused。
3. 锁定文档当前版本；读取base_revision之后连续历史。需要转换时按设计17转换；历史不足返回明确拒绝，不能直接将旧操作应用到新快照。
4. 一次求值生成候选图；校验类型、全部字段、分组、边、DAG、素材引用及版本。素材权限和可用性必须与提交之间具有可证明的一致性，不能仅依靠前端上传成功。
5. 接受：写节点/边/内容版本、revision+1、规范操作和必要前像、accepted回执；在同一事务提交。拒绝：不写图和成功日志，只持久化确定的rejected回执。基础设施故障回滚，不伪造终态。
6. 事务成功后才返回ACK与发出变化提示。通知可以丢失，客户端可从数据库版本与日志补齐；广播失败不能撤销已提交事实。

请求hash按规范化JSON及文档/语义版本计算，排除无意义键序差异，包含全部影响编辑的输入；跨版本仍保留原请求解释能力。不能安全识别请求身份时返回协议错误，不伪造回执。

素材元数据与画布处于同一数据库事务边界时，对被引用资产的状态/版本及项目授权做事务内校验，并与回收操作使用一致的锁/引用保护规则。若未来素材服务独立存储，必须先设计可验证的授权绑定/保留协议，不能以远程读取后再提交冒充原子校验；首轮不为此拆服务。

归档、撤权与保存必须有明确串行化边界：同一权限版本/项目生命周期锁下判断接受顺序，不能在事务外先授权后无限期写入。事务期间不调用供应商、不上传大文件、不做耗时图片处理。

### 7.7 素材与图提交的边界

先上传或处理文件，取得不可变素材身份；再创建或替换节点引用。替换通过expected_media_ref比较旧绑定，冲突时保留当前服务器引用及本地新素材回执供用户选择，不能默默覆盖别人刚替换的素材。

上传成功、图提交失败并非回滚整个上传：素材仍可在所属素材库发现并再次使用。图删除不删除素材；历史撤销/已执行任务引用的文件由素材保留规则保护。仅凭本页“未用到”不能物理清理对象。预览过期、加载失败和素材被回收是不同状态，均不将节点内容改为空。

### 7.8 图合法性与DAG

| 关系                   | 表达                   | 校验和删除语义                                                            |
| ---------------------- | ---------------------- | ------------------------------------------------------------------------- |
| annotation             | 用户整理思路的可视连线 | 可以构成视觉环；禁止自连、非法端点和相同方向/语义重复线；删节点时同时移除 |
| parent                 | 分组归属               | 父为同画布group，最多一个父，不成环；取消分组解除归属并保留世界坐标       |
| input                  | 当前可执行输入依赖     | 只有业务明确声明的节点/端口绑定进入依赖子图，禁止跨画布、自环和有向环     |
| reference              | 素材引用或节点引用     | 直接asset_id引用不进入DAG；声明为当前节点输入时才按input规则校验          |
| promote / 历史结果来源 | 已执行输入与输出的溯源 | 冻结版本和来源，普通编辑不可改写，不因UUID相同自动当成当前依赖            |

首轮普通连线只创建annotation。业务依赖只由所属业务入口写入，经相同事务校验；DAG拓扑只用于合法性与依赖解释，不自动运行任务。并发两条依赖各自合法但合并成环时，仅接受仍合法的提交，另一提交明确拒绝且不部分落库。未知旧关系不得猜测转换为annotation。

### 7.9 失败与恢复合同

| 结果                                                | 服务端语义                  | 客户端行为                                                          |
| --------------------------------------------------- | --------------------------- | ------------------------------------------------------------------- |
| accepted                                            | 已提交及稳定revision        | 按回执与权威变化确认；重复ACK不重复应用                             |
| rejected                                            | 持久业务拒绝，带op_id和原因 | 停止自动重发；保留本页意图供对照，用户修订后用新ID提交              |
| receipt_not_found                                   | 当前未发现原请求结果        | 不等于已拒绝；恢复当前版本与权限后，只能按原ID、原body再次查证/提交 |
| dependency_unavailable / 断线 / 超时                | 可能结果未知                | 待确认；不能换ID、改body或显示已保存                                |
| history_unavailable                                 | 无连续转换基线              | 查证未决回执，取新快照；不能盲目重放旧意图                          |
| schema_unsupported / graph_read_only                | 不能安全解释内容            | 保留内容并只读；不能读取失败后创建空图                              |
| source_unavailable / media_conflict / invalid_graph | 素材、绑定或图不合法        | 说明问题对象；不部分提交，不静默删内容修图                          |
| forbidden / session_invalid / not_found             | 无当前权限或不可访问        | 停止提交及私有推送，退出或重新验证身份                              |
| op_id_reused / unsupported_operation                | 请求身份复用或操作不支持    | 明确拒绝；不得被映射成可无限重试的基础设施错误                      |

错误响应含稳定code、关联op_id和允许暴露的对象位置；不输出数据库内部错误或他人资源信息。HTTP读取采用对应401/403/404/422/503，WebSocket用error消息承载；业务拒绝通过终态回执返回，不伪装为成功空图。

### 7.10 容量、历史与运维

首轮建议以2000节点、4000边、每批100个操作和1MiB上行消息作为有界合同候选；必须用代表性正文及混合素材元数据压测后确认，不能把限制数字当作流畅性承诺。服务端限制检查在事务前及转换后都有边界；队列、慢客户端及历史补齐另见设计15、17。

首轮不自动删除画布存续期内的回执和必要操作历史；必须监测增长。后续启用历史压缩/保留期限之前，先定义最早可补齐版本、不可再撤销边界与过期客户端拒绝规则，不能删除回执后将旧请求当成新请求再次执行。项目删除遵循资料保留政策，不由画布自行物理清库。

观测提交耗时、持久ACK耗时、远端可见延迟、拒绝原因、回执查证、历史缺口、队列大小和慢连接；记录文档/操作ID而非正文或凭据。应用进程重启及网络丢包不应丢失已提交事务；数据库灾难RPO/RTO、备份周期及容量目标必须用部署和恢复演练确定，不承诺任意灾难零丢失。
