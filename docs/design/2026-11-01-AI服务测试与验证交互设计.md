# AI 服务测试与验证交互设计

状态：2026-11-01用户确认落实设计与实现。唯一原始来源：需求04 SRC-AI-33；依赖已确认SRC-AI-26～32、CR-ADMIN-01～02。CC Switch事实见对应调研，三层测试与新交互均为本项目建议。用户已授权实现；真实供应商调用、提交与发布仍按当前会话授权执行。

## 1. 摘要

将分散的连接检查、模型验证、媒体试运行组织为同一“测试”工作区；在供应商旁快速进入，分别回答“服务地址能否连接、当前凭据能否访问指定只读接口、选定模型/模式是否实际可用”。三种证据独立显示，不用一个绿色状态概括全部结论。

## 2. 参与者

平台管理员手动发起测试、轮换凭据和启用；创作者消费既有发布结果，不看Key或管理员测试记录。后台worker执行供应商请求，API和页面只传凭据引用。产品确认人为用户，未知具体职能不补造。

## 3. 背景

当前列表测试入口不突出；详情概览里混合密钥配置、模型验证和折叠只读检查，音乐再跳模型管理。API Key标签也不适用于AK/SK。CC Switch当前是更多菜单发起地址连通检测，不验证Key/模型；旧流式检查不是当前实现，不能直接搬作Key有效性方案。

沿用现有详情Sheet、Tabs、Field、Badge、Select、Alert、Dialog、回执与operation/billing；保留已确认“保存后关闭接入弹窗、不自动验证”“验证一个可启用所选模型，但其他模型不冒充逐项验证”的首次接入合同；媒体模型继续保留真实逐模式试运行要求。详细设计必须区分建议接口与现有可调用接口。

## 4. 目标

- 入口可发现：桌面与手机均从服务行直接进入，不再先寻找折叠控件；打开不发供应商请求。
- 测试可解释：网络、鉴权、模型各有状态、范围、时间与下一步；保存和启用状态独立。
- 成本可控：只读与真实调用分区；真实调用显式确认，未知结果只恢复原任务。
- 证据可信：绑定服务端冻结版本；更换Key、端点、模型或发布后，旧结果不显示为当前通过。
- 全站一致：管理主导航仍与头像同排；测试作为服务详情局部页签，不增加全局管理主标签。

非目标：批量真实模型压测、供应商排行、自动定时测试/健康切换、任意URL测速、恢复开发试验、将所有模型自动改成已验证。

## 5. 使用场景

US-TEST-01：管理员从服务列表直接测试已保存连接，确认失败来自网络、凭据还是模型。
US-TEST-02：保存或轮换Key后，管理员主动检查当前凭据，旧验证记录保留但不参与当前启用判定。
US-TEST-03：管理员验证指定模型与模式，看到费用说明、真实结果与明确范围，再选择启用。
US-TEST-04：管理员在断网、关闭面板或刷新后恢复同一任务，避免重复付费。
US-TEST-05：音乐/语音管理员在相同位置看到不支持只读鉴权的原因并进入对应真实验证，不被误报Key无效。

## 6. 价值

缩短“录入Key后去哪里测试”的路径；将HTTP可达与真实可用分离，减少无效重试、错误轮换和付费误操作。保留统一入口，同时不抹平语音、视频和音乐的协议差异。

## 7. 方案

### 7.1 入口方案与取舍

A：完全照CC Switch只在更多菜单放检测，改动小但难发现，也不足以解释三种证据。B：列表测试快捷入口进入现有详情Sheet的“测试”页签，能复用状态、配置和历史，推荐B。独立全局测试页面会增加导航和上下文切换，本轮不采用。以上为设计推荐，待用户评审，不记录为用户已逐项选定。

| 位置              | 设计                                           | 行为与条件                                                                                                                       |
| ----------------- | ---------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| 服务列表桌面/手机 | 连接名称可打开详情；操作列保留“测试”和更多     | 测试打开同一Sheet并选中测试页签，**不立即调用**。更多保留查看详情、配置、启停等既有维护；测试不是图标隐藏操作                    |
| 详情Sheet         | 概览 / 测试 / 凭据 / 高级配置                  | 仅局部Tabs；将API Key改称凭据，音乐展示AK/SK。概览显示摘要与“查看测试”入口；原概览模型验证和折叠检查迁入测试页签，不保留重复按钮 |
| 凭据保存后        | 原位显示“已配置”和次要“检查凭据”               | 只导航到测试页签；不自动发起。网络未测也可直接鉴权，失败时再区分原因，不强制三步向导                                             |
| 接入弹窗          | 仍只负责选择服务、填凭据、选模型、保存         | 保留保存完成自动关闭和恢复焦点；成功Toast可含“测试”动作，Toast消失后列表仍能找到入口                                             |
| 模型管理          | 模型行或发布详情的“验证”                       | 进入同一测试面板，冻结服务、模型、模式、release上下文；高级发布保持原试运行入口契约，不能把验证请求指向另一个版本                |
| 批量选择          | 原有检查限定为只读；明确命名“检查凭据（只读）” | 不批量触发真实模型调用；暂不新增跨服务测试全部或自动收费能力                                                                     |

建议URL在现有`?connection=<id>`基础上扩展`view=test`及可选`model=<id>&release=<id>&mode=<mode>`；服务端重新验证归属，不信任URL提供的版本或权限。已有旧链接仍打开概览。关闭Sheet仅移除其拥有的参数，不清空查询词、分页或页面筛选；模型页返回恢复原行焦点。

### 7.2 测试页信息层级

1. 页头沿用Logo、连接名称、启用状态与配置状态；不显示密钥、尾号或复制按钮。
2. 固定三块内容依次为“网络连通”“凭据鉴权”“模型验证”，每块一行标题、状态与当前动作，必要时一行说明。
3. 模型验证块内：能力类型/模型/模式按需出现，普通文本只选模型；音乐选择歌曲/纯音乐，视频显示具体输入模式。字段默认继承该模型合法验证模板。
4. 音乐及正式release试运行在模型/模式后展开“验证输入”：扣费项目（必选）、该项目预算/余额、模型要求的参考素材及合法时长等参数。沿用已有ProjectPicker与受授权素材选择，不自动使用上一个项目或拿管理员素材跨项目复用。“准备验证”要求项目、必需参数、授权素材与必要预算上限齐全，点击后生成报价；“确认并验证”要求取得有效报价、预算准入通过且输入未变化。修改项目、模型或输入会使报价失效，需重新准备；缺项原位提示。简单文本首次接入不强行增加项目字段。
5. 下方“最近记录”默认收起，展开显示最近3条、更多分页20条；记录时间、类型、模型/模式、结果、耗时与查看详情。保留项目现有审计保存策略，不为此次设计新增清理期限。
6. 仅当满足现有启用合同才出现“启用所选模型”或“启用当前发布”，与测试按钮分开。旁注明示证据范围，不能因为一个成功样本显示“所有模型已验证”。

桌面沿用520px Sheet，24px内边距和现有语义颜色/Geist。手机为整屏Sheet（320/390px），16px内边距，44px触达；模型Select与操作按钮保持同一行，长名称截断且保留可访问名称。正文独立滚动，底部必要动作保持可达，不能遮住结果与说明。

### 7.3 三层检查合同

| 检查     | 发请求与凭据                                                          | 成功含义                                                                   | 不能证明                                                  |
| -------- | --------------------------------------------------------------------- | -------------------------------------------------------------------------- | --------------------------------------------------------- |
| 网络连通 | worker向允许的固定供应商地址发无凭据GET，只读取响应头，不提交模型请求 | 收到HTTP响应；显示服务端响应头耗时、HTTP状态和测试时间                     | Key、模型授权、余额、生成质量、所有API健康                |
| 凭据鉴权 | 供应商提供的已适配只读接口，用当前保存的凭据引用                      | 指定接口返回已识别的合法成功响应；记录探测范围                             | 所有模型均可用、余额充足、图片/视频权限、后续任务必然成功 |
| 模型验证 | 显式选择精确模型/模式，用冻结配置执行一次合法最小样本                 | 同步文本/图片/音频得到有效结果；异步仅先证明任务受理，最终完成后才证明产出 | 其他模型/模式、大负载稳定性、无限期有效性                 |

网络探测建议沿用CC Switch的8秒单次超时、6000ms较慢阈值，只对超时最多重试1次，并显示总尝试次数；DNS/TLS/拒绝立即返回。该阈值是诊断提示，不承诺SLA，不改变正式任务路由/启用状态。凭据只读检查建议15秒、无自动重试；真实调用沿精确模型/任务的既有时间限制，不套用8秒探测超时。

网络HTTP401/403/404/5xx仍可达，必须附“只表示地址可达”；500不能作为鉴权成功。跳转不跟随，禁止把凭据带到新地址。空HTML/代理页或不匹配JSON不能判凭据成功。空模型目录可显示“鉴权通过，未发现模型”，不能伪造权限失败。

### 7.4 五类服务差异

| 服务     | 凭据鉴权                                                                 | 模型验证与说明                                                                                           |
| -------- | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------- |
| OpenAI   | 当前官方`GET /v1/models`，匹配模型目录响应                               | 当前文本走Responses；图片用Images，单张合法尺寸；列表成功不等于生成配额/模型权限                         |
| DeepSeek | 当前官方`GET /models`                                                    | 文本Chat API；使用该连接可用型号，不能拿方舟托管DeepSeek的Key互换                                        |
| 火山方舟 | 当前实现探测视频任务列表，只能证明该接口访问权限，展示“检查范围受限”     | 文本、图片、视频分别选具体模型/模式；只读403不能笼统称Key无效；需要更通用探测接口时先核官方合同再实现    |
| 豆包语音 | 当前适配未提供独立只读鉴权，显示“不支持只读鉴权”，动作改为“验证语音模型” | TTS短文本与合法音色；Seed-Audio独立真实模式。按所选接口发送X-Api-Key、资源ID等，不把网络可达说成凭据通过 |
| 火山音乐 | 当前适配未提供独立只读鉴权，明确AK/SK与服务开通要求                      | 歌曲/纯音乐分别沿发布试运行、报价、确认、任务查询和结果归档，时长使用模型合法最小值，不强制几秒无效样本  |

对后两类不构造故意错误/昂贵模型请求冒充免费Key检查，也不将“不支持只读检查”标红为验证失败。

### 7.5 真实验证与费用

点击“准备验证”先展示本次模型、模式、模板摘要、输出上限/图片数量/媒体时长及费用说明，再明确“确认并验证”。模板参数来自已审核模型版本，不向普通管理员暴露任意请求JSON或任意地址。普通接入无需手填价格，维持已确认的轻量接入合同。

- 若已有可信报价，显示币种、估算/预算和计价范围；供应商费用与平台积分分开。
- 若尚无供应商估价，显示“费用未估算，服务商按实际用量计费”，不显示¥0、免费或虚构金额上限；显式确认才派发一次。模型输出上限不是精确费用上限。正式发布/媒体试运行若既有合同要求预算或报价，则继续强制，不以该提示绕过。
- 测试文本如“请只回复OK”，但Token上限由该模型合法模板决定，不能为追求低耗把推理预算设得过低，再将未完成响应误报为Key无效。
- 图片只生成1张；语音用短合法文本；视频与音乐按模型最小时长/输入限制。TTS音色权限和音乐模型开通失败分别提示。
- 本次不做自动测试全部；换模型或模式后不自动调用，必须重新确认。控制台Key轮换后不能自动重试旧任务。

### 7.6 状态与恢复

三种检查分别维护结果，不用单个success布尔值驱动整页绿色。保存、凭据撤销、连接启用、模型发布亦各自独立。

| 场景                | 状态/主要文案                             | 可用操作                                                                                                                                            |
| ------------------- | ----------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| 未保存凭据          | 未配置；网络仍可查                        | 配置凭据；鉴权/模型验证禁用                                                                                                                         |
| 初次进入            | 网络未检测 / 凭据未检查 / 模型未验证      | 分别显式执行，不自动串行三步                                                                                                                        |
| 只读进行中          | 检查中，显示Spinner                       | 同种检查禁用，其他动作按并发规则控制                                                                                                                |
| 网络失败            | 无法连接，区分DNS/TLS/拒绝/超时           | 检查网络；允许重做只读检测                                                                                                                          |
| 网络收到401         | 网络可达；凭据尚未检查                    | 检查凭据，不把401当整页通过                                                                                                                         |
| 凭据通过            | 鉴权通过，注明接口范围和时间              | 准备模型验证；不自动启用                                                                                                                            |
| 凭据不支持          | 不支持只读鉴权（中性）                    | 引导真实模型验证                                                                                                                                    |
| 认证/授权异常       | 凭据被拒 / 权限不足 / 地域限制 /IP限制    | 查看脱敏原因或配置凭据，不能全部提示“Key错误”                                                                                                       |
| 费用异常            | 余额不足 / 额度不足（凭据不因此变成无效） | 前往已审核控制台链接处理；不自动重发                                                                                                                |
| 限流                | 请求过于频繁，支持时显示可重试时间        | 尊重Retry-After；不自动重发收费POST                                                                                                                 |
| 模型不存在/参数错误 | 模型不可用 / 验证配置不匹配               | 修改模型或配置，不建议无关换Key                                                                                                                     |
| 异步已受理          | 已受理，仍在生成                          | 查询原任务，不写“生成通过”；首次接入按现有accepted门槛可启用原所选模型，但标注其他模型未逐项验证。音乐正式release仍须逐模式完成及归档后按原门槛启用 |
| 调用结果未知        | 待确认；保留原请求                        | 只查原回执/任务，不显示重新验证；不可查询的同步POST转待核查，不伪造恢复成功                                                                         |
| 明确完成            | 已通过，显示模型/模式、时间、总耗时       | 查看结果；另点启用（按原合同）                                                                                                                      |
| Key/配置/模型已变更 | 原记录已过期（历史可看）                  | 明确验证当前版本，旧结果不得用于启用                                                                                                                |
| 权限撤销            | 无权继续查看/操作                         | 卸载敏感详情；后台不再派发新请求                                                                                                                    |

真实验证发起后关闭Sheet只停止当前视图等待，任务可在后台完成；若有“停止等待”必须明确不是取消供应商任务。重新打开或刷新查询原ID，同请求重复点击只产生一次派发；已成功不因Toast过期消失。只读网络错误不会抹掉先前模型成功历史，当前摘要标明时间和版本，不假定无限期可用。

#### 同步请求无法查询时的人工核查

“待确认”展开恢复说明，显示脱敏请求标识、发起时间及当前凭据版本引用，并提供已审核的供应商控制台链接。可复制请求标识，不复制密钥、私有URL、提示词或原始响应。管理员核对供应商账单/请求记录；有可验证回执时仍经既有结果归档与核对流程处理，不凭一句人工确认伪造模型通过。

若供应商不提供可查询结果，提供次要“结束追踪并保留未知”操作，要求记录核查说明，并明确“旧请求可能已产生费用，新验证可能再次收费”。该操作仅确认停止追踪，旧记录依然为unknown，不改为失败或通过，不释放原任务预算、不启用模型、不删除记录。只有当前账号权限、并发、现有预算准入均允许且用户再次显式确认重复费用风险，才可创建关联旧check_id的新request_id；不能复用旧幂等键。若既有工作流要求人工对账/结算，必须先完成它，按钮不能绕过。

### 7.7 结果语义与时延

只读延迟命名“服务端响应耗时”，不称模型速度。真实同步请求显示总耗时；当前非流式执行不展示“首Token延迟”或tokens/s，避免从HTTP头时间造指标。异步分别记录提交受理耗时、最终完成时间；不能用受理耗时作生成耗时。

服务端按供应商错误体的稳定error.code/type分类，不单看HTTP。至少区分OpenAI429的限流/余额/项目及组织额度、401认证/IP等、403权限/区域等。仅记录脱敏错误码、HTTP码、request-id等，不回显Authorization、Key、原始响应体、签名、私有URL或提示词素材。

### 7.8 数据、接口与兼容

实现合同保留provider_check和operation回执为事实来源，复用现有路径；网络小请求不创建收费operation。明确区分轻量固定模板验证与正式release试运行，后者保留项目、预算、参数及授权素材。

- 网络检测使用`POST /admin/providers/:id/checks/reachability`，不需要credential_id；原credential-test路径默认保持只读鉴权语义。两者均持久化接受回执及Outbox，由 PostgreSQL 工作记录与 Go worker 执行。
- 模型验证继续使用现有onboarding/model-access及release trial流程。面板统一展示不等于底层将音乐绕到轻量文本验证；按能力契约选择执行器。
- 检查记录至少有check_id、kind、provider_id、config_version_id、凭据版本引用（可空）、模型/版本/模式/release引用（可空）、request_id、status、网络结果、鉴权结果、模型阶段、错误分类、HTTP码、响应耗时、起止时间、upstream_task_id、可恢复动作。
- 只读记录不含Key且不更改启用状态。派发前重新核验管理员权限、当前配置与凭据状态、预设紧急开关；按供应商已有并发/限流调度。同一连接/版本/类型运行中时返回已有任务，不靠按钮disabled保证唯一。
- 记录接口分页读取当前管理员可访问结果；失败/未知不能因刷新变成未测试。旧数据按实际kind迁移显示“历史连接检查”或“历史模型验证”，缺失字段显示未知而非补造证据。
- 证据变更失效按版本匹配；不擅自增加“24小时后自动失效”之类新授权规则。移除模型验证重复UI不删除历史记录，也不改变已有价格/任务/发布状态。

## 8. 实施与验收

### 8.1 验收场景

- TS-TEST-01：列表桌面/320/390px打开测试页签，焦点进入标题；关闭恢复原行测试按钮，主导航与头像仍同排/共享窄屏布局。
- TS-TEST-02：进入面板、切换模型、保存Key都没有上游调用；无凭据只允许网络检测。
- TS-TEST-03：HTTP401/403/500均只证明网络可达；TLS失败不能通过。只读JSON不匹配不得标鉴权成功。
- TS-TEST-04：OpenAI/DeepSeek只读通过而模型权限/配额失败，正确区分；方舟检查注明权限范围。
- TS-TEST-05：语音/音乐显示只读不支持且仍可按各自合同进入真实验证；音乐AK/SK不变成Bearer。
- TS-TEST-06：收费确认展示真实范围，未估价不标免费；媒体/正式发布的报价预算限制保持。
- TS-TEST-07：同一请求并发点击、刷新、断线只有一次付费派发；未知同步POST不自动重发，音乐按原任务查询。
- TS-TEST-08：只验证模型A，B仍显示未逐项验证；首次接入启用与正式发布模式验证继续按既有不同合同判定。
- TS-TEST-09：轮换Key或改配置使旧证据失效；过期结果不能覆盖新版本状态；撤权卸载详情且后台拒绝新派发。
- TS-TEST-10：非流式不出现首Token速度，异步受理不写完成，结果可按具体ID恢复；键盘、读屏live状态和长名称可达。
- TS-TEST-11：音乐/发布试运行缺少项目、预算上限或所需参考时不能准备；输入齐全可先准备报价，无有效报价/预算准入不得确认。输入变化使报价失效，切换项目清空不再授权的素材。
- TS-TEST-12：同步未知无法查询时结束追踪仍保留unknown且不释放预算；新请求单独确认重复费用风险，不能把人工说明当通过证据。

### 8.3 实现接口与恢复绑定

| 操作               | 接口（省略/api前缀）                          | 合同                                                                                   |
| ------------------ | --------------------------------------------- | -------------------------------------------------------------------------------------- |
| 当前证据和最近记录 | GET /admin/providers/:id/checks?offset=0      | 固定20条分页；当前配置/凭据/模型版本独立匹配                                           |
| 无Key网络探测      | POST /admin/providers/:id/checks/reachability | 固定审核地址GET，不跟随重定向；8秒超时，仅超时最多重试一次                             |
| 服务所属模型       | GET /admin/providers/:id/test-models          | 区分轻量验证与正式release试运行                                                        |
| 读取原异步任务     | POST /admin/provider-checks/:id/query         | 原配置、模型版本、TaskID和原Key绑定；允许仍供恢复的draining Key；上游只GET，不重新提交 |
| 结束同步未知追踪   | POST /admin/provider-checks/:id/end-tracking  | 核查说明必填，结果仍unknown；不释放预算或伪造启用证据；后续新请求关联旧check           |
| 项目预算快照       | GET /projects/:pid/budget                     | 复用项目授权；快照不代表报价或预算预留                                                 |
| 正式试运行恢复     | GET /admin/model-releases/:id/trial-recovery  | 当前管理员本人最近已接受请求；按原operation读取，确认键稳定；刷新不创建新任务          |

所有写入使用Idempotency-Key。新的只读与轻量模型检查共用供应商并发/速率计数；accepted与未结束unknown持续合并，避免重复生成。正式release试运行接受草稿或当前有效的active release，继续由operation/billing裁决并发、报价、确认与归档。历史任务查询不会更新当前Key的鉴权摘要，也不会变成当前模型的启用证据。权限、预设紧急开关、已停用Key和已删除对象仍限制操作。

轻量验证按保存的模型与版本执行固定短模板，不是自定义参数或全部模式验收；正式试运行按冻结版本模式/参数与素材表单，费用确认显示实际准备的输入与上限，恢复时读取原operation的冻结摘要。只读鉴权限时15秒；OpenAI/DeepSeek须匹配模型列表JSON，方舟须匹配任务列表JSON；HTML、未知JSON或错误体不能被标为鉴权成功。

### 8.4 极简呈现修正（2026-11-01用户追加）

默认视图只保留三类测试名称、状态、当前动作与模型选择。网络和凭据改为紧凑行，以分隔线代替重复卡片外框；去掉每块重复原理说明、尚未检测/尚未检查等与Badge重复的文字，以及页底自动调用声明。服务列表标题下的泛化副标题一并移除。

HTTP状态、耗时、尝试次数、时间、版本与候选模型收在默认折叠的“检测详情”，有实际记录时才出现，原任务查询和历史证据仍可访问。网络可达不代表Key有效的范围说明仅在详情内呈现。未配置时凭据行直接给“配置”动作，不叠加一个禁用检查和第二个配置按钮。

模型区保留选择及“准备验证”，将一般收费提示集中到确认弹窗；缺少凭据由“未配置”状态及配置入口引导。已受理/未知/错误的必要状态与恢复动作保留，成功不再反复解释已验证范围。模型完成时间与耗时按需收在验证详情。确认弹窗只保留本次范围、费用未知/可能收费、未知不自动重发及重复费用风险，不削弱原有确认和预算准入。

实现决策：采用渐进展示，保留原面板及组件，避免新增“简洁/专业”开关；纯文案与布局优化，不修改服务端、供应商协议、幂等、计费或授权。更新既有13个Figma状态，再按同一结构修改代码，浏览器核对桌面、390/320px及详情展开和费用取消。
