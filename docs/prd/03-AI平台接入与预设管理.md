# PRD：AI 平台接入与预设管理

更新：2026-10-14。使用 pm-execution 的 create-prd 方法整理。用户已确认平台管理员统一配置 Key、首轮火山引擎和 OpenRouter、沿既定方案细化；本次仅文档。下列交付细则待评审，未实现、未迁移、未进行真实供应商接受。

文档链路：[需求03](../requirement/03-AI平台接入与预设管理需求.md) → [设计06](../design/06-AI平台接入市场调研与架构设计.md) → **PRD03** → [计划08](../plan/08-AI平台接入与预设管理实施计划.md)。详细 FR/BR/DR/NFR/AC 以需求为唯一来源，机制和接口以设计为准。

## 1. 概述

为平台管理员提供可管理、可验证的 AI 平台配置，使火山方舟和 OpenRouter 能通过内置预设添加 Key、配置模型并开放给创作者。创作者使用已启用模型和明确的参数/费用，无须了解平台请求协议，也不能接触平台 Key。

平台预设、账号连接、模型版本和上线发布组合分别管理，让新增模型、调整价格、轮换 Key 与历史任务恢复有明确边界。

## 2. 背景

现有后端已有供应商、加密凭据、模型/价格版本和任务活动合同，前端供应商与模型页面仍为未开放状态。已有代码不能证明火山或 OpenRouter 的真实执行链路可用。来源和具体缺口见设计第4节。

本次先把配置与接入工作定义完整，再实施。低配置负担参考 CC Switch 的预设方式，但织光还需处理多用户权限、素材引用、长期视频任务和费用。市场比较保留在设计第2节，PRD 不重复竞品排名。

## 3. 产品目标与完成标准

| 目标                | 首轮发布前的接受条件                                                                                 | 衡量方式                                                          |
| ------------------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| KR-1 配置可用       | 两个内置平台在账号已开通且模型模板齐备的条件下，基础接入只需填 Key；预设/连接/模型管理全部可保存读回 | AI-AC-01～07、13～15；记录成功路径字段、测试步骤与服务端状态      |
| KR-2 变更可靠       | 预设升级、模型启用、价格变更、Key 轮换及停用用例中，没有静默换平台、历史任务配置改写或重复派发       | AI-AC-05、08～11、14、17～19；固定故障脚本与任务/结算记录         |
| KR-3 权限与接受真实 | 非平台管理员管理接口越权成功数为0；四条执行链路分别取得真实输入、输出及费用证据                      | AI-AC-12、16、20及全部AC；平台/团队管理员角色矩阵与真实供应商验收 |

这些是接受目标，不是已有实测结果。首次接入耗时、首次生成成功率、单位被采用结果成本先建立基线，不编造百分比提升或上线日期。

## 4. 使用人群

| 人群             | 需要完成的工作                                               | 约束                                                                       |
| ---------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------- |
| 平台管理员       | 建立并维护共用 AI 服务，选择可用模型，追踪配置变化和费用异常 | 仅当前有效的平台管理员可配置；管理 Key 不自动授予全部私有项目素材读取权    |
| 个人与团队创作者 | 在自己的授权项目中选择模型、组织输入、知道费用、找回结果     | 不配置平台 Key；团队管理员也不能维护平台供应商；模型能力与素材权限同时生效 |

## 5. 用户价值

| 六项要素       | 平台管理员                                                   | 创作者                                         |
| -------------- | ------------------------------------------------------------ | ---------------------------------------------- |
| 谁             | 维护公共 AI 能力的人                                         | 使用图像、视频和文本能力创作的人               |
| 为什么         | 希望快速接入并能安全升级，避免不可解释的故障和费用           | 希望知道模型能做什么，提交后能找到真实结果     |
| 之前怎样做     | 可手动维护 URL、Key、模型 ID 和参数表，反复核对差异          | 可分别访问供应商工具，再下载重传结果           |
| 怎样改善       | 预设填充、分项检查、版本化模型配置与受控启用                 | 统一能力表单、费用确认、任务恢复与资产入库     |
| 之后的结果     | 能解释每次配置生效范围，定位账号、模型及协议问题             | 不学习多个平台协议，保留同一项目输入与产物关系 |
| 替代与选择理由 | 直接写配置或使用通用网关；选择织光以连通模型配置、创作和结算 | 使用平台控制台；选择织光以保持项目与素材上下文 |

“之前”描述可行替代方式，未进行用户访谈。价值主张：管理员配置一次并持续管理可用能力，创作者在同一工作流中获得可解释的参数、费用和结果。

## 6. 方案与首轮范围

主流程：选择火山方舟/OpenRouter 预设 → 创建停用连接 → 填 Key → 分项验证/模型发现 → 确认模型参数与价格 → 明确确认试运行 → 启用经过验证的发布组合 → 按能力设置默认 → 创作者使用。

| 必须交付          | 边界                                                                                  | 对应需求          |
| ----------------- | ------------------------------------------------------------------------------------- | ----------------- |
| 平台预设管理      | 内置与自定义、复制/编辑/发布、版本对比/升级/回退、归档、紧急停用、无秘密导入导出      | FR-01/02/04/05/18 |
| 多连接与 Key 管理 | 平台共用、只写不回显、多账号独立、诊断、轮换/撤销、刷新后恢复                         | FR-03/06/13/17    |
| 模型配置与发布    | 发现候选、手动 ID、按模式的能力/引用/参数、价格版本、验证与启用分开                   | FR-07/08/14/15    |
| 实际执行          | 火山 Seedance 视频；OpenRouter 文本、图像、视频分别适配与验收，每类至少一款已开通模型 | FR-06/08/10/11/16 |
| 默认与创作使用    | 按能力固定选择；不静默 fallback；报价确认复核、已有任务冻结配置                       | FR-09/10/19       |
| 权限与诊断        | 平台管理员服务端授权、创作者安全目录、审计/用量/错误分类、预算约束                    | FR-12/20及BR/NFR  |

表中 FR 均指需求03的 `AI-FR-*`。普通 Key 测试不触发生成；管理员试运行需要明确确认及预算。模型上线不能靠“HTTP 200”或“保存配置”判断，必须有对应能力证据。

范围内的技术约束：复用 catalog/operation/billing/media 与现有页面入口；平台差异通过适配器和小接口处理；不新增独立网关服务。UI 明细、状态机、字段及 API 见设计第6～8节。

## 7. 假设与依赖

平台管理员权限以用户系统新合同为依赖，不能把旧 org admin 视为已满足。四条链路的具体 model ID、可用模式、样本、上游成本与平台售价在计划 A0 固定，当前不保证全部型号均可开通。火山免费鉴权/模型发现接口尚需核验；没有合适接口时支持模板或手动配置，并明确显示未验证。

provider 活动执行端归属、队列及部署版本须查明；新状态下的在途任务恢复和旧数据迁移必须先在隔离环境验证。实时试运行需要提供合法样本与预算，当前文档任务不发起该调用。

## 8. 发布与接受

首轮包含上述完整管理闭环和四类执行链路；按计划 A0～A8 顺序推进，可分阶段演示，但不能以后台表单完成代替平台接入完成。建议先完成配置持久化，再执行协议，最后进行真实账号和浏览器综合接受；不设未经估算的工期。

BytePlus、第三平台、个人/团队 BYOK、自动跨平台路由、独立音频生成、提示词市场及新的聊天产品不在首轮。自定义预设仅配置已实现的两平台协议，不是可执行脚本或任意协议插件。

接受需逐项满足 AI-AC-01～20并出具真实链路证据。任何链路未通过则保持关闭并在接受记录列为未完成；不能静默删掉该链路来宣布首轮完成。发布按连接/模型组合灰度开放；回退停新任务并保留兼容 worker、历史配置、凭据引用与账单。保存本 PRD 不等于产品接受或发布授权。
