# PRD：多参考提示词编辑器与全能参考

更新：2026-10-14。采用 pm-execution 的 create-prd 方法整理。Tiptap 方向已由用户确认；产品细则沿用现行需求与设计，E0 编辑内核已进入实施与工程验证，真实输入法尚未验收；E1～E5 及完整产品接受尚未执行。

文档链路：[requirement · 需求](../requirement/02-多参考提示词编辑器需求.md) → [design · 交互及技术设计](../design/05-多参考提示词编辑器调研与设计.md) → **prd · 本文** → [plan · 实施计划](../plan/07-多参考提示词编辑器实施计划.md)。本文汇总产品目标、交付范围和接受条件；具体行为与 AC 统一维护在需求中，状态、数据和接口机制统一维护在设计中。

## 1. 概述

为个人及团队创作者提供基于 Tiptap 的多参考提示词编辑器，让图片、视频、音频和主体能在正文中被明确引用。用户从组织素材、切换模式、保存草稿到确认生成，都能知道哪些输入将被采用，并能继续修改和复用。

## 2. 背景

全能参考需要同时表达人物、场景、动作和声音等关系。仅有文字与附件列表无法保证正文指代、素材用途和实际输入一致；模式变化、上传回执及自动保存还可能使同一创作意图在多个位置失配。这是本次需要解决的产品风险，不是已经测得的线上事故或用户访谈结论。

用户已确认采用 Tiptap，并要求重点保证多参考引用、模式切换和草稿保存的一致性。已有需求、组件调研和交互设计，当前补齐从设计到执行之间的产品交付定义；本轮不重开选型，也不把组件能力等同于生成能力。

## 3. 目标与完成标准

目标：让用户组织的输入在编辑、持久化和实际生成之间保持可解释、可恢复、可核对。

| 结果          | 对应模式开放前的接受条件                                                                                               | 证据                                                                          |
| ------------- | ---------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| KR-1 引用正确 | 在规定的同名、重复提及、排序、删除、主体展开及跨范围用例中，错绑、漏传、越权读取均为 0                                 | AC-REF-03～06、09、15、22、25；逐项核对绑定、编号恢复与实际媒体映射           |
| KR-2 草稿连续 | 在模式往返、上传/保存乱序、断网、双窗口和账号切换用例中，未经用户操作的内容丢失、跨对象写入、静默覆盖均为 0            | AC-REF-07、08、10、16～19、21、22、24、25；核对分支恢复、保存状态与服务端读回 |
| KR-3 生成一致 | 所有确认用例中，实际任务输入与用户确认的完整快照一致，重复执行意图为 0；开放的全能参考模型完成真实输入、结果和费用核对 | AC-REF-11、12、14、20、23；冻结快照、跨刷新提交恢复、幂等记录及真实供应商证据 |

上述为产品验收目标，E0 局部工程证据见实施计划第 6.1 节，尚无完整产品验收结果，不承诺所有设备或模型永不出错。完整交付还须覆盖 AC-REF-01～25，包括输入法、无障碍和性能；没有基线时不编造转化率提升或完成日期。

## 4. 使用人群

| 人群             | 需要完成的任务                                         | 约束                                                             |
| ---------------- | ------------------------------------------------------ | ---------------------------------------------------------------- |
| 个人多参考创作者 | 用多份素材表达一个生成意图，在不同模式间调整并继续创作 | 需要识别同名素材、正确设置用途，失败或离开后可恢复               |
| 团队项目创作者   | 在获授权的项目中复用素材、主体和画布结果，恢复与再生成 | 项目归属与访问权明确；历史或粘贴不能绕过权限；不包含多人同时编辑 |

## 5. 用户价值

| 六项价值要素       | 个人多参考创作者                                         | 团队项目创作者                                           |
| ------------------ | -------------------------------------------------------- | -------------------------------------------------------- |
| 谁                 | 组合图像、动作和声音的个人创作者                         | 复用团队项目资源的创作者                                 |
| 为什么             | 要准确表达每份素材的作用，并反复调整                     | 要延续项目创作，准确使用有权限的版本                     |
| 之前怎样做         | 可用纯文字描述并手动对应附件；对应关系依赖记忆           | 可手动记录素材、版本和节点来源；复用时再次检查           |
| 怎样改善           | 正文引用与素材区联动；切模式保留内容；完整草稿保存       | 固定引用版本与来源；按对象恢复；复用时重新校验权限       |
| 之后的结果         | 知道会提交什么，调整或恢复时无需重建引用关系             | 能追溯当时输入，继续创作时不混入其他项目内容             |
| 替代方式与选择理由 | 普通输入框加附件；选择本方案以减少手工对应并核对最终输入 | 复制文字和下载后重传；选择本方案以保留来源且遵守当前权限 |

“之前怎样做”描述可用替代流程，尚未经过用户访谈验证。价值主张：让多份参考成为可操作、可保存、可追溯的创作输入，让用户在调整模式和恢复工作时保留自己的表达。

## 6. 方案与范围

主要流程：选择模式与模型 → 添加参考并明确用途 → 在正文插入引用 → 处理不兼容或不可用项 → 保存完整草稿 → 查看输入摘要与费用 → 明确确认生成 → 查看历史或创建新草稿再生成。首页、生成弹窗和画布节点共享规则；详细交互、异常路径与技术机制见上游设计第 9～13 节。

| 必须交付的能力                                                                 | 需求来源              | 设计落点                               | 实施批次   |
| ------------------------------------------------------------------------------ | --------------------- | -------------------------------------- | ---------- |
| 文本与原子引用混排，中文输入法、选区、统一撤销及可访问操作                     | FR-REF-01、12         | 组件、交互与统一事务（第 5、9、10 节） | E0、E5     |
| 查找、添加、替换、排序、移除、主体版本、上传修复、授权粘贴及画布来源           | FR-REF-02～05、07、08 | 引用数据、交互和历史（第 6、9、10 节） | E1、E2     |
| 同一草稿切换模式，保留不兼容项并禁止生成；首尾帧显式映射、参数变更可撤销       | FR-REF-06             | 模式切换矩阵（第 11 节）               | E3         |
| 正文、参考、模式、模型和参数同一修订保存；迟到回执、未知结果、离线及冲突可恢复 | FR-REF-09             | 保存与恢复（第 12 节）                 | E1、E3、E5 |
| 从已保存版本报价，确认冻结输入；历史保留实际输入，再生成重新校验与报价         | FR-REF-10、11         | 编译与服务端合同（第 7、13 节）        | E4、E5     |

以上共同遵守 DR-REF-01～12。标签删除与移除整份参考的影响必须可辨认；素材区未在正文提及的已启用参考仍会提交。不兼容草稿可保存，但不能静默丢弃输入后生成。这些产品规则在三个入口保持一致。

以下一致性边界属于首轮 P0，不能留作可选增强：

| 产品接受边界   | 用户可观察结果                                                                    | 验收与交付             |
| -------------- | --------------------------------------------------------------------------------- | ---------------------- |
| 双窗口本地恢复 | 各分支都可找回，选择或清理一份不会丢掉另一份；账号切换仍隔离                      | AC-REF-21；E1/E5       |
| 上传前保存     | 没有素材 ID 也能保存占位，刷新重选仍在原位置；未就绪时不生成                      | AC-REF-22；E1/E2/E5    |
| 未决提交恢复   | 刷新、清缓存或换设备先找到原提交；不自动确认未确认报价，不创建替代执行意图        | AC-REF-23；E4/E5       |
| 模式查询与撤销 | 待选期间撤销后不会被迟到查询切回；恢复模式重新核验当前能力                        | AC-REF-24；E0/E3/E5    |
| 编号跨恢复稳定 | 删除/撤销后刷新不复用已分配号；跨分支冲突需显式处理，生成内容相同仍保存编号元数据 | AC-REF-25；E0/E1/E2/E5 |

采用 Tiptap 开源 Editor、自定义引用节点与现有 shadcn/Radix 组件。保存完整结构化草稿，引用使用稳定身份；画布接入现有保存所有者，避免同一对象被两套保存机制竞争写入。报价与执行消费同一冻结输入，具体接口和修订规则不在 PRD 重复定义。

待验证：包版本兼容、真实中文输入法与移动端粘贴、模型能力与供应商映射、主体及团队资源权限、持久化升级与恢复。性能预算及自动保存时间仍是需求中的建议值，须由 E0/E5 实测确认。缺少真实供应商或团队权限条件时保留完整需求，只关闭受影响入口，不能标记为已交付。

## 7. 交付与接受

首轮完整交付覆盖上述 P0：首页/弹窗/画布共享编辑规则，独立草稿与节点输入保存，多参考与主体、模式切换、报价确认及历史复用。按 E0 内核验证 → E1 持久化 → E2 引用 → E3 模式 → E4 报价与历史 → E5 系统接受推进；这是相对依赖顺序，不是工期承诺。E0 的内部验证不能作为首个正式版本完成。

按已验收的入口和模型逐步开放；每项 AC 必须记录通过、失败或未执行及证据。受影响模式未通过的用例阻止该模式开放，不删除用例或据此缩小完整需求；宣布完整交付需要 AC-REF-01～25 全部通过。工程检查、浏览器/设备、隔离存储和真实供应商证据分别判断。错绑、丢草稿、越权或重复执行意图出现时停止相应入口开放，保留数据和历史，按实施计划回退。

后续可扩展时间片段/裁切、批量替换、模板和引用感知 AI 改写，另行定义需求及验收。本轮不包含文章排版、表格/字体工具栏、协同编辑、评论、主体训练及未被供应商支持的精确控制能力；不依赖付费编辑器服务。完整任务、故障注入、迁移及回退步骤以[实施计划](../plan/07-多参考提示词编辑器实施计划.md)为准。
