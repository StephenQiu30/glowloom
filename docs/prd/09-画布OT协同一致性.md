# 画布OT协同一致性 PRD

> 唯一来源设计：[17-画布OT处理设计](../design/17-画布OT处理设计.md)。原始来源：[10-画布OT协同一致性需求](../requirement/10-画布OT协同一致性需求.md)。实施状态只见[BACKLOG](../../BACKLOG.md)。

## 1. 摘要

多端同时编辑时保留兼容意图，明确处理冲突，撤销只影响自己的贡献，各端最终收敛到数据库确认的图。

## 2. 背景

2026-10-22用户明确要求根据原始需求重整设计，不以现有代码作为可靠依据。本PRD保留原COL能力与验收身份，旧协议、旧实现和旧验证记录仅在Plan按原时点使用，不决定当前目标合同。

## 3. 目标

多端同时编辑时保留兼容意图，明确处理冲突，撤销只影响自己的贡献，各端最终收敛到数据库确认的图。 成功依据是原始AC的行为证据，不是文档完整、代码存在或历史测试数量。

## 4. 目标用户

同账号多标签页、跨设备使用者，以及同一项目下获得授权的创作者。在线头像、光标、邀请和评论不纳入本专项。

## 5. 价值

创作内容与保存结果可理解，多端使用和故障恢复不依赖用户猜测。兼容性、稳定性和资源规模需分别证明。

## 6. 解决方案与范围

节点与字段、布局、连线、分组、文本/富文本、在途协调、本人贡献撤销及输入版本保护。不能将整图覆盖、仅最后写入或全部拒绝冲突称为OT。

| 能力                              | 用户结果                                           | 原始验收              |
| --------------------------------- | -------------------------------------------------- | --------------------- |
| CAP-COL-01 有限OT规则与可验证基础 | 兼容编辑保留，冲突确定裁决                         | AC-COL-01、02、05     |
| CAP-COL-02 完整字段与富文本适配   | 每个开放字段都有语义，正文/引用/IME不被整份覆盖    | AC-COL-01、02、04、05 |
| CAP-COL-03 在途与因果协调         | 远端变更与在途/后继意图正确协调                    | AC-COL-05、06         |
| CAP-COL-04 贡献撤销               | 撤销自己的贡献，保留别人的有效修改                 | AC-COL-03             |
| CAP-COL-05 协同接受与业务一致性   | 多端最终一致，迟到结果和重放不改写新输入或重复执行 | AC-COL-01～06         |

临时断线且最近已确认可写、基线可安全协调时，允许本页有界内存编辑；明确失权、首次未授权或无法安全重建时暂停。无浏览器业务持久缓存，不承诺刷新找回未送达内容。实际消息/字段/算法只由唯一来源设计维护。

## 7. 交付与验收

验证覆盖：实际节点操作对、三方多步交错、中文/emoji/IME与富文本引用、P/Q依赖、拒绝与重连、本人贡献撤销，以及真实双账号多端和数据库最终一致。普通文本局部通过不能替代富文本和全字段接受。

数据、通道与转换可以分层测试，完整交付仍须三专项联合接受。通信独立测试允许明确版本冲突，不代表取消原始OT需求。当前普通组件独立编辑通过也不能当作真实项目服务已接通。

实施步骤与旧证据见[计划](../plan/19-画布OT协同一致性实施计划.md)，旧成功和失败均保留当时环境及边界，不宣称适用于新设计。

## 8. 依赖与限制

依赖设计14的权威数据、原子回执与当前授权。容量、恢复时延、历史成本和生产部署条件须通过真实测量接受，不承诺未经验证的SLO。未支持或无法安全解释的历史内容必须保护，不能为简化当前界面而裁剪保存。当前只更新设计文档，未实现或发布新合同。
