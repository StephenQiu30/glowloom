# 画布WebSocket实时同步 PRD

> 唯一来源设计：[15-画布WebSocket实时通道设计](../design/15-画布WebSocket实时通道设计.md)。原始来源：[09-画布WebSocket实时同步需求](../requirement/09-画布WebSocket实时同步需求.md)。实施状态只见[BACKLOG](../../BACKLOG.md)。

## 1. 摘要

有权限的客户端自动收到已保存变化，用户能准确区分连接状态与保存状态，断线和回执丢失后可以安全恢复。

## 2. 背景

2026-10-22用户明确要求根据原始需求重整设计，不以现有代码作为可靠依据。本PRD保留原SYNC能力与验收身份，旧协议、旧实现和旧验证记录仅在Plan按原时点使用，不决定当前目标合同。

## 3. 目标

有权限的客户端自动收到已保存变化，用户能准确区分连接状态与保存状态，断线和回执丢失后可以安全恢复。 成功依据是原始AC的行为证据，不是文档完整、代码存在或历史测试数量。

## 4. 目标用户

同账号多标签页、跨设备使用者，以及同一项目下获得授权的创作者。在线头像、光标、邀请和评论不纳入本专项。

## 5. 价值

创作内容与保存结果可理解，多端使用和故障恢复不依赖用户猜测。兼容性、稳定性和资源规模需分别证明。

## 6. 解决方案与范围

编辑唯一WebSocket队列、初始化、确认、补齐、重连、授权与背压。HTTP可用于读取和素材传输，不可作为编辑保存兜底；心跳不替代业务确认。

| 能力                           | 用户结果                                                 | 原始验收       |
| ------------------------------ | -------------------------------------------------------- | -------------- |
| CAP-SYNC-01 双向实时连接       | 编辑、确认和远端更新都通过WebSocket，不需刷新            | AC-SYNC-01、04 |
| CAP-SYNC-02 断线恢复与保存反馈 | 未知结果保留原请求身份，补齐后恢复，未确认内容不误报成功 | AC-SYNC-02、03 |
| CAP-SYNC-03 权限与通道质量     | 授权贯穿连接生命周期，慢连接、重启和背压可控             | AC-SYNC-01～04 |

临时断线且最近已确认可写、基线可安全协调时，允许本页有界内存编辑；明确失权、首次未授权或无法安全重建时暂停。无浏览器业务持久缓存，不承诺刷新找回未送达内容。实际消息/字段/算法只由唯一来源设计维护。

## 7. 交付与验收

验证覆盖：双客户端顺序编辑、初始化期间并发提交、发送前/中/后断线、健康连接丢ACK、消息重复/迟到、历史不足、服务重启、撤权与归档。逐项对照数据库版本和操作回执；不只检查页面“已连接”。

数据、通道与转换可以分层测试，完整交付仍须三专项联合接受。通信独立测试允许明确版本冲突，不代表取消原始OT需求。当前普通组件独立编辑通过也不能当作真实项目服务已接通。

实施步骤与旧证据见[计划](../plan/18-画布WebSocket实时同步实施计划.md)，旧成功和失败均保留当时环境及边界，不宣称适用于新设计。

## 8. 依赖与限制

依赖设计14的权威数据、原子回执与当前授权。容量、恢复时延、历史成本和生产部署条件须通过真实测量接受，不承诺未经验证的SLO。未支持或无法安全解释的历史内容必须保护，不能为简化当前界面而裁剪保存。当前只更新设计文档，未实现或发布新合同。
