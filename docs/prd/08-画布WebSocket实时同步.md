# 画布WebSocket实时同步 PRD

> 唯一来源设计：[15-画布WebSocket实时通道设计](../design/15-画布WebSocket实时通道设计.md)。实施状态见[BACKLOG](../../BACKLOG.md)。

## 1. 摘要

通过WebSocket同步画布编辑、持久回执、远端变化和在线状态，支持连续创作及断线恢复。

## 2. 背景

实时通道连接Yjs客户端与业务接受服务，贯穿身份授权、初始化、编辑和恢复。

## 3. 目标

完整编辑自动提交，无需点击保存、失焦或停止输入；用户及时看到已接受的远端变化，准确区分连接、权限和保存状态，断线及服务重启后恢复一致内容。

## 4. 目标用户

同账号多标签页、跨设备使用者和同项目协作者。

## 5. 价值

多人创作与故障恢复具有明确反馈，未确认内容可查证。

## 6. 能力

| ID                             | 用户能力                                               | 验收           |
| ------------------------------ | ------------------------------------------------------ | -------------- |
| CAP-SYNC-01 双向实时连接       | 编辑、确认和远端更新通过同一会话同步，在线状态及时可见 | AC-SYNC-01、04 |
| CAP-SYNC-02 断线恢复与保存反馈 | 查证原提交，补齐已接受更新，恢复本页未确认内容         | AC-SYNC-02、03 |
| CAP-SYNC-03 权限与通道质量     | 授权贯穿连接生命周期，撤权、背压、慢连接与重启可控     | AC-SYNC-01～04 |

连续编辑使用有界本页内存队列；个人视图独立保存。presence按权限隔离并过期。HTTP负责读取与素材传输，WebSocket负责编辑及回执。

## 7. 验收

覆盖初始化并发、发送各阶段断线、丢回执、重复和乱序消息、增量补齐、服务重启、撤权、归档与在线状态过期。真实多账号浏览器与数据库逐项核对内容、修订及原提交回执。

证据见[计划18](../plan/18-画布WebSocket实时同步实施计划.md)，与数据及协作专项完成联合验收。

### 7.1 自动保存与断线恢复的接受边界

- AC-SYNC-01：完成正文/参数/节点/布局/连线/分组等编辑后，用户不点击保存也能收到持久确认、被另一端看到并在重开后恢复；持续输入不无限延迟提交。普通编辑无HTTP保存后备通道或独立定时保存器。
- AC-SYNC-01/02：有后继输入、未发布素材或未解决恢复项时，旧ACK不能显示整页已保存；预览取消不制造虚假已保存事务，保存状态与连接状态独立。
- AC-SYNC-02/03：临时断线在既有授权和有界本页内存内继续编辑；队列满前暂停接纳，已有内容不丢。未知结果保留原身份查证，确定未找到才原样重试；确定拒绝进入可解释恢复，不重复提交新请求。
- AC-SYNC-03/04：重连先确认身份、权限和文档谱系，再恢复原请求；旧epoch已接受事实可查，未接受内容不自动写入新epoch。应用内离页、账号/项目切换及迟到消息不混用旧会话内容。
- AC-SYNC-04：暂时不可写仍保留有权浏览的平移/缩放/预览；明确失去访问权后停止私有展示与接收，不能以断线恢复绕过授权。

浏览器持久业务存储及关闭页面的数据边界依赖[PRD07](07-画布数据库持久化与DAG.md)；安全合并和恢复取舍依赖[PRD09](09-画布协作编辑.md)。接受方法见唯一来源设计15，测试步骤见计划18。

## 8. 依赖

依赖统一授权、Yjs共享模型、原子持久化和可查询回执。应用服务通过Docker运行，资源与恢复上限按实际部署测量。
