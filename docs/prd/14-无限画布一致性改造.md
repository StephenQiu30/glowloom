# 无限画布一致性改造 PRD

唯一来源设计：[设计27—无限画布一致性改造](../design/27-无限画布一致性改造设计.md)。本文件是评审稿，定义交付什么及如何接受；工程合同沿该设计及其依赖，不另选第二来源设计。执行文件：[Plan23](../plan/23-无限画布一致性改造实施计划.md)；实施状态、优先级、容量与排期见 [BACKLOG](../../BACKLOG.md)。

## 1. 摘要

为创作者提供与即梦主要操作模式一致的无限画布，将节点编辑、素材引用、生成配置、任务结果和继续创作组成完整流程。完整范围覆盖60项研究需求；真实可用性、权限、保存与恢复属于交付条件。

交付采用可验收的功能组合；先证明核心创作闭环，再验收高级创作与全部边界。阶段划分不删除时间线、导演台或AI对话需求，也不将未开放菜单视为已实现。

## 2. 背景与问题

用户明确要求先独立分析即梦，再核对当前实现、彻底更新设计稿并落实代码。已有基线说明主要菜单和空态，但部分非空、异步与协作行为尚待补证。因此本 PRD 定义目标产品，不声称已经发现或修复某个当前实现缺陷。

需解决的问题是同一创作链路上的理解和状态断裂：用户应能知道选中了什么、参考是否有效、当前参数能否生成、任务结果去了哪里，以及编辑是否已被保存。

## 3. 目标与衡量

| 指标         | 接受标准                                                                                     | 测量方法                                                            |
| ------------ | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 需求可追踪性 | 60个JC需求全部关联故事、目标设计、任务和验收；不得有无处置项                                 | 交付矩阵检查；证据不足也要有明确结论与责任任务                      |
| 核心闭环完成 | 合法素材/正文 → 参考 → 模型配置 → 真实生成 → 采用结果 → 重开继续，全程无静默丢失或跨对象覆盖 | 对实际支持的媒体能力逐一执行，记录输入/任务/资源/画布身份及回读证据 |
| 完整范围接受 | AC-CJC-01～24均有实际验证结果；未覆盖不得记通过                                              | 产品场景、真实服务、双账号三客户端、设计检查分层记录                |

这里定义交付标准，不承诺未测的用户增长、耗时降低或吞吐数字。性能预算在样本测量后按设计27 Q-CJC-06确定；不得用缺少预算掩盖明显交互阻塞。

## 4. 目标用户与使用约束

| 用户群             | 核心任务                                               | 约束                                         |
| ------------------ | ------------------------------------------------------ | -------------------------------------------- |
| 视觉与多媒体创作者 | 将构思、素材、主体和多轮结果组织成可继续修改的作品     | 模型能力不同、素材有版本、任务异步且可能收费 |
| 项目协作创作者     | 共享素材与画布，在自己的编辑和他人的修改间保持连续工作 | 对象权限、断线、并发修改、撤销边界           |

只读访问者属于同一项目的访问角色，须有浏览与权限限制设计，不另设增长人群。上述分群依据创作任务，未声称已完成用户访谈或市场规模验证。

## 5. 价值主张

| 价值要素 | 多媒体创作者                                                          | 项目协作创作者                                                 |
| -------- | --------------------------------------------------------------------- | -------------------------------------------------------------- |
| 谁       | 需要多轮生成与素材整理的人                                            | 在授权项目中共同编辑的人                                       |
| 为什么   | 持续保持创意、主体、参考与结果的关系                                  | 理解谁改了什么、自己是否已保存                                 |
| 原有方式 | 在素材库、提示词表单、结果列表之间反复寻找上下文；为待验证的问题假设  | 依靠沟通或重开页面确认结果；为待验证的问题假设                 |
| 如何解决 | 节点、类型化参考、共用生成器、明确采用结果与历史                      | 同一协作会话、独立连接/保存反馈、权限与个人撤销                |
| 完成后   | 可沿同一作品继续编辑，能解释每个结果的来源                            | 可继续自己的工作，不因迟到结果或恢复覆盖新内容                 |
| 替代方案 | 即梦或分散的素材/生成工具；选择织光的理由是复用自己的模型、主体与资产 | 文件传递或独立副本；选择织光的理由是项目内连续协作与可核验保存 |

价值表达：让创作者在一个可追溯的画布内完成创作与继续修改，并让协作者明确区分本地输入、已接受内容和正在执行的任务。

## 6. 范围、故事与功能要求

### 6.1 交付范围与边界

“核心创作闭环”包含工作区、文本和媒体节点、合法参考与主体消费、多选基本组织、真实模型配置与生成结果、必要资产/历史、权限、保存恢复、设备与键盘可达性。

“完整创作范围”再包含导演预设、分镜组与复杂布局、非空时间线及实际导出、导演台与AI的已确定内部流程，并关闭完整连接矩阵、性能和复杂异常缺口。调度由 BACKLOG 管理；不能把完整范围永久退化为第一组合。

本次不交付新的支付/会员系统、新供应商平台、专有素材复制、新同步算法或未经范围确认的通用3D引擎。已有服务不支持某能力时应真实说明；完整能力验收仍保持未通过。

### 6.3 产品与交互要求

- 工作区采用上下文操作：单选类型工具、多选集合工具、文本编辑工具互不抢占。
- 参考要展示类型、稳定标签、预览、移除及失效原因；连接不自动执行任务。
- 文本、图像、视频、音频表单共享基础结构，各自遵循真实能力；展开和折叠保持同一草稿与引用。
- 生成提交固定输入；进度、失败、取消和未知结果有明确反馈；采用不会覆盖较新编辑。
- 时间线、导演台、AI对话以真实输入到结果回写定义完成，不能仅对齐菜单外观。
- 只读、空、加载、失败、无权限、保存待确认和恢复都属于主流程设计。
- 当前整体视觉、富文本无边框及已移除的版本历史入口继续有效，不能因竞品截图逆转用户明确决定。

## 8. 交付、风险与非目标

交付物为可编辑设计稿及状态说明、通过合同检查的应用变更、可重复的场景证据、存量升级与回退方案。产品接受要区分“文档齐备”“设计覆盖”“工程可运行”“真实服务通过”和“可发布”；彼此不代替。

外部风险主要是模型/导出能力不可用、竞品证据不足、并行主体/资产改造尚未接入，以及旧画布数据迁移。对应决策和补证要求由设计27持有，执行顺序与处理状态由 BACKLOG 管理。

没有团队成员可用时间与历史吞吐数据，本 PRD 不给出日期、故事点或周期承诺。先完成差异核对和依赖识别，再在 BACKLOG 按实际容量排入迭代。完整接受前不得对外声称“与即梦全量一致”。
