# 画布编辑与素材 PRD

> 唯一来源设计：[10-画布交互设计](../design/10-画布交互设计.md)。原始来源为[需求06](../requirement/06-画布组件迁入与定制需求.md)，按用户最新范围确认解释；当前实施状态只见[BACKLOG](../../BACKLOG.md)。

## 1. 摘要

让用户通过独立画布组件编辑文本、图片、视频、音频、分组和连线。项目保存及素材服务接线按数据专项完成，不将文件导出或组件局部通过当作正式项目可保存。

## 2. 背景

用户要求清理旧画布前端，只采用参考项目的画布编辑与素材体验，独立组件先行；随后要求重新设计数据库保存与后端接口。2026-10-22明确以原始需求为依据，删除冗余设计，不以现有实现定义正确方案。

旧即梦定制、提示词、模型、生成、助手和插件不再作为本轮交付前置；原来源保留，后续独立决定。当前组件与宿主的边界依设计10，不复制参考项目整个业务应用。

## 3. 目标与成功标准

| 目标               | 接受条件                                                                         |
| ------------------ | -------------------------------------------------------------------------------- |
| KR-CAN-01 一致编辑 | 五类节点可添加、选择、编辑、复制、删除；素材直接展示，输入焦点和取消行为明确     |
| KR-CAN-02 可控交互 | 平移缩放、框选、拖动、尺寸、分组、连线及浮层在目标屏幕可达；手势结束不依赖网络   |
| KR-CAN-03 可信内容 | 独立模式明确文件保存边界；正式项目接线后通过数据库持久确认及重开，不误报保存成功 |

目标是行为接受，不预先宣称性能或生产稳定。正式项目保存单独按PRD07验收，不能以浏览器文件往返替代。

## 4. 目标用户

需要在画布整理文字与媒体素材的创作者。首轮不增加团队管理、邀请或AI执行流程；后台仍须保护既有业务内容与权限。

## 5. 价值

减少重复组件和干扰界面，形成清晰的编辑与素材处理体验，同时让保存状态和内容归属可以理解。

## 6. 解决方案

- 文本、图片、视频、音频和分组为首轮节点；普通连线仅表达标注关系。
- 支持媒体导入、图片裁剪/拆分/像素缩放及替换；正式接线后先取得真实素材身份，再保存图操作。
- 取消、失败、只读、窄屏、键盘、IME与离开未保存提示都是正常体验的一部分。
- 正式画布不使用浏览器持久业务缓存；未知旧节点不能被静默删掉后保存。
- 独立组件文件导入/导出与服务器项目保存分开呈现；项目导入必须追加合法操作，不整图覆盖。

故事沿用ST-CAN-UI-01～ST-CAN-UI-07及ST-CAN-01～03，语义映射见设计10。AC-CAN既有编号不重编；其中生成、提示词及旧迁入阶段的条件保留在需求来源，不叠加为本轮全部任务。

## 7. 交付与验收

[计划13](../plan/13-画布编辑与素材实施计划.md)承接组件；[历史记录14](../plan/14-画布交互历史验证记录.md)仅保存旧批次证据；[PRD07](07-画布数据库持久化与DAG.md)及计划17承接数据库接线，SYNC/COL专项分别验证通信与并发。

验收逐项检查节点、正文、素材处理、分组、连线、撤销、手势取消、输入与窄屏。正式保存须使用真实身份、素材服务和数据库，在独立浏览器重开同一项目读回。旧Figma或旧代码测试不自动证明新组件或新设计通过。

## 8. 边界与依赖

本轮设计不授予新增业务实现或发布的授权。媒体、项目和用户权限沿其原始需求；历史正文、生成输入与结果的保护不可省略。生产容量及完整富文本协同接受由对应专项提供证据，不能合并成笼统“画布完成”。
