# 统一主体库与创作引用

唯一来源设计：[设计25](../design/25-统一主体库与创作引用设计.md)。用户来源沿设计25追溯需求12；外部证据沿研究09。实施状态只见[BACKLOG](../../BACKLOG.md)，实施和证据见[Plan21](../plan/21-统一主体库与创作引用实施计划.md)。

## 1. 用户、问题和价值

登录创作者需要将同一对象在多个项目中复用。当前项目和角色/场景/物品前置、详情再编辑、只搜本页会增加查找和设置成本；音色绑定未参与引用也会产生能力误解。统一主体库让用户先建立参考对象，再在有权访问的项目创作中引用固定版本。

## 2. 范围与非目标

范围：当前空间主体库、设置主体、正式主参考/补充参考/可选音色、服务端查询、收藏、时间排序、单项/批量管理、导出、@候选及创建返回、引用身份和模型能力反馈、旧数据兼容。桌面与390手机共享语义和状态。

不因本专项重构剧本角色、造型及台词身份，不复制即梦品牌、会员或营销；不把素材库收藏当主体收藏，不把目录选音色当智能配音产物，不承诺未经测试的即梦文件限制或下载格式。真实收费生成及生产数据库迁移需沿现有明确授权与运行流程执行。

## 3. 用户旅程

主体 → 新建主体 → 从本地/资产选择主参考 → 可选补充参考/音色 → 填名称与描述 → 保存 → 列表找到主体 → 在创作中@选择 → 固定版本引用 → 按真实模型支持的模式继续。卡片点击直接设置主体；删除需要确认目标与历史影响。保存、上传和生成不是同一个成功状态。

## 5. 假设与风险

即梦未验证的大小、时长、数量、批量部分失败和下载格式不能当产品事实。跨项目媒体需要明确绑定授权和历史保留；只改前端会在草稿或worker阶段失效。智能配音真实执行链当前存在缺口，必须分别报告UI、合同、真实产物、供应商消费和产品接受。状态、依赖和余项由BACKLOG维护，不在此承诺完成。

AC-SUB-17补充：按设计25的顶层架构补充验收双槽，进入批量后筛选/时间/排序仍可用，账号与搜索组暂时撤销；取消恢复公共组和批量入口焦点。路由卸载清除主体工具与替换状态，嵌入场景保持内联。系统行为交叉依赖FR-WB-19/AC-WB-19，不复制另一套外壳。
