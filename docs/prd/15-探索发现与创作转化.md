# 探索发现与创作转化 PRD

唯一来源设计：[设计28：探索发现与创作转化](../design/28-探索发现与创作转化设计.md)。原始诉求经该设计承接需求15；外部观察经该设计承接调研11。执行计划：[Plan24](../plan/24-探索一致性改造Agent执行计划.md)。文档性质：范围与验收评审稿；设计提案不自动视为用户逐项确认，实施状态只见 [BACKLOG](../../BACKLOG.md)。

## 1. 摘要

为需要灵感、复用方法和展示作品的创作者提供一个统一探索入口。用户可以按用途发现公开内容、查看创作信息，并使用含义明确的动作进入创作、添加技能或参与活动。

完整交付包括作品、技能、活动、搜索、发布及跨端恢复。共享顶栏的一级分类与右侧头像同行是明确要求；所有可点击业务动作必须对应真实能力和结果。当前没有本地功能差异审计结论，本PRD不以现有占位页面定义最终范围。

## 2. 参与与责任

使用者为公开内容浏览者、已登录创作者及作品发布者。产品维护范围与取舍，设计维护可交互原型，工程维护真实合同，质量维护可复现验收。具体人员与排期不补造，认领和调度见BACKLOG。

## 3. 问题与背景

用户要求按即梦探索进行系统性对齐，并先形成独立需求再落设计和代码。已见竞品将作品用途、场景、技能、活动和搜索类型分别组织，图片复用、只读过程及发布也具有不同后续流程。

本次解决的产品问题是：内容入口应当容易理解，用户看到有价值的作品后能带着正确上下文继续行动，而不是在若干视觉相似但含义不清的按钮之间试错。这是任务提出的目标，不是已经通过埋点或访谈证明的现有流失原因。

### 4.2 使用效果指标提案

这些是上线后的观测口径，不是已有数据或提升承诺。是否沿现有分析工具采集由设计D08确定；没有基线和流量样本时不填写虚构目标值。

| 指标                 | 分子 / 分母                                                   | 判断用途                                         |

事件最少包含事件名、内容类型、稳定对象ID、来源场景及结果类别；不采集提示词正文、凭据、私有素材地址。取消、失败与未知分别计数；匿名/登录合并和会话定义在采集前固定。

## 5. 用户分群与任务

按任务区分三组用户，不以年龄、职业或假想市场规模划分：

| 分群               | 主要任务                            | 关键障碍假设                       | 范围                               |
| ------------------ | ----------------------------------- | ---------------------------------- | ---------------------------------- |
| 寻找方向的浏览者   | 按用途快速找到可理解的作品          | 单一图片列表和混杂筛选让内容难找   | 导航、作品流、详情、搜索、游客边界 |
| 希望继续创作的人   | 复用提示词/参考、学习过程、添加技能 | 作品与可执行创作上下文之间存在断点 | 复用、过程/副本、技能、关系与恢复  |
| 希望展示与参与的人 | 发布自己的短片、浏览活动与作品      | 上传、发布、审核及参赛状态容易混淆 | 发布、活动、明确结果与权限         |

这些分群和障碍是假设性产品模型；需通过真实使用观察校验，不构成新增运营或营销项目。

## 6. 用户价值

| 六项价值要素       | 寻找方向的浏览者            | 希望继续创作的人                     | 希望展示与参与的人                      |
| ------------------ | --------------------------- | ------------------------------------ | --------------------------------------- |
| 谁                 | 需要内容方向的人            | 已有创作意图的人                     | 有可发布作品的人                        |
| 为什么             | 找到贴近用途的参考          | 把喜欢的结果转成自己的创作输入       | 让作品被看到并理解参与条件              |
| 原先如何做（假设） | 反复切换列表或外部搜索      | 手工抄提示词、保存图片、重新设置参数 | 在上传、活动说明和发布入口间往返        |
| 如何改善           | 分类/场景与搜索类型清晰分层 | 结构化交接草稿、只读过程及技能关系   | 明确发布必填、结果状态和活动规则        |
| 完成后的结果       | 能找到并打开合适作品        | 能在正确权限和模型条件下继续编辑     | 能确认投稿/发布是否被接受，失败后可恢复 |
| 替代方式           | 外部内容社区和通用搜索      | 手工整理参考或从头创作               | 外部视频平台或单独活动表单              |

核心价值主张：让发现的内容可以理解、可以合法复用，并能进入真实创作流程；让发布者知道每一步是否确实完成。选择Glowloom的理由需要由这条闭环的实际体验验证，不能仅靠外观相似宣称优于替代方案。

## 7. 产品范围、故事与验收

### 7.1 范围与非目标

完整范围包含设计28中的50条来源需求；可以分批验证，不以分批为理由删除技能、活动、发布或异常场景。第一条可演示闭环为“导航/搜索 → 作品详情 → 做同款/参考追加 → 真实草稿”，其余闭环仍在完整接受范围内。

本专项不包含：复制即梦模型或计费权益、抓取其作品作为本平台正式内容、建设新的技能交易市场、重写画布协作协议、另建认证/媒体服务、扩展全站运营后台、替用户参赛或对外发布。既有公开内容供给和审核若不足，记录为目标能力依赖，不能用假数据补齐后宣称上线。

### 7.5 假设、决策与风险

本地真实公开内容供给、技能存储和发布服务是否存在尚未审计；不能据此预估工程量。竞品未测结果也不能推定本平台必须用同样内部实现。设计D01～08负责搜索/分页、视觉、技能归属、分类迁移、发布、项目复制、未测交互和指标口径的收敛。

最大产品风险是用可点击原型冒充真实闭环；最大的集成风险是共享壳、资产、主体和画布并行修改导致规则冲突。以真实读回、权限负例、明确来源链和工作区所有权解决。只阻止依赖未知的任务，不因单个未知停止所有文档或独立工作。

## 8. 交付与接受边界

按可验收能力分批：先建立完整差异及规则；随后交付浏览与复用闭环；再完成技能、关系、活动、发布；最后完成跨端、旧数据和综合接受。各批是依赖拆分，不是删减完整范围或承诺排期。

每个能力必须具有设计状态、真实接口结果、异常验证和可复现证据。工程测试通过、Figma原型通过、真实业务接受、上线发布分开记录。只有22项必需接受及50项处置均有有效证据，才能称完整范围完成；生产发布仍需原有发布授权。

本PRD刻意不规定未经审计的数据库表、API路径、组件文件或第三方模型清单；它们由设计所有者和Plan首批审计收敛，不能由执行Agent凭空创建。
