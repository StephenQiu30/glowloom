# AI服务测试与验证

状态：2026-11-01用户确认落实设计与实现。唯一来源设计：[AI服务测试与验证交互设计](../design/2026-11-01-AI服务测试与验证交互设计.md)。原始需求04 SRC-AI-33。

- 服务列表提供“测试”快捷入口，进入服务详情局部测试页签；保存Key、打开面板或切换模型不触发调用。主导航和头像仍在共享顶栏。
- 页面分别显示网络连通、凭据鉴权、模型验证。网络可达不能冒充Key有效；只读通过不能冒充所有模型可用。
- 五类服务按实际鉴权与执行能力展示；语音/音乐不支持只读鉴权为中性状态，音乐保留正式模式试运行/报价/查询合同。
- 真实验证先显示模型/模式/输入输出范围及费用，再显式确认；未估价不显示免费，不自动验证所有模型。
- 状态区分认证、权限、地域/IP、余额/额度、限流、参数、模型、网络及结果未知；已受理不等于已完成。未知仅恢复原请求。
- 记录绑定当前配置、凭据和模型版本；轮换与改版不沿用过期通过。测试、启用及发布保持各自业务合同。
- 验收映射US-TEST-01～05、TS-TEST-01～12，具体字段、边界、恢复与可访问性以唯一来源设计为准。本轮按实施Plan落实代码，工程验证不发真实收费请求。

恢复要求：正式试运行刷新后以服务端原operation和稳定确认键恢复；旧配置异步检查只读取原TaskID与仍可恢复的原Key，不能重新提交或沿用到当前版本。结束同步unknown追踪后，核查说明保留，新验证必须再次确认费用并关联旧记录。轻量验证仅代表固定模板，完整模式/参数由正式release试运行验证。

用户追加极简要求：默认仅展示三项测试、状态与操作；技术信息和历史收在有记录时出现的检测详情。删除重复空态、常驻说明和装饰性卡片边框，未配置时直接提供配置入口。费用范围、错误、未知恢复及原权限/预算合同必须保留；具体呈现以设计8.4节为准。
