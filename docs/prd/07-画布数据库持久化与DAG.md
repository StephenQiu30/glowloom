# 画布数据库持久化与DAG PRD

> 唯一来源设计：[14-画布数据与接口设计](../design/14-画布数据与接口设计.md)。原始需求：[需求08](../requirement/08-画布数据库持久化与DAG需求.md)。当前实施状态只见[BACKLOG](../../BACKLOG.md)。

## 1. 摘要

用户关闭页面、清除浏览器数据或换设备后，可以从数据库恢复全部已确认画布；非法图、越权和失败不能产生部分保存，重复请求不能造成重复编辑。

## 2. 背景

原始需求要求整个画布节点信息入库、不使用本地持久恢复，并补齐DAG数据规则。2026-10-22用户要求以需求重整设计，现有代码和旧方案不能视为可靠依据。本PRD定义用户结果；技术字段和接口只在设计14维护。

## 3. 目标

全部正式内容可恢复；确认结果可核实；保存与素材权限一致；未知旧内容不被误删。正确性通过行为与故障验收确认，不用“已有数据库表”或“本地测试通过”替代。

## 4. 目标用户

需要跨会话继续创作的个人用户，以及同一项目下获得授权的编辑者。多端不要求先提供在线头像、邀请或评论产品。

## 5. 价值

内容保存在项目内，用户不依赖特定浏览器；失败可理解，重试不会重复创建节点或改写别人的内容。

## 6. 解决方案与范围

| 能力                             | 用户结果                                           | 原始验收               |
| -------------------------------- | -------------------------------------------------- | ---------------------- |
| CAP-DATA-01 可靠原子保存         | 一次编辑完整保存或完整拒绝，未知结果可查证         | AC-DATA-01、05、06、08 |
| CAP-DATA-02 合法图与引用         | 标注线、分组和依赖区分；引用有效；节点删除不删素材 | AC-DATA-03、05、06     |
| CAP-DATA-03 完整恢复与旧内容保护 | 全持久字段读回；旧数据库内容和未知结构不被静默丢弃 | AC-DATA-02、04、07     |
| CAP-DATA-04 存储质量与接受       | 无浏览器业务持久缓存，失败和恢复有真实证据         | AC-DATA-01～08         |

五类编辑节点的标题、正文/素材、布局、分组及关系必须覆盖。既有生成/工具内容按类型版本保护，输入与历史结果不因普通编辑而改变。上传二进制走素材服务，数据库保存稳定身份，临时URL不是内容来源。

画布普通编辑不发起任务或计费。依赖DAG校验不等于执行引擎。未知结果不能换操作ID重试；读取失败不能显示可写空图；临时断线仅有页面内存，不承诺刷新恢复未送达内容。

## 7. 交付与接受

[计划17](../plan/17-画布数据库持久化与DAG实施计划.md)按设计14建立契约验证，再核对和修正实现。数据层可在真实数据库中独立验收原子性、幂等、图约束和权限；正式客户端仍遵守需求09的WebSocket唯一保存，不新增HTTP兜底。

验收必须覆盖：五类节点字段逐项读回、独立浏览器恢复、上传后图提交失败、同节点素材替换、回执丢失查证、事务故障、非法依赖、越权与归档、未知历史结构。AC-DATA-04保留必要的备份/恢复和旧数据保护验证，不再单列重复迁移方案。

通信及OT分别按PRD08、09接受；完整联合通过前不得宣称多端稳定服务。旧运行记录仅证明其当时版本与环境。

## 8. 依赖与限制

容量、历史成本、备份及RPO/RTO需要部署验证；未取得数据前不承诺任意灾难零丢失或固定并发规模。接口与数据模型是目标合同，不要求无条件保留现有表或函数，也不能在未经差距核对和恢复验证时直接清库替换。
