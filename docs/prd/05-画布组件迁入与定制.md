## 1. 摘要

用户已确认按 Glowloom 规范定制画布。正式入口使用当前画布实现。

已交付的第一阶段为无限画布核心：可见渲染、文字/分组/标注线、合法编辑历史、相机往返及现有保存/创作衔接。FR/NFR和文件落点分别由需求06、设计10约束；真实业务接受和发布另记录。

2026-10-20先在独立Mock预览中验证画布操作与保存重开，随后通过正式登录及项目/画布接口补验真实创建、保存重开与素材处理。两阶段均保留实际证据；收费供应商、并发冲突、混合媒体及未接合同不能据此视为完成。先行Mock决定不撤销原完整需求。

## 2. 背景

画布包含视口、节点外壳、小地图，以及真实保存和生成衔接。权限、图保存、素材身份、报价与生成执行由宿主持有。

## 3. 目标

创作者能够组织、定位、编辑和继续使用素材；编辑与保存状态真实，放大画布或遇到失败时仍能继续工作。

成功标准是需求06的 AC-CAN-01～AC-CAN-12 按适用阶段完成，并有对应工程、浏览器、数据库和业务证据。NFR-CAN-01～NFR-CAN-06 约束容量可达性、高频交互、保存可靠性、输入、生命周期和维护。组件截图不能单独代表完整产品接受。

## 4. 目标用户

| 使用者                | 主要结果                                               |
| --------------------- | ------------------------------------------------------ |
| 图片/视频等内容创作者 | 素材与草稿在同一画布中可组织、比较、引用并继续生成     |
| 返回项目继续工作的人  | 重开、断网、冲突和结果未知时能辨认状态，原编辑得到保留 |
| 前后端维护者          | 画布交互与宿主的权限、保存、素材和生成合同保持一份     |

首轮聚焦以上三类任务：组织编辑、离开后恢复和宿主一致性共同决定可继续创作。先行Mock与随后真实项目/素材接口补验分别说明覆盖；两者均不能推断未验证的供应商效果。

| 六要素                   | 内容创作者                                                         | 返回项目继续工作的人                              | 前后端维护者                                 |
| ------------------------ | ------------------------------------------------------------------ | ------------------------------------------------- | -------------------------------------------- |
| Who：谁                  | 组织图片/视频等素材与草稿的创作者                                  | 多次返回同一创作空间的人                          | 维护画布与宿主集成的人                       |
| Why：为什么              | 需要比较、分组、引用与继续生成                                     | 需要知道原编辑是否保存、失败后如何继续            | 需要交互与权限/保存/生成合同一致             |
| What before：现在怎么做  | 在既有画布与素材入口间组织内容；原迁入问题见设计10                 | 依赖既有保存/重开与错误状态辨认；频率未调研       | 宿主持有真实权限、图保存、素材与生成合同     |
| How：如何改善            | 统一视口、编辑、分组、图片处理及就近引用；Mock与真实接口分阶段验证 | 合法历史、相机往返、保存读回与明确失败/未知状态   | 复用现有保存所有者和领域限制，不复制业务合同 |

价值表述：把素材组织与继续创作放在同一画布，编辑结果可保存、可找回且遵守宿主权限。替代方式与使用频率尚无研究证据；真实生成结果不由Mock证明。

## 6. 解决方案

### 6.1 体验与设计入口

在同一画布添加、组织和比较素材，分组拖入/拖出、多选操作、下载原件，裁剪/拆图/本地缩放后作为新素材加入并继续创作；原素材保持可用。具体交互见设计10/11；先行Mock预览以独立浏览器存储验证且生产不开放，随后真实项目/素材补验沿正式登录、画布及素材接口，范围见第6.3节。

### 6.2 首轮关键能力

| 能力包               | 需求来源             | 接受场景                        | 边界                                               |
| -------------------- | -------------------- | ------------------------------- | -------------------------------------------------- |
| 工程适配             | FR-CAN-07            | AC-CAN-01、AC-CAN-11            | 现有 App Router/shadcn，依赖与许可完整             |
| 视口、选择与节点编辑 | FR-CAN-01、FR-CAN-02 | AC-CAN-02～AC-CAN-04、AC-CAN-11 | 鼠标/触控板/触摸、输入法、键盘、浮层及取消         |
| 可见渲染与媒体       | FR-CAN-03            | AC-CAN-05、AC-CAN-09            | 规模可测，合法节点可达，媒体不全量激活             |
| 文档历史与复制       | FR-CAN-04            | AC-CAN-04、AC-CAN-06            | 一次编辑一条历史，遵守已保存节点删除限制           |

每个场景的前置、动作和预期只在需求06维护，技术机制只在设计10维护。对外开放生成连接、保存后完整撤销或删除等行为变化时，先更新需求及设计，再更新本范围与计划。
