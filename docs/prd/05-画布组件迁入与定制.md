# 画布组件迁入与定制 PRD

本轮补充：按需求05 CAN-S10及设计09第11节落实节点默认连线、全能参考模式弹层、就近参考选择与自动引用。接受标准是图保存重开、引用身份/版本及防重、空来源状态、移除后的提交输入一致，以及键盘和窄屏可用；沿用现有模型、报价、确认、权限与未知结果恢复，不以UI完成宣称真实供应商接受。

状态：正式入口已切换，缺表修复和本轮浏览器接受已实施；供应商效果另验。日期：2026-10-18。需求与验收来源：[需求05](../requirement/05-画布组件迁入与定制需求.md)；唯一对应技术设计：[设计09](../design/09-画布组件实现调研与迁入设计.md)；步骤：[计划11](../plan/11-画布组件迁入验证与定制实施计划.md)。

## 1. 摘要与确认边界

用户已确认按 Glowloom 规范迁入和定制成熟画布实现，文档参照 lucky 的结构；2026-10-18 进一步要求开始实施。本轮按CAN-S06完整迁入固定BeefTV画布原件，先验证完整性，再接入宿主和定制；infinite-canvas保留对照。目录和接入顺序见设计09。

已交付的第一阶段为无限画布核心：可见渲染、文字/分组/标注线、合法编辑历史、相机往返及现有保存/创作衔接。FR/NFR和文件落点分别由需求05、设计09约束；真实业务接受和发布另记录。

## 2. 背景

当前画布已有成熟来源的视口、节点外壳、小地图与真实保存/生成衔接。继续手写所有缺失机制会增加基础交互维护成本；完整搬入上游应用又会引入本地存储、任务和凭据等重复合同。详细现状和固定来源只维护在设计09，不在此重复技术字段。

## 3. 目标与成功标准

创作者能够组织、定位、编辑和继续使用素材；编辑与保存状态真实，放大画布或遇到失败时仍能继续工作。维护者能够说明每个迁入功能的来源、依赖、改写和验证，沿一个固定主来源持续维护。

成功标准是需求05的 CAN-A01～A12 按适用阶段完成，并有对应工程、浏览器、数据库和业务证据。CAN-N01～N06 约束容量可达性、高频交互、保存可靠性、输入、生命周期和维护。上游 CI、单测或截图不能单独代表完整产品接受。

## 4. 目标使用者与价值

| 使用者                | 主要结果                                                       |
| --------------------- | -------------------------------------------------------------- |
| 图片/视频等内容创作者 | 素材与草稿在同一画布中可组织、比较、引用并继续生成             |
| 返回项目继续工作的人  | 重开、断网、冲突和结果未知时能辨认状态，原编辑得到保留         |
| 前后端维护者          | 复用成熟功能包，个性化集中在宿主接缝，避免多套状态和业务执行链 |

## 5. 需求与功能范围

| 能力包                   | 需求来源     | 接受场景          | 边界                                                 |
| ------------------------ | ------------ | ----------------- | ---------------------------------------------------- |
| 迁入来源、依赖和工程适配 | CAN-F07      | CAN-A01、A11      | 固定 SHA，现有 App Router/shadcn，必要依赖与许可完整 |
| 视口、选择与节点编辑     | CAN-F01、F02 | CAN-A02～A04、A11 | 鼠标/触控板/触摸、输入法、键盘、浮层及取消           |
| 可见渲染与媒体           | CAN-F03      | CAN-A05、A09      | 规模可测，合法节点可达，媒体不全量激活               |
| 文档历史与复制           | CAN-F04      | CAN-A04、A06      | 一次编辑一条历史，遵守已保存节点删除限制             |
| 分组、连接与兼容         | CAN-F05、F08 | CAN-A07、A12      | 世界坐标及原受保护关系不丢失，不将视觉线当生成依赖   |
| 保存与正式创作衔接       | CAN-F06、F08 | CAN-A08、A10、A12 | 原身份/项目/版本、幂等、冲突、报价与结果采用         |

每个场景的前置、动作和预期只在需求05维护，技术机制只在设计09维护。对外开放生成连接、保存后完整撤销或删除等行为变化时，先更新需求及设计，再更新本范围与计划。

## 6. 交付与验证边界

已实现核心图编辑、可见渲染、历史与相机合同，沿现有素材/生成入口接入。工程和隔离 API 浏览器样本先验证；数据库、混合媒体规模和供应商接受分别记录，不调用收费模型充当默认回归。

用户随后确认即梦完整一致性目标，需求05 CAN-F09～F12覆盖全部状态、功能、手势、快捷键与浏览器接受，字体使用Vercel Geist。Agent和导演台进入目标；时间线已按CAN-S05移出，当前仍缺少部分完整执行能力；不能用第一阶段完成关闭本专项。远程插件和多人实时协作不因上游包含自动进入范围。

原件范围包含四个画布根目录及必要依赖、资源、原测试和许可，不能只搬视口或只留占位入口。原件迁入、原始检查、宿主切换与产品接受分别记录；原始AntD/store仅用于基线复验，最终界面沿shadcn与现有富文本。

## 7. 未决事项与接受状态

普通资源节点删除和撤销已实现，受保护业务节点继续遵守领域限制；视觉标注线不升级为生成依赖。真实数据库已完成备份、恢复演练和迁移应用。参考图片上传、提及、保存重开及本轮布局交互已通过浏览器接受。收费生成效果、视频/音频播放规模及目标设备固定性能阈值另行接受；证据见计划11，不将部分样本当全部上游功能或供应商效果接受。
