## 1. 摘要

让创作者在真实项目画布中，通过一致的图片、视频、文本和浮层组件完成素材组织、引用、编辑与继续创作。重点是拖动和连线反馈清晰、编辑器不遮挡当前节点、上传素材直接展示内容，以及输入和保存上下文持续保留。

交付顺序为设计文档 → Figma设计稿 → 代码 → 真实项目验证。Mock预览不属于产品功能，本版清理其页面、入口及冗余控件。

## 2. 背景

当前问题集中在同类节点使用不同编辑入口、上传素材出现多余面板、节点靠近底部时被pop遮挡、拖线时目标端口不可见，以及重复选中装饰和技术信息干扰。用户需要在移动节点、编辑正文和选择参考时使用同一套规则。

现有图文档、授权素材、保存、协同与生成服务继续承担原职责；本版统一交互和组件，不通过界面改动改变节点身份、引用版本或生成权限。

## 3. 目标与成功标准

| 关键结果             | 本版验收目标                                                                                                | 证据                                          |
| -------------------- | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| KR-CAN-01 一致编辑   | 图片、视频、文本三类节点符合AC-CAN-20；上传素材无下方pop，展开/收起不丢内容或历史                           | Figma实例、组件回归及真实项目浏览器操作       |
| KR-CAN-02 可控交互   | AC-CAN-21～23场景全部通过；50%、88%、100%、200%缩放下连线共点，浮层不遮挡所属节点，取消不误改图             | 几何/手势回归和浏览器实测，未覆盖设备单独标明 |
| KR-CAN-03 可继续创作 | 上传、库选择、引用、连接、编辑、保存和刷新读回串联；AC-CAN-24通过，无预览产品入口、重复草稿或原始错误码正文 | 正式接口回执、保存后读回、恢复场景及入口检查  |

以上为本版完成条件，当前不声明已经达到。引用防重、恢复及数据不丢失为发布必需条件；2000节点/4000边是既有协议上限，不作为已测流畅性能指标。不编造增长、满意度或固定工期目标。

## 4. 目标用户

| 用户任务                   | 问题与优先范围                                                                   |
| -------------------------- | -------------------------------------------------------------------------------- |
| 在项目中组织素材并继续创作 | 图片、视频、文字需要统一选择、编辑、连接和引用规则；首轮覆盖三类节点及资产库入口 |
| 返回已有项目继续编辑       | 需要恢复正文、引用和位置，加载或连接失败时保留工作；首轮覆盖保存刷新与原草稿恢复 |

使用频率与发布后的满意度尚无测量；维护成本通过共享组件和单一业务合同控制，不另设面向维护者的产品功能。

## 5. 价值主张

| 要素           | 组织素材并创作                                           | 返回项目继续编辑                                       |
| -------------- | -------------------------------------------------------- | ------------------------------------------------------ |
| 谁             | 同时处理图片、视频和文本的创作者                         | 多次打开同一项目的创作者                               |
| 要完成什么     | 比较素材、建立参考并继续编辑                             | 接续上次内容并安全恢复异常                             |
| 当前方式与障碍 | 在节点、生成面板和素材入口间切换，操作与展示不一致       | 依靠现有保存与加载反馈判断是否恢复，故障可能打断编辑   |
| 如何改善       | 统一节点、富文本、端口和就近浮层，素材来源直接展示内容   | 保留同一草稿与来源身份，保存后读回，失败就近重试       |
| 得到的结果     | 同一画布内完成添加、连接、提及和编辑，减少重复操作       | 刷新后继续原内容，失败不会被当作空草稿                 |
| 可选替代       | 下载到文件夹手工整理；统一画布可保留素材关系与创作上下文 | 手工复制或另存快照；原草稿恢复可避免重复创建与重新绑定 |

价值表述：创作者用一套操作组织和编辑不同内容，在移动、缩放、刷新及失败恢复后继续使用同一项目上下文。替代方式是任务层面的对照，不代表已完成市场调研。

## 6. 解决方案

### 6.1 核心流程

打开真实项目 → 上传或从资产库选择图片/视频 → 在对应媒体节点直接预览 → 拖线连接创作节点 → 在正文用`@`提及已连接参考 → 编辑并保存 → 刷新后继续。文本节点单击选中、双击进入正文编辑；展开/收起保持原会话，菜单和参数在当前操作位置打开。

Figma沿现有文件、主组件和状态实例更新，覆盖清单由[设计10第732节](../design/10-画布组件实现调研与迁入设计.md#732-设计稿与实现承接)维护；尺寸、定位和输入规则由设计维护，PRD不重复定义数值。

### 6.3 技术与业务边界

复用媒体、富文本和基础浮层组件；正文与提示词按用途配置能力，纯操作菜单不挂载编辑器。图变更通过既有命令提交；上传及引用沿正式素材身份与版本校验；生成沿模型能力、报价及明确确认流程。保留受保护节点、只读关系、未知结果查证和协同恢复约束。

### 6.4 假设与待验证项

- Figma状态与实际组件需本轮逐项核对，旧截图和旧通过记录不证明本版一致。
- 真实账号、可写测试项目、图片/视频样本及接口可用性在验收前核对；缺少某项只阻断对应场景，不伪造回执。
- 软键盘、触摸与目标设备性能需要实际环境。供应商生成效果与收费执行独立接受，不作为此次默认测试动作。
- 团队投入、迭代周期和故事估算未提供；计划列出顺序和退出条件，不承诺日期或容量。

## 7. 交付与发布

第一版覆盖P-CAN-01～07，先完成文档，再同步Figma并核对状态，随后实现和真实项目验收。功能授权与团队容量承诺分别记录，推进顺序见设计11。

本版不新增Mock产品预览、第二套编辑器/画布引擎、时间线、任意插件运行时、缺少正式合同的AI图像工具或工作流。已有业务能力、测试夹具与真实用户数据保留；清理旧实现前核对消费者和恢复用途。

发布条件：设计稿与实现对应；本版矩阵无未关闭的内容丢失、引用错绑、重复提交或主要操作不可达问题；工程和真实浏览器证据分别齐备。旧能力证据见[设计10](../design/10-画布组件实现调研与迁入设计.md)及[设计11真实补验记录](../plan/14-画布迁移实施方案.md#6-后续真实画布验收补充2026-10-20)，保留原覆盖范围。提交、推送与发布按实际授权执行，不因文档更新视为完成。
