## 1. 摘要

让创作者从统一工作台浏览内容、输入想法、选择项目并继续创作，在页面和创作类型之间切换时保留输入，清楚知道哪些能力可以使用。把现有共享布局、首页富文本、内容浏览和计费入口连成可验收的用户流程。

## 2. 背景

设计09和设计09已有用户指令、设计与多批实现记录，却缺少统一的产品范围和验收编号。本PRD依据需求11整理这些既有要求，避免把视觉落地误认为生成、钱包或支付服务已经开放。七类Tab、积分页和模型控件的存在均不足以证明相应业务完成。

## 3. 目标与衡量

| 目标                      | 判断口径                                     | 基线与目标                                             | 观察与证据                                                   |
| ------------------------- | -------------------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------ |
| KR-WB-01 开始创作不丢输入 | 输入→切模式→登录/选项目→恢复，含保存失败场景 | 发布前全部适用AC-WB-04/05/07通过；历史局部证据见设计09 | 每次相关版本开放前验证；记录浏览器、接口回执及恢复内容       |
| KR-WB-02 换页仍能操作     | 桌面/窄屏导航、搜索、主题、认证和焦点路径    | 发布前AC-WB-01/02/03/09通过；完整设备矩阵尚未接受      | 指定视口与键盘/IME检查，自动与人工结果分别记录               |
| KR-WB-03 正确认识可用性   | 私有数据范围、错误/空状态、未开放能力展示    | 发布前AC-WB-06/08通过；实际漏斗基线未知                | 后续统计开始编辑到成功继续原项目的比例；目标与观察周期待确定 |

## 4. 目标用户

首轮聚焦准备开始创作的访客，以及已有项目、需要找回输入和素材的登录创作者。管理员仍使用既有授权入口，不在本专项重做后台治理。无访谈或量化使用基线，不推定所有用户偏好。

## 5. 价值主张

| 六要素                   | 访客/初次创作者                    | 已有项目的创作者                                 |
| ------------------------ | ---------------------------------- | ------------------------------------------------ |
| Who：谁                  | 浏览灵感并尝试输入的人             | 在首页、资产与画布间切换的人                     |
| Why：为什么              | 希望开始前理解能力与登录要求       | 希望继续原工作而非重新整理材料                   |
| What before：现在怎么做  | 各页入口和功能可用性需要分别判断   | 分别进入页面找项目、素材与草稿                   |
| How：如何改善            | 统一输入、认证恢复与不可用说明     | 一致导航、明确搜索范围、项目与草稿衔接           |
| What after：之后得到什么 | 登录或选项目后保留输入，知道下一步 | 找回正确对象，切换不串输入和私有结果             |
| Alternatives：替代方式   | 先在外部记录文字再进入产品         | 手动记住项目并重复寻找素材；统一流程减少重复操作 |

## 6. 方案与接受

### 6.1 核心旅程

浏览公开内容 → 输入 → 切换创作类型 → 登录或选择项目 → 使用真实模型/引用/报价 → 进入生成或继续主画布。未开放类型给出原因；认证、保存和网络失败保留输入及可恢复入口。搜索范围随页面变化，画布维持沉浸工具栏。

设计与Figma版本入口沿设计09及设计09原记录，本次未重新核验设计稿。实现不得把这里的旅程变成第二套身份、草稿或生成状态机。

### 6.2 首轮能力与交接

| 能力                    | 用户结果及接受                   | 计划故事 | 专项边界                                    |
| ----------------------- | -------------------------------- | -------- | ------------------------------------------- |
| 共享导航、搜索、主题    | FR-WB-01～03/09；AC-WB-01～03/09 | ST-UI-01 | 身份/权限沿PRD01                            |
| 首页输入与开始/继续创作 | FR-WB-04/05/07；AC-WB-04/05/07   | ST-UI-02 | 编辑器PRD02、AI PRD03、项目PRD06、画布PRD05 |
| 公开内容与私有列表      | FR-WB-06；AC-WB-06               | ST-UI-03 | 上传沿PRD04；完整资产/主体生命周期不在本批  |
| 账号计费入口与综合接受  | FR-WB-08/09；AC-WB-08/09         | ST-UI-04 | 钱包/支付未开放；不以原型余额作为真实数据   |

### 6.3 技术与运营边界

复用共享布局、官方组件和现有页面API；费用、项目、媒体及权限仍来自原服务。页面外观调整不更改人民币预算、实际结算、个人/团队归属或已撤销权限。真实生成和支付由对应业务接受决定开放，禁止以UI验收替代。

### 6.4 假设与未决

| 未决                       | 影响                           | 关闭方式与职责                                     |
| -------------------------- | ------------------------------ | -------------------------------------------------- |
| 团队/邀请入口历史范围冲突  | 影响导航范围定稿               | 产品与身份职责按设计09第83节核对确认               |
| 未开放模式、钱包与会员合同 | 影响按钮可执行性和费用展示     | 业务职责提供完整合同及真实接受，之前保留不可用状态 |
| 用户漏斗和设备覆盖         | 无法承诺转化提升或全部设备通过 | 产品/测试建立基线，记录人工可访问性及真实业务证据  |
| 排期与人员容量             | 不能把已有故事当成新迭代承诺   | 设计09按就绪与容量确认；责任人尚未指定             |

## 7. 交付与发布

首轮为统一布局→公共状态→首页和内容页衔接→计费边界→逐条接受；已有实现不重新排为未开始，剩余项按设计09证据补齐。后续候选为其他生成能力、资产/主体完整管理、会员支付和社区；需各自产品定义与合同，不因入口已有而自动承诺。

发布前核对AC-WB-01～09及所依赖专项的适用接受；如果发生丢输入、跨账号数据、权限绕过或假费用展示，暂停相关入口并保留原草稿/任务供恢复。历史工程、浏览器和真实接口记录可引用，未测场景继续标记未接受。本次新增PRD及编号未获得新的产品接受或发布授权。

## 8. 全局设计一致性承接

FR-WB-10/11、AC-WB-10/11纳入现行范围：统一普通页面外壳与同类型容器；全局复用富文本，新建生成输入默认全能参考；基础UI采用现有shadcn Radix Nova、语义token与Vercel界面可用性规则。尺寸、模式能力边界及组件映射见设计09第75节。交付顺序为文档→Figma→实现→真实验收；本轮只交付设计更新，不开放新模型能力或改写已有草稿。设计09记录状态与证据。
