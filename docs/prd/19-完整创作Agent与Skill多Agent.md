## 1. 问题、用户与价值

创作者需要从想法或剧本出发，形成结构化角色/场景、分镜、镜头、声音、可编辑时间线和成片。当前入口按独立 Agent 合同实施；原单图阶段和自写图测试不属于当前产品接受证据。

目标在 agent 中使用 TypeScript 和官方 Pi Durable 独立运行；会话、run、计划及子 Agent 状态由 Agent 单独拥有，Go 只保留权限、模型出站、审批、计费、工具与业务数据权威。复用 PostgreSQL 实例，schema/角色隔离，内部 HTTP 通信；统一 Compose 启动，独立构建和重启。项目不再依赖 Temporal，普通业务任务有数据库驱动的 Go 执行器。减少运维依赖的同时，保留完整创作与真实恢复能力。

服务统一命名 agent，目标技术基线由设计32 §7.1.2 唯一维护。NestJS 迁移的接口注解和验收见[设计37](../design/37-Agent服务目录与TypeScript规范设计.md)。

## 2. 完整范围与非目标

1. 官方 Harness 的模型/工具循环、持久化会话、上下文压缩、请求去重及恢复。
2. 版本化计划、依赖、产物条件、用户接管、提案立即停止推进与审批接续。
3. 连续写链、画布/价格双版本校验与请求前的现场差异。
4. 真实多 Agent：制作人统筹，编剧、美术、分镜、镜头、声音、剪辑与质量检查专业角色具有独立上下文和受限工具。
5. 完整 Skill 包发现、导入、校验、安装、启停、版本选择、更新/回退、私人改写、导出和受控发布；按需加载，脚本经实际配置的隔离设施执行。
6. 规划、压缩、子 Agent、生成与脚本的统一预算/费用；参数和模型版本冻结，缓存按实际能力计量。
7. 真实媒体检查、产物归档/绑定、时间线组织、工程导出及继续精修。
8. 移除所有 Temporal 执行依赖；各原后台任务保持成功、失败、取消和恢复的业务语义。
9. 新系统只维护当前一套合同；旧任务在切换前清结/对账，旧记录离线保留，不提供旧历史读取、旧工作流接续或双轨执行。
10. 主Agent在既有授权内自动匹配Skill、形成任务书、并行委派、回收并验证结果；用户能看懂当前步骤、卡点和交付物，不必手工调度每次调用。
11. 作为客户端接入外部MCP：配置/授权/发现/启停、tools/resources/prompts区分、受权调用及结果归一、长任务查询与未知副作用恢复。站内工具和外部工具共用预算与动作回执边界。
12. 任务完成/人工决定/到期重查可唤醒原等待点；显式事件/定时规则有授权、预算及去重，具体规则产品范围仍需接受，不默认开启无人值守消费。

非目标：任何旧引擎/接口/配置/数据格式兼容、自动回退与旧记录产品入口、自写 Pi/LangGraph 替身、Go 托管 Node 子进程或两侧重复维护 Agent 执行状态、SQLite/JSONL 生产存储、任意宿主 shell、模型训练或自动发布到外部平台。本轮不顺带替换账号、团队、Kafka/Redis 或对象存储体系。

## 3. 产品路径与状态

路径：提交目标/剧本及参考和授权范围 → 主Agent规划、匹配Skill → 必要范围确认 → 自动委派专业子Agent及调用站内/MCP工具 → 持久等待/自动回收 → 生成或重大修改按原提案合同批准 → 归档并按规则或人工采用 → 验证可编辑工程/成片并交付。已经覆盖的动作不反复询问是否继续；新权限/费用/版本冲突仍按原合同处理。

面向用户的状态为已受理、规划、执行、等待批准、已暂停、待核对、失败、已停止、已完成。Pi 任务、业务 operation 与媒体 job 分别保留自身状态；界面投影不伪造共同的“成功”。刷新和重连恢复同一运行，等待批准不会因Agent 服务重启自动变成批准。

## 4. 用户故事

- US01 目标与计划：导入长剧本，查看可修改的分解计划、依赖和来源位置。
- US02 提案把关：生成或重大覆盖前展示候选和费用范围；确认前不推进相应动作。
- US03 协同与接管：用户修改场景/角色后，Agent 感知变化并重新对齐，已采用结果不被静默覆盖。
- US04 连续编辑：同轮连续创建分镜/节点，版本延续合法；外部修改仍触发冲突保护。
- US05 故障接续：关闭浏览器、重启 Agent 服务、重复输入后查看原运行，已执行工具和已接单生成不会重复提交。
- US06 专业协作：并行执行独立子任务，失败可局部重做，停止父任务时受控取消关联子任务。
- US07 Skill 管理：安装/选择固定版本，了解所需能力；进行中的任务不因更新静默改变规则。
- US08 后台处理：导出、转写、复制、归档与清理在离开 Agent 页面后仍能执行/取消/恢复。
- US09 统一切换：旧任务在发布前清结/对账，新系统只使用当前入口与状态；旧记录离线保留，不实现旧聊天/旧运行时的产品兼容。
- US10 自动协作：一次提出广告目标，系统自行选用已授权方法、委派脚本/美术等分支、等待镜头并组织声音和时间线，必要时让我选择，不要求我手工逐一调用。
- US11 外部能力：连接一个获准MCP服务，查看可用能力和作用域；Agent可用它检索资料/处理素材，外部服务失效时能看见原因，其他工作仍可继续。
- US12 稳定推进：离开页面或重启后，原等待点恢复；第三方已执行但响应丢失时不会自动重复执行，我能查看原结果、未知状态和可处理方式。

## 6. 测试场景

- ST-AH-01：从产品 API 创建 run，观察官方 Harness 的实际模型—工具—模型循环。
- ST-AH-02：提案后同一 run 整个父子 Agent 树停止新模型/写工具/委派；其他 run 不受影响。已授权在途请求只收集原回执。审批重复、并发提案的串行受理、驳回、过期和版本变化均有确定结果。
- ST-AH-03：同轮三次合法写入，回执 revision 接续；中间插入外部写触发真实冲突。
- ST-AH-04：修改画布，核对下一请求包含正式读取所得差异。
- ST-AH-05：循环、超预算及假死流触发限制，重启不重置额度。
- ST-AH-06：挂起、正在模型调用及工具业务已提交三个窗口分别 kill 后恢复。
- ST-AH-07：Skill 安装至导出生命周期、确切版本和资源哈希。
- ST-AH-08：官方两个子会话独立工作、父子取消、依赖顺序与结果回收。
- ST-AH-09：重复提交/重复批准/重复事件，仅产生原业务记录与原资金预留。
- ST-AH-10：压缩及宿主重启后，目标、Skill、计划与未决提案保持。
- ST-AH-11：长剧本分片合并、来源定位及用户修订。
- ST-AH-12：第三方脚本真实隔离、超时和无执行设施拒绝。
- ST-AH-13：规划/压缩/子 Agent 成本纳入同一预算。
- ST-AH-14：执行前撤权、价格变更、项目状态变化阻止副作用。
- ST-AH-15：图片/视频/音频实际读取与审核依据，不能仅检查 URL。
- ST-AH-16：归档、画布绑定、时间线、FCPXML/其他已支持工程导出与可解码成片。
- ST-AH-17：协作变动只重做受影响部分，已有结果保持。
- ST-AH-18：无 Temporal 条件下覆盖设计32 §7.7 全部后台任务。
- ST-AH-19：定时维护停机后补扫、并发领取与取消收尾。
- ST-AH-20：官方 Storage 全套一致性及真实 PostgreSQL 提交结果未知/断连/单写者恢复。
- ST-AH-21：SSE 重连补读、慢客户端和 Stop 与后续新输入竞态。
- ST-AH-22：新构建只存在当前引擎/API/配置/schema 合同；旧格式、旧入口和旧配置明确拒绝；无历史读取器、旧任务接管、双读双写或自动降级，旧数据未被擅自删除。
- ST-AH-23：Agent 服务单独重启/不可用、协议不符及旧 epoch 延迟请求；普通 Go API 仍可访问，Compose 无相互健康等待或 Go 启停 Node 的路径。
- ST-AH-24：父子会话共用根 owner/epoch；grant 续租或新 owner 注册不能解除审批/撤权/Stop。
- ST-AH-25：Go 控制决定持久化后投递丢失、重复、乱序和 Agent 应用后确认丢失；迟到 approve/resume 不能越过后来的 Stop。
- ST-AH-26：Pi 提交与事件生成间故障、snapshot/cursor 一致性、过期游标补快照及连续订阅不漏事件。
- ST-AH-27：Go/Agent 数据库角色相互拒绝跨 schema 访问，内部接口拒绝外部身份/伪造 scope，合同生成一致。

## 7. 假设、风险与接受限制

官方 Pi Durable 为实验 API，自定义 PostgreSQL Storage 与内部 HTTP/流式合同是本项目必须验证的边界；采用官方 Harness 不等于具备原生 PostgreSQL 或跨进程副作用原子性。

设计批准、工程测试、隔离基础设施验证、实际模型计费与完整创作产品接受分别记录。历史测试和原有完成标签只适用其原版本，不能替代本次迁移接受；不因框架安装、fixture 成功或类型检查通过宣布完整 Agent 已完成。
