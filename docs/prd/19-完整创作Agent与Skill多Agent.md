# 完整创作 Agent、Skill 与多 Agent PRD

唯一来源设计：[设计32](../design/32-完整创作AgentHarness与Skill多Agent架构设计.md)。用户原始要求沿设计追溯至需求19。本文定义范围与产品接受；具体状态/接口/权限/数据合同归设计32，可执行验证归[Plan28](../plan/28-完整创作Agent与Skill多Agent实施计划.md)，实施状态只见 [BACKLOG](../../BACKLOG.md)。状态：评审稿，未表示功能已实现。

## 1. 问题、用户与价值

创作者需要把想法或剧本变成能继续精修的短剧工程。仅有聊天、生图入口、单个模型请求，无法处理跨阶段素材一致性、专业分工、长任务恢复与局部修改。团队还需要复用创作方法，同时控制私人会话、共享工程、模型费用和第三方 Skill 的执行范围。

产品提供一个完整创作工作区：可见计划与待确认内容，专业 Agent 承担独立任务，Skill 承载可复用方法，结果仍保存为有版本的业务工程。成功标准是工程和产物可用、可继续、可追溯，不能用回复自然或SDK已安装代替接受。

## 2. 完整范围与非目标

完整交付包含：成熟 SDK Harness、持久会话/计划/工具、实际多 Agent 与剧本解析、Skill 包及生命周期/资源/隔离脚本、模型/业务桥与统一预算、可恢复的任务面板、版本化分镜与镜头、声音/时间线/成片交付，以及旧数据与部署升级保护。

不包含模型训练、开放宿主机任意 shell、自动向外部平台发布、默认让子 Agent 无限花费或跨项目行动。对外 MCP/CLI 可在相同工具权威之上另行扩展，本PRD不以其替代站内运行。

完整目标可分切片实现，但任何切片完成都只能声明其范围。脚本沙箱、分镜领域或真实供应商未验证时，不能标记整个产品完成。

## 3. 产品路径与状态

创作者进入同一 Agent 会话，选择目标、参考和已启用 Skill。系统先做免费确定性预检，检查模型、工具、Skill依赖与权限；缺项时指出具体项并保留输入。用户明确批准有限规划预算后，协调 Agent 才调用模型提出计划；计划审阅及执行预算批准是另一确认，媒体生成默认还须确认具体报价。 规划阶段仅可读取GoalManifest授权的上下文及选中Skill，不可生成、运行脚本、写业务提案或委派子Agent；解析Agent在有限执行计划获批后启动。

工作区持续展示根运行、专业 Agent 树、计划版本、步骤、费用、待确认项、业务任务及产物。执行无需浏览器持续在线；重开页面恢复同一 Run。用户可以修订计划、补充要求、暂停、停止、拒绝提案、采用结果或只重做一个步骤；已提交请求的参数不被悄悄改变。

系统分别表达等待确认、等待任务、依赖受阻、权限失效、预算/执行限额、版本冲突、待对账、部分完成与完成。停止后如仍有供应商任务，保留实际状态和可能费用；最终完成需要当前计划约定的产物与交付回执。

## 4. 用户故事

下列故事均来自设计32，确认条件是本稿的验收标准，不表示已完成实测。

### US-AH-01 目标与计划

作为创作者，希望把目标转成可修改的计划，以知道将生成什么及何时需要我确认。来源：设计32 §7.3～7.6。讨论：目标支持想法、剧本与授权参考；计划改变扩大范围时旧批准失效。确认条件：显示步骤/依赖/产物和费用边界，缺能力保留输入，非法/有环计划拒绝，拒绝后无新增副作用。追踪：ST-AH-01/02。

### US-AH-02 专业分工

作为创作者，希望协调 Agent 委派真正独立的专业 Agent，以并行推进并理解各自产物。来源：§7.9。讨论：子会话独立、权限/预算收敛，不能只在聊天中更换角色名。确认条件：可看Agent树/输入输出/状态，重复委派返回原子任务，失败保留其他成功结果，父取消传到后代且不误报外部任务取消。追踪：ST-AH-03/04/05。

### US-AH-03 剧本解析

作为编剧，希望从长剧本得到有来源定位的分集、场景、人物和台词结构，以便核对和修订。来源：§7.10。讨论：同名、代词、说话者不明需提示；原文版本改变使提案失效。确认条件：分片合并不重复、不丢来源定位；错误结构不能采用；人工修订、采用与版本比较可用。追踪：ST-AH-06。

### US-AH-04 Skill 获取与管理

作为创作者，希望导入/安装/启停/更新/回退与改写Skill，以复用方法且保持可控。来源：§7.8。讨论：安装、活跃与公开发布互相独立。确认条件：查看来源commit、版本、资源、依赖/权限与不兼容原因；更新不替换运行中的pin；私人fork不改原包；送审/公开有明确操作。追踪：ST-AH-07/08/09。

### US-AH-05 Skill 在运行中生效

作为创作者，希望选择的Skill在长会话和恢复后仍按固定版本工作，以避免方法被摘要丢失。来源：§7.8。讨论：Skill不能授予权限；紧急撤销与普通禁用有不同语义。确认条件：正文按需加载，辅助文件可授权读取，压缩/重启后保持同一pin；释放/替换有修订与确认影响；撤销即时阻断新增动作。追踪：ST-AH-10/11。

### US-AH-06 Skill 受控脚本

作为创作者，希望执行Skill明确声明的加工脚本，以扩展创作而不暴露工作区和凭据。来源：§7.8。讨论：未配置沙箱时必须阻止依赖步骤；脚本有成本和资源限制。确认条件：真实隔离、限额、取消/未知恢复与产物归档可测；不能访问其他项目、宿主文件、密钥或未批准网络。追踪：ST-AH-12。

### US-AH-07 模型、授权与费用

作为付费创作者，希望所有Agent、模型和工具只在我批准的范围内执行，以控制花费和数据。来源：§7.4/7.6/7.7。讨论：压缩与子Agent消耗计入根任务；一次批准不等于无限生成。确认条件：并发预留不透支；未知请求不重发；模型能力缺失不伪造；身份撤销立即阻止新副作用；Key不进入Host或前端。追踪：ST-AH-13/14/15。

### US-AH-08 工程协作与局部修改

作为团队创作者，希望AI结果与手工编辑共用同一工程，以保留版本并只重做受影响部分。来源：§7.7/7.11。讨论：私人对话不随共享资产公开；陈旧版本不能自动覆盖。确认条件：通过正式应用命令保存，修改角色/镜头展示失效后代，冲突可比较/重新提案，成功素材保持可读。追踪：ST-AH-16/17。

### US-AH-09 检查与成片

作为导演，希望看到实际媒体检查和可播放成片，以判断创作是否满足要求。来源：§7.11。讨论：编码检查、模型评价和人工接受不同；taskID不是完成。确认条件：实际读取媒体后才声明检查；镜头/声音/字幕/时间线对应，导出可解码，保留编辑工程与来源。追踪：ST-AH-18/19。

### US-AH-10 中断与继续

作为创作者，希望离开页面、断网或服务重启后继续同一任务，以免重复生成与丢失结果。来源：§7.5/7.13。讨论：流式token可由快照替代，但权威业务回执不能丢失。确认条件：Host恢复原会话/工具/子任务；业务提交与SDK确认之间崩溃不重复执行；旧epoch拒绝；过期游标明确刷新快照。追踪：ST-AH-20/21。

### US-AH-11 数据与版本保护

作为已有用户，希望升级后仍能读取旧会话、查在途任务，并在回退时保住数据。来源：§7.13/7.14。讨论：旧记录不成为新引擎执行输入；跨主机恢复不能依据过期租约冒险双写。确认条件：隔离库增量幂等、旧请求不重放、SDK存储版本检查/备份恢复可演练，关闭新准入不破坏已有运行。追踪：ST-AH-22/23。

### US-AH-12 可用界面与治理

作为创作者/管理者，希望通过清楚可达的界面选择Skill、审阅任务和处理异常，以使桌面与手机都能完成流程。来源：§7.12。讨论：管理员不自动读取私人聊天。确认条件：键盘/焦点/触控、长内容、错误恢复与状态标识覆盖；观察工具与行动依据，不展示内部隐含推理或秘密。追踪：ST-AH-24。

## 7. 假设、风险与接受限制

选择成熟 SDK 是路线确认，不是供应商质量或实验SDK稳定性的证明。SDK升级、存储单写者、模型网关与费用对账、沙箱部署和跨版本工程采用是独立风险，技术控制见设计32。角色/Skill命名、初始限额为可评审设计默认值，不是创作效果保证。

产品接受须包含真实Host、隔离业务库、实际媒体与至少一个有预算的真实供应商闭环；受控模型验证故障和边界，真实供应商验证兼容与费用，两者均不能替代人工创作接受。具体模型无权限、余额不足或沙箱不可用时，记录未完成项而不是降低“完整”定义。
