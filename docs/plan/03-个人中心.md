# 个人中心 Implementation Plan

> 唯一来源 PRD：[01-用户系统](../prd/01-用户系统.md)。技术合同沿其来源设计；实施进度、优先级、估算、承诺及阻塞只见 [BACKLOG](../../BACKLOG.md)。

**Goal:** 让本人真实保存资料、头像、偏好、换绑邮箱及管理设备。

**Architecture:** identity本人用例只修改当前账号，media负责头像验证与重编码；复用01会话和事件。界面按服务器读回展示成功。

**Tech Stack:** 既有Go/Gin/GORM/PostgreSQL与Next.js/React/shadcn/Radix/Vitest。

**Spec:** [SRS](../requirement/02-用户系统需求.md)、[数据库](../design/02-用户系统数据库设计.md#31-文首来源与范围)、[接口](../design/03-用户系统接口设计.md#31-文首来源与范围)、[PRD](../prd/01-用户系统.md)。

## 4. 文件与依赖

当前实现证据：本人资料、偏好、会话、头像和双邮箱换绑已有实际后端合同，前端通过生成客户端接入。账号页分别实现原图选择/显式裁剪、授权预览、CAS绑定及读回、清除头像，双邮箱分侧验证与取消/完成，以及会话、偏好和即时软注销。组件回归覆盖上传失败保旧、HTTP null解绑、双证明完成、401清理与迟到响应。正确的既有密码通过正常验证后建立普通会话，不以旧改密标记强制进入改密页；主动修改和邮件恢复仍保留。真实邮件、对象存储图片及多设备/手机浏览器接受由综合验收记录，不能仅凭本地门禁将T-USER-05、T-USER-06、T-USER-07整体标记接受。

新增self_profile/email_change/session_directory三组用例及各自存储/HTTP文件；账号页保留在app/account/_components，跨入口会话逻辑继续放components/auth。不建另一套全局用户store。
