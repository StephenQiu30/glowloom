# 管理页面统一与五服务接入 Implementation Plan

> 执行：本会话按 executing-plans 顺序落实。用户已明确授权设计、Figma及代码；无需逐步骤重新请求批准。未经要求不提交推送。

**Goal:** 五类管理页统一全站设计，五服务入口与 OpenAI 正式执行闭环。

**Tech Stack:** Go / PostgreSQL / Next.js16 / React19 / shadcn / Geist。
**唯一来源 PRD:** ../prd/2026-10-31-管理页面统一与五服务接入.md
**Spec:** ../design/2026-10-31-管理页面统一与五服务接入设计.md

## Global Constraints

先Figma后产品代码；五个独立鉴权入口；保存与验证分离；保留历史；不读取真实凭据、不真实收费、不提交推送。

## Review Focus

非目标预设不能占用五入口；未知保存回执仍能恢复；手机导航可滚动且焦点可见；Responses拒绝/不完整不得标成功；OpenAI报价与提交使用同一冻结release。

## Task 1：设计与 Figma

文件：需求04、本设计、PRD、本Plan、BACKLOG。Figma复用既有管理示例与最新ProductSider，建立五页统一导航/标题与入口、凭据差异、验证和移动/浅色状态，回读层级/字体并截图。

## Task 2：共享管理布局与五入口

修改 frontend/src/components/governance/admin-layout.tsx、app/globals.css、providers-page.tsx、preset-connect.tsx。复用 PageHeader；先写入口排序/非目标过滤与待确认恢复测试，执行失败再实现；共享布局覆盖五页并浏览器验证。

## Task 3：OpenAI 协议与模型目录

修改 backend/internal/catalog/domain/adapter_spec.go、providerhttp/driver_openai.go、新增官方协议驱动；测试放backend/tests/catalog。先固定Responses输入/输出/用量、不完整、拒绝、图片参数合同，再实现；更新既有协议用例的OpenAI预期，保留DeepSeek等旧协议断言。

## Task 4：发布与冻结版本

修改 catalog/adapter/postgres/model_releases.go、operation/adapter/postgres/editor_submission.go。补OpenAI增量幂等测试与发布/冻结实际数据库回归，先失败后修复。不改已有连接快照或自动启用模型。

## Task 5：验证与交付

执行对应Vitest、eslint/Prettier、tsc、Next构建、Go测试/Race/vet等门禁；浏览器检查五页及接入，记录Figma节点和实际命令结果到research/evidence/2026-10-31-admin-services/validation.md。完整diff/工作区检查，不把跳过写成通过。
