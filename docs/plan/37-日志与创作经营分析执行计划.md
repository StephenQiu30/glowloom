# Plan37｜日志与创作经营分析

唯一来源 PRD：[PRD28](../prd/28-日志与创作经营分析.md)。技术合同：[设计42](../design/42-日志与创作经营分析设计.md)。本文件定义未来实施步骤，不表示已授权执行代码、迁移或部署；调度与状态仅见 [BACKLOG](../../BACKLOG.md#logs-analytics-20261113)。

## 1. 目标与前置

交付运行诊断、审计衔接、完整创作与经营分析和受控导出。复用当前 Go、Agent、Canvas、Next.js、PostgreSQL 与业务事务/Outbox；不引入独立日志微服务、数据仓库或自助 BI。

实施前核对实际 Git 状态与部署版本，保留并行修改。准备隔离数据库与A/B授权范围、各职责账号、受控供应商/支付回执、候选/采用/导出/资金夹具。生产日志、真实用户私有正文和凭据不得复制到测试夹具。支付、会员及采购分摊缺来源时只开放可证实部分，不用生成模拟记录冒充真实经营结果。

## 3. 执行任务

### T-LOG-01｜事实清单与可执行合同

- 核对四个服务日志、错误/追踪、审计、安全事件、任务、采用、交付、支付、钱包、采购与收入分摊的实际来源。标明“已存在且可重放／仅当前快照／需新增事实／未接入”，逐项覆盖 MET-LOG-01～03、MET-ANA-01～07。
- 固定事件白名单、字段版本、错误等级、request与业务ID边界、指标分母/维度/同期群/时间窗、状态映射及权限矩阵；每项指标绑定真实表/回执/接口与唯一归属。不把本计划中的候选名称当现存表。
- 固定接收、查询、钻取与导出DTO/路径，及分页快照、范围切换/撤权语义。准备包含跨团队、重复、未知、取消、部分完成、手工路径与迟到更正的手算夹具。
- 测量代表性请求量、记录大小、实例数、表规模和查询基线；确定队列/批次/超时、进程关闭预算、连接池余量、诊断空间上限与报表查询预算，裁决DEC-LOG-01～04后回写设计。
- **退出：** 每个完整范围指标有来源、缺口、验收样例和责任领域；缺来源不能被静默删除。字段/权限/容量约束足以进入实现，未决条件只阻断对应开放。

### T-LOG-02｜结构化记录与最小诊断闭环

依赖T-LOG-01。先以AC-LOG-01～03、09写失败回归；再统一Go、Agent、Canvas、BFF的服务/版本/角色、请求完成、错误及业务关联。显式核对panic、嵌套异常、流式断开、非法ID、未匹配路由与上游返回错误。

实现有界异步摘要、内部批次身份校验/去重/限流、短期存储和查询；默认时间与分页按设计42。保留JSON标准输出，设有限轮转；健康探针不刷屏。故障测试覆盖队列满、接收失败、DB慢、进程关闭，断言不改变业务结果且丢弃可见。审计仍用原合同，不迁入短期诊断表。

**退出：** 一条获授权真实应用请求可从错误反馈定位到记录；全输出脱敏检查通过；没有因查询而触发新的外部任务。

### T-LOG-03｜质量概览与审计衔接

依赖T-LOG-02。先测多实例去重时间桶、合并直方图、进程资源/DB池缺项与缺报、HTTP/业务/attempt不同分母、未知与积压年龄。实现固定运行概览、日志列表/详情和原审计来源跳转；保留原用户系统授权，运行日志读取本身有安全审计摘要。

验证同一筛选下概览与可检索样本的差异解释：健康探针、轮询抑制、日志丢弃不被隐藏；部分采集不标全量。对诊断和审计分别做跨组织、降权、任意ID反例。**退出：** AC-LOG-01～04、08、09及11中的运行故障部分可复现，普通用户看不到内部错误详情。

### T-LOG-04｜业务事实投影与创作全流程

依赖T-LOG-01；运行采集不得成为本任务的可靠性依赖。先用AC-LOG-05、06、10、11固定精确去重与同期群预期，再接入已提交身份、项目、operation、attempt、采用、资产引用和导出回执；必要历史事实在所属提交边界补充，复用原Outbox与worker。

实现来源唯一键、重放、水位、修正和受影响时间桶重算，受限分页回补只采用可证明事实。补白名单行为接收：登录身份、限流、字段大小和事件ID去重；访问→注册按获准的站内短期匿名会话方案接入，服务端关联注册回执。测试会话到期/重复上报/已有账号登录/拒绝采集/跨设备未归因和关联清理，匿名会话数不得当真实用户数。客户端事件只用于观察而不证明收费/成功。完成 `/analytics` 创作页签及阶段/模态/模型/项目钻取；手工项目路径与Agent发起人语义独立验证。

**退出：** 用户/项目/业务/attempt/产物数量均能手算；采用、交付、复用与D1/D7正确；缺历史事件/访问数据明确显示，AC-LOG-05、06、10及11的创作部分通过。

### T-LOG-05｜经营、支付与成本

依赖T-LOG-04及所属领域可核验回执；付款/会员业务仍由原计划提供。先按AC-LOG-07、10、11固定现金、积分、采购、赠送、退款、补偿、迟到费用与收入分摊反例，再接入只读经营投影。

复用原计价/账本金额与采购版本，核对付款空间和用户去重；实现首付同期群、30日复购、现金收退款、积分批次与余额/冻结时点、补贴、已知成本覆盖及模型/渠道比较。仅在净收入分摊与可变成本齐备时展示设计36贡献利润，不自行制定新的财务分摊政策。

**退出：** 每个金额可回到已核验原流水/凭证；重复投递与更正不多算；缺支付/会员/采购分摊时相关指标标未接入/待核对。通过已有真实来源只证明该来源，不外推为完整经营接受。

### T-LOG-06｜统一钻取、授权与导出

依赖T-LOG-03～05。先测范围/口径/快照绑定、组织切换、撤权、缓存失效、越权关联及10,000行边界，再补固定筛选、趋势、明细与经营授权。依原受控导出能力实现复验、审计、CSV防公式注入和下载重授权，原始运行日志批量导出不开放。

用实际页面完成有数据/空/未接入/部分/陈旧/失败状态，键盘、焦点与窄屏核对；图表配同口径表格。**退出：** AC-LOG-08、12通过，图表到明细、导出保持同一筛选与快照；治理权限不会扩大财务或私有内容权限。

### T-LOG-07｜容量、来源与联合接受

依赖前述任务。按T-LOG-01预算执行代表性负载，观测业务请求、采集丢弃、查询耗时、数据库连接/IO、磁盘与投影延迟；注入接收关闭、DB慢、投影重启、重复/乱序更正，证明可降级与重建。容量未达标先缩小查询/保留范围并说明产品限制，不能以测试规模冒充生产容量。

浏览器贯穿原请求定位→创作生成/采用/交付→授权经营明细→CSV；数据与源库/回执逐项核对。真实付费或支付仅使用另获授权的原任务/凭证，模拟夹具不当实账接受。核验完整FR与AC覆盖，未接入的支付、会员、采用或成本依赖保留在BACKLOG，不能把部分开放签为完整需求完成。

**退出：** AC-LOG-01～12有分层证据，来源覆盖与容量限制明确；只有达到实际开放范围的指标才能发布。

## 4. 验证方法与记录

实施时先运行所属新增失败测试，再执行相关成功测试和 PROJECT 质量门禁。Go涉及范围采用 `go test -race`、vet及项目lint；Node按各服务现有脚本执行typecheck/test/build/lint；DTO变更同步OpenAPI生成与前端api检查；前端执行相关单元测试、类型/构建及实际浏览器流程。命令使用实施时的真实测试文件与项目脚本，不在文档预造不存在的测试名。

隔离PostgreSQL核对幂等、金额、授权、分页水位、并发更正与回补；单元mock不替代数据库证据。PRD每个场景记录版本/日期/环境、前置夹具、角色、实际步骤/命令、可观察计数或回执、失败与例外结果。证据存任务产物，必要结论回写本计划；状态仅在BACKLOG。

## 5. 初始化、迁移与回退

1. 在隔离空库按唯一schema初始化并验证；存量库先比对实际结构、拟议DDL、权限、索引与数据量，由部署管理员审阅精确增量。禁止直接向存量库执行完整schema，应用启动不自动建表。
2. 新采集和报表默认关闭，先接少量明确服务/范围，校验诊断缺口与业务账务无写入影响。回补按获批起点分页，可暂停/重放并核对源数量与金额；不扫私有正文。
3. 保留策略先只读演练受影响数量与空间，获准后仅清理明确短期诊断数据；审计、账本、既有媒体和项目不在清理范围。
4. 回退时停接新诊断批次、停分析消费者/回补并关闭新页面，保留标准输出和原审计/业务能力；保存水位与已接事实，不删业务记录、不回滚账本。不倒退schema；后续从原来源重放重建分析投影。
