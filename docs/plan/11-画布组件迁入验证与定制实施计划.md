# 画布组件迁入验证与定制实施计划

状态：待评审计划，本轮未启动代码实施。日期：2026-10-18。唯一交付来源：[PRD05](../prd/05-画布组件迁入与定制.md)。技术合同沿其[设计09](../design/09-画布组件实现调研与迁入设计.md)读取，验收场景沿[需求05](../requirement/05-画布组件迁入与定制需求.md)读取；本文不另定义字段、API、性能数值或业务范围。

## 1. 前置与修改边界

实施前读取 AGENTS、PROJECT、DESIGN 与专项来源，核对实际 Git 根、分支、工作区和并行修改。当前有未提交的存储专项文件，本计划不处理它们。用户未要求时不创建/推送分支、PR、标签或发布。

路线、功能包与接受值在来源文档评审；保存后撤销、分组移动与生成连接必须先明确合同。后续实现仍在当前 frontend 和已有 Go 领域内，不迁入上游后端或启动新的画布服务。

## 2. C0：固定来源与功能包

1. 按设计09核对主要候选与现有迁入版本的差异，固定 SHA；使用一个主来源，必要补丁单独登记。不追随浮动 main 或把 lucky 的批准版本当本项目决定。
2. 沿每个功能入口的 import、动态加载、样式、worker、资源、补丁及测试夹具建立依赖闭包。每条清单写明源路径、目标、改写、依赖、动作和 CAN-Axx；许可更新仅反映实际采用。
3. 核对当前可达 CanvasPage/CanvasEditor、生成 API、图命令和受保护字段。旧图样本覆盖草稿、媒体、分组、边和只读业务投影。

出口：CAN-A01 的来源/边界清单可复核，后续功能包可在当前项目内构建；没有第二套上游存储或生成调用。

## 3. C1：交互基线、渲染和媒体验证

1. 先复用现有手势测试，增加连续视口移动时新区域进入、面板锚定、失焦与取消的行为验证。仅针对需要改动的行为补测试。
2. 将空间查询、可见窗口、迟滞和媒体激活按同一坐标接入；保留输入/拖动/播放/焦点节点。必要时按测量再接 Leafer 辅助层，不预建无消费者图形框架。
3. 使用 50、200、2000 节点的稀疏/密集图和图片、视频、音频、3D 样本；加入跨视口曲线、超大组、远处节点与多选。上游 280/420/720 DOM 截取不能静默隐藏合法数据。
4. 记录设备/浏览器/主题、样本/媒体尺寸、缩放、首个可操作时间、输入到可见更新延迟分布、长任务、React 提交、挂载节点、媒体请求与可测内存。相同样本比较改前/改后，形成性能接受建议，再由产品确认数值。

出口：CAN-A02～A05、A09、A11 的适用部分有实际证据，性能问题能定位到渲染、媒体、状态或存储；不能用上游测试名中的 50k 目标作为本项目容量证明。

## 4. C2：历史、保存与相机往返

1. 为本地可编辑字段确定操作边界、before/after 与逆操作能力，区分 Tiptap、文档历史和恢复分支。已保存草稿不可删除，相关撤销明确限制。
2. 沿现有命令生成与严格回执扩展必要能力；相机先读取服务端，再按已接受策略提交，验证重开。不得重置或覆盖未知/只读字段。
3. 验证原请求键与冻结载荷、超时未知回执、重复保存、两窗口冲突、原地继续编辑、切画布/账号、撤权及迟到响应。
4. 测试复制的新 UUID、内部引用与父子映射；旧任务/采用/执行身份不继承，不因撤销或重做调用模型。

出口：CAN-A06、A08、A12 通过适用的单元、协议、真实数据库和浏览器往返；保存前/后撤销限制与真实状态一致。

## 5. C3：分组、连接与创作衔接

1. 核对 group 的世界坐标、可编辑成员集合和原子批量移动；不依靠父 transform 重复位移。组创建、移动、解组和重开验证同一结果。
2. 先接正式允许的 annotation；生成引用要沿原草稿/引用合同，必要字段回来源设计后再修改 DTO、注解和生成客户端。受保护边不可用视觉操作重写。
3. 使用现有素材读取、上传、报价、确认、生成与结果采用；先用 fixture 验证交互与协议，真实供应商按现有权限及费用授权另行接受。
4. 校验旧图与业务投影，媒体失效、结果迟到、目标被更改及取消操作均有真实反馈；每个可见动作有实际处理。

出口：CAN-A07、A10、A12，布局关系、生成引用、业务执行和结果身份不混淆。生成恢复查原任务，不借重试再次收费。

## 6. C4：工程与综合接受

实现改动后按 PROJECT 运行适用门禁；前端为 ESLint、Prettier、Next typegen、TypeScript、Vitest、生产构建；后端变更按 Go 与合同生成检查。影响依赖/播放器补丁/资源时，补全新锁定安装与镜像构建。仅文档阶段只检查格式、链接、锚点、编号及事实。

浏览器覆盖 320/390/768/1440px、深浅主题、短屏、输入法、键盘、触控板/触摸、嵌套弹层与焦点恢复；持续打开/关闭媒体和切画布验证资源释放。CAN-A01～A12 逐项记录实际环境、结果与未执行项，缺少数据库/真实媒体/供应商证据不报通过。

发布前应保留代码基线和旧图兼容证据；本轮不运行数据迁移或回退。后续若引入新字段，先评审兼容和增量迁移，不重放 schema.sql；需要回退时恢复代码并保留图和本地分支，不清理业务数据。

## 7. 本轮已执行与后续出口

本轮完成了固定源码、当前入口、lucky 文档结构、官方 SDK 文档及选型建议核验；现有画布 4 文件、12 项单元测试通过，准确命令与范围见设计09。未实施 C0～C4 的迁入任务，未运行实机性能、浏览器、真实数据库或供应商接受。

后续收口交付包含实际采用清单、源→目标与许可、CAN-A 证据、性能基线、未决能力和兼容结论。若主路线在关键场景验证失败，再以相同场景对照 React Flow；不在生产同时维护双画布引擎。
