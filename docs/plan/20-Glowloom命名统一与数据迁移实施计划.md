# Glowloom命名统一与数据迁移实施计划

用户于2026-10-21要求统一织光 / Glowloom命名，并保护原项目、主画布、素材和历史事实。

## 范围与规则

- 当前工程标识统一使用Glowloom（展示）或glowloom（机器标识）；已有LV_*变量继续作为配置接口，不另建第二套环境变量协议。无关外部服务账号和凭据不因品牌更名而改值。
- 现有项目、主画布、素材和用户标识不变。已发布提示词基线ID保持稳定，更名不让用户自定义模板变为过期。
- 当前本地使用glowloom数据库、glowloom_app授权角色、glowloom-local工作流命名空间及glowloom-media对象桶，容器卷使用glowloom前缀。
- 数据库角色采用原OID重命名并保留授权。已有数据库采用名称迁移，禁止用空库schema覆盖；原有资源在校验完整后切换配置。
- 历史审计、财务账本、已执行工作流和已导出的文件是保留事实，不能通过品牌替换批量改写私有正文或删除历史。旧资源只作迁移回退及历史档案，当前服务使用新命名；不伪称不可重命名资源已原地更名。
- 事件生产者与消费者一起切换；先核验在途工作、Outbox与所有分区消费位点。只迁移确有必要的未投递工作，不重放历史事件；infra.processed_event的逻辑消费者名不等于Kafka group，不随品牌替换。
- 名称修订不授权Git历史改写、提交、推送或生产发布。并行代码修改保留。

原命名任务按 ST-GL-01 追踪，边界与原执行清单保持一致。

## 执行与验收

- 盘点234个含旧标识的工程文件，保存任务前源码快照；源码、测试、schema、配置示例与文档统一，当前可编辑仓库扫描无旧品牌字面量。
- 素材包新标识测试先失败后通过；9个已发布提示词基线ID保持不变。
- 补充历史素材包读取、不可变结算记录回放的精确兼容测试，失败复现后通过；独立复审核对原发布标识指纹。
- 隔离参考库与运行角色使用新命名，完整后端Race、前端测试与工程门禁通过。
- 本地数据库、对象桶、工作流命名空间及容器配置按保护清单迁移，健康检查与真实画布CRUD通过。
- 当前画布30天清理计划转入新命名空间，验证只安装项目清理并经实际worker完成一次无到期对象运行。
- 更新PRD06、设计13与Plan15当前落地状态，区分源码、隔离测试、本地运行与生产接受。

## 已发布格式兼容

提示词定义通过已发布内容/合同摘要映射保留原模板UUID，新定义采用Glowloom命名种子。旧v1素材包App标识与历史结算note前缀使用精确SHA256格式指纹识别；只接受已发布旧标识或当前标识，不泛化为任意同后缀品牌。原v1结构、字段白名单、金额和摘要校验继续执行。新导出与新结算写入当前名称，历史文件及账本正文不重写；兼容测试使用归档字节夹具，不把旧品牌重新引入当前机器标识。
