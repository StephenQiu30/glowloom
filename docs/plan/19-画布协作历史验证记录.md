### 7.2 存量库升级与回退边界

唯一完整DDL仍为`backend/db/schema.sql`。空库使用它一次性初始化；存量业务库禁止重放完整schema。以下仅为本轮增量审阅清单，实施前核对实际约束名、备份与部署窗口。本轮只在独立旧schema测试库演练，不执行业务库迁移。

```sql
BEGIN;
ALTER TABLE canvas.document ADD COLUMN operation_version integer NOT NULL DEFAULT 0 CHECK (operation_version IN (0,1));
ALTER TABLE canvas.command_log ADD COLUMN op_id uuid, ADD COLUMN base_revision integer, ADD COLUMN operation_version integer NOT NULL DEFAULT 0;
CREATE INDEX canvas_operation_tombstones ON canvas.command_log USING gin(commands jsonb_path_ops) WHERE operation_version=1;
CREATE UNIQUE INDEX canvas_operation_identity ON canvas.command_log(document_id,create_by,op_id) WHERE op_id IS NOT NULL;
ALTER TABLE canvas.save_receipt ADD COLUMN status text NOT NULL DEFAULT 'accepted';
ALTER TABLE canvas.save_receipt ALTER COLUMN result_revision DROP NOT NULL;
ALTER TABLE canvas.save_receipt DROP CONSTRAINT save_receipt_result_revision_check;
ALTER TABLE canvas.save_receipt ADD CONSTRAINT save_receipt_result_revision_check CHECK ((status='accepted' AND result_revision IS NOT NULL AND result_revision>1) OR (status='rejected' AND result_revision IS NULL));
COMMIT;
```

顺序：先升级schema和支持v1的后端，再接入协议2前端。首次成功操作事务才把单文档operation_version设为1；读取/加入连接不切换。旧成功回执仍可查证，文档切换后旧CAS写入拒绝；跨缺少规范前像的旧日志须重同步。回退时暂停新写，保留新列、v1日志及接受/拒绝回执，不能将已切换文档强改回0或回滚到只懂旧回执的后端。已部署双栈后端可暂只保留读取和原请求查证，待兼容客户端恢复。没有上线、生产迁移或外部供应商接受证据时，不宣布生产可用。
