# 画布数据库持久化与DAG实施计划

> 唯一来源PRD：[07-画布数据库持久化与DAG](../prd/07-画布数据库持久化与DAG.md)。目标合同见[设计14](../design/14-画布数据与接口设计.md)，实施进度与调度仅见[BACKLOG](../../BACKLOG.md)。

## 1. 目标与顺序

按原始需求建立可靠的节点保存与读取闭环。先确认数据/接口合同和契约用例，再核对实现差距，最后实施及验证；不能先复用旧代码，再用文档解释它为什么正确。当前实施范围与状态见BACKLOG，本计划原位追加实际验证证据。

## 2. 前置与责任

数据、前端、素材和权限职责共同核对持久字段与失败结果；具体人员不预填。设计14的操作语义、协议/结构版本、媒体身份及授权原子性必须明确；计划18/19分别承接通道和转换，不重复建设保存服务。

## 3. 任务与退出条件

保留原任务ID用于追踪，按目标合同更新交付内容，不沿用旧实现路径作为强制方案。

| 任务 | 工作 | 退出条件 |
| --- | --- | --- |
| T-DATA-01 数据与读取合同 | 形成目标schema/DTO/操作契约，逐字段列权威与派生归属，再核对现有实现差距 | 五类节点与受保护历史结构可解释；同版本一致读取；未知版本不丢字段 |
| T-DATA-02 统一原子提交 | 权限、版本、回执、图、日志一次事务；确定拒绝与未知结果分离 | 并发重试一次效果；同ID不同body拒绝；提交前后故障结果可查证 |
| T-DATA-03 图与素材完整性 | 分组、标注、DAG、删除、媒体替换、输入版本保护 | 并发候选图合法；替换保留ID和边；图失败不删除已上传文件 |

## 4. 实现差距核对方法

在目标设计确定后再逐项检查现有代码和数据库：符合项也须契约验证；缺失项补齐；与目标冲突的实现修正或替换。输出按字段、接口、事务和失败场景记录，禁止把源码存在当作验收。

重点审查全图覆盖、不同版本读取拼接、回执早于事务提交、幂等键重建、只在连接时授权、媒体URL作身份、上传失败假节点、未知字段被过滤、正文/队列写浏览器持久缓存。代码路径和可复用范围在此步骤之后确定，不预建通用适配框架。

## 5. 验证矩阵

| 情境 | 必须观察 |
| --- | --- |
| 编辑→确认→独立浏览器重开 | 节点/正文/布局/分组/素材/边及版本逐项相同 |
| 上传成功，图提交拒绝 | 原节点引用不变，新素材仍可合法复用；无误删文件 |
| 提交前、中、后断线 | 零部分写入或一次接受；原ID查证；无虚假已保存 |
| 撤权/归档与保存交错 | 接受顺序有依据；之后无越权读写 |
| 非法边、依赖成环、分组循环 | 拒绝且无部分提交；普通标注环仍合法 |
| 旧节点/未知字段/旧客户端 | 原文保留，只读或明确拒绝，不静默裁剪保存 |
| 关闭、清浏览器数据、应用重启 | 数据库已确认内容可恢复；不承诺找回未送达内存 |

## 6. 交付边界

工程测试、真实数据库、正式浏览器、故障恢复和生产容量分别记录。没有目标协议的真实契约/故障证据就不能认定现有服务可靠；历史局部通过不得升级为新设计接受。各次实现和验证范围见下文；不得据局部工程通过宣称全部需求接受或生产发布。
