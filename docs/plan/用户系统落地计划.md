# 用户系统落地计划

状态：候选实施与验收计划，未进入本轮业务实现。更新：2026-10-14。依据[软件需求规格](../requirement/01-用户系统需求.md)与[系统设计](../design/用户系统设计.md)。同一账号支持个人与团队创作；平台用户管理与团队成员管理分别交付并共同验收。

## 1. 需求基线与进入条件

已确认邮箱 + 密码、注册验证邮箱、平台/团队双层管理及团队称谓。FR/BR/DR/IR/NFR 的具体规则、建议参数和发布批次按需求第 9 节审阅；接受后形成当次实施范围，不把已确认方向重复提问，也不把未定保留政策填成假定值。

每批进入条件：所需规则明确、目标设计接受、关联接口与数据变更可审阅、环境与数据操作范围明确。外部条件未满足可完成独立实现和隔离测试，但不能声称真实投递、迁移或上线通过。

每批都包含必要审计与通知，不等 D 才记录认证安全事件。D 的全局禁用不能先上线、后补“唯一团队管理员被禁用后的冻结与接管”。E 的团队界面不可在 B 的服务端隔离未完成时开放。P1 资料/偏好/治理/导出/注销仍在完整范围，允许分批但不能不记录就删掉。

共享 NFR 的证据可以复用：记录版本、环境与适用范围；新功能改变授权、容量或恢复路径时增量验证。月度可用性尚无整月观测时只接受监控与故障演练准备，不报告 99.9% 已达到。

## 3. 软件工程实施步骤

1. **需求检查**：逐条检查演员/前置/输入、正常结果、失败与权限边界；FR 有 AC，NFR 有 QA 和测量条件，BR/DR/IR 无冲突。将未决项关联具体批次。
2. **设计与契约**：核全局身份、平台角色、team/member、个人/团队资源边界、权限矩阵与迁移；从接受的设计产生 Handler/DTO/契约和客户端，不从旧单 OrgID 反推目标能力。
3. **实现与单元验证**：先覆盖唯一性、状态/角色/期限和最后管理员等核心失败路径，再实现重构；复用现有模块与工具链，不预建企业组织平台。
4. **集成验证**：隔离 PostgreSQL 运行并发/事务/恢复；实际路由核验身份、CSRF、字段投影、scope、缓存与队列撤权；故障注入不依赖正常路径假设。
5. **系统验证**：真实授权邮箱、浏览器/多设备、多团队多角色、压力/容量、备份恢复与业务消费者回归。界面 fixture 与真实服务结果分别记录。
6. **接受与发布准备**：对照 AC/QA，登记结果、未覆盖与风险；迁移需预检、备份与可恢复管理员，发布需运行/邮件/告警条件具备。未经明确环境授权不执行生产/业务数据库变更。
7. **运行验证**：观察实际注册/邮件/性能/错误与治理操作，按接受的指标报告；指标不达标回到同一需求修订，不能伪造完成率或写一份互相冲突的新规范。

## 4. 验收记录格式

每条 AC/QA 的证据记录：需求编号、设计/代码版本、目标环境、输入与角色、个人或团队范围、执行步骤、预期/实际结果、持久状态与副作用、证据路径、执行时间、通过/失败/未执行及接受结论。真实凭据/邮箱访问链接不进入报告。

| 证据层           | 能证明                                               | 不能替代                               |
| ---------------- | ---------------------------------------------------- | -------------------------------------- |
| 文档检查         | FR/BR/DR/IR/NFR 编号与映射完整、引用有效、无范围冲突 | 实现、性能或业务成功                   |
| 单元与契约       | 合成状态、失败路径、接口边界                         | 真实数据库/邮件/浏览器                 |
| 隔离存储与 API   | 唯一性/锁/事务/权限、字段与路由、撤权读回            | 业务环境迁移和产品接受                 |
| 浏览器与真实邮件 | 特定版本/断点的交互、实际收信与验证                  | 整月可用性、未测浏览器或全部邮箱供应商 |
| 压测/容量/恢复   | 指定环境下的 NFR 数值与恢复完整性                    | 不同部署规模或未观察周期               |
| 产品接受         | 当次范围内的真实用户结果和已接受质量条件             | 未交付的 P1 或其他批次                 |

工程命令遵循 [PROJECT](../../PROJECT.md#4-质量门禁)。需求追踪的唯一表在[规格第 8 节](../requirement/01-用户系统需求.md#8-需求追踪与完整性)，不在计划另建不同编号体系。

## 5. 停止条件与未决处理

- 跨个人/团队越权、平台/团队角色混用、成员移除误停全局账号、旧角色被自动提权：停止相应批次发布。
- 最后管理员竞态、待接管无法恢复、幂等重试多建账号/团队或审计丢失：停止相应管理写入上线。
- 迁移归属不清、缺邮箱/冲突或恢复不能证明安全撤权：停止受影响切换，不猜测、清库或重建身份。
- 邮件条件不足：继续独立工程验证，不跳过验证或宣称真实收信通过。
- 保留策略、SLO/容量参数未接受：报告待决和受影响验证，不自报达标；注销执行保持关闭。

本轮仅更新文档与检查，不执行上述实现、外部发信、数据库操作、Figma 修改、提交或发布。
