# Plan 导航

文档整理参考[模板与使用说明](../templates/README.md)及[编写规范](../templates/00-文档体系设计与编写规范.md)，采用当前连续编号并保留业务来源。PRD参考create-prd、Plan参考sprint-plan的标准内容，不强制调用技能。总入口：[文档索引](../00-文档索引.md)。更新：2026-10-20。

Plan负责迭代目标、周期与容量、故事就绪/选择、负责人、依赖和关键路径、风险应对、任务及完成标准；每份计划关联来源 PRD，不自动启动实施、改动业务数据或授权发布。编号代表阅读顺序，实际顺序按依赖。

## 容量与故事就绪口径

本目录原文件多为已实施部分能力的技术计划与证据。2026-10-20整理时新增的是剩余范围的迭代规划视图，不把历史完成量反推成团队速率，不重排已确认业务范围，也不将实现状态退回草稿。每份故事引用原任务与AC；计划11为运行手册，其工作归计划10容量，不能重复承诺。

| 规划输入       | 本次可确认的信息                                      | 形成新迭代承诺前的关闭条件                                                            |
| -------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 目标及优先级   | 沿各PRD、需求和既有任务依赖；不新增业务优先级         | 选出单一主要用户价值与明确范围                                                        |
| 周期和人员     | 未提供确认周期、人数、可用性、休假/会议/值班占用      | 实际交付团队确认周期、资源日历及负责人                                                |
| 速率或工时     | 未提供最近三个可比迭代的实际完成量和故事估算          | 计算可比平均速率，或采用有依据的理想工时；不混加单位                                  |
| 缓冲和容量     | 15%～20%是建议比例，尚无本轮实际预算                  | B为扣除已知占用后的预测容量，R=B×r，C=B−R；确认r和单位                                |
| 故事选择       | 正文故事是既有范围的归组，不是新增已承诺迭代          | AC明确、已估算、无未解决阻塞、责任已落实后，从高优先级选择；估算总量E≤C，达到容量停止 |
| 关键路径与风险 | 已有任务顺序可识别依赖链，无足够时长/日历计算最长工期 | 核对外部负责人、稀缺知识/环境与任务时长，明确风险触发和备选处理                       |

C−E为未分配容量，不能与预留缓冲R重复使用；故事与其子任务、总览与分计划不能重复计数。外部Key、真实邮件、数据库恢复、收费供应商等条件未就绪时，保持相关故事候选或阻塞，不能用模拟证据宣布就绪或接受。

原始工程与接受记录保留其时间和环境边界。下文或各旧步骤中的“本轮”“当前”“未提交”属于原记录语境；本次正文整理没有运行产品代码、变更环境或验证所有历史结论。Git交付状态以本次交付记录和实际Git为准。
