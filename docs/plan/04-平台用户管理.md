# 平台用户管理 Implementation Plan

> 唯一来源 PRD：[01-用户系统](../prd/01-用户系统.md)。技术合同沿其来源设计；实施进度、优先级、估算、承诺及阻塞只见 [BACKLOG](../../BACKLOG.md)。
> 执行说明：保留原技术任务与验证步骤；本次按模板补齐规划内容，不要求调用特定技能或改变已约定的执行方式。

**Goal:** 建立全站账号目录、独立平台权限、治理、审计及受控导出。

**Architecture:** identity负责全局治理，app同库事务协调账号禁用与workspace团队冻结。平台投影与业务内容授权分离，读写都查当前权限。

**Tech Stack:** 既有Go/Gin/GORM/PostgreSQL、Next.js/React与生成客户端。

**Spec:** [SRS](../requirement/02-用户系统需求.md)、[总体设计](../design/01-用户系统总体设计.md#31-文首来源与范围)、[数据库](../design/02-用户系统数据库设计.md#31-文首来源与范围)、[接口](../design/03-用户系统接口设计.md#31-文首来源与范围)、[PRD](../prd/01-用户系统.md)。

## 4. 文件与依赖

当前实现证据：平台目录、详情、治理、邀请、设置和事件已有实际HTTP合同及生成客户端。前端位于 `frontend/src/app/users/_components/`，按当前 `allowed_actions` 显示操作，密码复验与原因确认共用 `components/governance/confirmation.tsx`；不提供临时密码建号或强制登录改密。已注销账号保持只读。统计与CSV导出复用目录的已应用筛选，展示统计/快照时间，导出使用授权同站下载、明确状态、到期与撤权清理；没有永久私有URL或后台密钥进入浏览器。平台团队历史邀请通过独立平台投影读取，不放宽团队成员权限。源合同与本地工程检查、实际通知/对象存储及浏览器产品接受分别记录，后两者未由组件测试代替。

复用users页面并明确其平台范围；新平台handler取代旧组织后台handler。共享EventQuery定义于identity/application，self/team/platform分别投影；读模型不复用含秘密的持久化User。
