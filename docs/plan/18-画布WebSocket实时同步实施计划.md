# 画布WebSocket实时同步实施计划

> 唯一来源PRD：[08-画布WebSocket实时同步](../prd/08-画布WebSocket实时同步.md)。进度与阻塞见[BACKLOG](../../BACKLOG.md)。

## 1. 目标

接通Yjs同步、持久提交与回执、远端变化和临时在线状态，支持连续编辑与安全恢复。

## 3. 实施顺序

固定消息与接受合同→实现授权和同步→接入客户端会话→恢复与presence→故障和资源验收。数据接口依赖计划17，共享模型与拒绝恢复依赖计划19。

## 4. 验证矩阵

验证初始化期间提交、连续本地编辑、远端更新、重复与乱序、发送前中后断线、回执丢失、原提交查证、旧epoch拒写、撤权、归档、慢连接和服务重启。比对已接受内容、数据库修订及回执；检查presence过期和个人视图独立。

### 4.1 队列与同步屏障验证方法

依据设计15 §7.2～7.5完成T-SYNC-01～05：打开期间持续提交，核对基线屏障后无缺口；A的P在途时继续产生Q，收到P回执不能误清Q；队列满后不丢最旧编辑；健康连接丢ACK仍查证原P。捕获元数据验证业务写入只走submit，state vector握手、跨标签页消息或HTTP不存在旁路写入。

同时检查Cookie续期后重新握手、明确撤权停止投递、presence与业务队列独立背压。运行案例和退出条件见[计划19](19-画布Yjs协作编辑实施计划.md#41-故障场景与退出条件)，模拟成功不代替真实WS和数据库。

### 4.2 自动保存与会话隔离退出条件

按PRD08 §7.1补足T-SYNC-01/03/04/05：

1. 不点击保存且不主动失焦，分别完成各类业务编辑；持续输入期间仍产生接受回执。记录动作→入队→发送→accepted→B到达版本的关联，重开逐字段核对，不能只抓到WS报文便算通过。
2. 延迟ACK，继续编辑；上传未完成/失败、恢复项未处理、参数无合法值或IME仍组合时，P/Q为空也不能误报已保存。队列到限前的手势/IME完整结束，超限粘贴不先应用再丢弃。
3. 分别注入accepted、rejected、权威not_found、查询unknown/超时；核对是否沿原ID/载荷查证或重试。服务仍在线而回执丢失也须恢复；已进入因果链的撤销不能直接删Q字节。
4. 账号/项目切换、应用内路由离开、主动退出、只失写权及失读权分别验证；旧续期/上传/ACK迟到不修改新会话。页面缓存恢复先复核授权，仍有浏览权的暂停写入状态不锁死平移/缩放。
5. 同epoch日志不足走一致基线恢复；切epoch后查证旧请求但不自动提交旧队列。记录恢复区内容、当前权威内容和用户选择，验证不重复生效。

具体联动用例见计划19 CASE-COL-04/08/10～14；所有阈值（队列字节/事务数、单事务预算、恢复预算）在执行前记入测试配置。

## 5. 运行验证

Docker启动协作应用服务并连接现有基础依赖，检查鉴权、健康状态、重启恢复、连接释放和资源上限。记录测试规模、延迟、队列及恢复结果。

## 6. 证据

记录实际版本、命令、环境、浏览器交互、WebSocket消息身份和数据库回读。实施进度登记BACKLOG。
