# 团队创作与成员管理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 同一创作者可创建或加入团队，按团队独立管理成员、内容范围和职责交接。

**Architecture:** workspace拥有team/member/scope，identity拥有全局账号与邮箱邀请；消费方小接口由app注入。团队成员变化不能修改全局密码/邮箱/状态。

**Tech Stack:** 既有Go/PostgreSQL与Next.js/React；复用01范围授权、03邀请和治理。

**Spec:** [SRS](../requirement/01-用户系统需求.md)、[数据库](../design/02-用户系统数据库设计.md)、[接口](../design/03-用户系统接口设计.md)、[PRD](../prd/01-用户系统.md)。

## Global Constraints

- 前置01与03-P2，03-P3邀请端口复用；团队名称2～50字符；未归档创建≤5、加入≤20、每团队成员active+suspended≤100、pending邀请≤100。
- archived只读；suspended只由平台恢复原状态；governance_blocked在接管成功后清除。
- 邀请48小时，提案48小时；最后可用团队管理员必须交接；被移除/暂停不能用旧邀请复活。
- 只修改当前团队关系，作品归属不因退出/移除变化；执行[总览](00-用户系统执行总览.md)共同检查点。

## Review Focus

- 同一人并发建第5/第6团队 → 04-P1 `TestTeamCreationQuotaRace`。
- 普通目录包含邮箱或他队信息 → 04-P1 `TestTeamDirectoryProjection`。
- 接受邀请与撤回竞争、已暂停成员接受旧邀请 → 04-P2 `TestTeamInvitationRace`。
- 两管理员并发退出/交接/降级 → 04-P2 `TestLastTeamAdminRace`。
- A→B切换迟到回执和团队停用恢复原归档状态 → 04-P3 `TestTeamGovernanceRestore`及组件测试。

## 文件与依赖

团队资料/成员用例在workspace，不放全局users页面。新团队页面位于app/teams/[teamId]；跨页面空间选择器放components/spaces，平台治理页面独立位于app/platform/teams。

当前前端已接入创建、资料/头像、成员生命周期、邀请/提议和平台治理。普通团队角色为 member，全局普通身份为 creator，两者不能混用。空间切换按身份/空间代次取消旧请求并清除私有journal；同空间角色或可写资格下降也清除旧视图，403先权威重读资格。成员统计/导出使用同一角色、状态、时间筛选，平台历史邀请使用独立元数据投影。完整后台与A管理员/B成员/平台治理的实际浏览器、真实通知及对象存储仍归综合验收，不把组件门禁视为产品接受。
