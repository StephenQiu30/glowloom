# 画布Yjs协作编辑实施计划

> 唯一来源PRD：[09-画布协作编辑](../prd/09-画布协作编辑.md)。进度、阻塞与下一步见[BACKLOG](../../BACKLOG.md)。

Yjs共享画布、Tiptap协作正文、稳定引用、个人撤销、在线状态、持久确认、断线恢复和历史版本恢复。

## 3. 实施顺序

先固定共享模型和接受合同，再验证并发语义；接通协作服务、持久化与Docker运行后，接入节点及Tiptap编辑，完成会话恢复、在线状态与个人撤销，最后验证存量转换与完整链路。

每个画布按epoch切换唯一写入通道。切换前保留原始快照并核对内容与引用，切换后验证旧客户端拒写。代码清理随调用方迁移和回归验证完成。

### 4.1 故障场景与退出条件

以下场景当前未执行，仅定义如何验证；共同前置为隔离真实PostgreSQL与对象存储、Docker Go/JS运行时、两个授权账号及三个独立浏览器上下文，记录实际版本/schema/epoch与部署配置。只读账号补用于撤权与接收验证；不在用户现有未保存画布试验。

| ------------------------------ | ----------------------------------- | ----------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |

| CASE-COL-02 合并成环           | ST-COL-01；AC-COL-02                | 同基线分别提交X→Y与Y→X，并让B继续基于其待决更新编辑                                                   | 仅合法候选接受；被拒因果链不广播、不隐藏进Yjs；后继输入显式恢复                                                                                    |

| CASE-COL-11 素材与保存分离     | ST-COL-02；AC-COL-04/06             | 延迟/失败上传，编辑独立文本；分别在同会话重连、删除/替换目标或切项目后返回上传结果；图绑定丢ACK后重试 | 独立编辑及已授权占位可保存，但上传待办仍明确可见；无原文件须重选；同会话重连保留并复用素材回执，切范围后的迟到结果不绑定错对象；无blob URL持久写入 |
| CASE-COL-12 范围与内存边界     | ST-COL-03/05；AC-COL-05/06          | 满队列时IME/手势/超大粘贴；应用内离页、账号切换、撤权及页面缓存恢复，旧异步回调迟到                   | 接纳前限制且不驱逐旧输入；权限内仍可浏览；新会话不被旧数据污染，失读权内容释放，无业务本地兜底                                                     |
| CASE-COL-13 回执与谱系         | ST-COL-03/05；AC-COL-06             | 分别返回unknown/超时/not_found/accepted/rejected；P未决时切epoch；已commit丢ACK后关闭重开             | unknown不换ID/不当拒绝；not_found原样重试一次效果；旧epoch回执可授权查证但不重放旧队列，重开读到实际已接受内容                                     |
| CASE-COL-14 拒绝后的继续协作   | ST-COL-01/03；AC-COL-02/06          | 拒绝U1且已有U2/U3；恢复期间B再改同字段/删除引用对象；另撤回已进入Q的动作                              | 被拒因果结构不传播；兼容意图安全重建，竞争内容显式处理；不回放已接受动作，不丢Q依赖，未解决恢复不显示已保存                                        |

每例记录步骤、预期与实际、版本、WS提交ID/回执、数据库修订及可复核投影摘要；不记录凭据或私有正文。后台结果交错另沿AC-COL-04核对taskId和冻结输入版本；未接通真实供应商时只验保存合同，不称为真实生成验收。容量场景须先记录规模/人数/RTT及目标，未定阈值不能计性能接受。

同字段竞争专项还须用不同发送顺序/延迟验证CASE-COL-01/14：accepted、被并发更新覆盖和rejected各有独立观察结果，不以服务端到达顺序推定字段胜者。保存状态按本页操作是否处理完毕判定，不以每个历史赋值仍出现在最终JSON作为成功条件。

### 4.2 迁移和回退边界

转换在复制的持久快照上验证；正式切换锁定画布、排清或明确处理未决请求、写入新epoch/mode并关闭旧协议写入口，同一画布不双写两种算法。若尚无新epoch接受，可按已验证方案恢复旧模式；一旦新epoch已有接受，回退必须先保存全部新接受记录并证明可反向转换，否则暂停写入恢复，不能直接切回旧快照丢内容。回退与演练数据分别记录，未做即未通过。
