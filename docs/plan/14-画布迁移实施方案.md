## 1. 画布交互统一实施计划

### 1.1 目标与容量

迭代目标：创作者在真实项目中用一致的节点、引用与浮层完成编辑，拖动和缩放不遮挡内容，保存刷新后可继续工作。

| 规划项 | 决定 |
| --- | --- |
| 本轮范围 | 7个候选故事覆盖P-CAN-01～07；顺序明确，未作为已估算的Sprint容量承诺 |
| 周期与人员 | 未提供周期、团队人数、可用时间及会议/休假/值班占用；由实际参与者补齐 |
| 历史速率 | 未提供最近3个可比迭代完成量，不能从代码行数、测试数量或AI执行时间推算 |
| 估算方式 | 使用理想工时估算，逐故事确认后与净可用工时比较，不混用故事点 |
| 缓冲 | 建议预留净可用工时的20%处理组件耦合与交互缺陷；尚未分配具体小时 |
| 容量计算 | 净可用工时B＝各参与者可投入工时减已知占用；建议缓冲0.2B，可承诺容量0.8B；入选总估算不得超过容量及关键参与者可用时间 |
| 当前状态 | 文档与现行Figma组件/状态已同步，完成原型结构和关键画面截图检查；代码和真实验收待后续阶段 |

容量未知不填零，不将全部候选自动视为承诺。先估算和核对前置条件，再按优先级选入；达到容量即停止，其余保留后续。下表职责用于分工，不代表已指定人员。
