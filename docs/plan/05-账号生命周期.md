# 账号生命周期 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 提供可解释、可续办且不破坏团队资源的本人注销流程。

**Architecture:** identity协调注销状态，资源模块通过明确清理接口处理个人数据；团队作品保留作者墓碑，清理任务幂等续办。

**Tech Stack:** Go/PostgreSQL、既有任务设施及Next.js账号页。

**Spec:** [SRS FR-USER-14](../requirement/01-用户系统需求.md#fr-user-14-本人注销与数据处理)、[数据库](../design/02-用户系统数据库设计.md)、[运行设计](../design/04-用户系统测试与运行设计.md)、[PRD](../prd/01-用户系统.md)。

## Global Constraints

- 前置01～04；冷静期、资料/审计/备份保留、邮箱再用及团队引用政策由用户接受后填入Policy，未接受时不开放执行。
- 注销需5分钟密码复验与邮箱确认；最后平台/团队管理员先交接；pending立即撤销全局会话/挑战/个人公开分享。
- 账号被额外禁用后不能通过取消注销恢复；不级联删除团队作品、不转移所有权；执行[总览](00-用户系统执行总览.md)检查点。

## Review Focus

- 最后管理员申请注销与并发交接 → 05-P1 `TestDeletionDutiesAndRevoke`。
- 无旧会话的冷静期撤销 → 05-P1 `TestDeletionCancelProof`。
- pending后平台新增禁用 → 05-P1 `TestDeletionCancelDoesNotEnable`。
- 个人素材被团队引用、任务已外发 → 05-P2 `TestDeletionPreservesTeamAssets`。
- 清理中断恢复及备份复活 → 05-P2 `TestDeletionWorkerResume`，06-P2恢复演练。
