# 迁移切换与综合验收 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 证明存量身份与资源安全迁移，并按真实证据接受完整用户系统。

**Architecture:** 先预检再扩展/回填/切换/收缩，HTTP与worker同一授权模型；恢复安全撤权需已有可用恢复环境的证据。工程、真实邮件、产品接受分别记录。

**Tech Stack:** PostgreSQL、现有Go测试/迁移工具与前端测试工具；不增加项目shell脚本或Makefile。

**Spec:** [SRS](../requirement/01-用户系统需求.md)、[总体设计D6](../design/01-用户系统总体设计.md#8-d6-迁移与切换)、[测试与运行设计](../design/04-用户系统测试与运行设计.md)、[PRD](../prd/01-用户系统.md)。

## Global Constraints

- 06-P1是01的前置；06-P2/P3在相关实现完成后执行，编号不是允许跳过依赖的串行脚本。
- 用户ID/作品ID/拥有者/作者引用保持；旧admin不能自动成为platform_admin；缺邮箱与混合归属不猜测。
- 只复用当前已连接数据库及已启动服务；禁止创建隔离库、恢复副本、集群或容器。先只读预检，写验证必须审查并确保事务回滚；不满足此条件的并发、负载、恢复用例标记未执行，不冒充通过。
- 量化性能/容量/可用性/恢复目标仍为待接受值；RPO15分钟/RTO4小时、99.9%月可用性不能用一次短跑冒充达标。
- 遵守[总览](00-用户系统执行总览.md)共同检查点，未授权不commit/push。

## Review Focus

- 缺邮箱/大小写冲突/重名不同人 → 06-P1 `TestMigrationInventoryBlocksAmbiguity`。
- 一个旧物理范围混合个人与共享资源 → 06-P1 `TestMigrationPreservesOwnership`。
- 只更新登录遗漏下载、worker或旧管理入口 → 06-P2 `TestIdentityCutoverNoLegacyBypass`。
- 恢复旧库使已禁用/注销身份复活 → 06-P2 `TestRecoveryReplaysRevocation`。
- 测试跳过、负载排队、邮件只提交未收信 → 06-P3证据审查与负载/真实邮件验收。
