# AI服务测试与验证实施

唯一来源PRD：[AI服务测试与验证](../prd/2026-11-01-AI服务测试与验证.md)。用户于2026-11-01确认落实设计与实现；沿用现有main工作区，不创建或推送分支，不执行真实收费测试。

## 全局约束

保留设计、需求、PRD及BACKLOG已有修改；复用现有provider_check、凭据测试Outbox/Temporal及正式发布trial；不将网络可达视为鉴权、不以目录通过代替模型通过；未知付费请求不自动重发。新结构仅用schema.sql及可幂等增量；不重放业务库schema。

## Task 1: 只读协议与错误分类

先补HTTP边界回归：无Authorization的GET、任意HTTP可达、不跟随跳转、仅超时最多一次重试、异常JSON不得鉴权通过、配额与权限分类。实现providerhttp方法及安全字段。

验证：go test ./internal/operation/adapter/providerhttp ./tests/operation，涉及数据库的测试使用隔离PG。

## Task 2: 持久化测试与恢复

扩展provider_check记录和列表分页；新增无凭据连通请求，经现有授权Outbox/Temporal在worker运行；凭据检查限时15秒；服务端并发合并。增加原异步任务查询、同步unknown核查说明，保持未知及预算边界。先数据库/应用回归后实现。

接口：provider checks列表/请求、check query/acknowledge；生成前端API客户端。默认旧credential-test语义兼容。

## Task 3: 入口与三层测试UI

列表直接测试、名称进入概览；详情概览/测试/凭据/高级配置；URL仅维护自身参数并恢复焦点。三卡独立状态、版本证据和最近记录，权限失效不保留敏感详情。先交互回归后实现。

## Task 4: 模型费用确认与媒体试运行

轻量模型显式准备、费用确认、只发一次；unknown只恢复原请求。将正式发布试运行组件归到共享catalog，由同一测试页选择模型/release；保留项目/预算/报价/授权素材门禁，不绕过音乐逐模式验证。保留首次接入accepted启用合同。

## Task 5: 验证与交付

运行适用Race、vet、lint、govulncheck、API一致性、前端完整测试/类型/构建、定向格式。Compose更新本地应用并检查桌面390/320布局、焦点及无自动请求。独立全改动代码审查后修复重要问题。证据与剩余风险写入research/evidence，状态仅在BACKLOG更新。

## 接口依赖

Task1输出安全协议结果→Task2持久化字段；Task2生成API→Task3读写UI；Task4沿用Task2模型回执与既有operation/billing。所有消费者以服务端版本归属和请求ID为准。

## Review Focus

无凭据检测不能触及secret；未知/accepted不得自动再次POST；同连接并发请求不重复派发；配置/凭据变化不沿用旧通过；模型选择/URL不能跨供应商；媒体真实输入与报价绑定；日志和DTO不暴露供应商原文/Key。

## 实际实现与证据入口

实现沿用本Plan的五个任务，Figma的13状态作为展示参考；具体测试、审查修复、实际浏览器截图、本地无Key网络结果、未完成的真实账号接受及共享工作区失败，统一见[实现验收](../research/evidence/2026-11-01-service-testing/implementation-validation.md)。本Plan不复制进度状态。

审查修复另外覆盖正式试运行服务端恢复、当前active release试运行、已受理请求并发合并、旧模型版本证据失效、只读限流计数、确定性拒绝后的表单解锁及冻结费用摘要。补充覆盖draining Key原任务只读查询、同步unknown状态保留与关联后续新请求，以及不依赖鼠标聚焦的关闭返回。回归先复现失败再修复；不会通过降低权限、放宽断言或重发真实收费请求取得通过。
