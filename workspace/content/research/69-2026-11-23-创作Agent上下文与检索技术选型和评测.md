## 2. 仓库里影响设计的事实

1. 模型适配器在出站前调用 `assertSources`，再向 Go 取当前快照。以 submission、task、checkpoint、attempt 组成键，相同键命中持久快照就复用；新快照的 JSON 超过 131072 字节时直接报错。之后才将快照和 Pi transcript 序列化为本次输入并计算调用哈希。现有检查给出了接入点，也说明**模型预算要覆盖最终序列化请求**。工具 schema、系统段、摘要和图片都占窗口。[模型出站](https://github.com/StephenQiu30/glowloom/blob/37eaf7242/agent/src/pi-durable/model-provider.ts) · [消息序列化](https://github.com/StephenQiu30/glowloom/blob/37eaf7242/agent/src/business/transcript.ts)
2. Go 的运行快照聚合画布、剧本、交付、目标、原任务和费用。Pi 状态文档按 conversation 管理，context section 从根读取 goal、plan、adopted、pending proposal 和预算。只读设计应区分当前业务事实、用户已确认的长期决定和本次生成的假设。恢复旧调用与发起新调用具有不同的版本语义。[Go 快照](https://github.com/StephenQiu30/glowloom/blob/37eaf7242/backend/internal/app/agent/wiring.go) · [上下文扩展](https://github.com/StephenQiu30/glowloom/blob/37eaf7242/agent/src/pi-durable/context.ts) · [状态文档](https://github.com/StephenQiu30/glowloom/blob/37eaf7242/agent/src/pi-durable/docs.ts)
3. Go 已有 worker、带租约与死信的 outbox、媒体转写和 OTLP 依赖。转写段有精确毫秒起止，转写自身标注为待复核草稿。Agent 的 `PhaseTelemetry` 目前负责传递模型任务关联，若只替换成通用 tracer 会破坏 `modelPhase` 的运行约束。Workspace 使用 Fumadocs 搜索研发文档。拆出检索服务前要先确认真实业务索引、接入拓扑和源事件覆盖。[outbox](https://github.com/StephenQiu30/glowloom/blob/37eaf7242/backend/internal/platform/outbox/relay.go) · [媒体转写](https://github.com/StephenQiu30/glowloom/blob/37eaf7242/backend/media/mediatool/domain/transcription.go) · [Pi 任务追踪](https://github.com/StephenQiu30/glowloom/blob/37eaf7242/agent/src/pi-durable/telemetry.ts) · [文档搜索入口](https://github.com/StephenQiu30/glowloom/blob/37eaf7242/workspace/app/api/search/route.ts)

**容量和成本口径。** 1024 维 float32 的一百万条 dense embedding 仅向量数值约 4.096 GB，双版本约 8.192 GB，另算 PG 元组、HNSW、元数据、WAL、备份和副本。重建时要为两个版本共存预留容量。索引成本按新增／变更的实际片段 token、批请求量或 GPU 时长计；在线查询分别计查询向量、候选对数×重排成本、入模证据 token、压缩和生成。自托管记 GPU 空闲与峰值，托管记数据出站条件、实际费率与配额。线上 p95 看完整请求的分布，按阶段另记耗时和队列等待。这里没有 Glowloom 流量、硬件或采购实价假设。

## 4. 两组隔离实测

### 中文词法能覆盖哪些表达

本机 PostgreSQL 18.4，UTF-8，`en_US.UTF-8`，pg_trgm 1.6。使用一次性本地 Unix socket 集群，语料均为人工构造。输入 8 条资料，其中一条属另一项目，一条是过期决定。先按当前项目与有效状态取候选，再用小写子串命中或 `word_similarity(query, text) >= 0.3` 召回，按子串命中、相似度降序和 ID 升序取第一名。两组只改变检索文本是否加入事先编写的别名。

| 查询 | 期望资料 | 标题＋正文首条 | 加入别名首条 |
| --- | --- | --- | --- |
| SH-02 | S02 栏杆 | S02 | S02 |
| 黄色雨衣 | C01 阿岚 | C01 | C01 |
| 开场镜头 | S01 晨渡 | 无 | S01 |
| Lan | C01 阿岚 | 无 | C01 |
| 手部特写 | S02 栏杆 | 无 | S02 |
| 汽笛 | A01 渡轮汽笛 | A01 | A01 |
| 不许有人念解说词 | D01 只用同期环境声，不加旁白 | 无 | 无 |
| 看不清远岸的那幕 | S01 轮船穿过浓雾，码头渐显 | 无 | 无 |

命中为 **3/8 → 6/8**。另测 `simple` 字典下完整字符串“清晨渡轮穿过浓雾”与词项“渡轮”，全文匹配返回 false。这组刻意含已知别名和改写表达，只说明覆盖差异。单用户合成查询尚未验证中文分词器、embedding、跨租户业务授权或生产命中率。

复核用的六条有效记录依次为「SH-01 晨渡／轮船穿过浓雾，码头渐显／开场镜头」「SH-02 栏杆／乘客握住潮湿栏杆／手部特写」「阿岚 乘客／黄色雨衣，右肩磨损／Lan 小岚」「声音决定／只用同期环境声，不加旁白／声音约束」「渡轮汽笛／靠港时的一声汽笛／鸣笛」「站台灯光／最后一盏顶灯熄灭／灯灭」。干扰记录分别是过期的“全片使用旁白”和另一项目的同名晨渡。

### 强项目过滤如何影响近邻召回

独立临时 PostgreSQL 18.4 与 pgvector 0.8.6。单进程生成 20,000 条 32 维随机向量，按 ID 对 100 取模分项目，只搜项目 7 的 200 条。固定数据随机种子 0.314，以 10 个查询各取 cosine 最近 5 条；关闭近似索引扫描得精确的 50 个“查询、资料”对。建立 HNSW，固定 `ef_search=40`，通过执行计划确认走全局向量索引后过滤项目。按每个查询逐项和精确结果对照。

| 路径 | 返回条目／应返 50 | 与精确 Top 5 相同的条目 | 本次含义 |
| --- | --- | --- | --- |
| 项目内精确扫描 | 50/50 | 50/50 | 小候选集合的真值 |
| 全局 HNSW，迭代扫描关闭 | 1/50 | 1/50 | 过滤后候选严重不足 |
| 同索引，strict_order 迭代扫描 | 50/50 | 49/50 | 返回数量补齐，近似结果仍有差异 |

实验刻意指定计划来观察机制；生产优化器可能选用项目过滤后精确排序。HNSW 建图含随机性，重跑数字可能浮动。这些向量没有语义；没有测中文模型质量、端到端时延或生产负载。首版采用“小可见集精确搜索”的依据在此。切换 ANN 前应按授权选择率、分片、并发和增量写入重复测量，同时记录**实际返回数量**与**对授权精确集的召回率**。[pgvector 过滤与迭代扫描](https://github.com/pgvector/pgvector#iterative-index-scans)

## 5. 评测方法的选择

LongMemEval 分开测试信息提取、多会话推理、时间推理、知识更新和无依据时弃答。映射到画布后，需要额外加入「协作者无权查看私聊」「版本变动后改镜」「重新连接未决订单」。Anthropic 的 Agent 评测建议使用独立试次、校验最终环境状态并区分单次成功与重复可靠性。两者解释了为何只给模型回复打分会漏掉严重故障。[LongMemEval 论文](https://arxiv.org/abs/2410.10813) · [Agent 评测方法](https://www.anthropic.com/research/demystifying-evals-for-ai-agents)

先在同一标注集比较 A 显式引用／ID 直读、B 加词法与别名、C 加向量与 RRF、D 加有限候选重排，使用相同生成模型、预算、语料快照及权限。另做两组独立消融：关闭项目记忆测跨会话连续性；缩小上下文测试压缩前后硬约束保留。检索实验固定上下文组装，记忆实验固定检索结果，能定位收益来自何处。模型裁判对相关性和创意质量作辅助，权限、版本、费用、采用与召回有明确真值时直接核对记录。数据集、建议阈值、阻断条件和上线观察口径见[设计32 评测合同](../design/32-完整创作AgentHarness与Skill多Agent架构设计.md#creative-context-evals)。

**尚需真实数据回答的问题。** 真实项目的材料种类、每项目有效片段数量与权限选择率，中文改写查询的实际占比，哪些角色有权将私聊结论正式发布，同一个组织是否允许外部 embedding／judge 处理内容，以及业务愿意为一次回答承担多少延迟与成本。上面的技术路径可以在未开通外部模型时完成可验证基线。
