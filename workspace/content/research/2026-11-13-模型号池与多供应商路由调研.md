# 模型号池与多供应商路由调研

2026-11-13 · 研究对象：织光拟建模型接入与计费服务 · [原始需求 26](../requirement/26-模型号池与多供应商路由需求.md)

本研究为从零设计的模型接入与计费服务提供外部依据。公开产品合同、发行包及固定源码分别支持不同结论。织光服务可用性列为待验证。

## 1. 市场对照：八个对照项目各解决哪段问题

研究对象是为已有应用接入模型的团队。创作者在意选定的模型、参数和价格不变；接入管理员在意换 Key、停渠道不用改客户端；值班和账务人员需要追到每次尝试。以下比较影响自建或采购的因素；公开目录数量不能说明织光账号可用率，也不据此估算市场份额。

| 产品 / 交付方式 | 一手资料显示的机制 | 对织光的取舍 |
| --- | --- | --- |
| OpenRouter / 托管聚合、平台结算或 BYOK | 同一模型可有不同端点；请求可限制端点、必需参数、回退与价格。BYOK 可定义优先或备用 Key，回到共享容量会改变付款来源。[路由](https://openrouter.ai/docs/guides/routing/provider-selection) · [BYOK](https://openrouter.ai/docs/guides/overview/auth/byok) · [价格](https://openrouter.ai/pricing) | 可作为一个已验证的供给渠道；白名单、数据处理和成本约束要能贯穿到实际端点。不能证明下游遵守约束的线路不入池。 |
| New API / 开源自托管中转 | 按分组和模型找渠道，优先级内按权重分配；渠道内部再选可用 Key；任务有公共 ID 和上游身份。见 §2。 | 最接近号池运维。采用两层选择和单 Key 隔离；不用其用户分组销售、倍率或账户体系替代织光账务。 |
| LiteLLM / 自托管代理或 SDK | 客户端请求模型组名，多个部署可共用该名；同组换部署与跨组 fallback 可分别配置。[部署契约](https://docs.litellm.ai/docs/router/learn/deployments_and_model_groups) · [可靠性](https://docs.litellm.ai/docs/router/learn/reliability) | 借鉴独立冷却和有界尝试。若只缺同模型换路，单独部署另一层路由将增加重试和对账责任。 |
| Portkey / 开源网关、托管服务 | 可限制触发 fallback 的状态码，并用同一 trace 查看各次目标请求。[开源网关](https://github.com/Portkey-AI/gateway) · [回退](https://portkey.ai/docs/product/ai-gateway/fallbacks) · [套餐](https://portkey.ai/pricing) | 借鉴同一业务请求下的尝试记录；生成任务不能只凭 HTTP 状态码判定上游未受理。 |
| Cloudflare AI Gateway / 托管网关、BYOK 或统一结算 | 路由有草稿、发布与回滚；可强制使用自有凭据，阻止自动转入平台付费容量。[动态路由](https://developers.cloudflare.com/ai-gateway/features/routing/dynamic-routing/) · [凭据与结算](https://developers.cloudflare.com/ai-gateway/features/unified-billing/) | 借鉴可回退的配置版本与付款边界；不需要可视化规则编排器。 |
| CC Switch / 本机配置与路由工具 | 对各客户端可分别直连、经本机路由或按模型聚合；仅路由模式支持队列故障转移。[三种模式](https://github.com/farion1231/cc-switch/blob/db7a0e755ad6a81db21e8464d54dedcc831629ab/docs/user-manual/zh/2-providers/2.2-switch.md#L5-L15) | 最适合参考管理员的接入、切换和诊断交互。聚合名单不等于备用池。 |
| Magpie / 本地模型网关、可共享给受限客户端 | 同供应商可有多把 Key，各有模型、协议和套餐限制；路由组可跨供应商甚至跨模型，视频原任务又有独立的身份约束。[Key 定义](https://github.com/yetone/magpie/blob/11ab58c5874268d2607ff43f6ce13abb366c518b/internal/provider/keys.go#L23-L67) · [路由组](https://github.com/yetone/magpie/blob/11ab58c5874268d2607ff43f6ce13abb366c518b/README.md#L176-L188) | 最适合参考逐 Key 发现、共享额度和原任务找回；跨模型、订阅账号调度及估算账务不适用。 |
| BeefTV / 视频创作工作台 | 渠道模型映射到上游规格，按目录给出媒体报价，按托管任务编号取回产物及费用字段。证据见 §4。 | 可参考从创作参数到报价、从受理到取回的业务流程。 |

**替代方案。** 只购买托管聚合服务，接入快，但平台必须能约束下一跳、解释采购账单并恢复媒体任务；只保留厂商直连，身份最清楚，却需要人工为每个故障换配置。建议保留直连与聚合两类线路，让二者通过同一入池验收。衡量收益看可恢复故障挽回多少请求、是否保持原报价和原任务，而不是接入品牌数。

## 3. CC Switch 与 Magpie：从录入一把 Key 到找回原单

此前[模型预设调研](2026-11-09-模型预设音频与统一计量调研.md)核对了预设和目录；本次重新读取两个上游 Git 快照，沿配置、实际选路、失败和恢复追到代码。CC Switch 取 `farion1231/cc-switch@db7a0e75`，Magpie 取 `yetone/magpie@11ab58c5`，下列链接均固定到完整提交。两者是相邻产品：前者首先解决多个客户端怎么切配置，后者本身承担代理选路。取证是静态阅读，未启动软件、导入账号或发出模型请求。

### 3.1 CC Switch：当前配置、聚合名单与故障队列是三件事

| 环节 | 实际行为与证据 | 织光取舍 |
| --- | --- | --- |
| 录入 → 保存 | 通用预设以模板、实例 ID、地址和 Key 产生一份独立配置，复制模型映射；该通用配置以 JSON 存本机 SQLite。[预设实例化](https://github.com/farion1231/cc-switch/blob/db7a0e755ad6a81db21e8464d54dedcc831629ab/src/config/universalProviderPresets.ts#L96-L115) · [持久化](https://github.com/farion1231/cc-switch/blob/db7a0e755ad6a81db21e8464d54dedcc831629ab/src-tauri/src/database/dao/universal_providers.rs#L58-L70) | 公共预设、私有凭据、模型映射各有生命周期。复用表单语义；CC Switch 自身声明的是[单用户本机信任边界](https://github.com/farion1231/cc-switch/blob/db7a0e755ad6a81db21e8464d54dedcc831629ab/SECURITY.md#L14-L22)，不能据此推断已有团队秘密托管与撤权。 |

| 选路 → 隔离 | 关闭自动切换时走当前供应商；开启时按队列取候选，跳过熔断项，熔断身份为应用类型 + provider ID。固定官方身份有单独处理。[候选生成](https://github.com/farion1231/cc-switch/blob/db7a0e755ad6a81db21e8464d54dedcc831629ab/src-tauri/src/proxy/provider_router.rs#L83-L125) | 有序主备易解释，但 provider 级熔断不能直接解决“同一渠道里只有 K1 失效，K2 仍可用”。 |

### 3.2 Magpie：一个供应商可以有多把权限不同的 Key

| 环节 | 实际行为与证据 | 织光取舍 |
| --- | --- | --- |
| 预设 → 凭据 | 地区或套餐可分别指定端点、目录和取 Key 地址；同供应商的 Key 可以绑定不同协议、权重和套餐。批量录入按指纹去重；对外展示另供掩码、启停及冷却信息。[地区预设](https://github.com/yetone/magpie/blob/11ab58c5874268d2607ff43f6ce13abb366c518b/internal/provider/presets.go#L87-L108) · [Key 属性](https://github.com/yetone/magpie/blob/11ab58c5874268d2607ff43f6ce13abb366c518b/internal/provider/keys.go#L23-L67) · [录入](https://github.com/yetone/magpie/blob/11ab58c5874268d2607ff43f6ce13abb366c518b/internal/provider/keys.go#L271-L305) | 不能只按供应商品牌建池。易读名称与不含秘密的凭据版本引用用于排障；只有授权的正式 API Key 进入织光。 |
| 发布配置 → 刷新 | 保存前保留上一份可读配置，再写入本地私有文件并通知变更。[读取](https://github.com/yetone/magpie/blob/11ab58c5874268d2607ff43f6ce13abb366c518b/internal/provider/provider.go#L797-L810) · [保存](https://github.com/yetone/magpie/blob/11ab58c5874268d2607ff43f6ce13abb366c518b/internal/provider/provider.go#L913-L937)。发给本地网关客户端的访问 Key 与上游供应商 Key 分开，拒绝把后者用作前者。[访问身份](https://github.com/yetone/magpie/blob/11ab58c5874268d2607ff43f6ce13abb366c518b/internal/access/access.go#L109-L147) | 借鉴有效版本和身份分离。本机文件替换不证明多个服务实例同步撤销；织光应分别管理调用方身份和供应商凭据。 |
