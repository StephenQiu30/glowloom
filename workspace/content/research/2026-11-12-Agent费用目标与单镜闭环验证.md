# Agent 费用、制作目标与单镜闭环验证

日期：2026-11-12。实施来源为需求19 `SRC-AGH-23`，范围为 Plan28 R1/R2/R3 和 Plan33 D1。以下为本地执行证据，不代替生产发布、真实供应商账单或作品质量接受。实施进度及部署前置条件统一见 BACKLOG。

## 实现对应关系

| 合同 | 实际实现与复用 |
| --- | --- |
| 根费用 | `agent/adapter/postgres/cost_projection.go`读取原 call、operation、reservation、settlement；报价承诺转换为原实际收费或退款，不重复冻结钱包。归集不可用、未知费用和超额均阻止新的收费，原免费查询保持。用户费用与采购证据分别表示。 |
| 制作义务 | 扩展现有 `run_authorization.goal_contract`，公开 Start 仍先 AdmitRun，再按原 request/root 转发 Node，不建第二受理表。Go 覆盖 manifest 目标；生产目标不能凭空交付集合完成。 |
| 交付判定 | Go 按当前 root 正式批准及 create/reuse 回执、来源/规格、原两份导出及审核事实计数；别的 root 旧成功、仅提案或仅批准不能满足。Node 校验冻结目标 hash，采用 Go 的 required 完成裁决。 |
| 自动推进 | 原生成在途只保存原 ID、首次等待、绝对截止和下次唤醒；原 operation 完成后用“root、执行段、原 operation、正式交付进度”形成幂等接续键，通过官方 `root.submit` 继续采用与交付。无进展或超过策略次数停车；等待审核不追加模型调用。 |
| 故障恢复 | `agent.recovery_backoff`只保存既有 run/control 的退避与原因。定义不符显式停车，扫描失败和关闭失败可见；排空未证实时不提前释放租约。暂时读不到业务快照仍保留原 ID 和截止时间，不推定任务消失。 |
| 人工继续 | 临时停车与执行定义不可用分开。沿原 pause/resume，Go 确认有效回执后仅清原 root 的 Run 退避，重放同一控制同样收敛；不重置费用、步数、制作接续历史或 unknown。 |
| 浏览器 | 短剧视频页复用 ConversationWorkspace；制作目标与现有画布冻结进 session/原请求，URL 保留会话。复用原导出 API 预览、明确确认和下载；校验原 revision/SHA，丢失审核回应复用原 key，新版本须重新检查。 |

执行步数、子角色限制、深度、默认分配及制作接续次数集中在 `agent/src/pi-durable/policy.ts`；进程 root 槽与 Go 货币上限保持独立。Go 复用所属 domain 的节点、动作、调用及资金状态常量。时间线规格使用同一构造函数，前端导出身份与字节验证从原 TimelineExport 抽取复用。

本切片没有开放真实子分支收费并行，`allocated_unused=0`；BudgetAllocation 随 R4 实际消费者实施。没有新增空 MCP、Skill 自动选择或整集生产接口。

## 当前 main 的真实跨服务 Race

`go test -race ./tests/operation -run '^TestAgentShotHarnessPublicRunOriginalTasksAndReviewedDelivery$' -count=1 -v -timeout 8m`，用例22.34秒通过，package24.590秒，无 race 报告。

该测试拉起独立编译 Node，通过 Go 公开 Start、真实 BusinessClient/模型网关、正式报价/提案/批准/确认及交付工具，使用实际 PG、受控 HTTP 模型/视频供应商、原 managed worker、Yjs、FFmpeg 和工程导出。供应商接单丢回应和对象 PUT 确认丢失均沿原身份恢复；Node 在原视频完成前停止，重开后采用原结果。测试进程拉起不改变生产 Go/Node 独立服务边界。

审核前实际读取成片及工程，执行 SHA、完整 FFmpeg 解码、ZIP/FCPXML 与素材身份验证；未审核不能完成。正式审核后下载再核对字节。失败清理由正式 Go Stop 围住本次唯一 root，保留账本、不清共享表；独立 Node 子进程等待退出。

测试暴露并修复两个生产阻断点：公开 Start 冻结输入时丢失 SessionID/CredentialEpoch，现传原认证 principal；导出审核持项目授权锁后升级用户写锁形成死锁，现使用模块 principal 事务 advisory 锁并保留用户 SHARE/授权保护。两项均有确定性 RED→GREEN，未加业务死锁自动重试掩盖错误。
