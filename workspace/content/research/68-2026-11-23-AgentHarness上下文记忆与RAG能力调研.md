# Agent Harness 上下文、记忆与 RAG 能力调研

2026-11-23。基线为 Glowloom `37eaf7242` 与锁定的 `@earendil-works/pi-durable@1.5.0`。证据来自当前仓库的正常调用链、现有测试源码与官方资料。外部能力按各自产品文档核对，存储选型、效果和开销尚待同一数据集验证。[需求19 用户补充](../requirement/19-完整创作Agent与Skill多Agent需求.md#src-agh-25) · [设计32](../design/32-完整创作AgentHarness与Skill多Agent架构设计.md) · [画布调研67](67-2026-11-23-画布AI对话与故事板竞品调研.md)

## 结论

Glowloom 已有 pi 执行底座和同会话恢复。画布首版优先需要四组能力：**上下文组装与压缩、项目决策记忆、项目内有权限的检索与引用、可复核的评测和回执**。这四组一起回答“上一回合说了什么”“项目最终定了什么”“依据是哪一版资料”“这次为何读到它”。推荐保留现有 Agent／Go 权责，在项目语料上先验证结构化定位和关键词基线，再用带标注样例判断混合检索的收益。独立部署、向量引擎、重排服务和画像类长期记忆仍是待评估选择。

以渡轮样片为例。当项目从空画布开始，Agent 可只用本轮简报讨论方向。导演确认“乘客视角、15 秒、无旁白”后，换新会话仍能从当前项目带入这三个决定。用户问“保持雨衣造型，参考前一个开场的雾感”时，系统应分别定位已确认角色设定及对应镜头或素材并展示来源。若参考已替换、删除或不可读，系统提示缺项，保留其余确认条件；需要制作样片时仍走原报价、任务与采用回执。

## 2. 成熟做法对照

| --- | --- | --- |

| Anthropic | 长任务组合压缩、结构化笔记和按需读资料。Memory 工具的存取由应用方控制，Context editing 可清理模型输入里的旧工具结果 | 只在需要时读相关内容，记住经过确认的决定，给大量输出保留原对象指针。权限变更时，要同时检查原文、历史工具结果、摘要等实际出站路径。[上下文工程](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) · [Memory 工具](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool) · [Context editing](https://platform.claude.com/docs/en/build-with-claude/context-editing) |
| Dify | Knowledge Pipeline 把解析、分段、索引、召回和重排做成可查看的阶段；支持元数据过滤和引用。关键术语与语义搜索可组合 | 借用阶段记录和独立检索测试。按剧本段落、角色条目、场景、镜头、媒体片段等有意义的边界切分；保留上级语境和原文定位。[Knowledge Pipeline](https://www.dify.ai/rag) · [官方源码文档](https://github.com/langgenius/dify-docs/blob/main/en/self-host/use-dify/knowledge/knowledge-pipeline/create-knowledge-pipeline.mdx) |
| Anthropic Contextual Retrieval、Ragas | 前者用文档内上下文补充片段再组合词法、向量与重排。后者可分别评估召回、排序和答案依据 | 用同一中文样例集单独判断找没找到、排序是否合适和回答有无依据。研究方的基准结果仅说明候选方法，需用 Glowloom 数据复现收益。[Contextual Retrieval](https://www.anthropic.com/research/contextual-retrieval) · [评测指标](https://docs.ragas.io/en/latest/concepts/metrics/available_metrics/) |

## 3. 能力清单与首版建议

“首版”指画布创意对话与故事板的共同验收建议。每条约束仍需回到设计32、设计35 与相关业务所有者确认后落入正式规格。

| 优先级 | Harness 能力 | 对用户和业务的实际作用 |
| --- | --- | --- |
| 首版 | 上下文选择、预算与按需加载 | 优先放本轮意图、已选或明确引用的对象、已确认决定，再按相关度补充材料。把历史、Skill、工具定义与检索片段分别计入窗口，留出输出余量。图像、长文件和子 Agent 附件纳入限额。超限仍保留硬约束并说明没有读到的内容 |
| 首版 | 同会话记忆与恢复 | 官方 transcript／compaction 负责会话连续性，结构化运行状态保留当前任务决策与未决事项。断线和摘要后重新读取受权事实，原任务和采用仍查原单 |
| 首版 | 跨会话的项目记忆 | 先覆盖确认过的创作方向、风格约束、角色设定、项目限制与选定参考。记录类别、作用域、来源版本、确认者及生效版本。用户可查看、更正、撤回；冲突决定并存为候选并提示复核。草案、模型猜测和未采纳的子 Agent 结果可作为临时材料 |
| 首版 | 统一只读检索入口与精确定位 | 服务端按当事人的组织、空间、项目、对象授权生成范围。支持按稳定 ID／当前选中对象优先直读；支持名称、编号、关键词和资料类型检索文本及媒体元数据。同名时呈现来源与版本供选择。未命中与服务异常显示不同状态 |
| 首版 | RAG 摄入与来源可定位 | 仅接入当前项目发布或明确选择的资料；首批考虑已确认剧本/设定、画布文本和正式素材元数据，故事板上线后直接沿镜头权威读。保存来源 ID、版本、片段定位与提取状态。索引更新以来源版本驱动，换版、撤权、删除可失效；旧版本只在有权的历史场景按需查 |
| 首版 | 证据回填、出处与新鲜度 | 回答或工具结果可点回来源；剧本按段落、镜头按稳定 ID、媒资按对象版本，已有时间码时定位区间。后续写入和报价前复核该对象的当前版本。仅展示有权对象的标题、摘要、缩略图和链接 |
| 首版 | 运行授权、隔离、恢复和费用 | 把检索资料标为低信任数据，工具调用仍使用经 Go 验证的身份、角色和预算；素材正文不能改变规则或批准操作。子 Agent 只得任务所需资料并重验授权。检索、向量化、重排、摘要与模型用量可追踪，出现重试沿原请求去重，有歧义显示待核对 |
| 首版 | 用户可理解的上下文与可诊断评测 | 在现有对话／故事板显示“本轮参考”和来自项目的决定，支持去掉自动加入的可选证据。记录召回和保留的来源 ID 及版本、弃用原因、实际 token／延迟与模型版本，诊断日志使用脱敏身份和计数 |
| 跟随效果验证 | 语义召回、混合排序和重排 | 用中文别名、跨语言项目术语和“雾里的开场”这类语义需求对比基线、关键词＋向量、混合＋重排。收益达到约定后按被批准的语料和模型版本启用 |
| 后续候选 | 个人长期偏好、团队知识、多模态深度检索 | 个人偏好由用户显式保存，保有私有边界；项目共享记忆按参与角色控制。团队库和跨项目借用需来源权利和明确分享。ASR／OCR、视频关键帧和时间码可以后续独立验证 |

### 3.1 记忆与业务事实

| 信息 | 读取范围 | 写入与失效 |
| --- | --- | --- |
| 会话工作记忆 | 当前私有会话，任务所需片段可在同一运行内委派 | 原消息及 Pi 状态由运行时提交。压缩产物可淘汰或重建，沿用原历史的可见边界 |
| 项目决策记忆 | 具备项目角色的人可按已授权范围读取 | 用户明确确认才写入共享事实。模型可提出带来源的候选。更正升级版本，撤回立即停止后续使用；项目成员能查已发布决定及出处 |
| 可检索知识 | 当前用户能读取的项目资料和明确授予的附件 | 来源服务掌握正文与修订。索引为可重建投影，删除与权限变化优先在读取端生效，随后异步清理衍生内容 |
| 任务和账务 | 原任务、回执及账务权限范围 | 以现有 formal operation／报价／资金／媒体数据为准；只持久保存所需定位。模型可陈述查询到的状态，任何记忆条目均无业务写权限 |

优先使用本轮明确指令解释创作意图，涉及已发布项目约束的矛盾先向用户确认。确定性的权限、对象修订、收费及采用规则始终由业务服务裁决。使用来源的两道检查分别发生在**检索前**与**召回结果出站前**，打开引用和执行写操作再次走业务授权。授权撤回后，即使派生索引未更新，也要阻止相关内容通过缓存、历史工具输出、压缩摘要、已排队模型请求和子会话重新送出。若现有 Pi 历史无法只移除失效片段，保留历史记录并提示用户从干净上下文继续，带入仍授权且已经确认的项目决定。区分可拦截的后续出站与先前已合法出站的内容。

## 4. RAG 技术候选与决策条件

RAG 的最小链路为来源授权 → 解析和按版本入库 → 候选搜索 → 权限和版本复验 → 有界证据 → 回答、可定位引用与反馈。用当前创作域的读模型建立基线。数据库／搜索部署由数据、延迟和权限证据决定。

| 候选 | 适合验证 | 采用前要证明 |
| --- | --- | --- |
| 既有 PostgreSQL、结构化查询和词法基线 | 稳定 ID、别名、项目内筛选、角色名、镜号、版本和标签。可用受限范围内的 PostgreSQL 查询与既有文本能力起步 | 中文短词、同义词、混合文字与镜头编号的召回效果；索引大小、写放大、热查询延迟。中文检索不能直接套用英文分词预期 |
| PostgreSQL + pgvector | 需要语义召回且能够控制数据库扩展、资源和数据位置时，先比较强过滤后的精确搜索，再看近似索引 | 现有部署可安装扩展，单租户和强权限过滤下 Recall@K 达标，运行压力可接受。pgvector 文档说明近似索引可先扫描再过滤，强选择性条件会减少命中，须专门测。[pgvector 过滤](https://github.com/pgvector/pgvector#filtering) |
| 独立 Meilisearch | 词法体验、混合检索和索引负载独立。官方支持混合搜索与租户令牌 | 证明中文和专业名表现、同步和删除复验、按组织和项目隔离、部署成本。令牌限制只是索引访问一环，动态 ACL 仍要查询业务所有者。按数据出站政策选嵌入执行位置。[混合搜索](https://www.meilisearch.com/docs/capabilities/hybrid_search/overview) · [租户令牌](https://www.meilisearch.com/docs/capabilities/security/overview) |
| 独立知识平台或托管 RAG | 大规模异构接入、审核索引及处理流水线时，可比较运营和开发成本 | 原文和嵌入的出站边界、逐对象撤权、版本回放、销毁证明、费用和迁出。基础能力完备且本地检索方案无法满足需求时再考虑 |

索引要支持去重、失败重试、重建和原子换版。以来源、片段定位、内容摘要、索引配置和 embedding 版本追踪，重复任务不得覆盖较新的来源修订。Embedding 或 rerank 供应商若需要私有内容，须单独确认出站和计量合同。下游只保存业务需要的证据标识，避免同一份私聊、摘要和素材全文扩散到多个索引。

## 5. 如何评估能力是否够用

用同一组已授权的中文创作样例，保存预期来源版本、应拒绝的来源及哪些结论要有出处。比较当前显式引用、词法基线、混合检索和混合加重排四组。首次评审可先用合成素材，后续由真实授权项目验证大小、成本和延迟。专题[调研69](69-2026-11-23-创作Agent上下文与检索技术选型和评测.md)补充两组隔离实测和组件对照。端到端命中率、时延及成本仍待授权业务样本测定。

| 场景 | 可观察的结果 |
| --- | --- |
| 同会话压缩与恢复 | 最早硬约束在长段工具输出和进程恢复后仍正确。恢复原任务，新增收费任务数为零 |
| 跨会话继续故事板 | 新会话读回同项目已确认的三个创作决定，能点回出处；更正后采用有效版本，其他项目和协作者私聊仍不可读 |
| 精确定位与语义定位 | 两组同名角色或镜头、中文别名、跨语言描述混合查询。记录 Recall@K、MRR／Precision@K、可打开出处比例和回答中有出处的事实比例。分开看精确与语义样本 |
| 无匹配、旧版本和权限变化 | 未命中时可继续发散讨论；若任务依赖缺失资料，提示补充。在缓存热、索引落后、压缩之后、授权变化与在途并发下，查验新出站及 UI 的无权原文、标题、摘要、图片和签名链接均为零 |
| 定位第二镜并只改该镜 | 重排后操作仍指向用户当时选中的稳定 ID。资料更新和镜头修订竞争可见，其他镜头和旧采用版本保留。查资料和改稿阶段无隐式媒体下单 |
| 故障与观测 | 分开记录召回服务失败、权限拒绝、无命中。留存检索 P50／P95、索引更新延迟、输入与 retained token、每轮调用及成本、误写／错误引用率。诊断能凭版本链复核失败原因 |

**需要评审的产品决策。** 首版开放哪些项目资料作为自动检索范围，哪些需要用户通过 `@` 显式选用。项目决定由什么操作确认，谁能发布或撤回。用户是否需要在回复旁看到全部实际来源还是先看主引用。是否已有可接受的 embedding 运行位置和费用预算。优先对这些边界形成共识，再决定 RAG 物理部署、长期记忆策略及上线顺序。
