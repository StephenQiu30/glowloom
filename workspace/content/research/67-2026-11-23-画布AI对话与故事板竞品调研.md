# 画布 AI 对话与故事板竞品调研

调研日期为 2026 年 11 月 23 日。对象为即梦国内版、LibTV、BeefTV，以及用于比较镜头选版和剪辑的 Google Flow、Storyboarder。研究问题是：创作者如何让 AI 看懂现有素材，把创作意图变成一组可修改的镜头，并在花费积分前决定具体制作哪一镜？

## 1. 结论与产品机会

**已确认的首版目标是让创作者只带一句创意，和 Agent 一起定方向，得到可编辑的故事板，并制作一镜可采用的样片。** 用户无需先准备商品视频、剧本或角色参考。素材在构思逐渐具体后加入，打开故事板、查看和引用项目素材也是独立可用的入口。镜头数量、片长和题材取决于用户的任务。

三个最有区分度的发现：

1. **即梦解决“从哪开始聊”。** 显式点「创作分镜」会准备一份技能草稿；直接输入一个模糊创意时，实测得到三个叙事方向、拍摄取舍、推荐及可点击的后续话题。Glowloom 截图已很接近这个入口，设计的重点是点击或发送之后如何推进创作。
2. **LibTV 解决“在聊哪份东西”。** 用户截图所在的就是已选中的「故事板」。本次项目的首屏按文本、图片及用途组织素材；打开文本详情有「添加到对话」。切到工作流，同名的四个节点在画布中可定位。故事板的素材视图与逐镜可编辑的分镜表，是两个都值得设计的工作面。这一实测没有展示统一的镜头行字段。
3. **BeefTV 解决“刚才改了哪一镜，哪些需要花钱”。** 可只建镜头表，各行独立绑定图片和视频，可比较修订；制作单再决定哪些目标要生成。其官方八镜案例实际只完成三条视频。Glowloom 应分别回答“分镜定了吗”“哪些镜头有素材”“哪些版本已采用”。[分镜操作源码][beef-rows] · [官方案例][beef-example]

这项需求延续已有 pi Agent，纳入类似即梦的画布对话和 LibTV 故事板。首轮访谈已确定创作起点和成功终点。[原始需求与确认记录](../requirement/20-对话工作台与参考输入一致性需求.md#src-conv-10)

## 3. 竞品工作流拆解

### 即梦：同一画布内，从一句话到带参考的任务

| 走查步骤 | 当前可见行为 | 对产品设计的启示 |
| --- | --- | --- |
| 进入已有画布，点「与 AI 对话」 | 画布及三个原节点仍可见。侧栏可调宽、可切浮窗和收起。空态显示一个新会话，限制再创建一个空会话，发送禁用 | 用户可以一边看素材一边写目标。空草稿与已提交任务分别处理 |
| 点「创作分镜」 | 输入框获得焦点，出现分镜技能以及询问用法的可编辑文字，发送变为可用。清空后重新禁用 | 显式选技能表达创作方法；是否发送和想创作什么由用户决定。首页、普通画布、短剧助手的快捷方式分别核对 |
| 打开添加和引用入口 | 附件菜单可上传、从资产库添加、从画布添加，另有引用参考入口。该画布同时有空视频节点及带产物的图片节点 | 需区分节点、节点上已采用的素材、未生成的空位。模型实际能读取哪种内容应让用户看得见 |
| 打开「创作设置」 | 媒体设置分视频和图片。视频可选智能模型、比例及清晰度；对话模型在输入栏单独选择 | 无可用视频模型时，仍应根据对话模型的可用性决定能否继续写脚本；执行前展示此次实际媒体规格 |
| 从既有对话回到历史产物 | 11 月 12 日站内观察记录了活动、已生成图片、回复与积分；较早记录还区分重新编辑、再次生成和暂停 | 对话历史应保存提交时的引用和产物；恢复、重新编辑、新购买是不同动作。[既有登录态观察](41-2026-11-12-即梦多模态创作与Agent服务拆解.md) |

国内短剧工作室的官方手册还给出两条入口：从 Agent 的资产阶段切入项目画布，或从空画布起步。可以将角色及场景接入图片节点，再以图片作为视频参考。国际版 Dreamina 的教程给出多选参考、按镜头拆解及加入时间线的示例。两地产品说明分别使用，本轮没有在国内普通画布验证整条国际版流程。[即梦短剧画布手册][jimeng-manual] · [Dreamina 官方教程][dreamina]

**补测 JM4：一句创意的首轮真实回复。** 11 月 23 日，国内普通画布、零节点、新会话、Doubao 2.1 Lite、无附件、未手动选技能。原输入为「我想拍一条关于清晨第一班渡轮的短片。先只聊文字，不生成图片、视频或音频。」输入限定了媒体消费范围，未指定是否追问、给几个选项或是否写分镜。

1. 回合显示执行中，并公开标明使用「故事创意」技能。回复先解释题材的叙事价值，再给三个风格不同的构想：老船长的告别、年轻人从昨夜过渡到新一天、渡轮承载未说出口的告别。各方向包含人物或设定、戏剧支点和整体气质。
2. 助手比较了共鸣、拍摄难度和创作风险，推荐较容易拍出效果的年轻人故事。结尾问哪个方向打动用户，也允许补充真实城市或航线。页面提供「按推荐方向写大纲」「换成具体航线」「细化人物」三类跟进建议。
3. 回合标为已完成，费用显示「本次消耗 0 积分」，画布仍为零节点。观察止于这一次回复；下一步按钮没有点击。本样本支持“给可比较的方向并帮用户选择”，无法证明即梦固定输出三项、所有文字对话免费或选完一定直接写故事板。Glowloom 的下一步是产品负责人确认的本产品设计。

### LibTV：从项目素材切入导演对话，再回到工作流

| 对象 | 在本次项目中看到的行为 |
| --- | --- |
| 故事板总览 | 顶部「故事板」已选中，标题为「项目素材」。文本栏可按剧本、其他筛选；图片栏可按角色、场景、物品、其他筛选。各栏有数量和收起动作。另有按名称搜索、添加素材及批量操作入口 |
| 素材和详情 | 「添加素材」提供资产库和本地上传。点文本素材后在同屏打开详情，可「添加到对话」、下载或打开更多操作。两张同名图片卡仍分别展示，已有结果的一张显示模型和分辨率。产品侧必须用对象身份区分同名素材 |
| 工作流 | 切到工作流看到两份文本和两个图片节点，侧栏可定位到节点。工作流的「添加节点」有脚本、视频、导演台、智能剪辑等入口。返回故事板重新显示项目素材及导演面板。未实测跨视图写入后的传播时延、冲突与删除语义 |
| 导演空态 | 提供感知画布、从预设原创、上传故事改编及批量优化提示词；另有原创、改编、导演执导三种入口。输入框提示可引用工作流、节点、资源；附件支持本地和素材库；Skill 目录能看用途和详情 |
| 执行方式 | 现场的手动模式说明每次生成前询问；自动模式说明可以直接消耗积分。走查只展开并读取两个选项。可见开关无法证明用户预算、超额拦截、扣费和退款规则 |

官方 CLI 手册的广告示例先搭脚本、引用、关键画面和视频依赖，再由创作者确认生成。已有画布可以先找空节点、缺失产物及其上游。官方插件仓库还展示导演提案、运镜及音乐广告技能。一个创作者署名的历史实操用连续画面展示了在故事板引用指定片段、返回工作流比较修复版，随后进入合成面板。手册、案例与本次账号界面支撑的是不同结论。[LibTV 官方手册][lib-manual] · [官方插件固定版本][lib-plugin] · [创作者实操图解][lib-case]

**故事板改稿复核。** 本次在用户已有的 LibTV 项目打开文本详情和执行方式菜单。文本节点即使处于「待确认后生成」，详情仍可看到「添加到对话」。两张同名图片卡可通过画面、模型名及尺寸区分。手动生成文案说明每次询问，自动生成文案说明可以直接使用积分。走查停在可读菜单和素材详情。REA 记录了目标发现 `ev_d5dc60c1c11acd1355a581686f38ee958f86cc792754382f4f5549e8db491edd` 与已恢复的故事板视口 `ev_93c9068cfe91644cf10ade4eea912982c5da01faece5a24debc73eb5c0f86854`。菜单与详情由 Chrome 可见界面复核。计费上限、扣费和退款仍未得到运行验证。

## 4. 市场定位与选择依据

下表按用户要完成的工作比较。产品页面和案例可以支持交互判断；哪类用户最愿意付费仍需访谈或试用数据。

| 参照 | 主要创作任务 | 对 Glowloom 有价值的动作 | 适用边界 |
| --- | --- | --- | --- |
| 即梦 | 带着想法或参考开始；进入画布继续细化 | 任务技能起笔、可见引用、对话模型和媒体验收参数分别选择 | 普通画布、首页和短剧工作室各有入口 |
| LibTV | 面对许多项目素材，找到对象并让导演继续创作 | 从素材详情加入对话；工作流与故事板互切；可见手动/自动生成含义 | 当前故事板现场只含文本与图片，其他项目会展示哪些组尚待核实 |
| BeefTV | 从创意、剧本到分镜行及分镜级生产 | 准备、局部修改、按镜头报价、逐项恢复 | 源码与厂商案例各有版本；未实测 SaaS 协作及真实资金回执 |
| Google Flow | 有多个视频候选后，选版、衔接并剪成场景 | 保留历史，提取单帧供下一镜引用，加入 Scenebuilder 后重排、裁切、预览 | 专业剪辑参考，未登录实测本轮生成质量。[官方编辑手册][flow] |
| Wonder Unit Storyboarder | 导演先用画格评审故事节奏 | 重排、复制、对白与动作、单镜时长和连续预演；稳定 ID 与显示次序可分别维护 | 传统分镜制作参照，可先在无视频产物的情况下排节奏。[官网][wonder] · [画格模型][wonder-code] |

**商业含义。** 创意探索、修改文字分镜、生成首帧、生成视频的成本和返工半径不同。若用户调换镜序就必须重新生成视频，失败代价会压过对话节省的时间。建议将文本推理按既有模型及预算规则计量，媒体制作另给选镜、规格、预计积分及已结算费用。竞品活动价缺乏统一规格，本轮不据此推算收入或设置售价。[LibTV 计费说明][lib-billing] · [织光销售与结算设计](../design/41-模型销售定价与结算设计.md)

| 画布与参考 | Yjs 工作区已挂载可调宽的对话侧栏，向它提供当前画布上的媒体和主体。用户截图的发送区显示「暂无可用模型」；原因及其他账号的可用性未知。[实际挂载][g-mount] | 明示本次引用和可用能力。缺对话模型时可整理素材、手改故事板并保存草稿；只有媒体模型缺失时保留可用的文字创作 |
| 会话与技能 | 画布助手已有私有会话、修订、草稿与前次 operation 的关联。当前「创作分镜」在编辑器插入名称和说明，输入区支持讨论/图片两类，已生成任务用 TaskDetail 展示。[画布助手][g-panel] · [现有会话合同][g-session] | 对接正式 pi 回合、已授权技能、公开步骤和带业务对象的结果。设计已有画布历史的读取与接续方式，避免上线后旧会话消失 |
| Agent 与副作用 | pi Durable 已承担持久会话与任务；项目有按任务委派子会话、加载技能和工具约束。Go 已有授权读画布、按版本原子提交和原调用回执。[会话运行时][g-pi] · [委派实现][g-registry] · [画布命令][g-command] | 能力按范围授予。草拟、提议修改、真实写入、生成、采用分别留回执。对用户显示结果和可恢复步骤，内部工具或子 Agent 数量不作为产品目标 |
| 分镜信息 | 已有三镜头画布模板及 `storyboard-plan/v3` 结构，含画面、时长、台词、人物、景别、运动、光线、连续性和素材引用。画布「转为分镜组」目前在合格图片选择下仍显示成功态尚未接入。[模板][g-template] · [分镜结构][g-schema] · [画布分组入口][g-container] | 沿用创作字段。把计划中的人物名称解析到有权限的素材版本，再建立可编辑、可定位、可采用的制作镜头；首次阅读只展示创作者需要的几列 |
| 短剧与采用 | 单集已有片段编辑、保存/确认；短剧中可进入正式对话。独立 `/storyboard` 重定向分集，单集「生成片段」目前只传正文；单镜交付校验会拒绝带 RowID 的来源。[分集操作][g-episode] · [短剧对话][g-drama] · [故事板路由][g-route] · [单镜交付边界][g-shot] | 普通画布先确认故事板的项目归属；短剧沿用集、镜头、修订与候选版本。把镜头和原操作带到生成与采用，再通过同一身份回到画布 |

Context7 对 pi Durable v1.4.0 给出的规则是：崩溃后能否重新执行中断的工具，取决于其保存的策略和当前声明。本地锁定版本为 1.5.0，上游该版也明确区分可安全重放与中断。对生成请求而言，恢复会话后应先核对原业务回执，未知订单继续查询；缺少回执时不能因为 pi 恢复了任务就再次购买。[Context7 对应规范][pi-spec] · [上游 1.5.0][pi-current] · [项目依赖][g-deps]

## 6. 建议的产品体验与服务分工

**一次评审演示。** 空画布上，创作者只说「我想拍清晨第一班渡轮」。Agent 协助把想法定为“从乘客的视角，讲一座城市苏醒”。一份 15 秒的候选板可以安排空码头 4 秒、乘客踏上甲板 6 秒、船离岸 5 秒。创作者要求第二镜从拍脚步改为手握栏杆的近景；如果此时有自己的参考片，可只绑定到该镜。确认制作后得到一个 6 秒候选，预览并选用；重开画布能从同一镜头找到该素材和原任务。秒数、题材和镜数仅用于演示。

| 工作面 | 用户看见与操作 | 建议由谁负责 |
| --- | --- | --- |
| 画布内对话 | 可直接问素材、改提示词、讨论剧本，也可请求建板。任务明确就给草案；缺关键输入只问会改变产物的问题。引用以可移除卡片展示 | 复用现有富文本、素材选择器和私有会话。普通问答留在对话；用户表达落板意图时才产生故事板候选 |
| 故事板的项目素材 | 从已有工作流切换，按类型找剧本、角色、场景、道具及结果，可预览、加入对话、定位回节点。空节点提示需要补充什么 | 复用项目资产、主体与画布节点的实际身份。同名、已删除、不可读及素材换版分别处理 |
| 故事板的镜头 | 镜头行默认呈现镜号、代表画面、画面动作、计划时长及采用状态。按需查看对白/声音、景别/运镜、关联角色场景、参考版本和历史候选。支持手改、调序、选镜讨论与比较候选 | 复用既有分镜结构及制作镜头/Take 设计。调序只改顺序；插入、删除、拆分及下游影响在正式设计细化。共用项目内容，对话记录按现有私有边界处理 |
| 修改与授权 | 「只改第 2 镜」先定位到镜头和版本，预览画面或提示词的差异；引用变化影响其他镜时列出范围。媒体生成前列出镜头、模型、规格、预计费用和可执行动作 | 主 Agent 组织计划，Skill 提供方法。Go 校验项目权限、版本及预算并返回正式结果；其他成员并行修改时保留双方内容供比对 |
| 生成、采用与恢复 | 媒体进行中可继续讨论其他镜头。成功候选可播放/预览、比较和选用；失败项可处理，回执未知可查询。重连后回到原进度 | 媒体任务、资金和资产沿现有服务。正式采用后同一素材版本可定位到镜头与节点；进入时间线时保留剪辑端手改和来源关系 |

界面沿现有 Geist、Neutral、shadcn 和单一输入器。桌面让画布或故事板与同一对话并排；窄屏优先展示当前工作面，切回保留选镜与草稿。重要信息就地出现：引用显示在输入区、改动显示在目标镜头、预计费用显示在生成按钮附近。用户可一直只聊天，或始终在故事板里手工调整。[对话设计35](../design/35-对话工作台与参考输入一致性设计.md) · [Agent 设计32](../design/32-完整创作AgentHarness与Skill多Agent架构设计.md) · [制作对象设计38](../design/38-短剧工作室一致性设计.md#73-生产身份候选版本与采用关系)

## 7. 用哪些结果判断值得做

以下是建议的试用验收。可用同一份简报分别测试「仅从文字构思镜头」和「结合已有素材构思镜头」，记录创作者在哪一步需要离开画布、复制提示词或纠正助手。

| 场景 | 可检验的结果 |
| --- | --- |
| 从素材到可评审镜头 | 三镜的时长相加符合简报，人物/产品引用有来源，每镜有可见动作且前后连续。由创作者评判能否用于拍摄或生成，记录首次可评审耗时及返工原因 |
| 只改其中一镜 | 先手工精修一镜，再指示修改另一镜。比较修改前后的镜头 ID、字段、引用和候选，非目标镜或手改字段出现意外变化即失败 |
| 挑一镜制作 | 只出现所选媒体项的报价、原订单和可播放候选。未选镜继续保有草稿。界面分别计数计划镜头、已有可用媒体的镜头、已采用镜头 |
| 恢复与协作 | 重复点击、断线、服务重启或写入回执丢失后查回同一次受理；多人改同镜先显示冲突。无权限引用不泄露内容，其他成员可看已采用项目成果，私有对话依旧受限 |
| 缺模型、失败或费用未知 | 区分规划和媒体能力。保留用户已写的镜头、既有成功素材及原任务。失败候选与已采用素材分列，资金状态以账本为准 |

试用指标建议采用**首板采用率**（得到第一份草案的创作会话中，实际采用至少一份镜头方案的比例）、**首次可评审耗时**（提交简报至第一份可编辑草案可见，计中位数与高分位）、**单镜修改正确率**（满足修改意图且无越界改动的用例占比）及**每个已采用镜头的实际媒体成本**（同批次所有已结算媒体费用含失败或废弃候选 / 已采用的不同镜头数）。未结算批次单列，分母为零另计。保留不采用原因，如故事不通、认错素材、镜头不可拍、操作太重或费用不合适。当前没有可发布的基线。

## 8. 证据结论与需求确认

| 调研问题 | 结论及范围 |
| --- | --- |
| 即梦画布怎么开始有效对话 | 已核实当前入口、素材菜单、分镜技能草稿、两层模型设置，以及一个从模糊创意开始、给出三个方向的完整文字回合 |
| LibTV 的故事板具体做什么 | 已核实当前项目的素材视图、分类、详情到对话、工作流往返及生成模式。富项目中的逐镜制作有官方流程及创作者案例，当前账号下未实测在故事板创建完整多镜作品 |
| 怎样保护局部改稿和人工劳动 | BeefTV 固定源码可复核，Flow 与 Storyboarder 补充选版和节奏。竞品服务端并发算法、实际订单和效果质量未知 |
| Glowloom 能否沿现有框架做 | 已识别可复用的会话、权限、分镜结构、预算及画布命令。目标侧栏到正式故事板、多镜逐项生产和选版的端到端流程尚待产品验收 |

**首轮访谈结论。** 产品负责人选择「从一句创意起步，由 Agent 协助定方向」和「可编辑故事板＋一镜可采用样片」。后续设计以空画布起步进行验收；已有商品素材及已有剧本是扩展场景。全片剪辑与导出可由后续制作链承接。

**最终确认。** 模糊创意先获得少量方向、取舍和推荐，用户可以选择或补充。已有清晰方向时直接出分镜。故事板默认按镜头展示，能切到项目素材；用户选镜、确认费用、预览后采用，重做保留旧版。已纳入[正式需求](../requirement/20-对话工作台与参考输入一致性需求.md#src-conv-10)、[设计35 §7.11](../design/35-对话工作台与参考输入一致性设计.md#canvas-storyboard-conversation)及[PRD22验收](../prd/22-对话工作台与参考输入一致性.md)。本报告中的渡轮演示、指标及阈值设定方法供试用评估。
