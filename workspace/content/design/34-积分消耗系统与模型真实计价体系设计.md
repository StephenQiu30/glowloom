# 积分消耗系统与模型真实计价体系设计

本文是[PRD21](../prd/21-模型计价透明与结算恢复.md)的唯一来源设计；[Plan30](../plan/30-模型计价透明与结算恢复实施计划.md)承接执行。接入依赖[设计33](33-多设计模式驱动的模型与供应商接入扩展体系设计.md)，Agent权限依赖[设计32](32-完整创作AgentHarness与Skill多Agent架构设计.md)。调度和实施状态只见[BACKLOG](https://github.com/StephenQiu30/glowloom/blob/8549d9d56fab089ac8ca294462899825bcd420a6/BACKLOG.md#beeftv-adoption)。

商业扩展由[设计36](36-模型商业计费与积分钱包设计.md)单独承接购买/会员/赠送批次、到账资金及支付退款，本设计继续拥有原计量与消费安全合同。当前商业生成的整数积分与资金准入按设计36的“创作空间付款与整数积分技术合同”及SRC-CREDIT-05执行；历史精确金额合同不回算。设计要求与真实验收分别判断，不据文档或旧实现宣布所有商业能力完成；BeefTV统一估价的外部依据见[11-05研究](../research/2026-11-05-模型计费与积分竞品研究.md)。

## 1. 摘要

复用已有价格版本、报价确认、预算预留和结算账本，补充价格解释、结算证据及原结果恢复。生成、交付与费用分别表达，未知请求不能靠重发消除。

代码默认markup_multiplier=1、credit_ratio=10是实现事实；旧文档中的1:10积分、零加价商业承诺及全局/渠道倍率覆盖，确认出处仍需补齐。本文不发布价表，不改账本精度，不启动充值钱包。

[2026-11-03 SRC-AI-36](../requirement/04-AI平台接入与预设管理需求.md#src-ai-36)补充了首个Seedream 5.0 Flash的限定授权：0.12元/输出张、markup=1、ratio=10，整数预估积分向上取整为2，CNY微元账本仍结算120000。该模型按已审核官方来源发布；其他模型及全平台商业政策仍按下列待决项处理，不新增积分钱包或第二套定价引擎。

SRC-AI-38的最小扩展：在原`per_1k_tokens`规则增加可选缓存输入单价，报价按未命中预留，结算使用供应商缓存计数，缺失计数不当作0；视频复用该单位，输入价格0、输出按`usage.completion_tokens`，按冻结分辨率系数定价，禁止用文件时长替代Token。视频报价只对当前明确的Seedance图片/文本输入按尺寸、24fps与时长估算；含输入视频和自动比例的报价缺合同则拒绝。Pro图片沿原per_image/分辨率系数/每任务参考附加规则，引用数量由冻结媒体输入确定并贯穿结算。所有新价格仅配置为待验证发布；DeepSeek高峰/空闲两档分别审核留存，缺少可靠分时结算依据时不启用，不新增日历调价引擎。

SRC-AI-39补充：DeepSeek在既有`per_1k_tokens`高峰单价规则中增加`time_pricing="deepseek_cn_2026"`；这是一份固定2026年度的审核规则标识，包含北京时间周一至周五09:00–12:00、14:00–18:00及国务院公告的放假日期，调休周末仍按空闲。空闲系数为1/2，缓存、未命中、输出费用合并后仅做一次微元向上取整。原高峰/空闲价格版本保持不可变，新规则须另追加版本。来源：[DeepSeek价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)、[2026放假通知政府转载](https://www.beijing.gov.cn/zhengce/zhengcefagui/202511/t20251104_4258873.html)。

分时报价继续按高峰价和未命中预留，冻结规则标识与`reservation_period=peak`；积分沿用原比例。结算使用已冻结价格、原`dispatch_started_at`及Worker在供应商返回后、归档前立即记录并持久化的`received_at`。公开接口的`created`仅表示completion创建时间，不作为供应商扣费时间。仅当整个调用区间可确定处于同一费率且不超过现有HTTP请求上限5分钟时计算；缺时间、时钟倒置、跨费率边界、超时或未审核年份均保留费用未知和原预留，经原人工核验恢复，不按回放/恢复时间重算。2026规则不得外推未来年份，不增加日历服务、定时任务、表或钱包。新增模型仍须另行完成真实验收才可启用。

## 3. 背景

[pricing.go](../../../backend/internal/operation/application/pricing.go)已有按图、秒、请求、千Token、千字符计算和big.Rat/int64微元；[确认事务](../../../backend/internal/operation/adapter/postgres/confirm_single_quote.go)重检价格/预算；[结算](../../../backend/internal/billing/adapter/postgres/settlement.go)写settle/release/provider_overage及幂等事实；[调用证据](../../../backend/internal/operation/application/provider_call.go)已有ErrProviderCostUnknown。

这些源码不是所有供应商和端到端商业账单的验收证明。BeefTV公开价格消费端与结算观察可参考，远端钱包/退款账务没有在该桌面主线公开。视频Token不等同文本Token，参考账单分支的1.5也不构成Glowloom定价依据。

## 4. 目标

- 预估、预留、实扣、释放、退款确认和未知不混用。
- 同一确认冻结输入、价格、汇率及派发身份，不随当前目录重算。
- 失败、审核、取消、超时不自行证明未收费。
- 重复确认不二次预留，未知付费请求不重新POST。
- 结果恢复沿原消费；新增消费重新报价确认。
- 财务金额可复算，UI小数不降低账本精度。

## 5. 使用场景

1. 改变模型、清晰度、秒数或参考素材后核对明细。
2. 只有单价或账单预留时看到金额性质；缺平台认可收费规则时不以假零价派发。
3. 视频已受理但页面断线，刷新查原操作。
4. 已生成但下载失败继续交付；费用未知继续核查。
5. 有明确未执行/退款证据后处理原账，新生成重新确认。

## 6. 价值

让创作者理解批准内容与费用，管理员区分平台预算、上游欠费及速率问题，维护者用稳定身份核对账单。没有真实成本与争议率基线，不宣称节省比例。

### 7.2 价格来源与版本

记录精确供应商/模型/区域/模式、单位、币种、来源URL或审核账单依据、核验时间、适用参数、有效版本和汇率。没有一手来源的“实时价表”、测试fixture和目录名字不得作为发布价格。

新价格来源校验覆盖所有生成PriceRuleVersion的入口，包括直接发布与预设模板实例化；预设模板可携带source_url/reviewed_at，历史缺失仍可读取，不能据此新发布无依据价格。从现有release复制仅继承已有真实元数据；手工模板不得自动伪造来源或核验时间。既有连接和在途冻结价格不因历史缺失被改写。

目录更新只形成候选差异，管理员审核后发布新PriceRuleVersion；缺价不等于免费。旧请求沿冻结价格和汇率，确认时沿既有新鲜度检查。采购成本与客户销售价分别命名；CalculateActualCost可能包含加价，不能直接标“供应商纯成本”。

建议在现有安全模型目录增加pricing_preview：amount_kind为estimate/reservation/unit_only/unknown，amount_micros可空；只展示客户销售规则，不暴露采购明细。unit_only/unknown不创建operation、不提供确认票据。正式QuoteResponse保留非空quote_micros；只有可按已发布规则算出确定预留且满足既有权限/预算/输入合同，才产生confirmable=true的正式报价。reservation不代表硬上限；只有已接受的封顶政策才能另给max_charge_micros。缺价的正式报价明确拒绝，不用0承载未知。

### 7.3 金额与积分精度

保留1 CNY=1,000,000微元，int64保存、big.Rat中间计算，最终按既有规则向上取整至微元。ratio=10示例下1积分对应100,000微元。积分是展示/政策，不把微元账本改成微积分。

旧文档Decimal(12,4)不作为迁移指令；显示两位小数不截断账本。现有EstimatedCredits是整数向上取整预估；分数积分显示若采纳，须从微元和冻结ratio产生新的精确投影，不能误用该整数。

### 7.4 计量与费用说明

| 类型            | 预估与证据                                                             |
| --------------- | ---------------------------------------------------------------------- |
| 图/秒/请求/字符 | 冻结数量、模式/分辨率系数及单价；最终取可信计费数量                    |
| 文本Token       | 输入估算/max输出与独立单价；缓存须有明确互斥口径及费率，禁止套固定折扣 |
| 视频Token       | 只有单价不伪造总额；需独立合同，不塞入文本input_tokens                 |
| 参考图附加费    | max(计费参考数−免费数,0)×单价；按每任务/输出必须声明                   |
| 原币账单        | 预留不等于最终费用/封顶；需原币、金额、账单身份、请求关联与最终性      |

重复引用、mask、角色图和视频帧计数按模型合同冻结；不能用输出图数当参考图数。by_resolution仅为乘法系数，不能强装含独立附加项的矩阵。新增收费字段必须同时进入发布校验、报价及实际用量解析。

Glowloom建议新增规则字段为free_reference_images、reference_image_micros和reference_scope（per_task/per_output）；价格仍为原币微单位，沿冻结汇率转换。PricingInput.ReferenceImageCount由服务端已校验素材派生，实际BillableUsage.ReferenceImageCount使用指针区分缺失和0。此为本项目拟议格式，不冒称BeefTV同名完整合同；无对应模型计量依据不发布。

模式/分辨率系数先用于基础费用；参考图费用按独立单价与scope计算，per_output在预估使用计划输出数、最终使用可信实际计费输出数。两项合并后只应用一次冻结markup和汇率，最后向上取整至微元。已被供应商Token或基础单价包含的参考成本不得重复添加。

### 7.5 生成、交付、结算的安全投影

建议在既有GET /operations/:id追加billing_outcome，不建设与operation.status竞争的第二状态机。新增字段合同如下，生成API以实际后端注解为准：

| 字段                                                                 | 定义                                                                |
| -------------------------------------------------------------------- | ------------------------------------------------------------------- |
| charge_state                                                         | unknown / pending / settled / released / refund_confirmed           |
| provider_settlement_state                                            | 独立的供应商结算观察值，缺失为unknown，不替代用户账本               |
| reconciliation_required                                              | 证据冲突或尚需核查的标志，不改写本地已入账金额                      |
| delivery_state                                                       | pending / ready / recoverable / unrecoverable                       |
| regenerate                                                           | blocked / confirm / allowed；只读建议，不是写权限                   |
| reason                                                               | 稳定安全原因码，不含供应商原文                                      |
| reserved_micros / charged_micros / released_micros / refunded_micros | 当前未关闭预留、历史实扣、预留释放、已入账退款；CNY微元，缺失为null |
| evidence_present                                                     | 区分未读到字段与显式空串                                            |
| reconcile_deadline                                                   | 上游核对期限，不是免费重跑时间                                      |

| 已有事实                    | 允许动作                                |
| --------------------------- | --------------------------------------- |
| 明确未派发/未执行且费用为零 | 依原合同关闭/释放；新消费重新报价       |
| 受理或消费未知/pending      | 查原任务或核查；同消费身份blocked       |
| 已付费且可取回              | 继续原交付，不创建新购买                |
| 已付费且确定取不回          | 明示另行消费后confirm，不凭交付失败退款 |
| 明确退款/零收费             | 对应账务事实处理后重新报价              |
| 一般失败/审核/取消/超时     | 不据此清零或释放；继续取证              |
| 证据读取失败/冲突           | 保留占用与核查，不推断零费用            |

BeefTV usage_state=failed不是所有供应商的退款完成；字段缺失与空串分开。超过期限仍blocked并转核查，二次确认也不能覆盖未知重复消费风险。

charge_state描述平台用户账务，以本地reservation/ledger及已接受补偿流水为权威；provider_settlement_state仅表达上游观察。本地已settled而上游pending时仍显示原实扣并核查，不抹账；上游宣称refunded但平台未落补偿时不得显示refund_confirmed。金额或最终性冲突标reconciliation_required并阻止同消费身份再次派发。退款未入账不能改变charged_micros；原实扣与refunded_micros分列。

### 7.6 预留、结算和退款

沿现有确认事务锁定报价和预算，写reservation/reserve，再经原Outbox执行。最终可信用量沿冻结规则计价，在同一结算事务写settle/release/provider_overage和事件；不一致重放冲突。

预留释放不是已扣款退款。reservation关闭后收到退款，不能重复Settle(0)改历史；需另经接受的补偿事实/流水。在该合同未形成前不显示退款完成。CapAtReservation只在指定策略限制实扣，不能宣称所有预留硬封顶。

### 7.7 恢复与授权

复用operation查询、既有工作流query/delivery及manual resolution，不将BeefTV的/tasks/:id/recover当成本项目已有接口。必要新写入口需沿原命令边界定义。

同目标未决检查在服务端锁内执行，不只禁用UI。规范化屏障键为组织、项目、目标类型、目标ID、输出槽；画布目标从服务端校验的CanvasSource/source_context取得；画布operation的target_id可为空，不能以此跳过屏障，revision也不进入屏障键。输入哈希和模型版本属于原操作证据，不加入屏障键；同节点改提示词、模型或请求键也不能绕过未决任务。新报价与确认及真正派发均重检该键，冲突拒绝新增消费，不全局封锁同模型。

无持久目标的自由生成优先沿已有submission_id识别意图；不存在时以原operation_id及确认幂等键查证重放。刷新、失败恢复和Agent接续不得自动换键创建新报价。用户独立发起且明确确认的新报价是新消费，不按相同prompt哈希全局去重；这不是同一个未知操作的重发许可。

拟新增POST /operations/:id/recover，沿现有WorkflowControlCommand增加operation/recover动作，要求UUID幂等键；组织/项目由原操作读取并重新鉴权，不接受任意workflow ID或信号。仅对可查的原上游任务/已有交付证据写控制回执和Outbox；无恢复依据返回冲突，结果已就绪返回无动作。已有回执重放原样返回。worker只查询原任务或继续已有产物交付，不调用创建/确认/付费Submit，不改变原operation/attempt、价格或预留。202表示查证意图已接纳，不代表结果或退款完成；现有GET查询可持续读原事实。

异步任务的轮询和下载失败保留原查询回执。若原`v1`派发、冻结身份、供应商任务ID、已保存成功结果与有价成功查询全部一致，最终可信用量可覆盖同一任务此前未完成的只读查询；这不把未知提交或取消、其他身份的查询费用置零。结算使用原任务的消费事实，相同用量的重复终态查询不累计第二次费用。没有上述完整证据时保持费用未知和原冻结。

终态原交付补充：已结算但因执行权限撤销而收尾的任务，可能仍有原成功manifest/私有暂存产物。恢复不得重新进入OperationWorkflow的生成分支；允许固定`operation-delivery/<原operation UUID>`的专用交付工作流，仅复用原媒体归档管道。准入要求当前项目授权、本地已关闭预留和真实settle流水、原成功manifest、可归属且未被审核拒绝的产物；各阶段重新检查范围，不借新Key访问上游。终态归档须关联已持久接纳的恢复请求和当前请求人，在HTTP、relay、workflow/worker及实际媒体写入边界重检其项目与目标访问权限；原确认人失权不能代替当前请求人的授权，也不能据此解禁原付费执行或放宽Agent私有范围。原operation/attempt/价格/账本及终态保持，交付就绪由独立投影表达。无这些证据的终态返回冲突，不能推断不可取回或退款。重复恢复复用同一交付身份与幂等归档；不提供任意workflow名、Submit或新报价入口。

默认不启用同键再POST；将来补交须核验幂等键、内容摘要、原Key作用域及保留期，且可能触发首次收费，不能无条件标免费恢复。Agent批准与检查点不替代operation权限、预算、新鲜度及派发所有权。

完整故事在PRD21：US-BIL-01费用可解释、02确认可靠、03结算事实、04原结果取回、05配额核查。FR-AI-35～39、AC-AI-35～37及T-AI-22/23/25保留。T-AI-24由Agent主链承接，本设计仅声明费用授权依赖。

### 7.9 SRC-AI-40 版本化计量与计价算法

官方精确ID、采购价和参数矩阵见[11-05官方核验](../research/2026-11-05-官方模型接入预设与计价核验.md)，接入与预设对象归设计33 §7.8～7.13。以下是原引擎扩展设计，不宣称已经有策略注册表或这些新计量桶。

现有`CalculateQuoteDetailed/CalculateActualCostDuring`仍为用户计价入口；将真实模型差异从型号前缀和散落switch中提取为小而受限的策略组合：

```text
冻结模型/参数/媒体事实
  → MeteringStrategy.Estimate：估算数量、可信上界、缺失维度、算法版本
  → PricingStrategy：按冻结费率/维度定价
  → 冻结销售/汇率/最高支出 → 报价确认 → 原operation派发
  → UsageNormalizer：原回执/账单转换成带证据的计量桶
  → 同版本PricingStrategy → 采购事实/用户实扣 → 原账本结算
```

算法ID引用已安装、可测试的Go实现，不接受用户上传JS/Python、SQL、任意表达式或外部代码。注册表由组合根一次构建，引用版本必须存在；新增算法只在确有新合同的模型需要时增加，不为每个SKU复制整个引擎。旧算法与配置快照在在途任务关闭前保留，不能更新算法同名实现后重算旧消费。

### 7.14 既有引擎的首批版本合同（2026-11-05）

`PriceRuleVersion.rule`可选`pricing_strategy`，只允许安装版本：`image_flat_v1`（per_image）、`token_io_v1`（文本per_1k_tokens，沿原输入/缓存/输出与分时合同）、`seedance_video_tokens_v1`（四个精确Seedance型号的per_1k_tokens）。未知版本、null、空字符串或单位不兼容均拒绝；未携带该字段的历史价按原算法读取。算法版本、费率、FX均随原价格版本冻结，报价明细带回版本ID，不改已冻结价格或账本。

例如Flash普通单图的候选计算可用`{"pricing_strategy":"image_flat_v1","base_micros":120000}`；Fast无输入视频可用`{"pricing_strategy":"seedance_video_tokens_v1","input_micros_per_1k":0,"output_micros_per_1k":37000}`。这些只是可审核规则示例，代码不自动发布官方采购价为用户销售价。

所有策略继续使用原big.Rat引擎，数量×费率×已发表系数×markup×FX只在最终CNY微元处向上取整。`credit_ratio`延续既有显示积分合同，不代表设计36商业钱包已实现。新版本若使用价格矩阵，运行时遇到未配置分支拒绝，不能回退系数1；历史规则保持原读取语义。

Seedance预估沿原24fps像素Token公式，按精确型号限制时长/分辨率，2.5首帧adaptive保守取最大像素面积。参考视频仍无完整最低量合同，因此不准入该估算路径。结算使用供应商输出Token；版本化视频策略允许仅有output_tokens或额外显式input_tokens=0，拒绝混入张数/请求数/字符/缓存等冲突证据。不会用预估量替代真实usage。

### 7.15 SRC-AI-47 官方价目同步、倍率与缓存

来源：[需求04 SRC-AI-47](../requirement/04-AI平台接入与预设管理需求.md#src-ai-47)。本节是[PRD21 SRC-AI-47](../prd/21-模型计价透明与结算恢复.md#src-ai-47)的唯一设计来源；按[Plan30 SRC-AI-47](../plan/30-模型计价透明与结算恢复实施计划.md#src-ai-47)实施。Key 下模型发现仍依设计07/33与PRD03/20，不重复定义接入流程。

#### 公开事实与边界

模型可见目录与价目来源不是同一合同。OpenAI 的[模型列表 API](https://developers.openai.com/api/reference/resources/models/methods/list)返回可见模型元数据，价格见其[官方价目页](https://developers.openai.com/api/docs/pricing)；DeepSeek 的[模型列表 API](https://api-docs.deepseek.com/api/list-models)描述模型和能力，价格另见[官方价目页](https://api-docs.deepseek.com/quick_start/pricing)。OpenRouter 的[模型目录 API](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)包含 `pricing` 字段，但该值是 OpenRouter 渠道报价。官方机器可读价格缺席时，不能把模型发现响应或聚合商目录冒充厂商官方价。

目前的 `catalog.model_price_preset`/`data.sql` 是内置公开来源说明与可选规则的启动基线；它没有每日抓取记录、原文版本或审核状态，不足以独立表示同步历史。`catalog.price_rule_version` 及 `model_release` 仍是已审核、可执行价格和在途消费的权威版本。目录发现继续读取实际连接上的凭据并只产生候选，不因目录可见而自动建立可计费发布。

#### 数据流与建议的最小候选快照

```text
官方价目来源 ──每日只读同步──> PostgreSQL PriceCandidate
                                      │
                         规范化、校验、价格差异
                                      │
                         管理员审核与倍率设置
                                      ▼
               不可变采购价格版本 + 销售价格版本
                                      │
                    release / 报价冻结 / 结算
                                      │
                         版本化 Redis 缓存
```

建议增加版本化 `catalog.price_candidate`（或在实现时证明现有表能满足全部字段再复用），候选至少记录：`adapter_key`、精确 `provider_model_id`、地域/档位、币种/单位、规范化 `rule`、官方 URL、抓取时间、源更新时间（若来源提供）、源内容摘要、解析器版本、状态和审核信息。按来源身份与内容摘要幂等去重；保留历史候选供差异查看，不保存 API Key、凭据响应或整页无关内容。该表不是 operation 计费价，不作为运行时费率直接读取。

供应商专用同步器优先读取官方结构化价格接口；否则只对经过验证且稳定的官方页面格式采用窄解析器。所有数值在进入候选前校验单位、币种、精度、模型 ID、参数维度和已安装计价算法。来源变动但字段解析不完整时记为 `needs_review`，不得按缺失字段补零或覆盖最后有效记录。无结构化/稳定来源的供应商继续使用 [data.sql](../../../backend/db/data.sql) 基线和管理员人工复核。

当前 DeepSeek 官方分时价目只对精确的 `deepseek-flash` 与 `deepseek-v4-pro` 模型列尝试归一化：缓存命中输入、未命中输入、输出分别要求峰/闲两档，共六条价格证据；闲时价格须与对应峰时价格严格相差一半。使用有理数将 CNY/百万 Token 精确换算为 CNY 微元/千 Token，并绑定现有 `deepseek_cn_2026` 北京时间/法定节假日合同。只接受北京时间年份为 2026 的完整匹配表，候选仍为 `pending_review`；字段缺失/重复、比例不符、单位/币种/模型不符或日历年份未核验时保持 `needs_review`，不得外推到后续年份。

#### 每日调度与审核发布

在现有 provider/catalog worker 与持久化 taskruntime 中增加每日同步任务；同一来源单实例运行，使用来源级限流、条件请求（来源支持时使用 ETag/Last-Modified）、有限退避及结构化失败状态。每天同步只负责观测公开价目并写入 PostgreSQL 候选。抓取失败保留最后成功快照并标记陈旧；成功但价格没有变化不新建重复候选；模型或费率从官方目录消失则形成撤回候选，不能删除历史。

候选变化由管理端对照“当前采购费率、平台倍率、当前销售费率”后审核。审核通过才调用现有发布命令，追加采购价格版本和独立的销售价格版本，再按现有门禁生成或更新 release。源价改变、币种改变、倍率改变或适用参数变化均产生新版本；在途 operation 沿冻结 `price_rule_version_id` 计算，目录刷新不重算旧报价。只有将来明确评审并启用某个可信结构化来源的自动跟价策略，才允许候选自动进入该来源范围内的发布流程；默认不开启。

#### 销售倍率算法

设供应商发布的精确采购规则对一次请求得到原币金额 `C`，冻结汇率为 `FX`，销售倍率为 `M`，则用户销售价为：

```text
采购金额 = ceil_CNY_micros(C × FX)
销售金额 = ceil_CNY_micros(C × FX × M)
```

实际实现应在一个精确计算链内累计基础费用、缓存桶、模式/分辨率系数与附加费后，再乘冻结 `FX` 和 `M`，最后只在 CNY 微元边界向上取整；不得先把采购价逐项取整再乘倍率，也不得通过 `float64` 计算。`M=1` 表示销售价与公开价按相同计量口径一致；`M≠1` 是 Glowloom 的销售价，界面与费用明细必须同时说明供应商价和倍率，不能把销售价显示成供应商官方价。

复用 `PriceRuleVersion.rule` 中现有 `markup_multiplier` 合同与 `big.Rat` 引擎，但明确数据归属：采购版本保存纯供应商费率，不含 `markup_multiplier`、平台积分比例或采购版本自引用；销售版本只引用采购版本并冻结倍率及适用销售规则。现有 `UseOfficialRate` 发布路径默认倍率为1；要支持管理员调整，须扩展发布应用命令及管理表单，让倍率只能应用在生成的销售版本，且与采购版本一起审计。倍率变更不得修改采购数据或已发布记录。

#### 高频读取与性能

PostgreSQL 是唯一权威。Redis 缓存模型目录投影和按不可变价格版本 ID 读取的规范化规则，不能缓存授权、项目余额、预算锁或最终报价确认结果。发布事务成功后，以版本号/Outbox 事件更新目录指针或失效旧指针；旧事件不得覆盖较新版本。缓存键应包含 `price_version_id`（必要时含目录修订），设置 TTL；缓存未命中、过期、版本不匹配或 Redis 不可用时回源 PostgreSQL。不得以缓存中的旧 price pointer 放行新消费；正式确认仍走现有数据库事务及冻结版本重检。

为减少热路径上的数据库读取和 JSON 规则重复解析，应用可按不可变 `price_version_id` 缓存已校验/预编译的计价计划；运算对象需并发只读或每次克隆有理数，避免共享可变 `big.Rat`。Redis 适合跨进程保存版本化规范规则/投影，进程本地编译缓存适合避免每次重解析。计算公式保持原 `big.Rat` 精度，先记录报价 CPU/延迟和规则命中基线，再与缓存方案比较；没有基准数据前不承诺提升百分比，也不把算法替换为近似浮点数。

#### 失败和安全边界

- 定时同步只请求硬编码/注册的供应商官方 URL 与允许的来源域；不得根据用户提供的模型 ID/URL 发起任意网络请求，避免 SSRF。
- API Key 仅用于当前连接支持的只读模型发现/验证；价目同步优先公开官方来源，不把 Key 发给聚合商，不在缓存、候选、日志或错误详情保存凭据。
- API Key 的可见模型可能受组织、地域、权限和账号状态影响；目录差异只表明该连接的可见性，不自动推断供应商全量目录。
- 汇率仍在管理员发布时冻结；该同步不抓取汇率、不覆盖已有 `fx_rate_to_cny`。付费来源、动态折扣、账户专属合同、价格页面解析不确定和缺用量证据均进入审核，不自动变成可消费规则。
- 价格变化不触发供应商试运行、真实生成、商业库迁移或已验证模型自动启用。

#### 待评审项

自动发布白名单、倍率可接受上下限、陈旧价门槛、每日执行时刻/时区、供应商逐站抓取方式与官方页面使用条款、告警阈值及性能 SLO 由产品/运营/工程在实施前确认，并仅在 BACKLOG 跟踪状态。默认安全行为是候选待审，不能因存在调度器或缓存而视为价格已接受。

### 7.16 SRC-AI-48 统一计量、报价和积分合同

来源：[需求04 FR-AI-61、62及AC-AI-40、42、43](../requirement/04-AI平台接入与预设管理需求.md#src-ai-48)；接入绑定依[设计33](33-多设计模式驱动的模型与供应商接入扩展体系设计.md#src-ai-48)，公开依据见[本轮研究](../research/2026-11-09-模型预设音频与统一计量调研.md)。以下新增接线为评审建议；不修改已冻结金额，不发布本轮未核验的官方价格。

#### 一个计价入口，明确三种金额

供应商原始用量 → 协议用量归一化 → 冻结规则精确计算 → 采购/销售金额 → 商业整数积分。预设中的计量引用与算法参数、发布所选价格、报价和最终结算必须使用同一兼容合同。统一的是入口、量纲、版本与证据，不强行让四类模型都按 Token 或每次请求计价。

| 对象               | 权威与展示                                                                                                              |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------- |
| 供应商公开采购基准 | 原币费率、单位数量、渠道/区域/商品、参数分支、有效期、官方 URL、来源摘要和核验日期；第三方目录不能冒称官方直连价格      |
| 采购用量成本       | 按冻结采购规则及可信实际用量计算的公开基准成本；账户最终账单独立记录/核对，资源包、免费额或商务折扣不在缺证据时自动推算 |
| 平台销售金额       | 按冻结销售规则、倍率和汇率精确计算；引用采购版本，不能在纯采购数据中叠加销售倍率                                        |
| 本次积分           | 沿设计36的商业整数策略，从最终销售金额统一换算；UI、Agent、billing 不能各自取整                                         |

仍复用 `big.Rat`、CNY int64 微元、PriceRuleVersion 及现有 quote/operation，不新建公式服务或通用算法图。十进制费率、汇率、倍率和时长用精确十进制解析为有理数；不得经 float64 再转回小数。所有数量须非负、有单位、有来源和上界，溢出/维度不匹配/规则缺失直接拒绝，未知字段不得静默丢弃。

设 `q_i` 为按供应商规则处理后的可信用量、`r_i` 为原币单位价、`u_i` 为单位数量，`FX` 为人民币/原币，`M` 为销售倍率：

```text
C = Σ(q_i × r_i / u_i)                  # 原币精确公开基准成本
purchase_micros = ceil(C × FX × 1,000,000)
sale_micros     = ceil(C × FX × M × 1,000,000)
commercial_credits = ceil(sale_micros / 100,000)
```

采购与销售分别从未截断的 C 计算，不能用已取整采购金额再乘倍率。仅在供应商明确要求处进行其用量粒度/最低量舍入，随后合计费用、做一次微元取整，最后按商业政策做一次整数积分取整；不得每个 Token 桶或音频分片单独取整积分。旧报价未携带整数结算标记时仍按历史精确金额及 credit_ratio 语义，不能静默迁移。列表基准价格若为分数积分只能标“费率折算”，不能让它看起来是本次最终扣费。

#### 报价、展示与冻结

1. 服务器从同一请求规范化器得到默认值、有效模式、参考媒体事实和精确输入摘要，再读取不可变合同与价格版本。UI 不能传任意积分或实际用量。
2. 免费报价返回服务器金额、预估积分（可估时）、**最高扣除积分**、币种/单位、适用参数、版本、有效期和费用说明。预估不可靠时只展示“最高扣除 N 积分”，不能伪装成预计实耗；缺价格/上界则不可确认，不返回虚构0积分。
3. 确认绑定 quote/release、连接及凭据版本、模型 ID/合同、usage schema/算法版本、采购/销售价格版本、FX/M、整数结算策略、input_hash 和最高支出；在原事务内重检可用性和付款权限。参数或价格变化后重报，已确认 operation 仍沿原快照。
4. 先成功冻结已授权整数积分，再按原身份派发；沿同步或已启用 SAGA 的相应资金准入。缓存余额或仅返回202受理均不能当资金已冻结。
5. 结算对最终归一化用量运行相同冻结计价合同，核销不超过授权上限，余量依原合同释放。异常超上限不得静默多扣；按已有上限/核查政策处理并记录供应商成本，不能修改 usage 来凑上限。
6. 创作者在模型选择及参数变化后看到本次服务端积分；管理预设默认只展示适用的单位费率/计价说明，选定参数后才有本次金额。无输入上下文时不写一个固定“每次N积分”冒充所有组合的真实价格。

#### 音频终态、未知和幂等

TTS 新发布沿设计33的完整终态及用量证据要求；音频分片是产物片段，不是独立收费操作。Seed-Audio 持久保存原始响应计量摘要及原始/播放两种时长；当前浮点到毫秒向上取整路径须在新版本中换为精确解析和已核验计量规则，不重复取整秒数。字幕开关/格式等若影响费用，也进入参数摘要和规则覆盖。

生成失败、交付失败、用户取消、HTTP错误和缺少 usage 均不直接推导供应商零消费。无调用/可信零消费时才走零核销或释放；已消费按可信用量结算；受理或费用未知沿原身份核查，禁止换 Key/渠道重发。设计36 SAGA 收到的 `failed` 应是经过此费用分类的可全额释放事实，不能直接转发任意供应商任务失败事件。迟到回执按 operation/attempt/供应商请求身份及结算键去重；冲突证据进核查，不追加第二次扣款。
