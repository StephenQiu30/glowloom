# 模型销售定价与结算设计

**当前建设方法（SRC-AI-53）**：用户明确现有实现不可靠，要求从零完整重建，并允许清空旧测试数据。本文的有效产品规则继续作为输入；任何“复用现有Execution／号池／账本／表结构”的实施约束由[设计33重建合同](33-多设计模式驱动的模型与供应商接入扩展体系设计.md#ai-rebuild)替代。旧源码和测试只供审计，不能证明新方案可靠。

设计评审稿。2026-11-17 [SRC-AI-52 / DEC-GW-01](../requirement/04-AI平台接入与预设管理需求.md#src-ai-52)明确模型售价稳定、供应商成本分开，保持商业政策；定价和账本实现按SRC-AI-53重建。既有来源为[后台倍率和折扣 SRC-AI-49](../requirement/04-AI平台接入与预设管理需求.md#src-ai-49)、[号池 FR-POOL-09](../requirement/26-模型号池与多供应商路由需求.md)、[积分规则 SRC-CREDIT-04](../requirement/21-模型商业计费与积分系统需求.md#src-credit-04)。线路资格、派发和恢复由[设计40](40-模型号池与销售计费设计.md#pool-contract)持有。

产品验收见[PRD](../prd/27-模型销售定价与结算.md)，执行步骤见[Plan](../plan/36-模型销售定价与结算执行计划.md)。

## 1. 摘要

管理员为一个模型规格设置销售基准、常规倍率和折扣。系统同时显示采购参考、折前价和折后积分，发布后供各创作入口报价。每次确认固定用户能接受的最高扣费，实际命中渠道的采购成本独立核算。

## 2. 参与者

有定价权限的管理员可编辑、预览和发布。创作者或获授权的 Agent 可请求报价并在余额、预算内确认。账务人员依据供应商回执、账单和积分流水核对差额。服务端按付款空间校验读写权限。

## 3. 背景

即梦网页会随规格及账号权益展示单次积分。方舟 Seedance API 的 Token 回执提供采购计量依据。BeefTV 的报价模型分别表达已知金额、用量估算、预留额和未知项。设计采用这些区别来组织报价与账单。[外部研究 §4～5](../research/49-2026-11-13-模型号池与多供应商路由调研.md)

## 4. 目标

**已明确**　后台可调整倍率和折扣。每人民币元折 10 积分，整单向上取整，足额才派发，扣费受确认上限约束。短剧视频按实际计费 Token 结算。**建议**　首轮以模型和规格为定价范围，每个销售版本使用一项有效折扣。**待定**　视频销售费率及首批准售规格、倍率上下界、限免和会员优惠叠加规则。

## 5. 使用场景

| 来源 | 前置、角色与动作 | 确认条件 |
| --- | --- | --- |
| SRC-AI-49 | 管理员选定模型和模式，把常规倍率设为 1.5、销售优惠设为 8 折，选择示例输入预览。 | 预览可见折前、折后与适用版本。非法值保留草稿并指出字段。只有有权限的管理员可发布。AC-AI-44、AC-AI-45。 |

## 6. 价值

管理员可以核算一次调价对用户积分和预计毛利的影响。创作者可在生成前看到整单预算。对账时能解释采购价差、优惠和超确认价由平台承担的金额。

## 7. 方案

### 7.1 管理员价格发布

对应 FR-AI-65。采购价与销售价版本的来源见 FR-AI-55、FR-AI-56。[原始价格规则](../requirement/04-AI平台接入与预设管理需求.md#src-ai-47)

模型价格页显示当前有效版本及适用规格。上半部分选择有来源、币种、单位和审核时间的渠道采购价。下半部分编辑对外销售基准、倍率和折扣。销售基准须引用确定的参考费率及汇率版本，换路后仍可复算。默认倍率 1，默认 10 折。产品界面输入 8 折时，服务端保存精确十进制 0.8。首轮建议接受正倍率、折数大于 0 且不超过 10，零价活动另议。

管理员用示例输入预览已知采购成本或区间、折前金额与积分、折后金额与积分、预计价差。预览和正式报价使用同一计价规则。保存草稿后显式发布，操作带所见版本。并发改价引发版本冲突时展示最新差异。发布形成不可变销售版本，审计记录操作者、前后值、适用规格和生效时间。取消优惠发布 10 折的新版本。修改前已出具且仍有效的报价使用其冻结版本，过期或输入变化则返回新报价。

### 7.2 计量、换算与上限

对应 FR-AI-66、FR-AI-67。先用所选合同的基准费率计算各计费项，按冻结汇率换算为人民币并合计。对整单乘常规倍率和一次折扣，再乘 10 向上取整。保存中间的精确金额以供审计。采购独立使用各次实际命中渠道的单位、用量、采购价及账单。

| 计量合同 | 提交前所需数据 | 结算依据 |
| --- | --- | --- |
| 确定单价，如按张、按次或已约定的计费秒数 | 合法数量、规格、可收费附加项及币种。 | 合同规定的实际交付量与收费证据。部分成功按可核实的计费项汇总。 |
| 按实际用量，如文本或方舟视频 Token | 模型版本、单价分档、计量上下界。视频预估考虑分辨率、帧率、输入/输出时长及适用的最低用量。 | 对应任务的计费 Token 及其来源。单位不同的备线必须能提供冻结销售合同所需的计量证据。 |
| 只能获得账单或用量暂缺 | 单独展示估算和可兑现的确认上限。无可承诺上限时显示待报价。 | 收到账单后核实其与原任务及销售计量的关系，证据不足继续待核对。 |

例：人民币基准 ¥7.56，常规倍率 1.5。折前 ¥11.34 为 114 积分，8 折后 ¥9.072 为 91 积分。若确认上限为 91、可信实际基准金额为 ¥6.00，则实际扣 72、释放 19。若实际基准为 ¥8.00，按同一规则算出 96 积分，用户最多扣 91，其余 5 积分的售价差额由平台承担。该差额与采购账单的币种和金额分别记录。上述数值为设计验算。

### 7.3 报价、确认与对账交接

对应 FR-POOL-09。创作入口提交付款空间、模型规格、规范化输入和约束，报价返回报价号、版本、折前与折后预计积分、最高积分、有效期。确认时重新校验权限、空间预算、输入摘要和报价有效期。余额与预算足够时，一次事务冻结确认上限、生成任务并登记可派发记录。同一付款方、确认键和内容重放取得原任务，异内容冲突。执行端只消费已提交的派发记录。[派发约定](40-模型号池与销售计费设计.md#pool-contract)

| 可核对的事实 | 资金动作 |
| --- | --- |
| 可信用量及终态已取得 | 按冻结销售版本重算，核销实际积分与确认上限中的较小值，释放余量。采购差额按实际渠道单列。 |
| 收到明确未受理且无费用的证明，任务已终止 | 释放原冻结并记原因。安全补尝试仍在途时，冻结保留至任务终态。 |
| 受理、用量或费用未知，或回执与账单冲突 | 留存原冻结、尝试号及待核对原因。迟到回执先按付款方、任务、尝试与原上游编号校验归属，再以同一结算身份处理。 |
| 重复、乱序或事后更正 | 原结算只生效一次。重复事件返回原结果，互相矛盾的证据进入人工核对。已落账的更正以关联原流水的调整记录表达，用户累计实扣仍受确认上限约束。 |

### 7.4 供应商计价与统一账单

对应 FR-AI-75、CASE-GW-06/07。统一网关负责获取可信用量并交给现有定价/账本，不根据 SDK 的估算 cost 直接扣积分，不引入另一份余额。沿用现有价格版本、operation/attempt、冻结及流水，只补确实缺失的业务字段。

| 对象 | 最小合同 | 变更边界 |
| --- | --- | --- |
| 渠道采购价版本 | 供应商、端点/商品/区域、精确型号/规格、币种、计量单位、分档及附加费、来源、有效区间、审核时间 | 不同供应商独立维护；官网价仅是候选，实际账号折扣/套餐以可归属合同为准。 |
| 模型销售价版本 | 对外模型/规格、冻结参考费率、汇率、倍率、折扣、1元10积分及整次取整规则 | 用户已确认独立售价；换供应商不改费率、确认上限或付款方。 |
| 尝试用量与采购事实 | 原 attempt、上游编号、脱敏原始 usage、归一化用量、采购价版本、原币金额/汇率及账单证据 | 每次实际尝试分别登记；未知不补0，失败尝试的已发生成本也不能丢失。 |
| 用户消费单与积分流水 | 原 operation/Run/可选项目、模型、报价/上限、交付及收费状态、实扣与释放、关联流水 | 一次业务调用至多一次有效核销；调整反向记账，不改历史，不因多个采购尝试重复向用户收费。 |

采购和销售各用自己的计量合同：采购原币成本 `C_attempt = Σ(q_purchase_i / u_purchase_i × supplier_rate_i)`；销售人民币金额 `S = Σ(q_sale_j / u_sale_j × frozen_sale_base_rate_j × frozen_fx_j) × multiplier × discount`；用户积分 `P = min(confirmed_cap, ceil(S × 10))`。`u`为费率单位（如每百万Token），销售基准费率尚未包含倍率/折扣；`q_sale`只取原销售合同认可的业务用量证据，不累加失败或补尝试的采购用量。采购和销售单位不同时须有已验证映射，不能直接套同一usage。计算用定点/精确十进制，整次各计费项合计后只取整一次；采购保留原币，不把整数积分反写成采购单价。

稳定的是销售**费率与确认上限**，不表示所有请求实扣相同。实际输出量或缓存命中改变时，仍按冻结销售合同计算并在上限内结算；供应商切换本身不产生加价。

| 用量来源 | 归一化与收费规则 |
| --- | --- |
| OpenAI Chat/Responses | input/prompt 与 output/completion 是总数；cached、reasoning 等通常是总数内细分，不能再次相加。最终 usage 丢失则待核对。 |
| Anthropic Messages | 普通输入、缓存写入、缓存读取按协议分别处理；缓存写入需要时区分TTL。流内累计 usage 使用有效终态，不把每次累计值求和。 |
| DeepSeek | 按当前渠道协议区分 cache hit/miss、输出及已开放的附加计费项；不能把所有渠道当原厂官网统一单价。 |
| 图片/视频/音频/供应商工具 | 使用已发布的张、计费秒、Token、字符或次等真实单位；播放时长不等于视频Token，工具次数不折成猜测Token。 |

**纯算术样例，非供应商实价**：同一模型本次未缓存输入10万、缓存读取20万、输出5万 Token。A采购费率为每百万Token ¥2/¥0.5/¥6，成本¥0.60；B为¥3/¥0.8/¥8，成本¥0.86。冻结销售基准为¥4/¥1/¥12，基础金额¥1.20，倍率1.5、8折得¥1.44，整次15积分。确认上限18则核销15、释放3；命中A或B均沿同一销售规则，采购分别记账。若本次采购上限为¥0.90，成本上界超过该值的渠道不可派发。样例的整数积分面值为¥1.50，取整前售价¥1.44及差额独立保留；面值不是实际现金收入。

用户账单默认显示模型、时间、状态、预计/冻结/实扣/释放积分及任务入口，明细展开计量依据；管理员按供应商查看原币采购、费率版本、账单差异和待核对原因。费用未知时展示待核对及原单查询；超时不自动扣估算价或释放。人工核对须有责任归属和处理记录，处理时限沿运营策略评审，不在文档中编造承诺。供应商账单与真实现金收入的对账不同，充值和会员仍由设计36专项承接。

### 7.5 短剧视频按实际 Token 销售

[SRC-AI-56](../requirement/04-AI平台接入与预设管理需求.md#src-ai-56) 已确认按实际视频 Token 计费。销售按已发布的模型及规格费率版本执行，采购按实际线路、用量与账号合同核算。时长用于能力校验和报价估量，市场秒价只作研究参考。 [研究66](../research/66-2026-11-21-短剧视频秒价与模型接入对照.md)

#### 规格、报价与用量

**一期建议**　先选一条经审核的方舟线路，覆盖已验证的 720p 文生视频和单首帧生视频，每次生成一条。模型、分辨率、画幅、时长和参考方式来自发布目录。参考视频、自动时长等规格具备可信计量参数及可确认上限后可使用同一计费合同。已有任务按各自冻结版本复算。

销售费率按**对外模型版本、分辨率与是否含视频输入**匹配唯一价目，以人民币／百万视频 Token 表达。提交前根据冻结的画幅尺寸、帧率、输入与输出时长及适用最低用量估算 Token，并另算可冻结的费用上限。参考视频时长取服务端可信素材元数据。缺估量依据或无法确定上限时显示待报价。工作台、画布、短剧分镜和 Agent 共用服务端报价，确认前展示预计积分、最多扣费及有效期，账单详情展示费率和可信实际用量。

方舟 Seedance 结算取成功尝试的 `usage.completion_tokens`，字段含适用的供应商计量和最低用量。公式为 `应扣积分 = ceil(实际视频 Token ÷ 1000000 × 冻结销售基准费率 × 倍率 × 折扣 × 10)`，实扣为应扣积分和确认上限的较小值，释放余量。估算值、播放秒数和通用 `total_tokens` 均不能代入实际用量。换路须提供与已发布销售合同等价的计量证据，各尝试的采购按原线路账务事实记录。

**算术样例**　用测试费率 ¥100／百万 Token、1 倍、10 折，报价估算 90,000 Token 对应 90 积分，确认上限 100 积分。成功交付回传 93,600 Token 时，取整后扣 94、释放 6。回传 112,000 时，按上限扣 100，记录 12 积分售价差额。示例费率只用于验收。

#### 最小实现边界

| 现有责任 | 一期扩展 |
| --- | --- |
| 接入与发布 | 先在后台审核精确型号、能力和计量目录、采购价和销售费率，最后填 API Key 并验证。发布要求原任务能够回传可信视频 Token、成功归档，并能解释采购成本。只有鉴权通过的线路仍须完成规格验证。 [接入设计](07-AI平台接入市场调研与架构设计.md#src-ai-54) |
| 报价与确认 | 复用 `ai.quote` 和 `ai.request` 快照，保存价目和计量版本、归一化请求摘要、规格及参考素材事实、估算量、确认上限和有效期。确认后用 `ai.hold` 原子冻结，重复确认返回原单。在途调价沿冻结版本结算。 |
| 交付与核销 | 归属正确的资产归档就绪且有可信计费 Token 时一次核销。供应商受理、交付或计费 Token 未知时保留原冻结并查询原任务。迟到证据按请求与尝试身份复核。已确认不可交付时释放用户冻结，已发生的采购成本由平台记账。重新生成须另行报价确认。 |
| 两侧对账 | 销售用量取交付对应的成功尝试。采购逐次保存原回执、用量、币种、采购费率及可归属账单，含失败尝试的成本。计费 Token 已可信而采购账单未到时，用户可按原合同结算，采购金额继续待核对。迟到的采购金额只影响采购侧。 |

当前 `prepareMedia` 和媒体驱动以按次合同运行。视频 Token 合同须接通报价估量、提交、轮询、用量归一化和账单。现有媒体在核销后调度 `ai.deliver`。此合同凭原成功回执启动归档，归档就绪与可信用量齐备后由原请求核销。归档和回执恢复复用原任务身份与资金幂等键。沿用重建网关账本、媒体归档与已发布的历史合同。若需调整数据库结构，维护唯一的 `backend/db/schema.sql`，公共预设归 `backend/db/data.sql`。
