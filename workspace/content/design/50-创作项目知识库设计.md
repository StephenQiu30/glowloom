# 创作项目知识库设计

状态：评审稿。来源为[需求19 · SRC-AGH-32](../requirement/19-完整创作Agent与Skill多Agent需求.md#src-agh-32)。沿用 [AGH-049／050](../requirement/19-完整创作Agent与Skill多Agent需求.md#src-agh-27) 与 [PRD19 · AC-AH-60](../prd/19-完整创作Agent与Skill多Agent.md#5-可观察接受条件与需求追踪) 的项目证据、权限与评测约束。下文新增交互、来源生命周期和接口均为设计建议。

## 1. 摘要

在现有创作项目内提供「知识库」入口。创作者可以查看项目已采纳的剧本、共享约定和设定引用，显式加入项目文本资料，查找条目并打开带版本的原文。Agent 与创作者共用 Go 项目证据检索，沿用当前项目权限、来源版本和模型准入。

## 2. 参与者

| 参与者 | 职责 |
| --- | --- |
| 有项目读取权限的创作者 | 查询已生效资料、辨别同名结果、定位引用 |
| 有项目内容编辑权限的创作者 | 登记项目资料、选择发布版本、重试入库或撤回资料 |
| Go 创作、身份与媒体模块 | 管理来源记录、版本状态和检索；按当前项目及来源权限读取原文 |
| Agent 与 AI 网关 | Agent 按需检索并携带引用回执；Go 在入模时核验运行权限和证据版本 |

## 4. 目标

- 在项目内找到当前有效的剧本、设定和项目约定，检索结果能定位到对应版本、段落或现有业务对象。
- 文本资料可登记、查看处理状态、发布、替换和撤回；已发布版本在新版失败时继续可读，已撤回或失权时立即停止后续读取。
- 人和 Agent 查询同一证据集合。首版支持中文词法检索及结构字段定位；语义能力沿用已审批的项目策略。
- 首版限当前项目，涵盖既有权威来源与同空间的 UTF-8 TXT／Markdown 文本资产。空间级共享知识库、跨项目聚合、网页抓取、通用 PDF／OCR 解析和自动转写另行评审。

## 5. 使用场景

| 场景 | 预期 |
| --- | --- |
| 编剧在项目内查角色别名或跨集设定 | 在知识库看到剧本、设定和约定的片段，点击定位到当前有效来源；同名时可以按来源类型和版本选择 |
| 制作人员更新世界观说明 | 选择同空间文本资产生成候选版本；处理就绪后确认发布，提交前的检索继续使用旧的有效版本 |
| Agent 续写下一集 | 依据当前项目授权取得必要片段，回答带来源。资料缺失或冲突时提示补充或选择；生成产物按原有采用流程确认 |
| 团队移除成员，或维护者撤回资料 | 下一次检索、引用打开和相关历史正文读取按当前权限返回，索引清理延迟不会恢复权限 |

## 6. 价值

创作者能核对 Agent 为什么采用某条设定，并在原位置修正。团队更新资料时可以看到何时就绪、何时生效以及哪些引用需要刷新。剧本、资产、画布和项目约定继续在各自业务入口修改。

### 7.1 产品入口及授权

项目内提供「知识库」面板，包含搜索及来源筛选、结果与引用、资料列表及处理状态。对话或画布可打开同一结果组件并显式引用，引用的是服务端解析的版本化定位。资料列表标明「来自项目」或「已纳入」，来源管理动作仅向具备项目内容编辑权限的人展示。

Go 以登录会话或 Agent 运行授权解析 `actor_id → org_id / scope_id / project_id`。查询取当前项目可读范围、允许用途、当前有效来源的交集；后台任务使用可信发起者标识并检查实时权限。`source_ref` 由业务域按类型解析：项目证据要求同项目，纳入的文本资产要求同空间、已采用或授权给项目使用，且项目读者仍须符合来源读取条件。来源不可见时也不返回标题、摘要或总数。权限查询失败显示服务异常，零匹配只表示已授权范围内没有结果。 [空间授权实现](https://github.com/StephenQiu30/glowloom/blob/20e02016a7235c6b46f60b3d5002a7d4a5f09865/backend/internal/creation/workspace/application/scope_access.go#L78-L104)

### 7.2 来源、版本与索引

| 设计对象 | 关键内容 |
| --- | --- |
| 来源 | 稳定 `source_id`、组织／空间／项目、种类与业务资源引用、维护者、当前发布版本、撤回标记及并发修订号。首版以项目作为集合边界 |
| 来源版本 | `source_version`、源业务修订、内容哈希、解析器版本、处理状态。原文由业务域持有；索引只持有派生文本与定位，受原文读取资格约束 |
| 处理任务与切片 | 任务按项目、来源版本和解析器版本去重；切片记录段、起止位置、单位、内容与定位。现有 PostgreSQL 项目证据投影扩展到已发布资料，词法检索与回执核验共用这一入口 |
| 证据与引用 | `kind / id / part / version` 沿用现有证据身份，附标题、短摘录、定位和回执。业务版本与解析版本变化会生成新的证据版本；引用跳转由 Go 校验后解析 |

已采用剧本、受权主体设定和共享项目约定沿其各自的采用、绑定及撤回规则投影。已有画布、分镜和媒体证据行为保留，界面保留原来的来源类型和草稿标识。显式纳入的文本资料进入下方发布流程，选择已有资产时复用媒体读取与对象存储，来源记录不扩大资产的访问权限。PostgreSQL 结构归 `backend/db/schema.sql` 静态维护，异步处理沿用现有任务运行时。 [项目证据结构](https://github.com/StephenQiu30/glowloom/blob/20e02016a7235c6b46f60b3d5002a7d4a5f09865/backend/db/schema.sql#L9849-L9897)

### 7.3 入库、发布与撤回

1. 有编辑权的成员选择同空间的文本资产，Go 校验项目、来源读取权、项目使用授权、文件类型和可配置的字节上限。在同一事务记录不可变候选版本和任务，重复请求返回原记录。
2. 任务按登记的源修订读取文本，复核项目和来源权限，生成带定位的切片。候选依次经历 `queued → indexing → ready`；短暂失败有限次重试，格式或来源错误保留失败原因并要求更正。超限、空正文或源修订不符不能进入 `ready`。
3. 维护者显式发布 `ready` 版本。Go 在事务内重检写权限、源可用性、候选修订与预期发布指针，原子切换当前可检索版本。新版处理失败保留仍有效的旧版本；重复发布幂等，过期请求返回版本冲突。旧任务不得重新激活已经更换或撤回的来源。
4. 撤回先事务性取消可见状态，再异步清理派生切片、向量与缓存。项目撤权、源撤销或删除同样通过实时校验阻断读取。项目复制首版仅沿现有业务对象复制合同，需在目标项目重新登记来自文本资料的来源。

### 7.4 检索、引用与历史

1. 项目 UI 调用 Go 证据查询，Agent 走现有 MCP 工具。稳定 ID 或明确镜头用精确读取；名称、别名与正文先查词法。Agent 遇歧义展示候选，缺证据时明确告知；索引处理中显示对应状态。
2. 有语义策略、当前模型索引就绪且预算允许时，描述型查询可按现有网关路径进行混合召回。精确命中、明确镜头或稳定 ID 不触发查询向量；未就绪、提供商调用失败或策略失效时保留词法结果。首版新增文本来源默认仅进入词法，允许外发的类型与场景须单独纳入项目语义策略。新增片段也受模型正文外发的项目权限与数据策略约束。
3. 检索完成后再次校验命中，Agent 入模经 Go 核验当前授权、工具回执和证据版本。返回用户前、打开引用或重放历史时再检当前权限及版本；版本已变时提示重新检索，撤回或失权时隐藏旧引用和依赖它的正文。还不能定位依赖片段的历史回答按整条限制正文，保留允许显示的时间与运行状态。
4. 公开工程站、通用日志和 Mastra Working Memory 不收录项目来源正文。审计记录稳定标识、授权结果、版本与时间。退出项目或撤回不影响已存在的授权审计记录。

### 7.5 接口草案

沿用现有 `/api/projects/{pid}` 鉴权与错误语义。下表为拟新增的 HTTP 合同，Agent 复用当前已注册工具及回执合同。

| 接口 | 关键输入和结果 |
| --- | --- |
| `GET /api/projects/{pid}/knowledge/sources` | 游标、类型、状态 → 可读来源和状态；维护视图才展示失败细节 |
| `POST /api/projects/{pid}/knowledge/sources` | 资产引用、预期源修订、请求键 → 来源、候选版本、处理状态；可对已有来源提交新版 |
| `POST /api/projects/{pid}/knowledge/sources/{id}/retry` | 候选版本、请求键 → 原任务状态；只重试仍有效且可恢复的处理 |
| `POST /api/projects/{pid}/knowledge/sources/{id}/publish` 与 `/withdraw` | 目标版本（发布）和预期修订、请求键 → 当前发布指针及修订 |
| `POST /api/projects/{pid}/knowledge/search` | 查询、来源类型、结果上限 → 搜索状态和版本化证据 |
| `POST /api/projects/{pid}/knowledge/resolve-citation` | 证据身份和版本 → 允许读取的定位、版本变更或不可用 |

## 8. 实施与验收

实施顺序建议为「已有证据的项目面板及引用回源 → 文本来源入库、发布与撤回 → Agent 引用交付及历史复核 → 语义评测」。当前范围为设计评审；正式实施前确定文件限制、保留期限、外发清单及中文评测样本，继续按现有 [Plan43](../plan/43-Agent服务Mastra架构重构执行计划.md) 验证 Agent 底座。

| 验收场景 | 结果 |
| --- | --- |
| 同一资料重复登记，两个发布请求并发，新任务晚于来源撤回完成 | 相同请求复用原任务；只有一个发布指针生效；晚到任务无法恢复可见性 |
| 版本二处理失败、随后成功，源版本已被改动 | 旧版仍有效时继续可查；切换成功后旧引用显示变化；源修订不符时拒绝发布候选版本 |
| 个人、团队、同空间不同项目及已离组账号独立查询 | 候选、摘录、打开原文及历史正文均遵循当前项目和来源权限；禁止跨项目引用回执 |
| 命中后、入模前撤回，或模型返回后、用户收到前失权 | 网关拒绝继续使用过期证据；返回时重新校验并隐藏受影响正文；延迟清理不改变可见性 |
| 同名角色、中文别名、跨集查询、无答案、权限异常、语义降级 | 稳定 ID 和定位正确；结果逐项展示歧义或缺证据；权限故障与零匹配分开；只在获准语料上对照词法与混合检索的召回、引用准确性、无答案误报、延迟和费用 |
