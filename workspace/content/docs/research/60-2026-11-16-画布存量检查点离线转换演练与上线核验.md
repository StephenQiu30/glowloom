# 画布存量检查点离线转换演练与上线核验

来源：[需求10 SRC-SAVE-10](../requirement/10-画布协作编辑需求.md) → [设计17](../design/17-画布Yjs协作编辑设计.md) → [PRD09](../prd/09-画布协作编辑.md) → [计划19](../plan/19-画布Yjs协作编辑实施计划.md)。执行状态见 BACKLOG；前序优化与性能结果见[调研59](59-2026-11-16-画布同步写放大基线与共享检查点验证.md)。

## 1. 结论

隔离演练通过。旧版接受服务生成的 **6 个画布、17 个历史版本、23 份当前/历史二进制条目**在离线转换后逐条保持一致；九张投影/事实表的行数和内容摘要不变。23 个二进制引用映射到 **18 个同文档精确去重检查点**，无悬空引用、无无主检查点。

新版与旧版分别在独立备份副本中通过相同的六类协作/恢复测试，包括纯因果状态、转换前待发更新、原回执及恢复回执、双账号并发、删除撤销、旧 epoch/生命周期拒绝、原历史 ID 恢复与新服务实例回读。锁超时及转换末尾异常均整笔回滚；备份可还原为旧版服务可读写的数据库。

演练没有访问或修改现有业务库，也没有部署；演练阶段未提交或推送，后续提交按用户新增授权执行，状态见 BACKLOG。生产接受适配器、NestJS runtime 和规范性 schema 在演练中均未修改；新增的是无 DDL 的隔离验收夹具及文档。合成演练通过不代表真实存量数据库已可直接放行。

## 2. 隔离环境与旧数据

- 2026-11-16，本机独立 PostgreSQL 18.4 数据目录 `/tmp/glowloom-canvas-offline-pg-20261116`，监听 `127.0.0.1:55441`；Node 24.19.0，Go 模块工具链 1.26.11。
- 旧完整 schema、预设及旧接受适配器来自 `841d2617765ad58674afa270924de90199b58083`。旧接受服务在临时源码副本运行，使用同一正式私有 Yjs HTTP runtime 生成数据；没有用手工伪造二进制替代真实接受。
- `canvas_offline_source` 为生成后冻结的原始合成库；custom-format 备份分别还原到转换副本和旧版回退副本。`canvas_offline_expected` 仅从当前规范性 schema 初始化，作为结构与权限对照。
- 最终成功转换库为 `canvas_offline_converted_v2`，最终旧版回读/写入库为 `canvas_offline_fallback_final`。首轮及其他中间副本保留在同一独立集群中，没有覆盖原始合成库。

| 类型 | 初始节点规模 | 专门覆盖的旧事实 |
| --- | --- | --- |
| ordinary | 50 | 文字、位置、连线、多修订及原接受回执 |
| causal | 200 | 同内容 revision 的历史为 commitSeq=1，当前为 commitSeq=3，二进制不同；必须保留两份状态 |
| large | 2000 | 大状态、历史、连线与转换后原始历史恢复 |
| epochs | 2 | 已经恢复过历史的多 epoch、原恢复命令/回执和旧 epoch 待发输入 |
| lifecycle | 1 | 删除已接受，撤销删除尚未发送，另有旧生命周期输入 |
| team | 2 | 两个授权账号、提示词输入及转换前后正文协作 |

原始库共 2255 条节点记录（含已删除节点）、4 条边、12 条增量、12 条接受回执、1 条恢复回执和 30 条 Outbox。当前及历史二进制逻辑大小合计 7,812,404 字节，精确去重后的二进制合计 6,001,949 字节；这些是本组合成数据的逻辑大小，不能作为生产磁盘节省比例。

## 3. 离线事务演练与发现

转换由隔离环境中的管理员式事务执行，应用及 Go 验收夹具不执行 DDL。临时演练驱动位于仓库外；没有增加可发布的增量 SQL 文件、迁移目录或自动迁移入口。

事务先声明锁/语句超时、取得 head/history 表排他锁并核对旧结构；按当前规范性 schema 创建检查点，按 `(document_id, 完整 state 字节)` 精确去重。分别回填 head/history 的引用，逐条检查新旧字节一致和非空引用，再建立完整约束、索引与角色权限，移除旧 state 字段，最后提交。只按 revision、graph hash 或 sequence 合并均不被允许。

| 场景 | 观测结果 | 后续核验 |
| --- | --- | --- |
| 独立连接持有冲突锁，转换设置 200ms 锁超时 | SQLSTATE 55P03；预期失败 | 重新读旧结构和全部原始数据，逐条一致 |
| 所有回填/字段变更后、COMMIT 前注入异常 | 预期失败，DDL 与 DML 全部回滚 | 原始状态/历史及九表摘要一致；后续旧结构前置条件再次通过 |
| 最终完整事务 | 成功 | 23 份二进制及全部元数据不变，18 个精确状态、零无主检查点 |
| 与规范性新库对照 | 三张目标表的目标定义一致 | 列类型/非空/默认值、约束定义与验证状态、索引、owner 和 ACL 一致；不以 OID 或物理列序作为差异 |
| 原始合成源库复核 | 一致 | 转换与行为写入没有污染源库 |

首轮发现并修正了两个验收问题：

1. 仅复制 `glowloom_app` 的新表权限不足。规范性 schema 还会把 Canvas 所属权限授予 `glowloom_creation`；首轮目录对照准确检出缺少该域角色的 SELECT/INSERT/DELETE。补齐离线步骤后，从原始备份重新还原新副本，重做失败回滚、成功转换与目录对照；没有修改生产角色模型。
2. 直接要求恢复结果等于早期历史 DTO，会错误忽略既有“保留后来分配引用编号”的合同。该断言在新旧服务中同样失败，已定位到 `prepareYjsHistory` 保留 `editor.metadata.referenceLabels`。最终验收精确保留恢复前已接受的编号，再比较全部正文、配置、稳定身份、位置、尺寸及边；没有排除整个 editor 或放宽其他字段比较。

最终事务在本组合成数据上约 0.135 秒；该数字不包含备份、复制、全量核验和功能验收，**不能用来估算生产维护窗口**。

## 4. 核验范围与结果

`backend/tests/canvas/yjs_offline_upgrade_test.go` 分阶段运行，默认跳过，要求显式隔离数据库名与合成 manifest。夹具本身不初始化结构、不转换、不重置数据。

| 核验项 | 结果 |
| --- | --- |
| 6 个 head、17 个 history | 稳定键、document、二进制逐字节及完整 metadata 一致；仅排除被替换的物理 state/state_id 字段 |
| 历史 JSON 与版本元数据 | 原始历史 ID、正文、epoch、revision、writerTerm、commitSeq、graph hash、actor、reason、created_at 等均保留 |
| 九张关联表 | document、node、edge、node_input、command_log、collab_update、collab_receipt、collab_control_receipt、infra.outbox 的行数和按完整行计算的摘要一致 |
| 检查点共享 | 按同文档完整字节精确集合核对 18 份状态；当前纯因果状态未错误合并进同 revision 历史 |
| 新服务六类行为 | Race 下全部通过；所有历史列表及完整只读 DTO 均与转换前逐一比较 |
| 跨转换待发输入 | 使用原 epoch/session/update 身份接受，序列只推进一次，普通/纯因果/大图/多 epoch/团队均回读到预期文字 |
| 双账号并发 | 两份基于同一旧状态产生的输入并发提交，两个结果均等待完成，两段正文与连续序列保留 |
| 删除与恢复 | 转换前已接受删除仍可按原身份撤销，稳定节点 ID 保留；旧生命周期输入仍拒绝 |
| 历史恢复 | 使用原历史 ID 恢复，产生新 epoch 与更高 revision；再次提交原恢复命令返回同一结果，恢复后新实例可回读 |
| 原回执与旧 epoch | 原接受/恢复回执保持原结果；新身份的旧 epoch 输入仍按原合同拒绝 |
| 旧版备份恢复 | 独立还原副本由旧版接受服务运行同一六类测试，Race 全通过 |
| 转换后既有回归 | 20 组 Yjs 集成 Race 通过，涵盖 socket/授权、并发、writer fence、事务回滚、引用、删除/历史恢复与 Outbox |
| 静态与数据库规范 | 适用 vet、golangci-lint、gofmt/goimports、schema source 门禁通过；未增加其他 SQL 文件 |
| 漏洞检查 | `govulncheck -test ./tests/canvas` 调用路径漏洞 0；另有 1 个未被调用的依赖模块漏洞，不宣称全依赖无漏洞 |

逐条二进制核对与九表摘要在行为写入**之前**完成；后续测试提交和恢复产生的新修订、回执及 Outbox 属于预期行为，不要求其仍等于转换前数量。纯因果、恢复 epoch、引用编号的元数据均沿原始条目保存，没有用新计算值重写旧 hash。

## 5. 上线前核验步骤

以下是正式变更的放行步骤。本次只完成了合成副本演练，**没有执行这些步骤所指的现有业务库操作**。

1. **冻结版本与实际结构。** 记录旧/新服务版本、规范性 schema 与候选补丁哈希、目标数据库身份及运行角色。由管理员对实际列、约束、索引、触发器和 ACL 做 diff；不把新环境 schema 整份重放到已有库。生产 PostgreSQL 版本若不同，先在同版本副本重演。
2. **停止所有 Canvas 写入来源。** 覆盖接受 API/WS、任务结果投影及后台作业；协调 Outbox 处理，保证核验窗口相关表不被其他工作改动。确认旧/新实例不会同时写，核对现有连接与排队事务。进入维护窗口时按现有客户端合同保留或查证未确认输入，不更换其提交身份。
3. **先证明备份可恢复。** 对冻结状态创建受控备份，并在独立库完整还原。备份必须包含历史、回执、增量和关联事实，不能只备份 head。记录备份哈希、还原日志、原结构及数据核验结果；备份校验失败则停止变更。
4. **保存转换前清单。** 当前及全部历史按稳定键记录 document/epoch/revision/sequence/writer/hash、JSON、二进制校验值及全部元数据；为九张关联表记录完整内容摘要。合成夹具限定 `canvas_offline_` 库，不能把本次测试环境变量直接指向业务库；真实数据清单由管理员在受控环境保存和比对。
5. **在同版本存量副本先重演。** 包含真实存量的多 epoch、纯因果状态、删除墓碑、历史引用与大图。先验证原备份与旧服务，再执行受控离线转换、失败回滚及新服务验收；评估真实数据规模下的锁持有时间、WAL、磁盘和核验时长。此项生产规模证据尚未取得。
6. **执行受控事务。** 设定经核准的锁/语句超时，取得 head/history 表排他锁并核对源结构。以规范性 schema 的完整定义创建目标能力；只按同文档、二进制完全相同共享检查点，分别回填当前和历史。保留旧 state 字段直至事务内字节核验通过。不得以 revision 或 graph hash 代替字节相等。
7. **核对全部约束及角色。** state_id 必须非空，复合外键限定同文档，引用索引及原始约束完整。检查 `glowloom_app` 和实际 Canvas 域角色 `glowloom_creation` 的 SELECT/INSERT/DELETE；checkpoint 不授 UPDATE。核对 owner 与规范性权限展开结果，不能只看表已创建。
8. **提交后继续停写并只读复核。** 逐条对比转换前清单、全部历史 JSON/二进制/元数据及九表摘要，检查空引用、错文档引用、无主检查点、精确状态集合；与规范性空库对照列/类型/非空/默认值、已验证约束、索引和 ACL。任何差异均不得启动新写入。
9. **在独立副本完成行为验收。** 保持转换后核验基线库不被测试污染；在可丢弃副本中使用真实授权身份查证旧回执、重放原提交、接受原待发输入、双账号并发、删除撤销、原版本预览与恢复、新 epoch/旧输入拒绝、服务重建后继续读取。验证历史恢复保留已分配编号，并保留接受事务失败回滚与 Outbox 验收。
10. **汇总放行证据后切换。** 管理员确认结构/权限、逐条数据、还原与行为验收全部满足，再按实际授权启动对应新版 Go 接受服务和 Canvas runtime，最后恢复写入。旧版 Go 不支持删除旧 state 字段后的结构，不得与新版同时运行。本次没有该生产切换授权或执行记录。

## 6. 失败及回退边界

- 事务未提交前：锁超时、结构前置条件不符、字节映射不一致或其他异常均应整笔回滚，重新核对原结构与清单；不补写局部引用后继续运行。
- 事务提交后、仍未恢复业务写入：只读核验或放行失败时保持停写，按已演练的备份还原到受控目标，核对旧结构/历史/回执后再启动匹配旧版。不能仅回滚应用二进制而保留新结构。
- 已经接受新写入后：旧备份不包含新增修订、回执、增量和 Outbox，直接覆盖会丢失已确认事实。必须再次停写，保全新增数据并由管理员制定核对与恢复方案；本次没有演练这类补偿，不将“备份能恢复”称为无损在线回退。

上线核验表中任何一项不满足时均维持停写/未放行状态；本报告不构成执行现有业务库变更的批准。

## 7. 证据与复现

[机器证据](60-canvas-offline-upgrade-evidence.json)包含源文件与备份哈希、23 个条目的二进制/metadata 指纹、九表原始摘要、失败/成功事务结果、目标结构目录、全部阶段的通过记录。公开证据不包含合成 principal/session 的原始 manifest 或数据库备份；原始合成数据与日志仅保留在本机 `/tmp/glowloom-canvas-offline-*`。

无 DDL 验收入口：

```sh
# 仅用于明确命名的合成隔离库；旧版阶段须在旧适配器源码副本运行。
GLOWLOOM_CANVAS_OFFLINE_PHASE=seed \
GLOWLOOM_TEST_CANVAS_OFFLINE_DB_NAME=canvas_offline_source \
GLOWLOOM_CANVAS_OFFLINE_MANIFEST=/tmp/canvas-offline-manifest.json \
go test -race ./tests/canvas -run '^TestYjsOfflineUpgrade$' -count=1 -v -timeout=8m
```

另需显式提供对应隔离 DSN 和 CI 同款合成对象存储配置。阶段为 `seed`（旧适配器生成，manifest 使用独占创建）、`audit-old`（原结构只读核验）、`verify`（新适配器核验后行为写入）和 `verify-old`（旧版还原副本行为验收）。这些阶段不执行结构转换；管理员必须先在隔离副本完成离线事务，不能把测试当作自动升级工具。

最终新/旧行为阶段分别为 30.201s、29.422s（含 Race 开销）；转换后既有 20 组 Race 为 43.974s。所有正式结果使用原始备份的新副本复测，首轮失败样本未被覆盖成“成功”记录。

## 8. 剩余验证范围

尚未使用真实生产备份、生产数据规模或其他 PostgreSQL 版本重演；尚未测量生产维护窗口、锁竞争、磁盘峰值及恢复写入后的补偿。UI 的 IME、真实浏览器断网及外部模型/对象存储调用不属于本次新增验证。后续生产核验必须补齐实际结构 diff、真实副本与角色接入证据，不能用本组合成数据代替。

演练工作区只新增验收测试及本报告/证据，并更新需求、设计、PRD、计划和 BACKLOG。此前 Canvas 编辑器迁移、共享检查点实现及其他并行修改均保留；演练本身未创建分支或部署，后续代码提交与推送按用户新增授权处理，未执行业务库转换或生产上线。
