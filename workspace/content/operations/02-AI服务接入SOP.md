# AI 服务接入 SOP

**接入顺序。** 在管理页依次保存模型与销售价、采购路由与验证计划，最后在「验证与启用」填写 API Key 并确认预算。通过即启用或切换。存量环境上线前由管理员离线比对完整 schema，验证 Go Execution worker 及密封凭据配置。

依据 [设计07](../design/07-AI平台接入市场调研与架构设计.md#src-ai-54) 和 [PRD03](../prd/03-AI平台接入与预设管理.md#src-ai-54)。适用于 Glowloom 采购的云端 AI 服务。本地无 Key 的运行时沿既有本地准入及计量流程。

| 顺序 | 责任 | 操作与完成证据 |
| --- | --- | --- |
| 1. 核定渠道与模型 | 接入维护 | 确认供应商精确型号与版本、地区、端点、入站与上游协议、支持模式、最大输出、Key 权限与共享额度。记录官方来源及核对日期。公开目录用于发现候选 |
| 2. 准备模型预设 | 接入维护 / 工程 | 完成对外名称、模式、输入与默认参数、能力限制、请求和回执映射。已支持的协议和计量合同优先走后台配置。新增协议、任务生命周期或计量语义时，先补驱动和测试。文本按承诺验证非流、SSE、函数工具与终态用量。媒体验证创建、轮询、可用的取消能力、交付及原单恢复 |
| 3. 核定价格和候选 | 采购 / 定价维护 | 采购价绑定实际供应商、端点、型号、币种、量纲及版本，核对费用上限。销售价独立绑定对外模型版本及模式，核对最小与上限报价、积分取整和结算算例。复核候选、配额组、验证模式、测试内容及预算。前三步不需要真实 Key，保存、导入和读取产生零上游生成 |
| 4. 填写 Key 并验证 | 平台管理员 | 对预配置版本提供指定渠道的 API Key 并主动提交。通用云端接入使用实际生成验证权限、能力与计量，先确认测试内容、次数与最高费用，再由 Go 网关派发。只有供应商已提供且系统已适配免费验证方式时，才可先做免费检查。必需验收通过后，候选自动启用或原子替换旧版本。失败保持待验证。已发送但受理未知时先查原回执 |

## 验证与发布回执

- 用稳定操作身份识别同一份配置和同一次验证。刷新、网络超时和重复点击先读取原结果。只有确定未发送，或有明确未受理且无费用的证据，才按 Go 号池规则处理补尝试。
- 保存候选版本、协议和模式、精确上游型号、渠道及凭据引用、采购和销售版本、测试付款空间、预算、脱敏用量、上游请求或任务号、验证结论及切换记录。认证、模拟或实际能力、结算及对账各有证据。
- 候选与线上路由共用供应商账号时，保持同一配额组。网关会为线上路由保留一个并发名额和每分钟一个请求额度。已有线上路由的配额组至少需要并发 2、每分钟请求上限 2，采购表单会提示无法验证的配额组。符合门槛的配额组仍需有空闲容量。独立供应商账号使用各自的配额组。
- 真实测试沿既有报价、冻结、核销和采购归集。按次媒体对比实际交付及采购证据，文本核对用量桶和最终用量。缺用量或成本归属不明进入待核对。供应商账单延迟时，到账后关联原尝试，差异走既有调整流程。
- 在创作列表和已支持的 SDK 入口核对启用结果。已有同名版本时，先验证继承的对外模式，再同时启用新版及其合格路由。SDK 授权按其模型版本范围核验，需要新版时发放明确覆盖新版的授权。

## 停止新单与回退

出现产物错误、用量异常或采购差异时，暂停受影响版本的新单。先前版本的合同、凭据和路由仍合格时，把新请求切回该版本。已派发的任务、流、报价、冻结和结算沿原记录处理。供应商原单无法确认时保留待核对记录及关联凭据引用。
