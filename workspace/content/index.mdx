项目知识按 **requirement → design → prd → plan** 维护当前有效知识：为什么需要、如何设计、交付什么、如何实施。读者不必沿历史补丁推断当前规则。

## 领域入口

Agent 服务 Mastra 架构重构：[需求33](requirement/33-Agent服务架构重构与技术选型需求.md) → [设计48](design/48-Agent服务Mastra架构与技术选型设计.md) → [PRD34](prd/34-Agent服务架构重构与技术选型.md) → [Plan43](plan/43-Agent服务Mastra架构重构执行计划.md)，选型依据见[研究71](research/71-2026-11-25-Agent服务架构网关与评测技术选型调研.md)。以 Node 24 + TypeScript + Mastra 原地重建 `agent/`，移除 NestJS/Pi Durable/Prisma，采用强类型 gRPC + Go 内部 MCP + Go 统一渠道 AI 网关 + Kysely/Zod + 双轨 Evals（离线 Scorers + 线上自托管 Langfuse）。

通知中心与公告管理：[需求31](requirement/31-通知中心与公告管理需求.md) → [设计46](design/46-通知中心与公告管理设计.md) → [PRD32](prd/32-通知中心与公告管理.md) → [Plan41](plan/41-通知中心与公告管理执行计划.md)，事实见[研究57](research/57-2026-11-16-即梦通知中心拆解与设计核对.md)。覆盖顶部公告、5秒消息弹窗、Header一键已读、管理筛选和启停；实现与验证依据Plan41。

Go 模块化单体架构：[需求32](requirement/32-Go模块化单体架构改造需求.md) → [设计47](design/47-Go模块化单体架构与RPC集成设计.md) → [PRD33](prd/33-Go模块化单体架构改造.md) → [Plan42](plan/42-Go模块化单体架构改造执行计划.md)。将 Go 后端收敛为遵循 Google Go 规范的模块化单体，保留 Kafka 异步解耦，采用开源稳定组件库，并与 Canvas / Agent 通过标准 gRPC（方案 A）通信。

Workspace 知识库：[需求30](requirement/30-Workspace官方Fumadocs接入需求.md) → [设计45](design/45-Workspace官方Fumadocs设计.md) → [PRD31](prd/31-Workspace官方Fumadocs.md) → [Plan40](plan/40-Workspace官方Fumadocs执行计划.md)。已替代的历史方案与一次性阶段验收记录已清理删除（历史可通过 Git 追溯），不干扰现行阅读与搜索上下文。

## 内容板块分类

- [需求分析 (requirement)](requirement/00-需求导航.md)：有效需求、确认、业务规则、来源与稳定 ID。
- [方案设计 (design)](design/00-设计导航.md)：当前方案、模块职责、状态、权限、数据、接口、取舍及技术验收条件。
- [产品规格 (prd)](prd/00-PRD导航.md)：用户价值、功能范围、非目标、故事与产品验收条件。
- [实施计划 (plan)](plan/00-Plan导航.md)：依赖、步骤、任务、验证方法、退出条件、迁移与回退。
- [技术调研 (research)](research/00-调研导航.md)：可复查的外部事实与选型依据。
- [部署运维 (operations)](operations/00-部署运维导航.md)：对象存储等基础设施的配置与核验。
- [研发技能 (skills)](skills/00-Skill导航.md)：项目职责与能力使用说明。
- [研发工作流 (workflows)](workflows/00-工作流导航.md)：可阅读的协作步骤。
- [文档模板 (templates)](templates/00-模板导航.md)：各层内容边界与维护规则。
