# Plan 35｜模型号池接入与路由

唯一来源 PRD：[PRD26 · 模型号池接入与路由](../prd/26-模型号池接入与路由.md)。协作计划：[Plan36 · 定价与结算](36-模型销售定价与结算执行计划.md)。

## 目标与前置

从空池完成首条线路的配置与验证，再用同渠道双 Key 和另一条等价渠道验证故障隔离与切换。隔离环境准备甲、乙两个可记录所有请求的模拟上游，甲方两把 Key 共用或独立额度均可配置，提供同步、流式和异步任务样本。真实验证时另需明确的模型规格、账号归属、区域、采购上限和测试预算。

## 执行任务

任务顺序按数据依赖排列。核心分支先写失败场景，再实现并复跑。文件职责以功能归属说明，具体落点在实施时确定。

| 任务 | 前置与交付责任 | 操作、测试与退出条件 |
| --- | --- | --- |
| T-POOL-01 规格与任务交接 | 接入契约、派发契约、契约测试文件 | 定义可售规格查询、冻结成功后的派发输入、执行结果三类样例。字段覆盖版本、允许线路、付款范围、任务号、尝试号、回执及用量单位。与 T-SALE-01 对照正反例，双方均能解析同一任务和拒绝缺必需字段的输入。 |
| T-POOL-02 管理与发布 | 渠道/密钥存储、发布接口、管理表单，依赖 01 | 从空池录入、验证、发现、预览差异、整版发布。给刷新与发布加入凭据身份和版本检查。在隔离库中重放空目录、撤权、轮换中迟到响应、并发发布与回滚。后台能指出生效版本，明文 Key 不出现在响应及日志。覆盖 AC-POOL-01、AC-POOL-09、AC-POOL-10。 |
| T-POOL-03 候选与配额 | 候选筛选、授权、配额存储与路由测试，依赖 02 | 构造同名不同规格、原账号文件、固定端点和不可控下游。按渠道再按 Key 选择，两个执行实例同时争抢最后一个共享名额。对照上游接收记录，确认只有独立且合格的线路能收到请求。覆盖 AC-POOL-02、AC-POOL-03、AC-POOL-04。 |
| T-POOL-04 派发与恢复 | 尝试持久化、供应商适配、任务查询与归档，依赖 03 | 先登记派发权和尝试，再发送。对明确未受理、裸错误码、HTTP 发出后崩溃、首段流后中断、取回失败逐项注入故障。重启后用原任务查询。断言未知受理零补发、无重复工具调用、补尝试共享截止时间和次数预算。覆盖 AC-POOL-05、AC-POOL-06。 |
| T-POOL-05 管理及创作入口联调 | 渠道管理、任务详情、画布/工作室/对话及 Agent 入口，依赖 04 和 T-SALE-03 | 从真实产品入口确认、轮换、排空、紧急撤销并尝试回滚。用管理员与创作者身份检查界面和服务端权限。原单可追踪，撤销后新派发数为零，其他授权线路继续服务。接入 T-SALE-04 的交付与费用回执。覆盖 AC-POOL-07、AC-POOL-08、AC-POOL-10。 |
| T-POOL-06 渠道实单验收 | 供应商适配、运行验收记录，依赖两条链的隔离联调 | 逐个组合留存已脱敏请求、受理编号、实际结果、原身份查询、用量和采购凭证。先验证单线路，再在同规格双线下设置主路派发前维护，观察真实备线出单。由 T-SALE-05 核对该单资金效果。 |

## 初始化、回退与证据

隔离库从零线路开始。配置以草稿导入，获证的组合方可对新任务开放。回退时停止问题版本接收新单，发布仍有效的历史配置。已受理和受理不明的任务保留原尝试、凭据引用及原报价。演练回滚与撤销并发，验证撤销优先。

每个场景记录环境、版本、任务号、预期与实际上游发送次数、回执及结果。受控故障验证安全边界，真实回执验证具体组合可用性。未取得用量或账单时注明缺失项。本轮隔离验收覆盖普通派发前的凭据、模式与发布版本校验，轮换后原任务恢复，以及未验证 Key 拒绝新增派发。单线路实单与双线路隔离验证见[验收记录](../research/2026-11-13-模型号池与销售计费验收.md)。状态归 [BACKLOG](../../../BACKLOG.md#pool-sale-plans)。
