# Go微服务拆分执行计划

唯一来源：[PRD30 Go微服务拆分](../prd/30-Go微服务拆分.md)。技术合同沿该 PRD 的来源设计44展开；不单独定义业务语义。当前状态、优先级、后续顺序和阻塞只见 [BACKLOG](../../../BACKLOG.md#go-microservices-20261114)。

## 1. 前置条件与实施原则

- 需求29 SRC-GO-MS-02 确认四个业务服务＋轻量 Gateway 并授权分阶段实施；SRC-GO-MS-03 要求先提交 main 推送已有切片，再继续拆分并遵循 Google Go 目录规则。两者均不含生产发布、存量库操作、真实付费。
- SRC-GO-MS-06（2026-11-15）要求先按设计44 §7.5 归位已有目录，参照 Google 官方示例，不套唯一模板；本轮先执行 T-GMS-17/18，再继续尚未接受的完整 owner 任务。目录变化不等于领域、授权或资金事务已经迁出，不自动追加提交/推送。
- 保留共享工作树既有修改，尤其 Identity 源侧与前端/Workspace 并行内容；整迁当前实现和资源，不从 HEAD 重建或覆盖。只改实际切片所需文件，不预建四个空服务、抽象框架或另一份数据库规范。
- 遵循 Red → Green → Refactor。修改结构只在 `backend/db/schema.sql`；禁止其他 SQL、增量脚本与运行期 DDL。新环境初始化与存量环境受控比对分开。

## 3. 工程验证方法

在仓库根或 `backend` 使用现有工具直接执行，不新建脚本/Makefile：

1. 对变更 Go 文件执行 gofmt/goimports；`go vet`、golangci-lint 检查新入口、代理、维护及测试包。
2. `go test -race ./tests/gateway ./tests/boundaries -count=1`；重复生命周期测试检查流和停机，必要时使用 `-count` 增加复现次数。
3. `go test -race ./internal/infra/maintenance/... ./tests/maintenance -count=1`；未提供专用测试 DSN 时，明确 PostgreSQL 用例跳过。只在获授权的隔离空库运行旧租约恢复，不指向现有业务库。
4. `go test ./tests/db -run 'TestBackendSQLHasCanonicalSchemaAndPresetData|TestSchemaDoesNotScheduleRetiredRuntimeDDL' -count=1`；这仅证明 SQL 来源和退休种子约束，不等于完整结构、权限与分区策略通过。
5. `go list ./...`、`go vet ./...`、`go build ./...`，并对 `./gateway`、`./creation`、`./media`、`./cmd/glowloom` 分别执行 `go build -o <临时目录>/<二进制> ./<入口>`，避免输出名与服务目录重名；`govulncheck ./gateway ./creation ./media` 和适用 legacy/维护调用路径单列，不能外推全库零漏洞。
6. 以 `/dev/null` 为 env-file、使用 `--no-interpolate --quiet` 分别校验普通和开发叠加 Compose；如需拓扑断言，只给合成内存配置并捕获 JSON，仅输出断言、不打印凭据或启动整套栈。三个服务 Dockerfile 均从 backend 根 module 上下文独立构建，另核验 legacy backend/frontend 的许可、字体和电影目录资源路径；构建/网络失败或镜像未启动如实列出，不以 Go 编译代替容器接受。
7. 先核对 Workspace 最新 `package.json`，仅对本轮六份文档定点 Prettier，再执行 `pnpm --dir workspace check:content` 与 `git diff --check`；正文文件名/catalog 稳定 ID 和已有别名不变。只更新当前说明的有效路径，保留历史命令/证据；并行 Workspace 失败单列，不覆盖其修改。公共 DTO、RPC 源/生成物与资源内容保持原样，通过现有生成链及 hash 对比核验，不手改生成客户端。
8. 上传 owner 边界 AST 检查、无 DB 的失败关闭/事务端口与应用流水线 race 测试；隔离 PG 才运行清理等待项目锁、撤权/归档后结果核对。两个连接验证实际 `pg_blocking_pids` 和被阻塞的项目 UPDATE 查询，不能以同一 actor 的 Identity 行锁证明项目屏障。

9. Media 使用 `go test -race ./tests/medianormalization ./tests/mediaruntime ./tests/media ./tests/deployment ./tests/boundaries ./tests/app ./tests/config` 覆盖纯计算、真实 gRPC、真实 FFmpeg 与原上传回执链；独立 TCP 运行时分别验证 local 和自签 CA mTLS、非法身份、双探针及取消停机。501MiB 输出、短流/坏摘要/错误 magic、完整字节后失败状态均不得发布或遗留临时文件；检查 `go list -deps ./media` 不含业务状态模块或存储驱动，精确白名单只做路径一对一更新，不放行整个 owner 或 platform 子树。
10. 在 `backend/` 使用固定版本生成器，输出至临时目录后与提交文件逐字节比较，避免直接重写生成物掩盖漂移：`protoc -I api/proto --go_out=<临时目录> --go_opt=module=github.com/StephenQiu30/glowloom-server/backend --go-grpc_out=<临时目录> --go-grpc_opt=module=github.com/StephenQiu30/glowloom-server/backend api/proto/glowloom/media/normalization.proto`。`protoc-gen-go` 与 `protoc-gen-go-grpc` 的固定版本见设计44，不能使用未固定的 latest。
11. 独立镜像构建须单列依赖下载、Go 编译与容器启动结论；镜像失败或未启动时，不以宿主机运行时通过代替容器接受。Media 未迁移数据，无需新增 SQL 或自动 DDL。

12. Creation 使用 `go test -race ./tests/creationdocument ./tests/creationruntime ./tests/script ./tests/config ./tests/app ./tests/deployment ./tests/boundaries -count=1` 验证原生解析、客户端坏/短/超限结果、完整 JSON 后失败状态不成功、不重试、两个生产消费者、独立 TCP/mTLS、过载和强制停机后临时文件清理；`go list -deps ./creation` 只允许本切片、纯 `creation/script/domain`、协议和服务身份辅助包，不导入数据库连接或 Media。
13. 对 `api/proto/glowloom/creation/extraction.proto` 使用第10项固定生成器输出至临时目录并逐字节比较；分别解析两套 Compose，确认只有 API/Worker 接收 Creation 凭据，服务无共享文件/业务配置，独立镜像在只读根与有界临时盘下通过探针和 SIGTERM。独立镜像通过不等于整套 Compose 或生产证书部署通过。

14. 会话源侧使用独立新库，由 `schema.sql`/`data.sql` 离线初始化后以实际 Identity LOGIN 运行；原账号/会话锁的准入先与撤权先均以 `pg_blocking_pids` 核实，错误账号/精确会话/世代不得留下准入。真实四 writer RPC 覆盖当前/其他设备撤权、ACK 丢失重建、原准入旧命令拒绝、一次审计和无外层 SQL 事务跨网；增加非整微秒时钟首次成功、完成与有效重放的真实锁竞争、会话已清理后恢复原责任的用例。仍须另验全部公共退出/批量撤权入口与原凭据/CSRF 恢复后才能启用，不以技术能力测试代替该接受。

15. 目录/AST 门禁覆盖整个 backend 的 SQL 来源扫描、禁止旧业务目录复现、禁止业务反向导入 legacy app 及逐条跨 owner 导入边。按切片运行 Gateway/Media/Creation/边界/部署/app 与受影响业务 race，Identity 准入/撤权等真实 PG 行为断言不删减；仅在已有自有隔离夹具完整时执行全后端 `go test -race ./...`，缺失/跳过/旧基线失败单列，不读取真实凭据或连接业务库补夹具。Prompt 电影目录消费者另验前端生成链/测试及适用构建。

16. Google Go 规范检查使用全量 `golangci-lint run ./...`、`go vet ./...`、`go build ./...`，CI 固定检查器版本，不用新增行过滤或已有问题豁免冒充整体通过。全部生产包的内层依赖门禁先以真实 domain → application 反例验证为 Red，再将转换移至消费层；身份转换须保留原标识且不得补造会话或平台权限。服务启动探针的关闭与删除错误均须处理；OpenAPI 注解所引用的公开生成类型名保持稳定，对该工具引用精确说明例外，不删除合同或伪造 Go 引用压过检查。工具结果另配清晰性、小接口、Context 与并发生命周期人工审查；Google 建议、项目附加规则和业务 owner 未迁边界分别说明。

17. 公共撤权使用完整规范初始化的新隔离库、四个实际 owner LOGIN、真实 TCP writer 与 Gin HTTP：分别覆盖 legacy/access/refresh 自退出及批量撤权；Media 已提交但 ACK 丢失时错误响应不清 Cookie，清理凭据并令 access 过期后仍用原 key/proof/CSRF 恢复。批量目标固定、完成不重放、不补登记无效 refresh、错 CSRF/目标/协议拒绝；新操作仍须当前授权，原证明不能读取会话目录。真实 `NewBusinessRouter` 分别验证单个和批量路由，以及关闭签发/缺依赖/普通读取仍受保护。回执聚合标记不能覆盖未完成 target；规范三表只保留摘要和最小 ACL。真实前端 HTTP 传输另验同一身份未确认时保留原键、Creation scope 改变不丢键、当前 204 才释放、迟到响应不删下一原键；身份改变清空，显式调用方键及其他写请求不受影响，错误不自动重放，不引入浏览器凭据存储。回归现有会话恢复、退出及账户消费者，不手改生成 API。服务端另验接受请求与原 ID 恢复任务同事务：入队失败必须回滚会话关闭/请求/准入记录，凭据清理或浏览器消失后真实 worker 仍完成；旧版本缺失任务由有界 DML 补齐，既有 completed/failed 不重开，其他 owner 不可读/执行。实际替换任务 owner/epoch 后，旧 worker 的源侧完成和成功审计必须回滚，再重建 worker 按同 ID 接管；所有 goroutine 在取消后等待退出。还需单列默认 legacy 根及恢复 worker 未自动切换、页面重载丢失内存原键、生产 mTLS/Redis/真实 JWT 与完整 owner 入口的接受边界。

## 4. 验证记录与解释

### 4.1 测试先行证据（2026-11-14）

- Gateway 协议测试先因 `internal/gateway` 缺失编译失败，独立配置/停机测试再因 `internal/app/gateway` 缺失失败；随后实现真实入口与 HTTP 代理。
- 历史分区任务测试先报 `ordinary maintenance must not create partitions`；DML-only fake 对旧构造端口也编译失败，随后收窄接口并移除应用 DDL 路径。
- 以上失败只证明测试覆盖对应缺口，不代表网络拆分目标已完成。绿色验证及其环境边界见下节，并与 BACKLOG 当前状态交叉核对。

### 4.2 首个切片的证据口径

## 5. 运行交接与回退边界

- Compose 切换是代码配置交付，不自动执行 `up` 或重启现有环境。启动前由维护者核对既有依赖、端口和结构；Gateway 通过 readiness 后前端才能完整接入。
- 本地直接运行：为 Gateway 单独指定 `GLOWLOOM_GATEWAY_HTTP_ADDR`、`GLOWLOOM_GATEWAY_BACKEND_ORIGIN`，其余只读 `GLOWLOOM_ENV=local` 与日志级别；上游必须是无凭据、无路径/查询的 HTTP(S) origin。不能借入口拆分解除 backend 的 local/loopback 限制。
- 退出普通自动分区维护后，管理员必须核对预建分区覆盖窗口、监控默认分区和保留策略；不能等写入失败再让应用建表。本轮不自动处理存量权限或分区。
- Gateway 不持有业务写入权；如需撤销入口切换，由维护者在受控本地配置中恢复原拓扑，不能启动第二个数据 owner。后续领域 owner 转移后的回退另需围栏、排空和兼容证据，不套用无状态 Gateway 回退。
