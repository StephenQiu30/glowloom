# Go微服务拆分执行计划

唯一来源：[PRD30 Go微服务拆分](../prd/30-Go微服务拆分.md)。技术合同沿该 PRD 的来源设计44展开；不单独定义业务语义。当前状态、优先级、后续顺序和阻塞只见 [BACKLOG](../../../BACKLOG.md#go-microservices-20261114)。

## 1. 前置条件与实施原则

- 需求29 SRC-GO-MS-02 确认四个业务服务＋轻量 Gateway 并授权分阶段实施；SRC-GO-MS-03 要求先提交 main 推送已有切片，再继续拆分并遵循 Google Go 目录规则。两者均不含生产发布、存量库操作、真实付费。
- 保留共享工作树既有修改；只改实际切片所需文件，不预建四个空服务、抽象框架或另一份数据库规范。
- 遵循 Red → Green → Refactor。修改结构只在 `backend/db/schema.sql`；禁止其他 SQL、增量脚本与运行期 DDL。新环境初始化与存量环境受控比对分开。

## 3. 工程验证方法

在仓库根或 `backend` 使用现有工具直接执行，不新建脚本/Makefile：

1. 对变更 Go 文件执行 gofmt/goimports；`go vet`、golangci-lint 检查新入口、代理、维护及测试包。
2. `go test -race ./tests/gateway ./tests/boundaries -count=1`；重复生命周期测试检查流和停机，必要时使用 `-count` 增加复现次数。
3. `go test -race ./internal/infra/maintenance/... ./tests/maintenance -count=1`；未提供专用测试 DSN 时，明确 PostgreSQL 用例跳过。只在获授权的隔离空库运行旧租约恢复，不指向现有业务库。
4. `go test ./tests/db -run 'TestBackendSQLHasCanonicalSchemaAndPresetData|TestSchemaDoesNotScheduleRetiredRuntimeDDL' -count=1`；这仅证明 SQL 来源和退休种子约束，不等于完整结构、权限与分区策略通过。
5. `go build ./cmd/gateway` 和全后端只编译检查；`govulncheck ./cmd/gateway ./internal/infra/maintenance/...` 的结果仅覆盖这些调用路径。
6. 以 `/dev/null` 为 env-file、只给内存占位值执行 `docker compose config --format json`，分别检查普通和开发叠加拓扑；捕获 JSON 后只输出结构断言，不打印凭据，也不启动容器。
7. Workspace `check:content`、变更文档/JSON 的 Prettier 和 `git diff --check`；更新 catalog 稳定 ID，不覆盖已有别名。未改公共 DTO，不重写前端生成客户端。

## 4. 验证记录与解释

### 4.1 测试先行证据（2026-11-14）

- Gateway 协议测试先因 `internal/gateway` 缺失编译失败，独立配置/停机测试再因 `internal/app/gateway` 缺失失败；随后实现真实入口与 HTTP 代理。
- 历史分区任务测试先报 `ordinary maintenance must not create partitions`；DML-only fake 对旧构造端口也编译失败，随后收窄接口并移除应用 DDL 路径。
- 以上失败只证明测试覆盖对应缺口，不代表网络拆分目标已完成。绿色验证及其环境边界见下节，并与 BACKLOG 当前状态交叉核对。

## 5. 运行交接与回退边界

- Compose 切换是代码配置交付，不自动执行 `up` 或重启现有环境。启动前由维护者核对既有依赖、端口和结构；Gateway 通过 readiness 后前端才能完整接入。
- 本地直接运行：为 Gateway 单独指定 `GLOWLOOM_GATEWAY_HTTP_ADDR`、`GLOWLOOM_GATEWAY_BACKEND_ORIGIN`，其余只读 `GLOWLOOM_ENV=local` 与日志级别；上游必须是无凭据、无路径/查询的 HTTP(S) origin。不能借入口拆分解除 backend 的 local/loopback 限制。
- 退出普通自动分区维护后，管理员必须核对预建分区覆盖窗口、监控默认分区和保留策略；不能等写入失败再让应用建表。本轮不自动处理存量权限或分区。
- Gateway 不持有业务写入权；如需撤销入口切换，由维护者在受控本地配置中恢复原拓扑，不能启动第二个数据 owner。后续领域 owner 转移后的回退另需围栏、排空和兼容证据，不套用无状态 Gateway 回退。
