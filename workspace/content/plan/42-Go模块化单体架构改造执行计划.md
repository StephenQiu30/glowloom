# Go 模块化单体架构改造执行计划

唯一来源 PRD：[PRD33：Go模块化单体架构改造](../prd/33-Go模块化单体架构改造.md)。技术合同沿 [设计47](../design/47-Go模块化单体架构与RPC集成设计.md) 展开；进度、阻塞与下一步只在 [BACKLOG](../../../BACKLOG.md) 维护。本计划替代原 Go 微服务拆分计划（已清理删除，历史见 Git）。

## 1. 前置条件与实施原则

1. **文档先行与归档清理（已完成）**：完成 `workspace/content/` 文档重构并将已替代的历史方案及一次性验收记录清理删除（历史通过 Git 追溯）；`SRC-GO-MONO-02` 已确认 **RPC 方案 A（标准 gRPC + Protobuf + Buf）** 与 **保留 Kafka 异步解耦**。
2. **小步可验证切片**：每个 Phase 结束后必须保证全量编译、核心 `go test -race` 与相关集成测试通过，不长期保留“半拆半合”的损坏分支。
3. **不保留兼容双轨**：移除微服务入口、分布式围栏与内部 HTTP 胶水后直接切换为目标实现，不保留旧别名或双写分支。
4. **数据库红线不变**：所有表结构调整仅在 `backend/db/schema.sql` 维护并通过 `backend/tests/db/schema_source_test.go` 门禁，严禁运行时 DDL 或新增 `migrations/`。

## 3. 验证方法

### 3.1 Phase 0（本轮文档改造）

在 `workspace/` 与仓库根目录执行：
1. `pnpm --dir glowloom-server/workspace format:check`（或针对变更文档定点格式化检查）
2. `pnpm --dir glowloom-server/workspace types:check`
3. `pnpm --dir glowloom-server/workspace lint`
4. 检查新增与更新文档的相对路径、锚点与 `git status --short`

### 3.2 Phase 1～7（后续代码改造）

- **Go 后端**：`gofmt`、`goimports`、`go vet ./...`、`golangci-lint run ./...`、`go test -race -count=1 ./...`、`govulncheck ./...`、依赖方向边界测试与 `tests/db/schema_source_test.go`。
- **协议契约**：`buf lint`、`buf breaking` 及生成代码零漂移核对。
- **Node 服务**：
  - `canvas/`：`pnpm typecheck`、`pnpm check`、`pnpm test`
  - `agent/`：`pnpm typecheck`、`pnpm lint`、`pnpm test`
- **前端回归**：`frontend/` 下 `pnpm api:check`、`pnpm exec tsc --noEmit`、`pnpm exec vitest run`、`pnpm exec next build`。
- **部署校验**：`docker compose --env-file /dev/null config --no-interpolate --quiet` 校验普通与开发 Compose。

## 4. 回退边界

- **Phase 0（文档）**：纯文档变更，不影响现有运行代码，可直接按 Git 提交回退。
- **Phase 1～7（代码）**：按 Phase 独立提交并验证；每个 Phase 切换前确保无未决在途任务，若某阶段验收未通过，回退该阶段提交并修复后再继续，不引入新旧双轨共存。
