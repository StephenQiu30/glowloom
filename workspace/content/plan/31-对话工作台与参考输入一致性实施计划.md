# 对话工作台与参考输入一致性实施计划

唯一来源PRD：[PRD22](../prd/22-对话工作台与参考输入一致性.md)。Goal：落实首页、共享参考输入、私有对话历史、真实回复/产物及停止/重试的完整链。Architecture：扩展现有Go公共授权代理与独立Agent合同/持久投影，前端复用Tiptap和共享壳。Tech Stack：仓库现有Next.js/React/Tiptap/shadcn、Go、TypeScript/Pi Durable、PostgreSQL。Agent HTTP 框架迁移按 [Plan28](28-完整创作Agent与Skill多Agent实施计划.md#nestjs-框架切换顺序) 执行。技术合同随PRD的唯一来源[设计35](../design/35-对话工作台与参考输入一致性设计.md)读取，不新增另一套需求。

执行方式为当前会话逐任务实施；如需子任务并行，另按用户授权及适用指令安排。下列步骤描述执行顺序与退出条件，不记录完成进度；实施状态、阻塞与下一步唯一见[BACKLOG](../../../BACKLOG.md#conversation-workspace)。

## 1. 全局约束

- 先复核AGENTS、PROJECT、当前HEAD、所有未提交/未跟踪改动和独立Agent迁移合同；保留并行改动，不创建/提交/推送分支，不清库，不重放现有初始化SQL，不启动或重启未知服务。
- 当前已授权实现不开放真实收费：不调用即梦/真实模型生成、重试收费任务或买新结果。离线schema、mock模型、隔离`*_test`数据库与浏览器拦截测试各自标注，不冒称供应商接受。
- 核心输入、权限、状态、幂等与恢复按Red→Green→Refactor。先运行新的反例证明缺口，再写最小实现；已有失败、缺测试库或跳过记录不能算通过。
- Agent单独持有执行状态；Go只保留身份/引用/审批/预算/控制权威。execution_revision与authorization_revision独立；Stop依可靠投递/应用回执。未知原请求禁止新消费。
- 前端先读已安装版本`frontend/node_modules/next/dist/docs/`的相关路由/客户端文档，应用仓库要求的Vercel React规范。沿既有API Axios/SSE和类型生成链，禁止手改生成代码。
- PromptDraft最大1MiB、提交体2MiB；会话/run页默认20最大50，消息页默认50最大100且1MiB预算、文本片段最大16KiB UTF-8。固定slot64×84、视觉48×64、输入起点76、间距12、内边距16/圆角24，移动命中44。
- 浏览器业务恢复只在当前页面内存，禁止IndexedDB/localStorage/sessionStorage业务持久化；刷新只从服务器已接受内容恢复，服务端已保存草稿与尚未保存草稿区分，不承诺找回未上传文件。

### 相邻任务共用接口

- TypeBox `AuthorizedConversationInput`：`{schema_version:1,draft,input_hash,plain_text,media_pins,quote?}`；quote为服务端冻结的公开源文，原客户端`quoted_from={run_id,message_id}`只在同session解析。
- `RunSummary`：run/session身份、accepted_revision、created_at、status、input_excerpt、retry_of_run_id；`RunPage{items,next_cursor?}`。
- `PublicMessage`：`message_id/run_id/conversation_id/sequence/part_index/kind/content`；`MessagePage{items,next_cursor?,through}`。RunSnapshot增加input、retry关联、messages_page及snapshot_cursor，旧文本run无input时只读展示goal。
- Go `ConversationInputFreezer.Prepare(ctx, principal, projectID, sessionID, json.RawMessage, *QuoteRef, modelKey) (AuthorizedConversationInput,ConversationModel,error)`；`ControlStatusReader.ReadControlStatus(ctx, principal, projectID, sessionID, runID, requestID?) (ControlStatus,error)`。实现放application/adapter，通过构造注入，不包级服务定位。
- Agent `readSubmission(sessionId,requestId,identity)`、`listRuns(sessionId,query,identity)`、`listMessages(runId,query,identity)`、`readPublicMessage(runId,messageId,identity)`；返回类型依TypeBox，公共operationId依次为`getAgentSubmission`、`listAgentRuns`、`listAgentMessages`、`getAgentMessage`；Go控制查询为`getAgentControlStatus`。
- `getCurrentAgentSubmission`对应`GET /sessions/:sid/submissions/current`，返回最近已受理/活动run与未决业务标识；刷新无本地request时只发现核对，不自动重发。内部快照的`quote`由Go解析生成，不发送未经校验的客户端引用正文。
- 前端`canSubmitConversation({draft,planningModel,authorized,budget,busy,active})`返回`{allowed,reason?}`；`mergeRun/mergeMessages`只按稳定ID和revision合并；`useConversation({projectID,sessionID?})`暴露`snapshot/history/draft/send/stop/retry/refresh/loadOlder`，所有异步作用域显式绑定。

## 3. Review Focus

1. session创建成功但响应丢失，不能重复建历史：Task1/5覆盖相同创建键重投与刷新恢复。
2. 删除参考后晚到上传、切空间后晚到预览：Task2/4/5覆盖代次与bindingGeneration，不复活/串私有图。
3. 单run超过100条事件与文本超大：Task3/5覆盖分页through、消息分段、终态尾消息，不能只保留最新窗口。
4. Stop响应未知、刷新及Agent离线：Task1/6覆盖Go决定查询与pending恢复，不显示假stopped。
5. 旧run业务结果未知与新草稿同时存在：Task2/6/7覆盖服务器拒绝新收费重试、当前草稿不被原输入覆盖。
