# 画布编辑与素材实施计划

> 唯一来源PRD：[05-画布编辑与素材](../prd/05-画布编辑与素材.md)。进度与阻塞见[BACKLOG](../../../BACKLOG.md)。

## 1. 目标

完整画布用于正式 `/canvas`，接入当前账号、项目、素材、任务及Yjs会话；节点、Tiptap正文、引用与布局保存后可重新打开。

## 2. 交付范围

按需求06的FR-CAN-01～23及AC-CAN-01～24核对节点编辑、媒体工具、生成与工作流、协作与恢复、个人视图、侧栏和项目交互。产品命名统一为织光/Glowloom，保留来源许可。

## 3. 实施顺序

核对来源功能清单与业务合同→接入正式编辑器→适配节点及素材→接入生成与工作流→联合验证Yjs、持久化与恢复→依据最终Figma稿验证页面展示。各能力的实现和接受分别记录。

## 4. 依赖

数据与引用沿[计划17](17-画布数据库持久化与DAG实施计划.md)，长连接沿[计划18](18-画布WebSocket实时同步实施计划.md)，协作及个人撤销沿[计划19](19-画布Yjs协作编辑实施计划.md)。应用通过Docker启动，复用现有基础依赖。

## 5. 验证矩阵

覆盖节点创建、编辑、删除、复制、分组、连线、素材处理、正文与引用、参数和生成来源；检查鼠标、键盘、IME、手势取消、只读、窄屏、异常及个人视图隔离。真实身份与数据库验证上传→编辑→持久确认→关闭重开，单独验证未知回执及断线恢复。

## 6. 数据保护

未知结构保留或只读，不静默丢弃；读取失败不回写空图。素材和引用使用稳定身份，异步结果绑定发起范围。迁移与恢复先备份、演练并逐项比对，不清理既有业务数据。

## 7. 证据口径

记录实际版本、环境、命令与覆盖项；夹具、浏览器、数据库和真实供应商证据分开。必要的版本化实施结果在 BACKLOG 与 Git 追溯。

## 9. 正式画布技能工作流验收

承接 PRD 05 的 AC-CAN-26。frontend 将技能流程接入正式 Yjs 画布工具栏，复用协作会话完成一次图编辑和确认读取，移除旧页面及其专用保存和工作流装配。Go 和独立 Canvas 运行时沿已有数据及传输合同工作。

| 场景              | 前置与操作                                                                                          | 退出条件                                                                                          |
| ----------------- | --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| CASE-CAN-SKILL-01 | 用授权账号从正式路由打开已有内容的普通画布，选择技能模板，等待已保存，刷新并重新打开技能流程          | 对照原画布及刷新后的组、节点、正文和边，检查身份稳定且无重复插入。全程无 Agent 运行请求              |
| CASE-CAN-SKILL-02 | 在提交尚未确认时打开运行准备，随后收到保存回执                                                      | 运行输入来自已确认图，修订与图哈希和该版本一致。执行须另行提交                                      |

使用独立 PostgreSQL、Go 浏览器夹具和 Canvas gRPC 进程。回退应用版本时按现有画布合同读取已保存节点，无需变更数据库结构。

### 9.1 验收证据

2026-11-26 在基线 `1a984f3fc` 的实现工作区验证。用 `go test -tags browserqa ./tests/canvas -run '^TestYjsBrowserFixture$'` 启动独立 PostgreSQL 上的正式 Go 路由，连接独立 Canvas gRPC，以 Chromium 打开 `/canvas`。改动前画布已保存但无法找到技能流程入口，改动后使用 Next.js 开发实例及 standalone 生产构建分别复验。

- CASE-CAN-SKILL-01 实测通过。1440px 桌面插入「小说改编与分镜」，新增 1 组、7 个技能正文节点和 11 条边。390px 窄屏插入「短剧创作与审查」，新增 1 组、12 个技能正文节点和 16 条边。两次均收到接受回执，刷新后从服务端重读图哈希、节点身份、分组、正文和边，并能重新打开技能流程。PostgreSQL 最终读回修订 4、提交序号 2、2 条接受回执、24 个节点和 27 条边。全程未提交 Agent 运行。
- CASE-CAN-SKILL-02 由会话与技能控件定向测试验证。待确认时等待，确认后将同一快照的图、修订号及图哈希用于运行准备。运行实际供应商流程不在本次验收范围。
