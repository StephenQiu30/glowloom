# Plan 36｜模型销售定价与结算

唯一来源 PRD：[PRD27 · 模型销售定价与结算](../prd/27-模型销售定价与结算.md)。协作计划：[Plan35 · 号池接入与路由](35-模型号池接入与路由执行计划.md)。

## 目标与前置

打通管理员定价、创作入口报价、余额冻结、一次结算及迟到回执核对。隔离环境准备定价管理员、普通成员、余额足够与仅够一单的付款空间，以及按张、按秒、按 Token 的价目和脱敏回执。真实渠道价格版本、用量单位、预算和可归属账单是实单接受的输入。

## 验证样例

| 给定输入 | 检查点 |
| --- | --- |
| 基准 ¥7.56，1.5 倍，8 折；再发布 10 折 | 旧有效报价保持 91，新报价 114。相同确认键重放仍只有一次冻结。 |
| 确认上限 91，实际基准 ¥6 或 ¥8 | 分别得到实扣 72 或封顶 91。销售差额与渠道采购金额分别可查。 |
| 视频只提供预估秒价，销售合同按 Token；备线只回播放秒数 | 确认前排除无法提供计量证据的线路。若已交付却丢失用量，按原单追账，保留资金待核对。 |
| 一个钱包仅够一单，两个执行者同时确认；随后重启并重复投递回执 | 至多一笔成功冻结及派发。余额始终非负，核销与释放合计等于原冻结额。 |

## 初始化、回退与证据

从空销售目录发布首个有价规格。隔离余额通过测试夹具准备。后续撤回错误价格时停止用该版本出新报价，发布修正版本，保留有效报价、已确认任务与流水。已有结算错误时通过关联原流水的更正记录修复。演练在途改价及更正重放，检查用户累计实扣上限。

记录价格版本、报价输入和明细、业务任务与尝试编号、采购回执、资金流水及余额前后值。模拟回执与真实账单分别标明来源。缺少实账时保持该组合待验证。本轮覆盖独立折扣的不可变价格发布、后台服务端试算与实际用量计算。隔离 PostgreSQL 核验了采购与销售成对发布、重放及价格来源。浏览器试算、实际任务与采购凭证状态见[验收记录](../research/2026-11-13-模型号池与销售计费验收.md)。状态归 [BACKLOG](../../../BACKLOG.md#pool-sale-plans)。
