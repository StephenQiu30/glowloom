# Go微服务拆分 PRD

唯一来源：[设计44 Go微服务架构与技术选型](../design/44-Go微服务架构与技术选型设计.md)。原始确认经来源设计追溯至需求29 SRC-GO-MS-02。本文定义接受合同，不新增模型、支付、知识库或协作产品范围。

## 1. 目标与边界

将已有 Go 业务后端演进为 Identity、Creation、Media、Execution 四个业务服务与轻量 Gateway。Operation、Catalog、Billing 保持在 Execution 内，以事务语义、唯一写入权和独立运行证据判定拆分，不按目录或容器数量计数。

首个切片是可独立运行、无业务数据库连接的 Gateway，以及普通维护的运行期 DDL 移除。四个业务服务的独立写入权须逐域满足设计44 §8.1；不在该切片预建四个空服务，也不以 Gateway 上线替代全量目标。

不含生产部署、存量库结构或角色操作、真实付费模型调用、提交/推送，以及 Agent、Canvas、研发 Workspace 的全 Go 改写。

## 2. 使用者与价值

- 用户继续通过现有工作台和 `/api` 使用创作、素材及生成能力，不因入口拆分更换登录/幂等身份或丢失流式协作。
- 工程维护者可独立构建、配置、观察及停止公开入口，而不加载账务、存储与任务运行时。
- 数据库管理员保留唯一结构与受控分区操作，不再由普通 worker 自动创建、挂接或删除分区。

## 3. 接受场景

| ID | 前置与动作 | 可观察结果 | 来源 |
| --- | --- | --- | --- |
| AC-GMS-01 | 不提供 DB、Redis、Kafka、对象存储或身份密钥，独立启动 Gateway | 仅按自身监听地址、上游 origin 和日志配置工作；构建依赖闭包无业务模块及数据库/消息驱动 | 设计44 §7.14 |
| AC-GMS-02 | 同站请求经 Gateway 访问 `/api`，含写入、登录 Cookie、编码路径/查询和原幂等键 | 公共请求/响应语义及原状态保持；业务后端继续负责鉴权、资源权限和写入准入，不重生成业务合同 | 设计44 §7.6、§7.14 |
| AC-GMS-03 | 访问 `/internal`、伪造转发/身份头，或提交歧义路径/非法查询 | 非公开路由不转发；伪造头不成为身份权威；非法路径不被规范化后转到其他业务端点 | 设计44 §7.14 |
| AC-GMS-04 | 上游写入后丢失回执、依赖不可用或超时 | Gateway 不自动重放副作用；返回可关联的 Problem、不泄露地址/凭据；原请求恢复仍使用业务 owner 的已有查询 | 设计44 CASE-GOMS-03、§7.14 |
| AC-GMS-05 | SSE 输出后尚未完成；WebSocket 双向通信；随后客户端取消或进程停机 | 首帧不被缓冲；二进制升级通信保留；取消到达上游，停机关闭升级连接并等待所拥有 handler | 设计44 CASE-GOMS-09/10、§7.14 |
| AC-GMS-06 | 后端不就绪或退出 | Gateway 存活探针不依赖后端，readiness 有界失败且不回显后端诊断；恢复后可重新就绪 | 设计44 §7.11、§7.14 |
| AC-GMS-07 | 执行全部普通维护 handler，包括历史分区任务及重启后的过期租约 | Outbox/Inbox 保留 DML 清理；历史分区任务完成、不重试重排、不执行 DDL；空库规范不再播种该任务 | 设计44 CASE-GOMS-12 |
| AC-GMS-08 | 解析普通/开发 Compose | frontend → gateway → backend，无健康依赖环；1123 只公开 Gateway，backend 无宿主映射；Agent 内部调用不经过 Gateway；开发 watch 对应真实入口 | 设计44 §7.14 |
| AC-GMS-09 | 宣布任一业务域独立 | 有模块/数据/任务/事件/密钥 owner 清单、禁止跨域访问的角色证明、原事务等价协议、恢复/撤权/关闭与独立运行证据；缺一不称完成 | 设计44 G-GOMS-01～05 |

## 4. 验证层次

协议夹具、race、依赖闭包和 Compose 静态解析属于工程证据，不代表真实登录、数据库权限、部署或供应商接受。AC-GMS-07 的历史租约恢复须在隔离 PostgreSQL 验证；没有专用环境时明确未执行，不连接存量业务库替代。AC-GMS-09 逐域验证，不能由 Gateway 切片推定。
