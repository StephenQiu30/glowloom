# Workspace 知识库与研发工作流 PRD

文档状态：技术选型和双版边界已确认；产品接受条件待实施验证，非验收记录。

唯一来源：[设计43](../design/43-Workspace知识库与研发工作流服务设计.md)。本 PRD 将其方案细化为产品范围、用户故事和接受条件，不新增来源设计。执行拆解见 [Plan38](../plan/38-Workspace知识库与研发工作流执行计划.md)，实施状态、优先级和排期只见 [BACKLOG](../../../BACKLOG.md#workspace-20261114)。

## 1. 摘要与交付边界

在业务代码同一 Git 仓库建立可独立运行、构建和部署的 `workspace/`，把现有项目文档沉淀为人和 Agent 共用的知识库，并承载 Skill、研发工作流、工程关联与文档朗读。Git 中的正文是知识权威，页面、搜索、上下文包和朗读都是同一版本的派生产物。

先完成文档无损迁移与静态阅读，再提供可发现的 Skill 和可交接的工作流定义，随后增加在线编辑、持久运行及首个实际执行器。预生成音频的静态讲读可在静态阅读完成后独立交付；真实 TTS 生成在缓存、费用授权和回执恢复可验证后接入。

SRC-WS-07已确认Markdown／Git、Next.js／React／TypeScript、Tailwind／shadcn、Geist／Neutral、Node24／pnpm、Pagefind、Mermaid、静态export、在线standalone与PostgreSQL独立schema，以及原生音频／cue播放路线。具体合同以设计43 §7.2、§7.6为准。

SRC-WS-08已授权本地完整实施，按下列接受合同验证；SRC-WS-09暂不启用真实TTS。范围内的构建、解析、播放器与本机在线协作分别验证，真实供应商、团队SSO、远程部署及效率提升幅度不得从本地检查推定。当前进度和未覆盖项只在根BACKLOG维护。

本机在线首版使用单所有者访问令牌、CSRF／Origin保护、受限PG与认证Unix执行桥；写文档须提交并审阅提案，实际落地前再次比对修订。执行前冻结TaskContext，主机原句柄断连后先查状态，未知时不重派；阶段接受不能代替产品、提交或发布接受。部署与音频导入操作合同见[使用与部署](../templates/04-Workspace使用与部署.md)。

## 3. 背景与问题

现有文档已经具有 requirement → design → PRD → Plan 的主链，但依赖文件管理器或编辑器阅读。进入项目、定位上下游与交接任务仍需要人工解释；缺少独立静态展示、统一搜索、Skill 发现验证和可恢复的运行记录。朗读材料目前也没有版本、切片与正文定位合同。

设计43的调研清单是历史基线，实际迁移必须重扫当前 Git、未跟踪知识文件、附件及脏修改，不能用旧文件总数作为无损证明。第三方截图用于理解职责分工；受限正文、未取得源码和演示中的宣传不构成我们的验收事实。

Workspace 服务与完整知识树同仓，便于同次评审文档和代码。现有 frontend、backend、agent、canvas 仍拥有业务实现；根规范、业务 schema、预设数据和生成契约保持原归属。研发 Workspace 与产品中的画布 workspace、用户会话和创作 Agent 分别负责各自状态。

## 4. 目标、衡量与约束

### 4.1 可衡量目标

| 目标         | 接受信号                                               | 取证方式                                                     |
| ------------ | ------------------------------------------------------ | ------------------------------------------------------------ |
| 找到正确知识 | 从中文关键词或业务 ID 定位正确文档、章节和来源设计     | 固定真实问题集，保留首次定位时间、命中文档和版本             |
| 无损且唯一   | 每个应迁移文件有唯一去向，引用可达，未授权变化未被覆盖 | 当前清单、摘要、链接／锚点报告与迁移差异                     |
| 静态独立可用 | 无业务 API、中间件、模型连接时仍能阅读、搜索和看图     | 相同产物的独立托管验收，记录网络依赖                         |
| 任务可以交接 | 新会话据输入包找到工程入口，恢复原运行而无重复副作用   | 固定版本的任务包、句柄、尝试与恢复证据                       |
| 降低重复劳动 | 定位、审阅、返工、交接和合成复用的变化可比较           | 实施前后使用同类任务记录人工耗时、总耗时、返工次数与实际费用 |

功能必须满足本文接受条件。效率先记录基线再比较，不预设节省百分比、固定秒数或虚构人效；缺失费用、未知耗时显示未知，不能计为零。性能预算在实施前用实际全量文档、390px 设备和目标托管环境定标并记录到 BACKLOG，不能只有空页面跑分。

### 4.2 范围约束

- 根 AGENTS、PROJECT、DESIGN、BACKLOG 保留根位置；实施调度只写 BACKLOG。流程运行日志、截图、音频和测试报告使用受控产物及引用，不向知识正文持续追加原始日志。
- 目标正文在 `workspace/content/`，迁移完成后不维护可写的旧 docs 副本。Skill 正文在 `workspace/skills/`，原生发现入口只关联唯一来源；不复制业务源码进 Workspace。
- 数据库结构只由 `backend/db/schema.sql` 定义，公共预设只由 `backend/db/data.sql` 定义；无增量 SQL 迁移目录、自动迁移或运行时 DDL。
- 复用既有视觉与工程基线；已确认技术栈按设计43实施，具体依赖版本和许可在实施时锁定；选型确认不等于服务已存在。
- 本范围不建设通用编排 SaaS、向量数据库、自研模型循环、自动多 Agent 平台或全量语音克隆。静态阅读不依赖这些能力。

## 5. 用户与核心场景

| 用户               | 任务／痛点                               | 获得的结果                                       | 替代方式与选择理由                                       | 使用频率                   |
| ------------------ | ---------------------------------------- | ------------------------------------------------ | -------------------------------------------------------- | -------------------------- |
| 阅读与评审者       | 找当前方案、核对上下游、长文阅读耗时     | 有版本的目录、搜索、关系图和可选朗读             | 相比逐文件查找，统一定位并保留原文；不生成另一份权威摘要 | 每次范围或交付评审         |
| 实施者与研发 Agent | 新会话缺上下文，工程入口和有效命令不明确 | 有限上下文包、工程引用、适用 Skill、可继续的任务 | 相比复制聊天记录，引用可核对的修订、授权和真实句柄       | 每次任务进入与交接         |
| 知识及服务维护者   | 文档过期、双份编辑、运行状态与发布混淆   | 可审阅提案、冲突保护、独立产物及真实接受状态     | 相比手工同步多个知识库，维护单一正文和版本化派生物       | 文档修改、流程变更及发布时 |

以上按“对象、任务、痛点、收益、替代方式、选择理由”表达价值；角色名不要求先搭建多角色 Agent。小变更允许采用轻量流程，省略阶段须说明理由，不强制产生空文档。

### 6.2 知识库界面

| 页面           | 必须呈现的内容与动作                                   | 静态模式及异常                                           |
| -------------- | ------------------------------------------------------ | -------------------------------------------------------- |
| W01 首页       | 当前产物版本、知识分类、主链入口、最近内容修订         | 最近修订来自构建版本；无实时运行或部署状态假数据         |

| W04 知识关系   | 唯一来源主链与普通引用分开，节点返回原文               | 从实际声明和链接生成；图有文字替代，不推测依赖           |
| W05 Skill      | 触发／不适用条件、依赖、版本、验证入口、正文           | 阅读、查看或安装入口不自动执行脚本                       |

| W07 运行与交接 | 实际阶段、尝试、原句柄、证据、等待与未知原因           | 仅在线；未接主机显示不可用，不能用演示数据冒充真实运行   |

延续根视觉规范的中性色、字体和 shadcn；长表格与代码独立横向滚动，390px 不造成整页横溢。键盘可打开／关闭目录并返回焦点；正文、页内目录和播放器焦点互不抢占。静态页面直接刷新、中文路径、锚点、部署 base path 和 404 均须真实托管验证。

### 6.5 静态版与在线版的产品交付边界

| 用户可见边界     | 静态版                                               | 在线版                                                                    |
| ---------------- | ---------------------------------------------------- | ------------------------------------------------------------------------- |
| 阅读与知识版本   | 固定StaticRelease；目录、原文、图表、搜索和资源同版  | 展示内含知识快照及在线修订来源；草稿与已发布内容明确区分                  |
| 编辑、任务与主机 | 展示说明／原文入口，不提供写入或执行                 | 身份及权限通过后可提案、审阅、落地、发起和恢复实际运行                    |
| 朗读             | 只播放同版已归档音频／cue，无生成依赖                | 复用播放器；真实生成另需供应商、音色和预算授权                            |
| 运行环境         | 纯静态HTTP托管；不需要Node、PG、业务服务或模型在线   | Node24运行standalone；PG保存在线记录，执行与合成按各自外部连接可用性呈现  |
| 访问控制         | 完整内部产物由托管层保护；公开范围先过滤后生成       | 会话／角色与项目范围检查；正文、raw、搜索、音频同样受控                   |
| 更新与故障       | 内容变化须重建完整产物；发布失败保留旧站             | 在线升级独立；数据库／主机异常如实呈现，不改静态版状态                    |
| 验收与回退       | 在无Node运行时的独立托管验收；回退整包，不改业务数据 | 从无构建工作区的运行包启动验收；回退先核对schema兼容，不回放SQL或重派任务 |

双版共享知识正文、内容模型和阅读组件，各有构建入口、配置、缓存、产物和版本回执。同次构建可使用同一知识快照；分别发布后版本允许不同，界面须标明实际来源。不存在把静态产物启动为在线服务的“部署开关”；在线编辑不会自动改写已发布静态站，静态发布也不重启在线服务。具体命令、路径及打包规则由设计43 §7.6.1和Plan38 §3.3维护。
