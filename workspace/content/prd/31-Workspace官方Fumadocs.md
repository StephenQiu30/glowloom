# Workspace 官方 Fumadocs

唯一来源设计：[设计45](../design/45-Workspace官方Fumadocs设计.md)。原始需求见设计中的来源链接。

## 用户与价值

项目成员与研发 Agent 从同一份 Markdown／Git 内容了解需求、设计、PRD、计划、Skill 和工作流；访问者直接打开知识库，搜索并阅读所需章节。

## 范围

采用正式 Fumadocs UI／MDX，单入口、免登录阅读、中文内容目录、全文搜索、图表、原始 Markdown 和 CSV 下载。保留旧文档 ID 及可承接的引用。Skill 与工作流仅作为文档，不提供任务执行、在线提案或语音服务。

## 验收标准

| ID | 用户可见结果 | 验证 |
| --- | --- | --- |
| AC-FD-01 | 原有 content 文件和并行修改保留；迁移的 Skill／工作流原文一致 | 逐文件哈希，迁移前后及当前工作树比较 |
| AC-FD-02 | 现有 Markdown 的阅读 ID 和 raw 地址可用，CSV 下载内容一致；旧别名导向对应内容 | 全量 HTTP 请求及文件比较 |
| AC-FD-03 | 官方侧栏、TOC、代码块、图表正常；每篇正文主标题不重复 | 实际浏览器阅读与 Mermaid SVG |
| AC-FD-04 | 快捷键开启官方搜索，内置 `/api/search` 查询返回内容，点击可到达正文 | 浏览器及接口验收 |
| AC-FD-05 | 1130只有一个知识站，直接阅读与搜索；旧协作和任务 API 不存在 | HTTP／浏览器，旧入口404，无令牌表单 |
| AC-FD-06 | 手机无页面横溢，侧栏可开合，键盘焦点和深浅主题可用 | 移动与桌面浏览器 |
| AC-FD-07 | 标准 Next.js 与知识库质量门禁通过，不依赖业务 PG、桥或 TTS | `docs:check`／`lint`／`types:check`／`format:check`／`build`／`test:e2e`；CI 配置检查 |
| AC-FD-08 | 工具过程文档不出现在目录、阅读、原文或搜索；COS 归部署运维，文档编号在分类内唯一且导航与页标题一致，原 ID／链接可用 | 文件与引用检查、页面／raw／旧别名、真实索引和浏览器核验 |
| AC-FD-09 | 桌面／手机导航显示项目正式 Logo，浏览器及 Apple 图标可加载，深浅主题清晰可辨 | 浏览器实际图片加载、响应式和主题核验、原生图标 URL 检查 |
| AC-FD-10 | 正文直接保存在 `workspace/content/`；既有 `/docs` 阅读、导航、搜索、Markdown 和 GitHub 源文件入口正确 | 文件清单与引用检查、构建及真实浏览器验证 |
| AC-FD-11 | 打开根路径即可进入文档索引；专题文档的侧栏、唯一主标题和搜索使用同一编号文件名 | 浏览器核对根路径、标题、搜索结果、原文和原阅读地址 |

## 排除范围与接受边界

不保留自研文档底座、双构建、运行器和 TTS。标准 Next.js 预渲染不等于额外提供纯静态部署包。本机通过不代表远程部署或 CI 终态已通过；仅当实际运行后记录相应结论。实施进度与未覆盖项只在根 BACKLOG。
